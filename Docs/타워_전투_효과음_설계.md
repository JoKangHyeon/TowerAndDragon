작성일: 2026-08-23

관련 문서: [마일스톤](./타워_전투_효과음_마일스톤.md) · [구현 현황](./구현현황.md) · [타워 투사체 연출 설계](./타워_투사체_연출_설계.md) · [타워 이펙트 작업 노트](./타워이펙트_작업노트.md)

이 문서는 다른 개발자나 AI 에이전트가 추가 판단 없이 타워 효과음 작업을 이어받을 수 있도록 만든 실행 명세다.
기획 내용은 `기획종합_v2.md`가 우선하며, 이 문서는 기획을 복제하지 않고 현재 코드에 효과음을 붙이는 방법만 다룬다.

> 프로젝트 규칙상 생성형 도구로 음악·SFX를 새로 만들지 않는다. 필요한 소리는 이미 팀 저장소에 있는
> `Assets/Imported/Gamemaster Audio - Pro Sound Collection/`에서 청취해 고른다. 적절한 클립이 없으면
> 임의로 생성하지 말고 팀에 에셋을 요청한다.

## 1. 확정 결정

다음 항목은 2026-08-24 논의에서 확정됐다. 작업자는 임의로 되돌리지 않는다.

1. 공격 또는 회복 투사체가 있는 타워는 **발동 시점의 Launch음**과 **도착 시점의 Resolve음** 두 가지를 사용한다.
   - 공격 타워의 Resolve는 명중/파열음이다.
   - 생명 타워의 Resolve는 파괴적인 충격음이 아니라 치유 적용음이다.
2. 오라형 타워(시간·은신·영혼·강화)는 투사체가 없으므로 Launch/Resolve음을 억지로 넣지 않는다.
   - 이번 범위에서는 오라가 비활성에서 활성으로 바뀔 때 공용 `AuraOn`을 한 번만 재생한다.
   - 오라 지속 루프와 `AuraOff`는 이번 범위 밖이다.
3. 사운드 ID와 타워별 배선은 `TowerData`가 소유한다.
4. 신규 `SoundId`는 기존 enum과 `SoundCatalog.asset`의 **끝에만 추가**한다.
5. BGM과 기존 효과음은 지금 방식 그대로 두고, **타워 효과음만** 카메라 화면 기준으로 감쇠·컷오프한다(§6-0).
6. 소리 우선순위(강한 타워가 약한 타워를 밀어내는 규칙)는 이번 범위 밖이다. 화면 밖 컷오프 후에도 풀이 포화되면 그때 설계한다.

### 용어

- **Launch**: 타워가 공격 또는 회복 투사체를 실제로 발사하는 순간. “머즐 효과음”과 같은 뜻으로 사용한다.
- **Resolve**: 투사체가 목적지에 도착해 명중 VFX와 공격/회복 효과를 적용하는 순간.
- **AuraOn**: 오라형 타워가 실제 가동 조건을 충족해 오라가 활성화되는 순간.

`Fire/Impact` 대신 `Launch/Resolve`를 쓰는 이유는 생명 타워의 치유도 같은 데이터 구조로 자연스럽게 표현하기 위해서다.

## 2. 범위와 타워 분류

### 2-1. 투사체·효과 적용형

| 타워 | 실제 데이터 | 이벤트 | 사운드 쌍 | 방향 |
|---|---|---|---|---|
| 마나 | `TD_Arrow` | Launch + Resolve | `Mana` | 마법 차징 → 짧은 에너지 파열 |
| 석궁 | `TD_CrossBow` | Launch + Resolve | `Crossbow` | 시위 발사 → 짧고 둔탁한 타격 |
| 머스킷 | `TD_Musket` | Launch + Resolve | `Musket` | 탄환 비행 → 묵직한 포성 |
| 대공 | `TD_Anti_Air` | Launch + Resolve | `AntiAir` | 마법 차징 → 짧은 에너지 파열 |
| 불 | `TD_FireTower` | Launch + Resolve | `Flame` | 화염 투사 → 폭발과 잔불 |
| 얼음 | `TD_IceTower` | Launch + Resolve | `Frost` | 결정성 냉기 → 얼음 파쇄 |
| 암석 | `TD_StoneTower` | Launch + Resolve | `Boulder` | 낮고 무거운 투척 → 암석 강타 |
| 생명 | `TD_LifeTower` | Launch + Resolve | `Life` | 따뜻한 치유 방출 → 부드러운 치유 적용 |

타워 8종이 각각 고유한 Launch/Resolve 쌍을 가지므로 **투사체형 신규 ID는 16개**다.
마나·석궁이 한 쌍을 공유한다는 이전 설계는 폐기됐다. 다만 대공·생명의 일부 클립은 마나와 같은 파일을 쓴다(§7).

### 2-2. 오라형

| 타워 | 실제 데이터 | 현재 동작 | 이번 이벤트 | 방향 |
|---|---|---|---|---|
| 시간 | `TD_TimeTower` | 공속·재활성화 속도 오라 | `AuraOn` | 공용 버프 활성음 |
| 은신 | `TD_StealthTower` | 은신 오라 | `AuraOn` | 공용 버프 활성음 |
| 영혼 | `TD_SoulTower` | 보너스 인구 오라 | `AuraOn` | 공용 버프 활성음 |
| 강화 | `TD_EnhancementTower` | 공격력 강화 오라(`TAD_EnhancementAura`) | `AuraOn` | 공용 버프 활성음 |

오라형 4종은 **하나의 공용 ID `TowerAuraOn`**을 쓴다. 따라서 이번 작업의 신규 `SoundId`는 **총 17개**(투사체 16 + 오라 1)다.
가시 타워(`TD_ThornTower`)는 투사체도 오라도 없으므로 이번 범위에서 제외한다.

### 2-3. 범위 밖

- 새끼용(`BD_*`), 몬스터, 용 스킬의 신규 효과음
  - 단, `TowerAttack`의 공용 발사음 제거로 새끼용이 조용해지는 회귀를 막기 위해 새끼용 데이터 5종의
    `_launchSound`에는 기존 `SoundId.TowerFire`를 마이그레이션 배선한다. 신규 클립이나 Resolve음은 추가하지 않는다.
- 타워 건설·피격·비활성화·부활 효과음
- 오라 해제음과 지속 루프
- 적 재질별 명중음 분기
- 3D 팬닝·도플러(좌우 정위). 거리 감쇠는 §6-0으로 이번 범위에 포함된다
- 소리 우선순위 기반 소스 뺏기
- 생성형 도구를 이용한 SFX 제작

## 3. 현재 코드 상태

### 3-1. 사운드 기반

현재 구조는 다음과 같다.

```text
SoundId enum
  ↓
SoundCatalog.asset
  └ SoundEntry { Clip, Volume, PitchRange, MinInterval }
  ↓
SoundManager.Play(SoundId)
  └ 2D AudioSource 풀 × 12, AudioMixer의 SE 그룹
```

이미 구현되어 있어 재사용할 기능:

- `SoundEntry.NextPitch`: 재생마다 피치를 무작위로 바꾼다.
- `SoundEntry.MinInterval`: 같은 ID가 너무 짧은 간격으로 겹치는 것을 막는다.
- `SoundManager.TakeSeSource()`: SE AudioSource 풀을 순환한다.
- 클립이 비어 있으면 경고 없이 무음 처리한다. 에셋 선정 전 상태도 안전하다.

### 3-2. 공격 타워 경로

```text
TowerAttack.Fire()
  ├ Launch음 재생 위치
  ├ 투사체 없음 → AttackSO.Execute()
  └ 투사체 있음 → ProjectilePool.Spawn()
                     → Projectile.Launch()
                     → 도착
                     → ApplyHit()
                     → ProjectileVisual.OnHit()
                     → Resolve음 재생 위치
                     → 풀 반납
```

현재 `TowerAttack.Fire()`는 일반 타워와 공격 모드 새끼용 모두에서
`SoundManager.Play(SoundId.TowerFire)`를 하드코딩해 호출한다.
`Projectile`은 발사한 타워의 사운드 정보를 보관하지 않는다.

### 3-3. 생명 타워 경로

생명 타워는 일반 적 공격 경로를 사용하지 않는다.

```text
LifeTower.CanAttackInCurrentMode == false
  ↓
TowerAllyHealer.Fire()
  ├ 현재 공용 TowerFire 재생
  ├ 아군 타워를 대상으로 Projectile 직접 Instantiate
  └ Projectile.Launch()
```

따라서 `TowerAttack`만 수정하면 생명 타워가 누락된다. `TowerAllyHealer`를 반드시 함께 수정한다.

### 3-4. 오라형 경로

`TD_TimeTower`, `TD_StealthTower`, `TD_SoulTower`, `TD_EnhancementTower`는 `_attack`과 `_projectilePrefab`이 비어 있다.
오라 활성 여부는 `TowerAuraSystem.TryGetActiveAura()`가 다음 조건을 실시간으로 판정한다.

- 타워가 부활 중이 아님
- 마비 상태가 아님
- 유효한 `TowerAuraDataSO`가 있음
- 일반 타워는 `ITowerStaffing.CanOperate == true`
- 계산된 오라 반경이 0보다 큼

현재 오라 활성/비활성 전환 이벤트는 없다. `AuraOn`을 구현하려면 상태 전환을 감시하는 작은 컴포넌트가 필요하다.

### 3-5. 직렬화 주의사항

- 현재 `SoundId`는 0~13이며 `SoundCatalog.asset`이 정수로 직렬화한다.
- enum 중간에 새 값을 끼우면 기존 모든 사운드 배선이 밀린다.
- enum 기본값 0은 `UiButtonClick`이다.
- 새 `TowerData` 필드를 `SoundId`로 바로 선언하면 미배선 타워가 UI 클릭음을 낼 수 있다.

## 4. 데이터 설계

### 4-1. `OptionalSoundId`

신규 파일: `Assets/Scripts/Sound/OptionalSoundId.cs`

```csharp
[System.Serializable]
public struct OptionalSoundId
{
    [Tooltip("끄면 이 사운드는 재생되지 않는다. 값을 채우지 않은 기존 에셋의 기본 상태다.")]
    [SerializeField] private bool _isEnabled;

    [SerializeField] private SoundId _id;

    public SoundId? Value => _isEnabled ? _id : null;
}
```

기본값이 무음이므로 미배선 데이터가 엉뚱한 UI 클릭음을 내지 않는다. 다만 현재 공용 `TowerFire`를 내는
새끼용까지 자동으로 무음이 되므로, 새끼용 데이터 5종에는 기존 `TowerFire`를 명시적으로 배선해 동작을 보존한다.

### 4-2. `TowerData` 필드

수정 파일: `Assets/Scripts/Buildings/Tower/TowerData.cs`

```csharp
[Header("Sound")]
[Tooltip("공격 또는 회복 투사체를 발동하는 순간 재생할 효과음.")]
[SerializeField] private OptionalSoundId _launchSound;

[Tooltip("투사체가 목적지에 도착해 공격 또는 회복 효과를 적용할 때 재생할 효과음.")]
[SerializeField] private OptionalSoundId _resolveSound;

[Tooltip("오라가 비활성에서 활성으로 바뀔 때 한 번 재생할 효과음.")]
[SerializeField] private OptionalSoundId _auraOnSound;

public SoundId? LaunchSound => _launchSound.Value;
public SoundId? ResolveSound => _resolveSound.Value;
public SoundId? AuraOnSound => _auraOnSound.Value;
```

사운드를 `AttackSO`에 두지 않는다. `AttackSO`는 일반 타워와 새끼용이 공유할 수 있어 한쪽 배선이 다른 쪽으로 전파되기 때문이다.
오라음도 `TowerAuraDataSO`가 아니라 `TowerData`에 둔다. 오라 수치가 아니라 소리를 내는 타워의 정체성에 속하는 데이터다.

## 6. 런타임 구현 명세

### 6-0. `SoundManager` 위치 기반 오버로드

수정 파일: `Assets/Scripts/Sound/SoundManager.cs`, `Assets/Scripts/Sound/SoundCatalog.cs`

BGM과 기존 UI·건설·몬스터 효과음은 지금 방식 그대로 둔다. **타워 효과음만** 위치를 넘기는 오버로드를 쓴다.

```csharp
public static void Play(SoundId id, Vector3 worldPosition)
```

감쇠는 월드 거리가 아니라 **화면 기준**으로 계산한다. 카메라가 오르소그래픽이고 줌으로 보이는 범위가 바뀌므로,
월드 거리를 쓰면 줌아웃했을 때 화면에 보이는 타워가 안 들리는 일이 생긴다.

- `Camera.main.WorldToViewportPoint(worldPosition)`으로 뷰포트 좌표를 구한다.
- 화면 중심에서의 거리: `d = Max(|vp.x - 0.5|, |vp.y - 0.5|) * 2`. 화면 가장자리가 정확히 `1.0`이다.
- `d <= _seFullVolumeViewportRatio` — 감쇠 없음.
- 그 바깥은 `_seCutoffViewportRatio`까지 선형으로 0까지 줄인다.
- `d >= _seCutoffViewportRatio` — **재생하지 않는다.**
- 최종 볼륨은 `entry.Volume * falloff`다.

좌우 정위도 같은 뷰포트 좌표로 처리한다. 화면 왼쪽 타워는 왼쪽에서 들린다.

```csharp
source.panStereo = Mathf.Clamp((vp.x - 0.5f) * 2f, -1f, 1f) * catalog.SePanAmount;
```

구현 규칙:

1. 재생 파라미터 3개(감쇠 2 + 정위 1)는 `SoundCatalog`에 둔다. 씬마다 있는 `SoundManager`에 두면 `SampleScene`과 `Tutorial` 값이 어긋난다.
2. 거리로 걸러낸 재생은 `_lastPlayTimes`를 갱신하지 않는다. 들리지도 않은 소리가 다음 소리의 `MinInterval`을 막으면 안 된다.
3. `Camera.main`이 없으면 감쇠 없이 기존과 동일하게 재생한다. 카메라 없는 테스트 씬이 그대로 동작해야 한다.
4. `spatialBlend`는 계속 0이다. 3D 롤오프·도플러는 넣지 않는다. 리스너가 카메라에 붙어 있는데 줌은 `orthographicSize`만 바꿔 카메라가 움직이지 않으므로, Unity 3D 감쇠는 줌에 반응하지 못한다. 좌우 정위는 `panStereo`로 대신한다.
5. **`Play(SoundId)` 경로는 재생 직전 `panStereo = 0`으로 되돌린다.** 소스는 풀에서 돌려 쓰므로, 되돌리지 않으면 직전 타워음의 정위가 UI 클릭음에 남는다.
6. 기존 `Play(SoundId)`는 시그니처와 호출부를 그대로 둔다(내부에서 `panStereo`만 초기화).

초기값: `_seFullVolumeViewportRatio = 1.0`, `_seCutoffViewportRatio = 1.8`, `_sePanAmount = 0.6`.
화면 안은 원래 볼륨, 화면 밖으로 살짝 벗어나면 작게, 화면 폭의 0.4배 이상 벗어나면 무음이다.
`_sePanAmount = 0`이면 정위가 완전히 꺼진다. 과하다고 판단되면 코드를 되돌리지 말고 이 값을 0으로 내린다.

### 6-1. `TowerAttack`

수정 파일: `Assets/Scripts/Buildings/Tower/TowerAttack.cs`

`Fire()`의 공용 호출을 데이터 기반 호출로 교체한다.

```csharp
if (_towerData.LaunchSound is SoundId launchSound)
{
    SoundManager.Play(launchSound, LaunchPosition);
}
```

Launch음의 위치는 `LaunchProjectile()`의 `spawnPosition`과 같은 기준을 쓴다. 투사체가 없는 타워도 같은 값을 쓴다.

```csharp
private Vector3 LaunchPosition =>
    _firePoint != null ? _firePoint.position : transform.position;
```

투사체를 발사할 때 Resolve음을 전달한다.

```csharp
projectile.Launch(
    target,
    Attack,
    in context,
    _towerData.ProjectileSpeed,
    _towerData.ResolveSound);
```

### 6-2. `TowerAllyHealer`

수정 파일: `Assets/Scripts/Buildings/Tower/TowerAllyHealer.cs`

- `Fire()`의 `SoundId.TowerFire` 하드코딩을 `Data.LaunchSound`로 교체하고, 발사 위치를 함께 넘긴다.
- `Projectile.Launch()`에 `Data.ResolveSound`를 전달한다.
- 생명 타워의 Launch/Resolve가 일반 공격 타워와 같은 시간 규칙을 따르게 한다.

생명 타워는 풀을 사용하지 않고 투사체를 직접 `Instantiate`하지만, Resolve음의 보관과 재생은 `Projectile`이 담당하므로 별도 명중 로직을 만들지 않는다.

### 6-3. `Projectile`

수정 파일: `Assets/Scripts/Combat/Projectile.cs`

```csharp
private SoundId? _resolveSound;

public void Launch(
    IAttackTarget target,
    AttackSO attack,
    in AttackContext context,
    float speed,
    SoundId? resolveSound = null)
```

구현 규칙:

1. `Launch()` 첫 줄의 `ResetState()`는 유지한다.
2. 타겟·공격·속도 검증 실패 경로를 모두 지난 뒤 `_resolveSound = resolveSound`로 저장한다.
3. `ResetState()`에서 `_resolveSound = null`로 초기화한다.
4. 도착 시 순서는 다음과 같이 유지한다.

```text
ApplyHit()
→ ProjectileVisual.OnHit()
→ Resolve음 재생 - `SoundManager.Play(id, transform.position)`
→ Release()
```

명중 VFX와 Resolve음은 같은 프레임에 발생해야 한다. 투사체가 날아가는 동안 원래 타겟이 죽더라도 현재 VFX가 목적지에서 터지는 규칙과 맞춰 Resolve음도 재생한다.

`resolveSound`는 기본 인자 `null`로 둔다. 기존 `MonsterAttack` 호출부를 수정하지 않아도 몬스터 투사체는 무음으로 유지된다.

### 6-4. `TowerAuraSoundEmitter`

신규 파일: `Assets/Scripts/Sound/TowerAuraSoundEmitter.cs`

이 컴포넌트는 시간·은신·영혼·강화 타워 프리팹에만 붙인다.

책임:

- `Awake()`에서 같은 오브젝트의 `Tower`를 캐시한다.
- `LateUpdate()`에서 `TowerAuraSystem.TryGetActiveAura(tower, out _, out _)`로 현재 활성 여부를 구한다.
- 첫 관측 시 활성 상태라면 `TowerData.AuraOnSound`를 타워 위치와 함께 한 번 재생한다.
- 이후 `false → true` 전환에서만 다시 재생한다.
- `true → false`는 상태만 저장하고 소리는 내지 않는다.
- `Update()`가 아니라 `LateUpdate()`를 사용해 `Tower.Start()/Setup()` 이후 데이터를 관측한다.

필요 상태 예시:

```csharp
private Tower _tower;
private bool _hasObservedState;
private bool _wasAuraActive;
```

재생 조건은 타워가 존재한다는 사실이 아니라 **실제로 오라가 활성화됐는지**다. 따라서 인구 0, 마비, 부활 중 상태에서는 재생하지 않고, 인구가 들어오거나 재활성화되어 오라가 다시 켜질 때 재생한다.

- `Assets/Data/TowerData/TowerPrefab/TP_TimeTower.prefab`
- `Assets/Data/TowerData/TowerPrefab/TP_StealthTower.prefab`
- `Assets/Data/TowerData/TowerPrefab/TP_SoulTower.prefab`
- `Assets/Data/TowerData/TowerPrefab/TP_EnhancementTower.prefab`

Unity 에디터의 프리팹·컴포넌트 조작은 프로젝트 규칙대로 Coplay MCP를 사용한다.

## 10. 플레이 검증표

### 10-1. 투사체·효과 적용형

- [ ] 마나 한 대: Launch와 Resolve가 각각 한 번 발생한다.
- [ ] 석궁 한 대: 마나와 **다른 음색**(시위 + 타격)이 난다.
- [ ] 마나와 대공: 같은 클립이지만 피치·볼륨 차이로 구분된다.
- [ ] 머스킷: 마나·석궁보다 묵직하고 대공과 구분된다.
- [ ] 대공: 공중 적이 있는 웨이브에서 Launch/Resolve가 발생한다.
- [ ] 불: 화염 Launch 뒤 VFX가 터지는 순간 화염 Resolve가 난다.
- [ ] 얼음: 얼음 VFX와 Resolve가 같은 프레임에 발생한다.
- [ ] 암석: 명중음이 VFX보다 길게 남지 않는다.
- [ ] 생명: 피해 입은 아군 타워를 회복할 때 Launch/Resolve가 난다.
- [ ] 생명: 회복 대상이 없을 때 반복 소리가 나지 않는다.
- [ ] 타겟이 비행 중 죽어도 기존 명중 VFX와 Resolve음이 함께 발생한다.

### 10-2. 오라형

- [ ] 시간: 인구 0에서는 무음이고 인구 투입으로 오라가 켜질 때 1회 재생한다.
- [ ] 은신·강화: 시간 타워와 같은 상태 규칙을 따르고 같은 클립을 쓴다.
- [ ] 영혼: 항상 가동 조건을 만족하면 배치 후 1회 재생한다.
- [ ] 마비/부활 등으로 비활성화될 때는 소리가 나지 않는다.
- [ ] 다시 활성화될 때 `AuraOn`이 정확히 1회 난다.
- [ ] 활성 상태로 유지되는 동안 프레임마다 반복되지 않는다.
- [ ] 오라 타워 4대를 연속 배치해도 소리가 겹쳐 터지지 않는다.

### 10-3. 회귀·믹싱

- [ ] 공격 모드 새끼용은 기존 공용 `TowerFire`를 유지하고 신규 타워음은 내지 않는다.
- [ ] 몬스터 투사체는 신규 타워 Resolve음을 내지 않는다.
- [ ] 시간 타워는 공격하지 않으며 Launch/Resolve도 내지 않는다.
- [ ] 타워 10대 이상에서 SE가 자주 뚝 끊기지 않는다.
- [ ] 화면 밖 타워의 발사·명중음이 들리지 않는다.
- [ ] 화면을 그 타워로 옮기면 다시 들린다.
- [ ] 줌아웃해서 화면에 들어온 타워는 들린다(월드 거리 기준이 아님을 확인).
- [ ] 화면 좌우 끝의 타워가 각각 왼쪽·오른쪽에서 들린다.
- [ ] BGM·UI·건설·몬스터 효과음은 카메라 위치와 무관하게 이전과 같고, 좌우로 치우치지 않는다.
- [ ] SE 볼륨 0에서 모든 신규 소리가 사라지고 BGM은 남는다.
- [ ] 2배속에서도 과도한 소음이 되지 않는다.
- [ ] 설정·UI·건설 등 기존 0~13 사운드가 이전과 동일하다.

## 13. 인계 체크리스트

새 에이전트는 작업을 시작할 때 다음 순서를 지킨다.

1. `AGENTS.md`, `Docs/구현현황.md`, 이 문서를 읽는다.
2. `git status --short`로 기존 사용자 변경을 확인하고 보존한다.
3. `SoundId.cs`와 `SoundCatalog.asset`의 현재 마지막 ID가 13인지 확인한다.
4. M0부터 순서대로 진행하며 한 번에 하나의 마일스톤만 완료 처리한다.
5. Unity 에디터 작업·컴파일 확인·플레이 테스트는 Coplay MCP를 사용한다.
6. 생성형 SFX 기능은 사용하지 않는다.
7. 각 M 완료 후 이 문서의 상태와 실제 결과를 갱신한다.
8. 코드 본문에 볼륨·피치·간격 리터럴을 넣지 않는다. 해당 값은 `SoundCatalog.asset`에 둔다.
9. 커밋 전 컴파일 에러 0과 플레이 모드 진입 가능 여부를 확인한다.
10. 문서와 커밋 메시지는 한국어로 작성한다.

1. `타워 전투 효과음 데이터 구조 추가`
2. `타워 투사체 발사 및 명중 효과음 연동`
3. `오라 타워 활성 효과음 연동`

## 14. 열린 문제

### 화면 밖 소리

타워 효과음은 §6-0의 화면 기준 감쇠·컷오프로 이번 범위에서 해결한다. BGM과 나머지 효과음은 2D 그대로다.
남은 것은 감쇠 비율 2개의 실전 조정(M6)이다. 좌우 팬·도플러는 소스 풀 구조를 바꿔야 해서 넣지 않는다.

### 소리 우선순위

`TakeSeSource()`는 풀이 차면 재생 중인 가장 오래된 소스를 덮어쓴다. 중요도 개념이 없어서 암석 명중음이 마나 발사음에 잘릴 수 있다.
화면 밖 컷오프로 동시 재생 수가 크게 줄므로 풀 24개가 실제로 포화되는지 M6에서 먼저 확인한다. 포화가 관측되면 그때 `SoundEntry`에 우선순위를 넣고 뺏기 규칙을 설계한다.

### 오라 해제음·루프

현재는 `AuraOn`만 구현한다. 타워마다 루프를 틀면 여러 채가 있을 때 지속적인 소음이 되므로 보류한다.
필요성이 확인되면 “카메라 근처 또는 선택된 타워만 루프” 같은 제한과 함께 별도 설계한다.

### 클립 최종 확정

§7의 클립 17개는 확정됐다. 남은 것은 길이·볼륨·피치·MinInterval이며 M6 결과로 §8에 갱신한다.
머스킷·얼음의 Launch/Resolve 순서는 §7-3의 확인 대기 항목이다.
