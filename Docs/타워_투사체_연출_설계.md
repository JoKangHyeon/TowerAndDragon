# 🎯 타워 투사체 연출 설계

작성일: 2026-08-20 · 전체 현황: [구현 현황](./구현현황.md)

밤 전투에서 타워 종류마다 다른 투사체 연출(파티클 궤적 + 명중 이펙트)을 붙이기 위한 설계 문서입니다.
기획은 `기획종합_v2.md`가 우선합니다.

> **이 문서는 설계안입니다.** 코드·프리팹 작업은 아직 시작하지 않았습니다.

---

## 1. 한눈에 보는 전체 그림

```
[TowerAttack.Fire]
   │
   ▼
[PrefabPool.Spawn]  ← TowerData._projectilePrefab (타워별 전용 프리팹)
   │                  풀이 씬에 없으면 Instantiate로 fallback
   ▼
[Projectile.Launch] ──▶ [ProjectileVisual.OnLaunched]
   │                       궤적 파티클 Clear 후 Play
   │
   ▼ (MoveTowards로 타겟 추적)
[명중] ──▶ [AttackSO.Execute] 피해 적용
   │
   ├──▶ [ProjectileVisual.OnHit] 궤적 정지 + 명중 이펙트 스폰
   │        └─▶ [PrefabPool.PlayForSeconds] 수명 후 자동 반납
   │
   └──▶ [PrefabPool.Release] 투사체 본체 반납
```

**연출 범위**: 투사체 본체 + 궤적, 명중 이펙트. 발사(머즐) 이펙트는 이번 범위 밖.

## 2. 현재 구조

### 2-1. 데이터

`TowerData`에 이미 투사체 필드가 있습니다.

```csharp
[Header("Projectile")]
[SerializeField] private GameObject _projectilePrefab;
[SerializeField] private float _projectileSpeed;

public bool HasProjectile => _projectilePrefab != null && _projectileSpeed > 0;
```

- `ElementalTowerData`·`BabyDragonData`가 `TowerData`를 상속하므로 같은 필드를 그대로 씁니다.
- **`MonsterData`는 `TowerData`를 상속하지 않고** 같은 이름의 필드를 따로 가집니다. `Projectile` 클래스만 공유합니다.

### 2-2. 지금 배선된 투사체 프리팹

| TowerData | 프리팹 | 속도 |
|---|---|---|
| TD_Arrow | ProjectileView | 10 |
| TD_CrossBow | ProjectileView | 10 |
| TD_Musket | ProjectileView | 10 |
| TD_Anti_Air | ProjectileView | 10 |
| TD_FireTower | Projectile_Fire | 10 |
| TD_IceTower | Projectile_Ice | 10 |
| TD_StoneTower | Projectile_Stone | 5 |
| TD_TimeTower | (없음) | 0 |

- 앞의 4종이 공용 `ProjectileView` 하나를 공유합니다 — 타워별 연출을 넣으려면 여기부터 분리해야 합니다.
- `TD_TimeTower`는 `_attack`이 비어 있어(`CanAttack == false`) 공격 자체를 하지 않습니다. 대상 아님.

### 2-3. 프리팹 구조

`Projectile_Fire`를 포함해 현재 투사체 프리팹은 전부 단일 GameObject입니다.

```
Projectile_Fire
├── SpriteRenderer (Sorting Order 1)
├── Light2D
└── Projectile
```

**프로젝트 코드 어디에도 `ParticleSystem` 사용 사례가 없습니다.** 이번이 처음입니다.

## 3. 지금 막혀 있는 것

1. **`Projectile.Update`가 명중 즉시 `Destroy(gameObject)`** → 궤적·명중 파티클이 재생 도중 잘려나갑니다.
2. **발사마다 `Instantiate`/`Destroy`** → 파티클 프리팹은 스프라이트보다 Instantiate 비용이 큽니다. 밤 웨이브에서 타워 여러 개가 동시에 쏘면 프레임 튐이 생깁니다.
3. **연출 훅이 없습니다** — `Projectile`에 발사/명중 시점을 시각 컴포넌트에 알릴 지점이 없습니다.
4. **`Projectile`이 진행 방향으로 회전하지 않습니다** — 방향성 있는 파티클(Stretched Billboard, 화살)에 영향을 줍니다.
5. **`_isLaunched`가 한 번 true가 되면 false로 안 돌아갑니다** — 풀링으로 재사용하려면 상태 초기화가 필요합니다.

| 패키지 | 프리팹 수 | 2D 지원 | 판정 |
|---|---|---|---|
| **AAA Stylized Projectiles Vol1** (Hovl) | 163 | **`Projectiles 2D/` 27종 전용** + 2D 데모 씬 + `HS_ProjectileMover2D` | **채택** |
| AAA Projectiles Vol2 (Hovl) | 72 | 없음 (3D 전용) | 보조 |

### 4-1. Stylized Vol1을 고른 이유

`2D Projectile 16 fire.prefab` 구조:

```
2D Projectile 16 fire
├── ParticleSystem ×3 (본체 + SubSmoke + SubSparks)
├── Rigidbody2D + CircleCollider2D    ← 2D 물리
└── HS_ProjectileMover2D
```

- **`Rigidbody2D` / `CircleCollider2D`** — 다른 3D 팩들은 `Rigidbody`/`Collider`라 우리 2D 아이소 씬에 그대로 못 씁니다.
- `ParticleSystemRenderer`에 `m_RenderMode: 1`(Stretched Billboard)이 섞여 있어 진행 방향 늘림이 이미 잡혀 있습니다.
- 27종이 **`Projectile` / `Flash` / `Hit` 3종 세트로 짝이 맞습니다.** 우리 설계의 궤적 + 명중 이펙트 구조와 그대로 대응됩니다.

### 4-2. ⚠️ `HS_ProjectileMover2D`는 쓰지 않습니다

에셋에 딸려온 무버 스크립트는 우리 `Projectile`과 정면 충돌합니다.

| 항목 | HS_ProjectileMover2D | 우리 Projectile |
|---|---|---|
| 이동 | `rb.linearVelocity = forward * speed` (직진) | `MoveTowards`로 타겟 추적 |
| 명중 판정 | `OnCollisionEnter2D` (물리 충돌) | 도착 지점 도달 |
| 피해 | 없음 (연출 전용) | `AttackSO.Execute` |
| 수명 | `Start()`에서 `Destroy(gameObject, 5)` | 명중 시 반납 |

**작업 절차**: 프리팹을 임포트한 뒤 각 프리팹에서
`HS_ProjectileMover2D` · `Rigidbody2D` · `CircleCollider2D`를 **제거**하고,
우리 `Projectile` + `ProjectileVisual`을 붙입니다. **파티클 자식만 가져다 씁니다.**

## 5. `PrefabPool` — 프리팹 단위 GameObject 풀 (신규)

`Assets/Scripts/Util/PrefabPool.cs`

`SoundManager`와 같은 **정적 접근점** 패턴을 씁니다. 이유도 같습니다 — 호출자 대부분이 런타임에 Instantiate되는 프리팹(타워·몬스터·투사체)이라 씬 오브젝트를 `SerializeField`로 주입할 수 없습니다.

**씬에 없으면 fail-open**: `Instantiate`/`Destroy`로 그대로 동작합니다. 팀원 테스트 씬과 튜토리얼 씬에 새 필수 배선을 만들지 않습니다.

### API

```csharp
static GameObject Spawn(GameObject prefab, Vector3 position);
static void Release(GameObject instance);
static void PlayForSeconds(GameObject prefab, Vector3 position, float seconds);  // 명중 이펙트용
```

### 내부

- `Dictionary<GameObject, ObjectPool<GameObject>>` (프리팹 → 풀). `UnityEngine.Pool.ObjectPool<T>` 사용
- 인스턴스에 `PooledInstance` 마커 컴포넌트를 생성 시점에 붙여 원본 프리팹 키를 보관합니다.
  마커가 없는 인스턴스를 `Release`하면 `Destroy` — fallback 경로와 섞여도 안전합니다.
- `PlayForSeconds`의 지연은 **풀 자신의** `GetCancellationTokenOnDestroy()`로 돕니다.
  풀링된 오브젝트는 파괴가 아니라 반납이므로 그쪽 토큰을 쓰면 취소가 안 걸립니다.
- `[WiringOptional] GameObject[] _prewarmPrefabs` + `PREWARM_COUNT_PER_PREFAB`로 첫 발사 히칭 제거
- `OnDestroy`에서 `_current = null` (`SoundManager`와 동일)
- 프리팹 검증(`Projectile` 컴포넌트 유무)은 **풀 생성 시 1회**. 발사마다 `GetComponent` + 에러 경로를 타지 않습니다.

## 6. `Projectile` 개조

`Assets/Scripts/Combat/Projectile.cs`

- 스폰/반납을 `PrefabPool` 경유로 통일
- 반납은 스폰 시 주입받은 경로로만 — 자기 풀이 아닌 곳에 반납하는 사고를 구조적으로 막습니다
- **`ResetState()` 추가** — `_isLaunched` / `_target` / `_targetObject` / `_targetTransform` / `_lastTargetPosition` 초기화
- `Launch`의 실패 조기 반환(target null / speed 0 / 타겟 오브젝트 null)은 `Destroy`가 아니라 **반납**
- 연출 훅 2개를 `ProjectileVisual`에 전달 (컴포넌트는 풀 생성 시 캐시)
  - `OnLaunched()` — `Launch` 성공 직후
  - `OnHit(Vector3 hitPosition)` — `ApplyHit` 직후, 반납 직전

## 7. 호출자 통일 — 3곳 전부

| 파일 | 비고 |
|---|---|
| `Buildings/Tower/TowerAttack.cs` `LaunchProjectile` | |
| `Monster/MonsterAttack.cs:251` `LaunchProjectile` | `MonsterData`는 `TowerData` 상속이 아님 |
| 새끼용 | `TowerAttack` 공유 → 자동 반영 |

> **⚠️ 반쪽 마이그레이션 금지.**
> `Projectile`이 풀로 반납하기 시작하면, 아직 `Instantiate`로 만들어진 몬스터 투사체는 반납 대상을 못 찾습니다. 밤 웨이브에서 터집니다.

> **⚠️ `_projectilePrefab` 필드 타입은 `GameObject`로 유지.**
> `Projectile`로 바꾸면 YAML의 fileID가 안 맞아 `TD_*.asset` 8개 + 모든 `MonsterData`의 참조가 **조용히 null**이 됩니다.

## 8. `ProjectileVisual` — 연출 담당 (신규)

`Assets/Scripts/Combat/ProjectileVisual.cs`, 투사체 프리팹 루트에 붙입니다.

```csharp
[SerializeField] private ParticleSystem[] _trailParticles;   // 궤적, 프리팹 자식
[WiringOptional]
[SerializeField] private GameObject _impactPrefab;           // 비우면 조용히 생략
[SerializeField] private float _impactLifetimeSeconds = DEFAULT_IMPACT_LIFETIME_SECONDS;
```

- **`OnLaunched()`**: `Clear(withChildren: true)` **후** `Play(true)`
  > Clear를 빼면 world-space 파티클이 재사용 시 직전 명중 지점에서 새 발사 지점까지 줄을 긋습니다.
- **`OnHit(hitPosition)`**: `Stop(true, StopEmittingAndClear)` → `PrefabPool.PlayForSeconds(_impactPrefab, hitPosition, _impactLifetimeSeconds)`

> **궤적은 떼어내지 않습니다.**
> `HS_ProjectileMover2D`는 명중 시 자식을 unparent해서 파티클을 마저 재생시키지만, 그러면 풀이 자식 하나가 사라진 오브젝트를 돌려받습니다.
> "명중 후에도 남는 연출"은 궤적 잔상이 아니라 **별도 명중 이펙트**가 담당합니다 —
> `VillagerDispatchSystem`의 `_conquestCompletionEffectPrefab` + `_conquestCompletionEffectLifetimeSeconds`와 같은 구조입니다.

## 9. 데이터 작업 목록

1. `AAA Stylized Projectiles Vol1` 임포트 → `Assets/Imported/` 아래 원본 유지
2. `Projectiles 2D/`에서 7종을 `Assets/Prefabs/Projectile/`로 복제
3. 각 복제본에서 `HS_ProjectileMover2D` · `Rigidbody2D` · `CircleCollider2D` 제거 → `Projectile` + `ProjectileVisual` 부착
4. `Flash and hits/`에서 대응 `Hit` 프리팹을 복제해 `_impactPrefab`에 배선
5. 각 `TD_*.asset`의 `_projectilePrefab`을 새 프리팹으로 교체
   - 공용 `ProjectileView`를 쓰던 Arrow/CrossBow/Musket/Anti_Air 4종이 여기서 분리됩니다
   - 기존 `Projectile_Fire` / `Projectile_Ice` / `Projectile_Stone`은 교체 또는 파티클 자식 추가

## 10. 코드 규칙 (CLAUDE.md)

- 리터럴 상수 금지 → `DEFAULT_IMPACT_LIFETIME_SECONDS`, `PREWARM_COUNT_PER_PREFAB` 등 `UPPER_SNAKE_CASE`
- 지연은 `UniTask.Delay`. Coroutine 금지
- 구독 없이 훅 호출뿐이라 이벤트 초기화 순서 이슈는 없습니다

## 11. 구현 후 검증 절차

1. 컴파일 에러 0
2. `SampleScene` 플레이 → 밤 진입 → 타워 종류별 투사체가 각각 다른 연출로 날아가는지
3. **재사용 검증** — 같은 타워가 연속 발사할 때 궤적이 직전 명중 지점에서 늘어지지 않는지 (§8 Clear 누락 확인)
4. **몬스터 투사체 확인** — 원거리 몬스터가 성·타워를 공격할 때 null 없이 동작하는지.
   §7 풀 통일이 깨지면 여기서 먼저 터집니다.
5. `PrefabPool`이 없는 씬(팀원 테스트 씬)에서도 투사체가 정상 발사되는지 (fail-open)
6. Profiler로 밤 웨이브 중 GC Alloc 비교 (풀링 전/후)
7. **파티클 정렬** — 임포트한 프리팹의 `ParticleSystemRenderer` Sorting Order는 전부 **0**이고,
   기존 투사체 `SpriteRenderer`는 **1**입니다. `IsometricMath.ComputeDepthSortOrder` 기준 아이소 뎁스에서
   파티클이 타일·건물 뒤로 숨지 않는지 프리팹마다 확인해야 합니다.
8. `Tutorial` 씬도 확인 — 배선 누락 이력이 있는 씬입니다
