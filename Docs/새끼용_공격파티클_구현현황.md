## 1. 이 문서의 목적

새끼용 공격 발사체·발사 섬광·명중 이펙트의 현재 구현과 배선을 다른 세션이 바로 이어받을 수 있도록 기록한다.

- 이 문서는 **공격 Projectile VFX와 생명 회복 파동**만 다룬다.
- 공격·버프 범위 링과 검 마커는 `Docs/새끼용_범위표시_구현계획.md`를 따른다.
- 생성 원본은 수정하지 않았다. 모든 가공본은 요청에 따라 `Assets/Imported/Prefabs/BabyDragonEffect/Combat/`에 만들었다.

## 3. 공통 가공 규칙

### 색상

- 하드코딩한 프리팹 이름별 색상을 사용하지 않는다.
- `DragonAttributePalette.ColorOf(DragonType)`를 사용한다.
- 원본 재질과 공식 색을 곱했을 때 시간·암석이 지나치게 어두워져, 공식 색조를 유지하면서 HDR 강도를 높이고 밝은 원본 픽셀에는 최대 20%의 흰 하이라이트를 섞는다.
- 원본 공유 Material 자체는 수정하지 않는다.

### 정렬

| 구분 | Sorting Layer | Order |
|---|---:|---:|
| Muzzle | `Projectile` | 19 |
| Projectile | `Projectile` | 20 |
| Impact | `Projectile` | 21 |

성과 건물 앞에서 공격 이펙트가 가려지지 않게 하기 위한 값이다. 실제 전투 화면에서 성 앞·뒤 방향 발사 확인은 추가로 필요하다.

### 런타임 구조

- 발사체 루트에는 `Projectile`과 `ProjectileVisual`만 남긴다.
- Hovl 무버, Retro 랜덤 피치, 오디오, Collider, Rigidbody는 제거한다.
- `ProjectileVisual._trailParticles`는 빈 배열로 저장한다. 런타임 `Awake()`가 현재 자식 파티클을 다시 수집한다.
- Muzzle과 Impact는 `ProjectilePool.PlayForSeconds()`가 별도 인스턴스로 재생한다.
- 시간 투사체만 `ProjectileVisual`의 런타임 `TrailRenderer`를 사용한다. 풀에서 재사용할 때
  이전 발사 궤적을 지우고, 명중 시 즉시 방출을 멈춰 발사점과 이전 명중점이 연결되지 않는다.
- 원본이 정한 Local/World Simulation Space를 보존한다.
  - 모든 파티클을 World로 강제했을 때 코어 입자가 발사점에 남는 문제가 확인됐다.
  - 코어는 Local, 잔상은 World인 혼합 구성을 일괄 변경하지 말 것.
- 생성 스크립트를 다시 실행하면 같은 경로의 프리팹을 갱신하므로 기존 GUID가 유지된다.

  — 공유 머티리얼을 고치면 석궁 타워까지 같이 바뀐다.
- 정적 렌더 수치는 실제보다 작다. 이 프리팹의 파티클은 `rateOverDistance` 방출이라 실제로 날아갈 때만 나온다.

**손대기 전에 알아야 할 것**

- **상수만 바꾸면 반영되지 않는다.** 컴포저가 `[InitializeOnLoadMethod]`로 도메인 리로드마다 도는데,
  `VERSION_MARKER` 자식이 있으면 재빌드를 건너뛴다. 구성을 바꾸면 마커를 V6, V7로 올려야 한다.
  (Play 중에는 `playModeStateChanged`로 재빌드를 미루므로 플레이 세션은 깨지 않는다.)
- 화살 메시는 `MeshRenderer`라 `TuneParticles`가 정렬을 못 잡는다. `SortMeshRenderers`가 따로
  `Projectile` 레이어 / order 20으로 맞춘다. `Docs/ArcherPack_적용구상.md`의 실측 결론이다.
- 화살 방향 보정(자식 Z+180)과 화살 메시용 URP Unlit 머티리얼은 `Projectile_Tower_CrossBow_AP`에
  이미 구워져 있어 그대로 따라온다. **원본을 단순화하지 말 것** — 시간 새끼용까지 같이 단순해진다.
  석궁 타워는 여기서 `Glow`·`Sparks`·`Fire 2`를 뺀 `Projectile_Tower_CrossBow_Simple`을 쓴다.

| 항목 | 구성 |
|---|---|

- `RockDebris / Sparks / Spikes / stone (1) / rock / rock1~3 / Mountain`은 원래 크기·개수를 유지하고 시작 속도·방출 반경·추가 속도와 힘만 0.5로 낮춰 튀는 범위만 줄였다.
- `RockDebris`의 각 돌 파편은 형태가 찌그러지지 않는 균일 스케일로 0.30~0.65 사이의 크기를 개별 랜덤 적용한다. 파편 개수·이동 범위·수명에는 영향을 주지 않는다.
- 회색 바위 `RockDebris`는 구형 무작위 방출 속도를 추가로 0.6배로 줄이고, 중력은 기존의 0.2배로 낮춘 뒤 상향 속도 2.6~3.2를 더했다. 수명은 0.6배로 줄이고 후반부에 페이드아웃시켜 아래로 낙하하기 전에 상승 중 사라진다.
- `RockDebris`의 Velocity over Lifetime X/Y/Z는 모두 `Two Constants` 모드로 저장한다. 한 축만 다른 모드로 저장하면 런타임에 `Particle Velocity curves must all be in the same mode` 오류가 발생한다.
- 공식 보라색은 균열광과 속성 식별에 쓰고, 밝은 하이라이트 덕분에 회색 암석 본체도 남는다.
- 투사체 속도가 5로 가장 느리므로 꼬리와 코어가 비행 중 끊기지 않는지 확인해야 한다.
- Impact는 실제 공격의 반경 2.25를 정확히 그리는 범위 표시가 아니다. 순간 충격·파편 연출만 담당한다.

### 생명

| 항목 | 구성 |
|---|---|
| Projectile 기반 | `Projectile_V2_21_green` |
| 제거 | 독·암흑으로 읽히는 `Darkness` 자식 |
| Muzzle | `Muzzle_V2_21_green`, 루트 스케일 0.8 |
| Impact | V2_21의 `Fire/Sparks` + V2_01의 `Flash/Leaves/Leaves2/Glow` |
| Impact 루트 | 스케일 0.72 |
| 배치 | 대상 몸통 `Body`, 진행 방향 회전 없음 |
| 수명 | Muzzle 0.45초 / Impact 0.8초 |

- 공격 Projectile은 회전하는 생명 씨앗·잎 에너지로 읽히게 했다.
- 하트, 십자가, 방어막 구체, 독구름을 사용하지 않는다.
- 현재 새 폴더에는 `heart`, `V2_17`, `17_heal` 참조가 없다.
- 공격 명중과 아군 타워 회복은 서로 다른 프리팹으로 분리돼 있다.
- 명중 파편 `Leaves`·`Leaves2`·`Sparks`·`Glow`의 속도·힘·중력·속도 제한을 일괄 0.5배로 낮춰
  튀는 범위만 절반으로 줄였다(2026-08-26). 네 값을 같은 배율로 곱해야 궤적이 닮은꼴로 축소된다.
  파티클 크기·개수·수명·색은 건드리지 않았고, 제자리에서 피고 지는 `Flash`·`Fire`는 제외했다.
- 실측 최외곽 반경(월드 유닛): t=0.2 `1.889 → 1.008` / t=0.3 `2.486 → 1.231` / t=0.5 `2.851 → 1.418`.
  중앙 섬광만 남는 t=0.05와 t=0.8은 의도대로 변하지 않았다.
- 축소는 `CoplayScripts/ShrinkLifeImpactSpread.cs`로 프리팹에 직접 적용했다. 같은 배율을 생성기
  `BuildLife`의 `LIFE_IMPACT_DEBRIS_MOTION_SCALE`에도 심어 뒀으므로 재생성해도 유지되고,
  스크립트는 이미 축소된 프리팹을 만나면 아무것도 하지 않고 빠진다(중복 적용 방지).
- 잎 한 장의 크기는 1.8배로 키웠다(2026-08-26). `Leaves`는 0.21~0.315 → 0.378~0.567,
  `Leaves2`는 `size3D`라 가로 0.042~0.105 → 0.076~0.189과 함께 세로 0.3 → 0.54를 같이 곱했다.
  방출 개수·수명·속도는 그대로라 퍼지는 범위는 변하지 않는다.
  적용은 `CoplayScripts/ScaleLifeLeafSize.cs`(중복 적용 방지 가드 있음),
  생성기 상수는 `LIFE_IMPACT_LEAF_SIZE_SCALE`이다.
  범위를 절반으로 줄인 뒤 초록 잎이 연기에 묻혀 안 보이던 것을 보완한 것이다.
- `Lightning` 자식은 2026-08-26에 **의도적으로 삭제됐다**(에디터에서 직접). 생명 속성에 전광이
  어울리지 않는다는 판단이다. 생성기 `BuildLife`에서도 해당 `AttachNamedLayer` 줄을 지웠으므로
  재생성해도 다시 생기지 않는다. 되살리지 말 것.
- 이 프리팹은 에디터에서 직접 손보는 경우가 있다. **스크립트로 고치기 전에 에디터에서 이 프리팹을
  닫고, 현재 값을 먼저 읽어 확인할 것** — 동시에 고치면 서로 덮어쓴다.
  (참고: `LoadPrefabContents` → `SaveAsPrefabAsset` 왕복 자체는 편집 모드에서 24자식 프리팹으로

## 6. 생성·검증 스크립트

### 생성기

`CoplayScripts/BuildBabyDragonCombatVfx.cs`

- 원본 후보를 복제·분해해 복합 프리팹을 생성한다.
- 같은 출력 경로로 재실행할 수 있다.
- 5개 `BabyDragonData`와 생명 회복 효과 데이터를 자동 배선한다.

- 시각 수정은 생성된 YAML을 직접 손대기보다 이 스크립트의 구성값을 바꾸고 재생성하는 방식을 권장한다.

git add -f Assets/Imported/Prefabs/BabyDragonEffect/Combat
