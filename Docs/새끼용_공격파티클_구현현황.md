# 새끼용 공격 파티클 구현현황 및 인수인계

작성: 2026-08-25  
범위 표시 관련 문서: `Docs/새끼용_범위표시_구현계획.md`  
타워 VFX 관련 문서: `Docs/타워이펙트_작업노트.md`

## 1. 이 문서의 목적

새끼용 공격 발사체·발사 섬광·명중 이펙트의 현재 구현과 배선을 다른 세션이 바로 이어받을 수 있도록 기록한다.

- 이 문서는 **공격 Projectile VFX와 생명 회복 파동**만 다룬다.
- 공격·버프 범위 링과 검 마커는 `Docs/새끼용_범위표시_구현계획.md`를 따른다.
- 생성 원본은 수정하지 않았다. 모든 가공본은 요청에 따라 `Assets/Imported/Prefabs/BabyDragonEffect/Combat/`에 만들었다.

- Unity 컴파일 오류 0

## 3. 공통 가공 규칙

### 색상

- 하드코딩한 프리팹 이름별 색상을 사용하지 않는다.
- `DragonAttributePalette.ColorOf(DragonType)`를 사용한다.
- 원본 재질과 공식 색을 곱했을 때 시간·암석이 지나치게 어두워져, 공식 색조를 유지하면서 HDR 강도를 높이고 밝은 원본 픽셀에는 최대 20%의 흰 하이라이트를 섞는다.
- 원본 공유 Material 자체는 수정하지 않는다.

### 정렬

| 구분 | Sorting Layer | Order |
|---|---:|---:|
| Muzzle | `Projectile` | 19 |
| Projectile | `Projectile` | 20 |
| Impact | `Projectile` | 21 |

성과 건물 앞에서 공격 이펙트가 가려지지 않게 하기 위한 값이다. 실제 전투 화면에서 성 앞·뒤 방향 발사 확인은 추가로 필요하다.

### 런타임 구조

- 발사체 루트에는 `Projectile`과 `ProjectileVisual`만 남긴다.
- Hovl 무버, Retro 랜덤 피치, 오디오, Collider, Rigidbody는 제거한다.
- `ProjectileVisual._trailParticles`는 빈 배열로 저장한다. 런타임 `Awake()`가 현재 자식 파티클을 다시 수집한다.
- Muzzle과 Impact는 `ProjectilePool.PlayForSeconds()`가 별도 인스턴스로 재생한다.
- 원본이 정한 Local/World Simulation Space를 보존한다.
  - 모든 파티클을 World로 강제했을 때 코어 입자가 발사점에 남는 문제가 확인됐다.
  - 코어는 Local, 잔상은 World인 혼합 구성을 일괄 변경하지 말 것.
- 생성 스크립트를 다시 실행하면 같은 경로의 프리팹을 갱신하므로 기존 GUID가 유지된다.

## 4. 속성별 실제 구성

### 얼음

| 항목 | 구성 |
|---|---|
| Projectile 기반 | `Projectile_V1_06_blue_fire` |
| 추가 코어 | `Retro Arsenal/FrostMissile`, 스케일 0.58 |
| 제거 | Frost의 `SmokeTrail` |
| Muzzle | `FrostMuzzle`, 루트 스케일 0.8 |
| Impact | `FX_Impact_IceCrack` 0.85 + `FrostExplosion/Snowflakes` + `Impact_V2_05_ice/Snowflake` |
| 배치 | 대상 발밑 `Ground`, 진행 방향 회전 없음 |
| 수명 | Muzzle 0.45초 / Impact 1.1초 |

- 냉기 안개 꼬리와 픽셀 프로스트 코어가 함께 날아간다.
- 명중은 기존 지면 균열이 주 연출이고 눈송이 두 레이어만 추가한다.
- 초기 합성은 Impact 33개 파티클 시스템이었으나 과도해 24개로 줄였다.
- 얼음 감속·빙결 상태 VFX는 별도 시스템이므로 명중 파티클을 장시간 유지하지 않는다.

### 불

| 항목 | 구성 |
|---|---|
| Projectile 기반 | `Projectile_V1_16_fire` |
| 추가 꼬리 | `Retro Arsenal/DragonsBreath`, 스케일 0.32 |
| 제거 | DragonBreath의 `FireExplosion` 자식 |
| Muzzle | `Muzzle_V1_16_fire`, 루트 스케일 1.05 |
| Impact | `Impact_V1_16_fire` 0.75 + `FX_Impact_FireCrack` 0.9 |
| 배치 | 대상 발밑 `Ground`, 진행 방향 회전 없음 |
| 수명 | Muzzle 0.45초 / Impact 1.0초 |

- 현재 5속성 중 꼬리가 가장 길고 화려하다.
- `DragonsBreath` 전체 지속 화염을 발사체로 쓴 것이 아니라 폭발 자식을 제거한 짧은 꼬리 레이어만 사용한다.
- 실제 속도 10에서 꼬리가 과도하게 길거나 여러 마리가 동시에 쏠 때 화면을 가리는지 확인해야 한다.
- 화상 상태 이펙트가 별도로 있으므로 Impact는 짧은 화염 개화와 지면 균열까지만 담당한다.

### 시간

| 항목 | 구성 |
|---|---|
| Projectile 기반 | 네이티브 노란 `Projectile_V2_25_yellow` |
| 잔상 | 같은 코어 2개 복제: `x=-0.35, scale=0.68`, `x=-0.65, scale=0.4` |
| 추가 입자 | `Projectile_V2_09_trails/Sparks` |
| Muzzle | `Muzzle_V2_09_trails`, 루트 스케일 0.75 |
| Impact | `Impact_V2_09_trails`, 루트 스케일 0.55 |
| 배치 | 대상 몸통 `Body`, 진행 방향으로 회전 |
| 수명 | Muzzle 0.25초 / Impact 0.45초 |

- 처음에는 `V2_09_trails` 전체를 노란색으로 가공했으나 자홍색 전용 재질과 노란 파티클 색이 곱해져 주 궤적이 사라졌다.
- 공유 Material을 변조하지 않기 위해 네이티브 노란 코어 + 2중 잔상 + 중립 스파크로 변경했다.
- 정적 프레임에서는 잔상이 겹쳐 하나의 긴 노란 탄처럼 보인다. 실제 0.5초 연사에서 빠른 연속 발사로 읽히는지 확인할 것.
- 더 화려하게 만들더라도 큰 포탈·구체를 매 타격마다 남기면 연사 때문에 화면이 포화되므로 사용하지 않는다.

## 6. 생성·검증 스크립트

### 생성기

`CoplayScripts/BuildBabyDragonCombatVfx.cs`

- 원본 후보를 복제·분해해 복합 프리팹을 생성한다.
- 같은 출력 경로로 재실행할 수 있다.
- 5개 `BabyDragonData`와 생명 회복 효과 데이터를 자동 배선한다.
- 파티클 크기·방출·버스트·색·정렬을 함께 가공한다.
- 시각 수정은 생성된 YAML을 직접 손대기보다 이 스크립트의 구성값을 바꾸고 재생성하는 방식을 권장한다.

생성 로그:

```text
output/vfx_check/baby_dragon_combat_build.txt
```

### 검증기

`CoplayScripts/VerifyBabyDragonVfx.cs`

Combat 검증 항목:

- `BabyDragonData`가 **이름만 같은 이전 프리팹이 아니라 새 경로의 프리팹**을 참조하는지 확인
- Projectile 루트에 `Projectile`과 `ProjectileVisual`이 있는지 확인
- 자식 ParticleSystem이 존재하는지 확인
- Muzzle과 Impact가 새 `BabyDragonEffect/Combat` 경로인지 확인
- 외부/원본 런타임 `MonoBehaviour`가 남았는지 확인
- 모든 투사체 ParticleSystemRenderer가 `Projectile` 정렬 레이어인지 확인
- `V2_17_heal` 의존성이 남았는지 확인

검증 로그:

```text
output/vfx_check/baby_dragon_vfx_verify.txt
```

현재 결과는 `실패 0`이다.

주의: 같은 검증 로그에 나오는 `outer X/Y`는 범위 파티클 측정값이며 Combat Projectile 합격 기준이 아니다. 현재 값이 1.1 이상이어도 전투 VFX 검증이 실패하지 않는다. 범위 정확도 작업은 별도 범위 문서를 참고한다.

## 7. 정적 렌더 측정

동일 카메라·시간 샘플에서 생성된 최종 프리팹을 비교한 결과다.

| 속성 | Projectile 시스템 | Projectile Mesh | Impact 시스템 | Impact Mesh |
|---|---:|---:|---:|---:|
| 얼음 | 6 | 0 | 24 | 12 |
| 불 | 6 | 0 | 9 | 0 |
| 시간 | 5 | 0 | 5 | 1 |
| 암석 | 3 | 0 | 21 | 7 |
| 생명 | 5 | 2 | 7 | 0 |

- 얼음 Impact는 기존 `FX_Impact_IceCrack` 자체가 22개 시스템이라 여전히 가장 무겁다.
- 암석 Impact는 광역 공격이므로 다른 속성보다 무겁게 유지했다.
- 생명 Impact는 하트 제거 후 7개 선택 레이어만 사용한다.
- 정적 렌더는 형태·크기 비교용이며 실제 투사체 속도, 동시 발사, 카메라 가림까지 보증하지 않는다.

## 8. 다음 세션에서 우선 확인할 것

1. `Haneul_TowerEffectScene` 또는 실제 전투 씬에서 5속성 새끼용을 공격 모드로 배치한다.
2. 좌→우, 우→좌, 위·아래 방향 발사에서 파티클 방향과 회전이 정상인지 확인한다.
3. 성 앞에 새끼용을 놓고 Projectile 정렬 레이어가 실제로 성보다 위에 보이는지 확인한다.
4. 불 새끼용 여러 마리가 동시에 공격할 때 긴 꼬리가 화면을 과도하게 덮는지 확인한다.
5. 시간 새끼용의 0.5초 연사에서 2중 잔상이 단일 탄과 구분되는지 확인한다.
6. 암석의 속도 5 비행 중 코어가 사라지거나 꼬리가 중간에 끊기지 않는지 확인한다.
7. 암석 Impact가 사거리 링이 아니라 순간 광역 충격으로 읽히는지 확인한다.
8. 생명 공격 명중과 별도 타워 회복 파동이 한 효과로 뭉개지지 않는지 확인한다.
9. 프로파일러에서 얼음·암석 Impact 동시 재생 시 파티클 비용을 확인한다.

튜닝 우선순위:

- 불 꼬리가 과하면 `FIRE_BREATH` 레이어 스케일 0.32 또는 방출 배율을 낮춘다.
- 시간 잔상이 약하면 `AddTimeAfterimages()`의 X 오프셋을 넓힌다. 큰 지속 Impact를 추가하지 않는다.
- 암석이 너무 어두우면 공식 보라색 자체를 바꾸지 말고 HDR intensity/하이라이트만 조정한다.
- 얼음 Impact가 무거우면 `FX_Impact_IceCrack`의 자식을 선택 복제하는 방식으로 줄인다. 눈송이 레이어를 다시 전체 복제하지 않는다.

## 10. Git 인수인계 — 중요

`.gitignore` 161행의 `/[Aa]ssets/[Ii]mported` 규칙 때문에 새 `BabyDragonEffect` 폴더는 일반 `git status`에 나타나지 않는다.

프리팹을 커밋에 포함하려면 다음 경로를 강제 추가해야 한다.

```powershell
git add -f Assets/Imported/Prefabs/BabyDragonEffect.meta
git add -f Assets/Imported/Prefabs/BabyDragonEffect/Combat.meta
git add -f Assets/Imported/Prefabs/BabyDragonEffect/Combat
```

- 현재 세션에서는 스테이징·커밋하지 않았다.
- 강제 추가하지 않으면 `BD_*.asset`에는 새 GUID 참조가 남지만 실제 프리팹은 다른 세션·브랜치에 전달되지 않는다.
- 프로젝트에는 이 작업 전부터 많은 수정·미추적 파일이 있었다. 관련 없는 변경을 discard하거나 reset하지 말 것.
- `CoplayScripts/BuildBabyDragonCombatVfx.cs`, `CoplayScripts/VerifyBabyDragonVfx.cs`, `output/vfx_check/`도 현재 미추적 상태다.
