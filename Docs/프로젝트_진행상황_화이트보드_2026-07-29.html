게임 전체가 도는 방식

“낮의 선택이 밤의 생존을 결정한다”를 하나의 이벤트 흐름으로 구현했습니다.

01 · PREPARE

낮 · 선택

시간 제한 없이 도시와 전투 준비를 조정합니다.

  • 격자 위 건설·철거·회전·이동
  • 생산 / 방어 / 점령 / 연구 인구 배분
  • 원정 출격, 연구 즉시 해금
  • 용 스킬·새끼용 운용 준비
02 · DEFEND

밤 · 생존

활성 포탈의 웨이브를 자동 전투로 방어합니다.

  • 포탈별 병렬 스폰, 그룹별 순차 등장
  • 지상 경로 이동 / 공중 직행 이동
  • 타워 자동 타기팅·투사체·특수 적
  • 성 파괴 시 패배, 전멸 시 밤 종료
03 · SETTLE

정산 · 결과

밤을 넘긴 결과가 경제와 확장에 반영됩니다.

  • 생산시설 자원 획득
  • 연구 인구만큼 RP 획득
  • 인구 식량 유지비와 기아 처리
  • 원정 일수 진행·점령·적 강화
04 · GROW

다음 날

더 강해진 도시와 더 어려워진 적이 다시 만납니다.

  • 7일마다 보스
  • 주기마다 포탈 추가
  • 4주기 종료 시 승리

수치·웨이브·트리 데이터

시스템별 구현 현황

상단 필터로 발표에서 강조할 상태만 남길 수 있습니다. “진행”은 핵심 동작은 있으나 콘텐츠 연결이나 종료 조건이 남은 영역입니다.

SYSTEM 01

격자 맵 · 건설

통합됨

아이소메트릭 타일맵을 셀과 9×9 청크로 변환하고, 점령된 땅에서만 다양한 크기의 건물을 배치합니다.

구현 기능

  • 마우스 선택, 배치 미리보기, 회전, 철거, 이동
  • 건물 footprint 충돌·지형·자원 노드 조건 검사
  • 당일 철거 100%, 이후 70% 비용 환급
  • 전장의 안개·청크 경계·점령 표시·미니맵
GridMap → BuildingPlacementController → Building / Factory / Tower
근거 보기GridMap은 셀·청크·건물 footprint를 관리하고, BuildingPlacementController가 Input System 입력과 비용·선택·이동을 연결합니다.
SYSTEM 02

낮/밤 · 웨이브 · 포탈

통합됨

하루 이벤트와 4주기 일정을 분리해, 데이터만 교체해도 일차별 웨이브와 포탈 개방 순서를 바꿀 수 있습니다.

구현 기능

  • 낮 시작/종료·밤 시작/종료 이벤트
  • 4주기×7일, 7·14·21·28일 보스 데이터
  • 북→남→동→서 포탈 순차 활성화
  • 모든 스폰·모든 적 전멸 판정, 취소·디버그 완료
CycleManager → WaveCycleProgression → DailyWaveController → WaveManager
근거 보기WaveManager는 UniTask로 포탈별 스폰을 병렬 처리하고, 포탈 내부 그룹은 지연·간격 데이터에 따라 순차 처리합니다.
SYSTEM 03

타워 · 적 · 전투

콘텐츠 마감

타워 자동전투와 적 이동·공격의 뼈대는 연결됐고, 현재는 타워/적 변형을 추가하며 콘텐츠 폭을 넓히는 단계입니다.

구현 기능

  • 타원형 사거리, 최근접 타기팅, 투사체 동기화
  • 배치 인구 비율에 따른 공격 간격 변화
  • 타워 체력 0 → 비활성 → 지연 또는 아침 복구
  • 지상·공중·원거리·보스·자폭·치유·감전형 데이터
TowerAttack + AttackSO/EffectSO ↔ BaseMonster + Movement/Attack/Behavior
남은 연결이슈 #113 적 종류 추가와 #114 석궁/저격 타워가 열려 있습니다. 공중 원거리형 등 세부 콘텐츠 완료 여부는 발표 직전 재확인이 필요합니다.
SYSTEM 04

인구 · 자원 · 생산

핵심 작동

하나의 인구 풀을 네 사용처가 공유하고, 실제 투입 비율이 타워 성능·생산량·연구·원정에 영향을 줍니다.

구현 기능

  • 생산 / 방어 / 점령 / 연구 인구 할당
  • 건물별 정원, 일괄 배치·해제 UI
  • 셀 수율×인구 충원율×지역/용 버프로 생산
  • 식량 유지비 부족 시 미배치→방어→생산→점령 순 감소
PopulationManager ↔ *PopulationCoordinator / ResourceManager ↔ Factory
데이터 주의현재 코드는 기본 자원 3종(식량·목재·석재), 특화 4종, 속성 슬라임 5종입니다. 기획서의 기본 자원 4종과 차이가 있어 확정이 필요합니다.
SYSTEM 05

점령 · 안개 · 난이도

핵심 작동

인접한 가시 청크에 자원과 인구를 보내고 여러 밤을 버티면 땅·인구·자원 접근권을 얻는 확장 루프입니다.

구현 기능

  • 상하좌우 인접 조건, 여러 원정 동시 진행
  • 지형별 소요일·비용·인구 보상 데이터
  • 완료 시 주둔지, 주변 시야, 자원 해금
  • 점령 가치가 해당 지형 적 강화 프로필로 누적
ConquestManager → ChunkState/Fog → EnemyEnhancementManager
근거 보기정산 시 원정 일수를 진행하고, 완료 청크의 지형에 맞는 적 체력·공격·이동·방어막 배율을 이후 웨이브 생성에 주입합니다.
SYSTEM 06

연구 트리

기능 작동

연구소 인구가 밤마다 RP를 만들고, 낮에 RP와 자원을 소비해 3갈래 노드를 즉시 해금합니다.

구현 기능

  • 타워 / 생산 / 편의 3갈래, 27개 노드
  • 선행 노드·주기별 티어·비용·낮 단계 검증
  • 타워 피해 배율·청크 수율·자원 해금 효과
  • 확대/축소 가능한 트리와 상세 패널 UI
ResearchLab → RP settlement → ResearchManager → ResearchEffectSO
구현 방식공용 진행 규칙과 별도로 ResearchManager가 RP 비용과 연구 전용 효과를 책임집니다. 수치와 트리 연결은 ScriptableObject에 분리되어 있습니다.
SYSTEM 07

어미용 · 새끼용

연결 진행

5속성 성장 데이터와 UI, 액티브 스킬 기반, 새끼용 설치·급식·버프는 존재하지만 획득과 트리→전투 연결이 남았습니다.

구현 기능

  • 5속성×6노드 = 30개 용 성장 노드
  • 즉시/지점/적 대상 액티브 스킬 타기팅
  • 새끼용 5속성 데이터·인벤토리·설치
  • 매일 슬라임 급식, 범위 내 생산시설 버프
DragonTreeManager · SkillManager · DragonEggInventory · BabyDragonBuff
남은 연결이슈 #75 어미용 스킬트리와 #102 새끼용 획득·데이터 연동이 열려 있습니다. 코드에도 해금 스킬과 SkillManager 연결을 후속 범위로 명시합니다.
SYSTEM 08

UI · 승패 · 엔딩

한 갈래 미완

인게임 HUD와 주요 창, 성 파괴 패배, 최종 웨이브 승리는 연결됐습니다. 전략적 확장 엔딩은 아직 열린 작업입니다.

구현 기능

  • 자원·인구·일차·보스 진행·성 HP HUD
  • 건설·점령·새끼용·연구·용 스킬 창
  • 메인 성 파괴 → Game Over
  • 4주기 완료 → Victory Window
UIManager / UI_*Window ↔ GameManager.GameOver() / Victory()
남은 연결이슈 #106 “4포탈 봉인석 트랙”이 열려 있어, 현재 승리 조건은 최종 보스 트랙 중심입니다. 하루 자원량 UI와 스트링테이블 연결도 남았습니다.

구현 방식

데이터와 실행 로직을 분리하고, 매니저끼리 직접 얽히는 대신 이벤트와 Coordinator로 연결했습니다.

INPUT / VIEW

플레이어 조작과 UI

Input System과 UI 창이 “무엇을 할지” 요청하고, 실제 규칙 판정은 도메인 시스템에 맡깁니다.

FLOW

사이클과 진행 매니저

낮/밤, 웨이브, 연구, 점령의 현재 상태와 전환 시점을 책임집니다.

DOMAIN

조립형 컴포넌트

적은 Health·Shield·Movement·Attack·Behavior를, 건물은 역할 컴포넌트를 조합합니다.

DATA

ScriptableObject

적·공격·웨이브·타워·생산·연구·용 성장의 수치와 연결을 에셋으로 관리합니다.

COORDINATION

이벤트와 중재자

UnityEvent와 Coordinator가 시스템 변경을 전달해 Grid·Population·Resource 간 결합을 줄입니다.
