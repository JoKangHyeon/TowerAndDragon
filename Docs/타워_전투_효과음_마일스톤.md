## 공통 규칙

- 한 번에 마일스톤 하나만 완료 처리하고, 끝나면 위 표와 해당 절을 갱신한다.
- `.asset` / `.prefab` / `.unity`는 텍스트 편집기로 직접 고치지 않는다. Unity가 열려 있으면 재직렬화로 덮어쓰고, GUID 사고 이력도 있다. 에디터 스크립트 또는 Coplay MCP로만 배선한다.
- 코드 본문에 볼륨·피치·간격 리터럴을 넣지 않는다. 전부 `SoundCatalog.asset`에 둔다.
- 생성형 SFX 기능은 사용하지 않는다.
- 컴파일 확인은 Editor.log 최신 블록 + `Assembly-CSharp.dll` 갱신 시각으로 판정한다.
- 씬·프리팹 작업과 플레이 테스트는 먼저 사용자에게 직접 할지 물어본다.

## M1 — 투사체 Launch/Resolve 런타임 연결

- `SoundManager`에 `Play(SoundId, Vector3)` 오버로드 추가(화면 기준 감쇠 + 줌 감쇠 + `panStereo` 정위), `SoundCatalog`에 파라미터 5개 추가 (설계 §6-0)
- `TowerAttack.Fire()`의 `SoundManager.Play(SoundId.TowerFire)` 제거 → `_towerData.LaunchSound` + 발사 위치
- `TowerAttack`의 `projectile.Launch(...)` 호출에 `_towerData.ResolveSound` 인자 추가
- `Projectile.Launch()`에 `SoundId? resolveSound = null` 파라미터 추가, 검증 통과 후 필드에 저장
- `Projectile.ResetState()`에서 해당 필드를 `null`로 초기화
- 도착 처리 순서: `ApplyHit()` → `ProjectileVisual.OnHit()` → Resolve음 → `Release()`
- `TowerAllyHealer.Fire()`의 `TowerFire` 하드코딩과 `Launch()` 호출도 동일하게 교체

완료 조건:

- M3·M4 이전이라 아직 소리는 나지 않는다. 재생 호출이 도달하는지로 판정한다.
- 공격 타워·생명 타워 모두 Launch/Resolve 재생 호출이 각각 1회 도달(임시 로그 또는 브레이크포인트)
- 몬스터 투사체(`MonsterAttack` 경로)는 기본 인자 `null`로 무음 유지
- 기존 `Play(SoundId)` 호출부(UI·건설·몬스터·BGM)를 하나도 건드리지 않음
- 2D 재생 경로가 `panStereo`를 0으로 되돌려, 타워음 뒤에 난 UI음이 한쪽으로 치우치지 않음
- `Camera.main`이 없는 씬에서 예외 없이 동작
- 풀에서 재사용된 투사체가 이전 Resolve음을 기억하지 않음
- 실제 청취 확인은 M5에서 한다
- 이 커밋 시점에는 모든 타워·새끼용이 무음이다(TowerFire 제거 + 카탈로그·배선은 M3·M4). 회귀가 아니다
- 컴파일 에러 0

커밋: `타워 투사체 발사 및 명중 효과음 연동`

## M6 — 실전 웨이브 믹싱·마감

결과 (2026-08-27):

- 실전 웨이브 청취 결과 **조정 없이 초기값 그대로 확정**했다. 설계 §8이 확정본이다
- 머스킷·얼음의 Launch/Resolve 순서도 현행 유지로 확정했다(설계 §7-3)
- 단, 새끼용 5종이 아직 공용 `TowerFire` 하나만 쓰는 상태라 전장 밀도가 실제보다 낮다.
  새끼용 전용 효과음을 넣으면 §8 수치와 풀 크기를 다시 확인한다(설계 §14)
- 커밋 전 `Log Se Usage Peak`를 끈다

계측:

- `SoundManager`의 `Log Se Usage Peak`를 켜면 동시 재생 최고치가 갱신될 때마다 콘솔에 남는다
- 이 숫자가 풀 크기(24)에 닿으면 포화다. 포화 상태에서는 재생 중인 소스를 덮어써서 소리가 잘리고 피치·정위가 튄다
- 조정이 끝나면 이 옵션은 끈다

조정 순서 (한 번에 하나씩, 섞지 않는다):

1. 풀 크기 — 계측 최고치가 풀 크기에 닿을 때만 올린다. 소리 잘림은 볼륨으로 못 고친다
2. 화면·줌 감쇠 4개 — 확정값 1.0 / 1.8 / 6 / 0.4. 줌아웃 시 전장 파악이 어려우면 `_seMinZoomVolumeScale`을 0.6~0.7로
3. `_seTowerVolumeScale` — 전투음 전체가 크거나 작을 때. 항목별 Volume보다 먼저 만진다
4. `MinInterval` — 같은 소리가 몇 겹까지 쌓이는지 보고
5. 항목별 `Volume` — 암석 Resolve 0.70을 기준으로 고정하고 나머지를 맞춘다
6. `PitchRange` — 같은 클립을 쓰는 항목의 구분과 반복 피로만 본다 (설계 §7-2)
7. `_sePanAmount` — 과하면 낮춘다. 0이면 정위가 꺼진다

판정:

- 설계 §10-3 회귀·믹싱 체크리스트
- 타워 10대 이상으로 밤 웨이브 완주, 1배속·2배속 비교
- `MinInterval`은 `Time.unscaledTime` 기준이라 2배속에서 더 많이 걸러진다. 두 배속을 오가며 타협점을 잡는다
- 판정은 플레이 중이 아니라 녹화본을 다시 들으며 한다

남은 결정:

- 설계 §7-3의 머스킷·얼음 Launch/Resolve 순서. 뒤집기로 하면 `TowerSoundCatalogSetup.cs`의 `SPECS`에서 해당 4줄의 클립을 맞바꾸고 메뉴를 다시 실행한다
- 포화가 관측되면 설계 §14의 소리 우선순위를 별도 설계로 올린다

완료 조건:

- 소리가 자주 끊기지 않고 동시 발사에서 볼륨이 폭증하지 않음
- BGM·몬스터 핵심음·UI음을 과도하게 가리지 않음
- SE 볼륨 0에서 신규 소리가 전부 사라짐
- 최종 수치를 설계 §8에 기록
- `Log Se Usage Peak`가 꺼진 상태로 커밋

커밋: `타워 전투 효과음 플레이 검증 및 수치 조정`

## M7 — 새끼용 전용 효과음

M6까지는 새끼용 5종이 공용 `TowerFire` 하나를 썼다. 속성별 전용 Launch/Resolve로 교체한다.

- 완료: `SoundId`에 31~40 추가 (`BabyDragonFireLaunch` ~ `BabyDragonLifeResolve`)
- 완료: `TowerSoundCatalogSetup.cs`에 클립·수치 10개 추가
- 완료: `TowerSoundDataWiring.cs`의 `BD_*` 5줄을 `TowerFire`에서 전용 ID로 교체
- 런타임 코드 변경 없음. 새끼용은 `TowerData`를 상속하고 `TowerAttack`을 그대로 쓴다
- 실행: **TowerAndDragon / Sound / 타워 효과음 카탈로그 채우기** → **타워 효과음 데이터 배선** 순서로 두 메뉴 모두 누른다
- 주의: 카탈로그 도구는 재생 파라미터 6개(마스터 볼륨 포함)도 C# 상수값으로 덮어쓴다. 인스펙터에서 손으로 조정한 값이 있으면 메뉴를 누르기 전에 `TowerSoundCatalogSetup.cs`의 상수부터 고친다
- 선행: 씬 2개의 `Se Pool Size`가 아직 12다. 새끼용 10종이 붙으면 밀도가 늘어나므로 24로 올린 뒤 청취한다

완료 조건:

- 카탈로그 로그의 클립 누락 0, 배선 로그의 에셋 누락 0
- 기존 0~30 항목이 변하지 않음
- 새끼용 5종이 속성별로 서로 다른 소리를 냄
- 얼음·생명 새끼용이 같은 클립을 쓰는 타워와 피치로 구분됨 (설계 §7-2)
- 새끼용까지 붙은 상태에서 동시 재생 최고치 재확인 (`Log Se Usage Peak`)

커밋: `새끼용 전용 효과음 배선`
