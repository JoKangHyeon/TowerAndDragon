## 1. 빌드 목표

빌드 7은 신규 시스템을 넓히는 빌드가 아니라, 현재 구현된 게임을 **처음부터 끝까지 안정적으로 플레이할 수 있는
베타 상태**로 만드는 빌드다.

핵심 목표는 다음 다섯 가지다.

1. 건물 세이브/로드 예외와 진행 차단 버그를 제거한다.
2. 연구·봉인석 등 성장/승리 관문을 기획과 일치시키고 비어 있는 기능을 정리한다.
3. 튜토리얼 1~3일차를 실제 플레이로 완주하고 막힘·중복 안내·오배선을 수정한다.
4. 본게임 28일 완주와 두 승리 경로를 검증하고 밸런스를 확정한다.
5. UI·연출·사운드·로컬라이징·문서를 베타 배포 가능한 수준으로 마감한다.

## 2. 베타 완료 조건

다음 조건을 모두 만족해야 빌드 7을 완료로 판단한다.

| 튜토리얼 | 새 게임 기준 1~3일차 전체 완주 1회 이상 |

| 문서 | 구현현황·플레이 가이드·빌드 결과 보고서가 실제 빌드와 일치 |

## 3. 우선순위

### P0 — 베타 차단 항목

#### 3.1 대공 타워 세이브/로드 수정

- `TP_Anti_Air`에 고유 `PrefabId` 부여
- `BuildingCatalog`에 대공 타워 프리팹 등록
- 기존 머스킷 타워 ID와 중복되지 않는지 카탈로그 검증
- 저장 후 로드했을 때 대공 타워가 머스킷 타워로 바뀌지 않는지 확인
- 위치·회전·배치 인구·비활성 상태 복원 확인

**완료 기준:** 대공 타워 포함 모든 건설 메뉴 건물이 고유 ID로 저장되고 같은 건물로 복원된다.

#### 3.2 봉인석 연구 해금 연결

- `ISealStoneUnlockQuery` 구현체 연결
- 봉인석 해금에 사용할 확정 연구 노드 확인
- 연구 전 건설 메뉴 잠금 및 잠금 사유 표시
- 연구 후 건설 가능 상태 전환 확인
- 4포탈 봉인석 건설 시 즉시 승리 확인
- 봉인석 배치 상태의 저장/로드 확인

> 해금 노드나 비용이 기획서에서 `[미정]`이면 임의로 확정하지 않는다. 8월 22일에 기획 담당 확인 후 구현한다.

#### 3.3 연구 효과 공백 정리

현재 효과가 비어 있는 노드 10개를 다음 세 상태 중 하나로 확정한다.

| 상태 | 처리 |
|---|---|
| 기획 확정 | 실제 효과 구현·연결·저장 복원·UI 설명 검증 |
| 베타 제외 확정 | 트리에서 숨김 또는 해금 불가 처리, 선행 경로가 끊기지 않게 재배선 |
| 기획 미정 | 담당자 확인 전 구현 금지, 8월 22일 결정 항목에 등록 |

대상 노드:

- 타워: 속성 타워 해금, 속성 분기, 관통/범위, 역설계
- 생산: 외곽 기본자원, 대각선 생산, 자동 생산선
- 편의: 자동 정산, 일괄 관리, 성 즉시 수리

함께 확인할 항목:

- 속성 타워의 `_requiresResearchUnlock` 활성 여부
- `GridMap.ResearchUnlockQuery` 연결 여부
- 해금 전/후 건설 메뉴 상태와 경고 문구
- 연구 완료 상태의 세이브/로드

**완료 기준:** 플레이어가 비용을 지불했는데 아무 변화가 없는 연구 노드가 없다.

#### 3.4 튜토리얼 전체 완주 QA

- 1일차: 건설 → 인구 배치 → 첫 밤 방어
- 2일차: 생산시설 → 새끼용 → 점령 → 연구
- 3일차: 어미용 속성 변경 → 용 스킬트리 → 액티브 스킬 → 보스 → 엔딩
- 필수 목표 미완료 시 밤 진입 차단 문구 확인
- 자원·인구 하한 보장과 자유 건설 상한 확인
- 안내 오버레이 전환 시 깜빡임·중복·입력 잠금 확인
- `B`·`V`·`C`·`ESC`·마우스 휠 안내와 실제 입력 일치 확인
- 한국어·영어 각각 문구 잘림 및 키 노출 확인

**완료 기준:** 디버그 건너뛰기 없이 새 게임에서 엔딩까지 진행할 수 있다.

#### 3.5 세이브/로드 통합 검증

다음 상태를 한 슬롯에 구성한 뒤 저장 → 타이틀 → 이어하기로 검증한다.

- 이동·회전한 기본 타워와 속성 타워
- 대공 타워
- 인구가 배치된 생산시설·연구소
- 비활성화된 타워
- 공격/버프 모드 새끼용 타워
- 진행 중인 점령 원정
- 점령 완료 영토와 랜드마크 수령 이력
- 연구·용 스킬트리 해금 상태
- 봉인석
- 가이드 퀘스트 완료 상태

추가 확인:

- 낮 정산 후 자동 저장에서 생산·유지비가 중복 적용되지 않는지
- 1일차 새 게임/재시작 시 이전 자동 저장이 남지 않는지
- 구버전 슬롯을 읽을 때 오류 없이 정규화되거나 명확히 거부되는지

**완료 기준:** 데이터 유실·증식·건물 종류 변경 없이 동일한 낮 상태로 복원된다.

### P1 — 베타 품질 항목

#### 3.6 28일 밸런스 재검증

- 7·14·21·28일차 보스 난이도 기록
- 8·15·22일차 신규 포탈 개방 직후 난이도 확인
- 날짜별 보유 자원·최대 인구·배치 인구·타워 수 기록
- 점령 횟수와 추가 스폰 체감 기록
- 식량·목재·석재·슬라임 병목 시점 기록
- 사용한 어미용 속성·액티브 횟수·새끼용 수 기록
- 화살/석궁 중심 단일 전략이 다른 타워 선택을 과도하게 압도하는지 확인
- 최종 보스가 특정 속성이나 현재 체력 비례 스킬만 요구하는지 확인

**완료 기준:** 일반적인 플레이가 14일 이전에 반복적으로 막히지 않고, 28일차가 준비한 방어를 검증하는 난이도로 동작한다.

#### 3.7 전투·콘텐츠 마감

- 생명 타워의 베타 포함 여부를 기획 담당과 확정
- 포함 시 공격/회복 대상·인구·연구·건설 비용·UI 설명까지 연결
- 제외 시 건설 메뉴·도감·로컬라이징에서 개발 예정 또는 잘못된 노출 제거
- 대공 타워의 지상/공중 타겟 필터와 웨이브 역할 확인
- 적 툴팁의 체력·방어막·속성·상태·점령 강화 수치가 실제 값과 일치하는지 확인
- 몬스터 사망 자원 드랍은 기획 확정 여부를 확인하고, 미정이면 베타 범위에서 제외

#### 3.8 UI · 연출 · 사운드

- 주요 창의 `ESC` 닫기 순서와 배타 모드 충돌 확인
- 겹친 건물 선택 순환 및 툴팁 대상 일치 확인
- 미니맵·세이브 썸네일·설정창의 화면 비율 확인
- 슬라임 잔량 `▲`·`▼`·`!`와 실제 다음 날 정산 일치 확인
- 주민 풀링에서 잔상·중복·잘못된 목적지·회수 누락 확인
- 타워 공격·피격·비활성화·재활성화 이펙트 점검
- 낮/밤·보스·승리·패배·UI 사운드 누락 및 과도한 중첩 확인

## 7. 협업 및 변경 관리

- 기획서의 `[미정]` 항목은 임의 구현하지 않고 담당자 확인 후 진행한다.
- `SampleScene`·`Tutorial`·공용 UI 프리팹은 충돌 위험이 높으므로 작업 전 담당 범위를 공유한다.
- 씬 변경과 코드 변경은 가능한 한 작은 단위의 커밋으로 분리한다.
- 코드 본문 문자열과 리터럴 상수는 프로젝트 규칙에 따라 스트링테이블·상수로 분리한다.
- 기능 완료 선언 전 코드 확인, 씬 배선 확인, 플레이 확인을 구분해 기록한다.
- 밸런스 변경은 이전값·변경값·변경 이유·재테스트 결과를 `BalanceNote.md`에 남긴다.
- `Imported/` 원본 에셋은 수정하지 않는다.
