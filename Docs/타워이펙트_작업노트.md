# 타워 이펙트 작업 노트

타워 발사체·명중 이펙트를 만들면서 알게 된 것을 적어 둔다.
새 세션에서 이 작업을 이어받는 사람(사람이든 에이전트든)이 같은 함정에 다시 빠지지 않도록.

최종 갱신: 2026-08-23

---

## 0. 가장 먼저 알아야 할 것 — 프리팹이 결과물이다

**`Assets/Imported`는 버려지는 폴더가 아니라 팀이 공유하는 별도 private 저장소다.**

- 원격: `github.com/JoKangHyeon/TowerAndDragon_Imported`
- 서브모듈이 아니라 그 자리에 `Assets/Imported/.git`이 따로 있다
- 메인 저장소의 `.gitignore`에 `/[Aa]ssets/[Ii]mported`가 있어 **메인에서만** 빠져 있다
- 팀 규칙: 유료 외부 에셋을 여기에 넣고 팀원 전원이 이 저장소를 공유한다

그래서:

- 여기에 커밋한 프리팹은 **팀원 전원이 그대로 받아 쓴다.** 각자 생성기를 돌리지 않는다.
- 게임이 참조하는 것도 TowerData에 물린 **프리팹**이지 생성기가 아니다.
- 버전 상태를 볼 때는 `git -C Assets/Imported ...`로 물어본다.
  메인 저장소에서 `git status`를 돌리면 "추적 안 됨"으로 보여 **"되돌릴 수 없다"고 오판하기 쉽다.**
  실제로는 히스토리가 있고 `git -C Assets/Imported checkout <경로>`로 되돌릴 수 있다.

**`CoplayScripts/`의 생성기는 프리팹을 만들어 낸 발판이다. 타워 이펙트 작업이 끝나면 폴더째 삭제할 계획이다.**
생성기에 리팩터링·문서화를 투자하지 말 것 — 전부 버려질 코드다.
이펙트 변경 요청이 오면 "생성기에도 반영할까요?"를 기본 선택지로 내밀지 말고,
프리팹만 고치면 되는지 먼저 따진다. 생성기를 고쳐야 하는 경우는 앞으로도 그것을 계속 돌릴 때뿐이다.

작업이 끝나면 `Assets/Imported`에서 커밋해 팀에 공유한다.

## 2. 이 프로젝트에서 이펙트가 깨지는 이유 — 카메라

원본 팩은 **3D 지면을 내려다보는 카메라**를 전제로 만들어져 있다.
이 프로젝트는 카메라를 기울이지 않고(회전 0, z=-10 정사영) 타일 아트를 아이소메트릭으로 그린다.
여기서 두 가지가 어긋난다.

### 2-1. `HorizontalBillboard`는 아무것도 그리지 않는다

월드 XZ 평면에 고정된 렌더 모드라, 회전 0인 카메라에서는 **옆날로 서서 한 픽셀도 안 그린다.**
이 팩의 바닥 데칼은 대부분 이 모드다. 그대로 쓰면 지면 균열이 통째로 사라진다.

고치는 법: `Billboard` + `alignment = View`로 바꾸고, 세로만 절반으로 눌러 바닥에 누운 타원으로 만든다
(아이소메트릭 셀이 1 x 0.5이므로 바닥에 누운 원은 화면에서 2:1 타원이다).

`BuildStatusVfx`의 `LaysDecalsFlat` 옵션이 이 처리를 한다.
얼음·암석은 생성 후 `Apply*DecalTuning`으로 따로 걸었고, 화염은 생성기 안에서 한다.

### 2-2. 원본 기울기는 건드리지 말 것

처음에는 모든 자식의 X·Y 회전을 0으로 눕히는 게 맞다고 봤다(`FlattensToScreenPlane`).
실제로 놓고 보면 **원본 기울기가 그대로 맞다.** 57도쯤 뒤로 누운 메시가 화면에서 눌려 보이는 것이
곧 "셀 바닥에 놓인" 그림이 된다. 정면으로 세우면 오히려 바닥을 뚫고 선 것처럼 보인다.

지금 어느 정의도 이 옵션을 켜지 않는다.

## 3. 겪은 함정들

### 3-1. 자식 이름으로 후보를 거르지 말 것 ★

**이 팩들은 이름과 실제 그림이 자주 어긋난다. 반드시 렌더해서 픽셀로 확인한다.**

같은 작업에서 두 번 틀렸다.

- `Impact_Fire_V1`의 자식이 `Derbis`·`Sparks`·`BigSparks`·`GlowBlack`이라 "불기둥이 없다"고
  후보에서 뺐는데, 실제로는 **`Derbis`가 소용돌이치는 불덩이**였다. 최종 채택안이 됐다.
- 반대로 `FX_Crack_Firewave`의 `floorglow`·`flame`은 이름만 보면 바닥 불길인데
  실제로는 **아무것도 그려지지 않았다**(어두워서 임계값 미달).

측정 도구: `CoplayScripts/MeasureImpactChildren.cs` — 자식 하나만 렌더러를 켜고 구워
폭·높이·픽셀 수를 잰다.

### 3-2. 궤적이 흐릿하면 두께가 아니라 구조를 볼 것

석궁 궤적이 흐릿하다는 지적에 `TrailSizeMultiplier`가 없어서라고 진단했다가 틀렸다.
실제로 날려서 재 보니 배수 없이도 두께 0.06으로 화살(0.065)과 같은 대역이었다.
배수를 주니 0.49까지 부풀어 화면만 어지러워졌다.

진짜 원인은 **궤적을 만드는 자식이 다르다**는 것이었다.

- 화살 `01_nature_arrow`: `SubSparks`(작은 Stretch) + `Glow`(Billboard)가 겹쳐 **매끈한 한 줄**
- 석궁 `21_red_arrow`: `SubEnergy` 하나뿐인데 **넓은 삼각 조각이 흩날리는 그림**
  (렌더러 길이배율이 `-1.5` 음수라 진행 방향 반대로 늘어나기까지 한다)

발사체 원본을 바꿔야 해결된다. 배수로는 안 된다.

측정 도구: `CoplayScripts/RenderProjectileTrails.cs` — 한 프레임씩 Simulate하며 위치를 옮겨
실제로 날리면서 궤적을 굽는다. 제자리에서 Simulate만 하면 World 공간 파티클이 한 점에 겹쳐 쌓여
궤적을 볼 수 없다.

### 3-3. 색조(HueDegrees)는 `ColorOverLifetime`까지 돌려야 한다

`ApplyHue`가 `main.startColor`만 돌리고 `ColorOverLifetime`은 보지 않아,
어떤 색조를 줘도 궤적 선이 청록으로 남는 버그가 있었다(2026-08-23 수정).

원인: 선을 그리는 `SubSparks`는 `startColor`가 흰색이고 실제 색은
`ColorOverLifetime` 그라디언트에 박혀 있었다(`0.35,1,0` → `0,1,0.71`).
흰색을 아무리 돌려도 흰색이라 아무 일도 일어나지 않는다.

지금은 그라디언트 키를 하나씩 돌린다. 알파 키는 건드리지 않는다(페이드 타이밍이 같이 바뀐다).
채도 0인 키(흰색·검정)는 `ShiftHue`가 채도를 유지하므로 저절로 보존된다.

`HueDegrees`는 **절대값**이다 — 원본이 무슨 색이든 그 값으로 바뀐다(채도·명도·알파는 유지).
발사체뿐 아니라 머즐·임팩트에도 걸려 세트 전체가 같은 색이 된다.

### 3-4. 광역 AOE는 정사영 2D에 못 얹는다

암석 타워에 `FX_Crack_RockAOE`를 얹어 광역 반경을 표시하려 했다가 뺐다.
이 팩의 AOE는 3D 지면을 내려다보는 카메라를 전제로 한 큰 바닥 판이라,
정사영 2D에 맞추려고 빌보드로 세우면 반경을 알려주기는커녕 **솟아오른 바위를 정면에서 덮어 버린다.**
어떤 크기·색 배수를 줘도 "가리거나, 안 보이거나" 둘 중 하나였다.

**대신 들어간 것은 없다. 광역 반경 표시는 지금 없는 상태다.**
남은 지면 균열(ring)은 2.88칸이라 반경 2(지름 4칸)에 못 미치니 반경 표시로 읽으면 안 된다.
사거리를 보여줘야 한다면 별도로 만들어야 한다.

### 3-5. 방출 방식이 명중 연출의 성패를 가른다

명중 이펙트는 **버스트 방출**이어야 한다. 연속 방출(rateOverTime)은 입자가 쌓이는 데 시간이 걸려
명중 순간이 빈다.

| 원본 | 버스트 | 연속 |
|---|---|---|
| `FX_GroundCrack_Blue` (얼음 바탕) | 9 | 2 |
| `FX_Crack_Rock` (암석 바탕) | 13 | 4 |
| `FX_Crack_Risingfire` | **1** | **10** |

Risingfire를 화염 바탕으로 썼다가 물렀다 — t=0.06에 82픽셀밖에 안 그려지고(얼음 6188, 암석 8291)
반대로 t=2.0에도 9646픽셀이 남아 스스로 꺼지지 않았다.

수명 참고값: 얼음은 1.2초에 643픽셀, 암석은 0.6초에 0. 화염도 그 안에서 꺼지게 맞췄다.

### 3-6. 렌더 시트끼리 숫자를 비교하려면 카메라 배율이 같아야 한다

`orthographicSize`가 다르면 임계값을 넘는 바깥 픽셀 수가 달라져 **잰 폭이 통째로 어긋난다.**
한 번 이것 때문에 배수를 반대 방향으로 잡았다(줄여야 한다고 판단했는데 실제로는 키워야 했다).

### 3-7. 병합한 자식은 배수를 다시 잡아야 한다

다른 원본에서 자식을 가져오면 authoring 기준이 달라 그대로는 안 맞는다.

- 얼음: `Crack_BlueShock`의 파열에 ×2.6, `Crack_Blue02`의 줄기에 ×25
- 화염: `Crack_Risingfire`의 `Flash`는 루트 0.11 기준이라 루트 0.84인 쪽에 얹으니
  유효 크기가 36까지 뛰었다 → ×0.13

### 3-8. `RotatesImpactToTravelDirection`은 지면 이펙트에서 꺼야 한다

기본값이 `true`다. 화살·총알처럼 튀는 방향이 있는 임팩트에는 켜야 하지만,
**지면에 깔리는 이펙트는 꺼야 한다** — 켜 두면 아래로 쏜 발사체가 맞았을 때
균열과 솟는 석영까지 뒤집혀 땅을 향한다.

Ice·StoneMeteor·Fire가 `false`다.

## 4. 도구

전부 `CoplayScripts/` 아래에 있고 Coplay MCP `execute_script`로 실행한다.
`Assets/` 밖이라 유니티가 컴파일하지 않고 `MenuItem`도 없어서 **에디터에서 직접 호출할 수 없다.**

| 스크립트 | 하는 일 |
|---|---|
| `BuildStatusVfx` | Eric 팩에서 `FX_Impact_*` 조합. `Build`(있으면 건너뜀) / `Rebuild`(덮어씀+백업) |
| `AssignTowerProjectiles` | 타워별 클론 생성 + TowerData 배선. `BuildAssignAndValidate` / `RebuildAll` |
| `Apply*DecalTuning` | 생성 후 손튜닝(얼음·암석). 생성기를 다시 돌리면 다시 걸어야 한다 |
| `MeasureImpactChildren` | 자식 하나씩 렌더해 크기·픽셀 측정 |
| `RenderProjectileTrails` | 발사체를 실제로 날리며 궤적 측정 |
| `RenderImpactAlign` | 여러 임팩트를 같은 시트에 굽고 스폰 높이 기준 정렬 확인 |
| `VerifyTowerDataRefs` | ScriptableObject 참조가 살아있는지 검사 |

렌더 결과는 `output/vfx_check/`에 쌓아 뒀다(메인 저장소에서 추적됨).

**덮어쓰기 전에 반드시 백업한다.** 기본 진입점은 이미 있는 산출물을 건너뛰고,
`Rebuild`/`RebuildAll`은 프로젝트 루트 `VfxBackup/<시각>/`에 사본을 남긴다(`.meta`까지 — GUID가 거기 있다).
