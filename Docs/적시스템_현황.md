# 적(몬스터) 시스템 현황

작성일: 2026-07-09 · 최종 갱신: 2026-07-10 (공격·효과 시스템 전략 패턴 리팩터 반영) · 대상: 프로토타입 단계 적 시스템 코드
상세 기획은 `Docs/기획종합_v2.md`(13. 적)를 우선하며, 이 문서는 **현재 코드로 구현된 부분**과 그 **작동 원리**만 정리합니다.

## 1. 설계 방향

적은 "모든 것을 가진 거대한 부모 클래스"로 만들지 않았습니다. 대신 `BaseMonster`가 오케스트레이터 역할을 하고, 실제 능력(체력·방어막·이동·공격)은 프리팹에 붙이는 개별 컴포넌트로 분리했습니다.

핵심 원칙은 **상속이 아닌 조합(composition)**입니다. "지상/공중 × 공격/비공격 × 방어막 유무" 같은 적 종류의 조합을, 클래스를 새로 상속받아 만드는 대신 프리팹에 어떤 컴포넌트를 붙이고 어떤 `MonsterData`를 주입하느냐로 표현합니다. 덕분에 기획자가 코드 수정 없이 데이터 에셋만 복제해 "공중 원거리 방어막" 같은 변형을 직접 만들 수 있습니다. 이는 미션 필수 요건인 데이터 기반 설계(ScriptableObject)와도 맞닿아 있습니다.

## 2. 구성 요소 한눈에 보기

| 스크립트 | 역할 | 필수/선택 |
|---|---|---|
| `BaseMonster` | 오케스트레이터. 컴포넌트 조립 + 생명주기 관리 | 필수 |
| `MonsterData` | 적 한 종류의 스탯/구성 데이터 (ScriptableObject) | 필수 (주입) |
| `Health` | 체력 관리, 사망 이벤트 발생 | 필수 |
| `MonsterMovement` (추상) | 이동의 공통 기반 (전략 패턴) | 필수 |
| `GroundSplineMovement` | 지상 유닛 — 스플라인 경로 이동 | 이동 방식 택1 |
| `AirDirectMovement` | 공중 유닛 — 메인 성 직진 | 이동 방식 택1 |
| `MonsterShield` | 방어막. 데미지 선흡수 | 선택 |
| `MonsterAttack` | 공격 실행자. `AttackSO`를 주입받아 효과를 적용 (타깃팅·발사 루프는 골격) | 선택 |
| `AttackSO` | 공격 정의 (ScriptableObject). 사거리·간격 + 효과 목록 보관. 타워와 공용 | 공용 |
| `IAttackEffect` / `AttackEffectSO` | 효과 전략 계약 + SO 직렬화용 추상 베이스 | 공용 |
| `DamageEffectSO` | 즉발 데미지 효과 (전략 구현체) | 공용 |
| `AttackContext` | 공격 적용 시 부가 정보(시전자 등) 자료구조 | 공용 |
| `IDamageable` / `DamageInfo` | 데미지 전달용 공통 계약/자료구조 | 공용 |
| `MonsterMovementType` | 이동 방식 구분 enum (Ground/Air) | 공용 |

## 3. 생명주기 (작동 순서)

`BaseMonster`는 다음 흐름만 관리합니다: **주입 → 이동 → 데미지 라우팅 → 사망 → 삭제**.

1. **Awake** — 같은 게임오브젝트에 붙은 `Health`, `MonsterShield`, `MonsterMovement`, `MonsterAttack`를 참조로 캐싱합니다. (`Health`는 `[RequireComponent]`로 강제, 나머지는 있으면 사용)
2. **Setup(주입)** — 스포너가 `MonsterData`, 지상용 경로(`SplineContainer`), 공중용 목표(메인 성 `Transform`)를 넘겨 호출합니다.
   - 체력을 `MaxHealth`로 초기화하고 `Died` 이벤트를 구독합니다.
   - `HasShield`이면 방어막을 `ShieldAmount`로 초기화합니다.
   - `IsAttacker`(= `Attack` 슬롯에 `AttackSO`가 지정됨)이면 `MonsterAttack`에 그 `AttackSO`를 주입합니다.
   - 이동 컴포넌트를 구성하고 이동을 시작합니다.
3. **이동** — 매 프레임 자기 방식대로 목적지로 이동, 도착하면 `Arrived` 이벤트 발생.
4. **데미지 수신** — 타워 등 공격자가 `TakeDamage`를 호출 (아래 4절).
5. **사망** — 체력이 0이 되면 `Health.Died` → `BaseMonster.HandleDeath` → 현재는 `Destroy`로 정리.
6. **정리(OnDestroy)** — 구독했던 이벤트(`Died`, `Arrived`)를 해제해 누수를 방지합니다.

## 4. 데미지 파이프라인

공격자는 상대의 구체 타입을 몰라도 `IDamageable` 인터페이스로만 상호작용합니다. 적·타워·메인 성 모두 이 계약을 따르므로, 타워는 "적"이 아니라 "데미지 받을 수 있는 대상"에게 공격합니다.

데미지는 `DamageInfo` 구조체에 실려 전달됩니다. 지금은 데미지 양(`Amount`)만 담지만, 이후 방어막 속성 상성 등을 이 타입에 추가해 확장할 수 있도록 별도 타입으로 분리해 두었습니다(파라미터 객체 패턴 — 필드가 늘어도 `TakeDamage` 시그니처는 그대로).

공격 쪽에서도 데미지는 직접 넣지 않고 `DamageEffectSO`가 `target.TakeDamage(new DamageInfo(...))`로 전달합니다. 즉 "공격 효과"와 "데미지 수신"이 `IDamageable`/`DamageInfo` 계약 하나로 이어지므로, 타워든 적이든 같은 파이프라인을 공유합니다.

`BaseMonster.TakeDamage`의 흡수 순서:

1. 이미 죽었으면 무시.
2. 방어막이 있고 아직 깨지지 않았으면 **방어막이 먼저 흡수**한다. `MonsterShield.Absorb`는 흡수하고 남은 잔여 데미지를 반환한다. 방어막이 이 타격으로 0이 되면 `ShieldBroken` 이벤트를 발생시킨다.
3. 잔여 데미지가 남아 있으면 그때 본체 `Health`로 넘긴다.

즉 방어막 → 체력 순의 2단 방어 구조이며, 방어막이 없는 적은 곧바로 체력이 깎입니다.

## 5. 이동 시스템 (전략 패턴)

`MonsterMovement`는 추상 클래스로 공통 기반(속도 설정, 시작/정지, 도착 판정, `Arrived` 이벤트)을 제공하고, 구체 이동 방식은 파생 클래스가 구현합니다.

**지상 (`GroundSplineMovement`)** — 포탈에서 메인 성까지 이어진 스플라인 경로(`SplineContainer`)를 따라 이동합니다. 매 프레임 이동 거리를 누적해 경로 길이 대비 진행도(0~1)를 계산하고, 그 위치로 스플라인을 평가해 배치합니다. 진행도가 1에 도달하면 도착 처리합니다. 스포너가 포탈별 경로를 주입합니다.

**공중 (`AirDirectMovement`)** — 경로를 무시하고 메인 성을 향해 직진합니다(기획의 "지나가용" 계열, 까다로운 적). 매 프레임 목표 위치로 `MoveTowards` 하고, 도착 임계값(`_arrivalThreshold`, 기본 0.05) 이내로 들어오면 도착 처리합니다. 스포너가 목표(메인 성 `Transform`)를 주입합니다.

두 방식 모두 목적지 도달 시 `RaiseArrived`로 `Arrived` 이벤트를 한 번만 발생시킵니다(중복 방지).

## 6. 공격·효과 시스템 (전략 패턴)

공격은 이동과 같은 전략 패턴으로 구성되며, **"효과 하나 = 전략 하나"**로 쪼개 둡니다. 하나의 공격(`AttackSO`)이 여러 효과(데미지·둔화 등)를 조합해 대상에 순차 적용하는 구조입니다. 타워와 적이 동일한 애셋을 공유할 수 있어, "화염 화살(데미지+화상)" 같은 조합을 코드 수정 없이 기획자가 에셋으로 만듭니다.

네 개의 레이어로 책임을 나눕니다.

1. **효과(전략)** — `IAttackEffect`가 계약(`Apply(IDamageable, in AttackContext)`)이고, `AttackEffectSO`가 인스펙터 조합·직렬화를 위한 추상 SO 베이스입니다. 구체 효과인 `DamageEffectSO`가 즉발 데미지를 담당합니다(에셋 메뉴 `TowerAndDragon/Attack Effects/Damage`).
2. **공격 정의(데이터)** — `AttackSO`가 사거리·발동 간격과 효과 목록(`AttackEffectSO[]`)을 보관합니다(에셋 메뉴 `TowerAndDragon/Attack`). `Execute`는 효과들을 대상에 순차 적용할 뿐 **상태를 갖지 않습니다**. 여러 유닛이 같은 애셋을 공유하기 때문입니다.
3. **실행(런타임)** — `MonsterAttack` 컴포넌트가 `AttackSO`를 주입받아 실행합니다. 쿨다운 같은 런타임 상태는 공유 애셋이 아니라 이 컴포넌트가 보관합니다.
4. **대상(수신)** — 즉발 데미지는 기존 `IDamageable`로 전달합니다. 둔화·화상처럼 지속되는 효과는 효과가 직접 시간을 관리하지 않고 대상 쪽 상태 시스템에 위임하는 설계이나, 그 상태 시스템(`IStatusReceiver`)은 아직 미도입 `[미정]`입니다.

핵심은 **지속 효과의 책임 분리**입니다. 효과는 "대상에 상태를 걸어주는 역할"만 하고, 지속·틱·해제는 대상이 담당해야 `AttackSO`가 시간 관리까지 떠안지 않습니다.

## 7. 데이터 구조 (`MonsterData`)

적 한 종류의 스탯을 담는 ScriptableObject입니다. 에셋 메뉴 `TowerAndDragon/Monster Data`로 생성합니다.

- **Identity**: `NameLocKey` — 이름은 코드에 문자열로 넣지 않고 스트링테이블 key로 관리 (프로젝트 커밋 규칙 준수).
- **Stats**: `MaxHealth`, `MoveSpeed`, `MovementType`(Ground/Air).
- **Shield (선택)**: `HasShield`, `ShieldAmount`.
- **Attack (선택)**: `Attack` — `AttackSO` 참조 하나. 지정하면 공격형(`IsAttacker`가 자동으로 참), 비워 두면 비공격형입니다. (기존의 `IsAttacker`/`AttackDamage`/`AttackRange`/`AttackInterval` flat 필드는 `AttackSO`로 통합돼 제거됨)

## 8. 현재 상태 · 미구현 (TODO)

구현이 완료되어 동작하는 부분: 컴포넌트 조립·생명주기, 체력·사망, 방어막 2단 흡수, 지상 스플라인/공중 직진 이동, 데미지 인터페이스, SO 데이터 주입, **공격·효과 전략 구조(`AttackSO` + `DamageEffectSO`)**.

아직 골격만 있거나 미구현인 부분:

- **스포너 / 웨이브** — 실제 스폰·웨이브 로직 스크립트는 아직 없습니다. `Setup`을 호출하고 경로·목표를 주입하는 주체가 필요합니다. 웨이브 공식은 기획서에서도 `[미정]`.
- **성 도달 처리** — `HandleArrivedAtCastle`는 연결 지점만 있고 비어 있습니다. 밤 방어 로직(성 공격)과 함께 구현 예정.
- **타워 공격형 발사 로직** — 효과 적용 구조(`AttackSO`)는 완성됐으나, `MonsterAttack`의 대상 선정(타깃팅)·쿨다운·발사 루프는 팀 확정 후 구현 `[미정]`.
- **상태(지속) 효과 시스템** — 둔화·화상 등을 위한 `IStatusReceiver`와 상태 지속/틱/해제 시스템, `SlowEffectSO` 등은 미도입 `[미정]`. 효과 SO 구조는 이를 얹을 수 있게 준비돼 있습니다.
- **사망 후처리** — 슬라임/자원 드랍, 이펙트 연결 지점만 있습니다. 오브젝트 풀링은 보류 상태라 현재는 `Destroy`로 정리합니다.
- **속성 시스템** — 미도입. 추후 방어막(`DamageInfo` 확장)에 속성 상성을 붙일 예정.
- **보스** — 주기별 보스/최종 보스 미구현 `[미정]`.

> 마이그레이션 주의: 공격 필드를 `AttackSO`로 통합하면서 기존 `MonsterData` 에셋에 저장돼 있던 공격 수치(데미지·사거리·간격)는 유실됩니다. 공격형 적은 `AttackSO`(+`DamageEffectSO`) 에셋을 새로 만들어 `Attack` 슬롯에 다시 연결해야 합니다.

## 9. 확장 가이드 (새 적 만들기)

1. `MonsterData` 에셋을 생성/복제하고 스탯·옵션을 설정합니다.
2. 프리팹에 `BaseMonster`(+자동으로 `Health`)를 붙입니다.
3. 이동 방식에 맞춰 `GroundSplineMovement` 또는 `AirDirectMovement`를 하나 붙입니다.
4. 방어막이 필요하면 `MonsterShield`를, 타워 공격형이면 `MonsterAttack`을 추가로 붙입니다.
5. 공격형이라면 `AttackSO` 에셋을 만들어 사거리·간격을 넣고, `DamageEffectSO`(+추후 다른 효과) 에셋을 효과 목록에 담은 뒤, `MonsterData`의 `Attack` 슬롯에 연결합니다.
6. 스포너가 `Setup`으로 데이터·경로·목표를 주입하면 됩니다. **코드 변경은 필요 없습니다.**
