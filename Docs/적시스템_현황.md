# 적(몬스터) 시스템 현황

작성일: 2026-07-09

최종 갱신: 2026-07-13 (이슈 #15 적 공격 시스템 진행 상황 반영)

대상: 프로토타입 단계 적 이동·공격·피격 시스템

상세 게임 기획은 `Docs/기획종합_v2.md`를 우선합니다. 이 문서는 기획 내용을 확정하거나 복제하지 않고, 현재 코드로 구현된 범위와 실제 작동 방식을 정리합니다.

## 1. 현재 구현 목표

모든 적은 메인 성을 최종 목표로 이동합니다. 적 종류에 따라 이동 중 타워를 공격할 수 있으며, 최종적으로 메인 성에 도착하면 성이 파괴될 때까지 공격해야 합니다.

현재 구현 상태는 다음과 같습니다.

- 이동 중 타워 탐색·정지·공격·이동 재개: 구현
- 적과 타워의 공용 `AttackSO` 효과 적용: 구현
- 적 및 타워 피격 디버그 로그: 구현
- 타워 체력 고갈 시 비활성화와 지연 재활성화: 구현
- 메인 성 도착 후 성 공격: 미구현

따라서 현재 `MonsterTargetType.None`인 적은 메인 성까지 이동하지만, 도착 후 아직 성을 공격하지 않습니다. `MonsterTargetType.Tower`인 적은 이동 중 타워를 공격한 후 메인 성까지 계속 이동하지만, 마찬가지로 도착 후 성 공격은 아직 연결되지 않았습니다.

## 2. 핵심 구성 요소

| 구성 요소 | 역할 | 현재 상태 |
|---|---|---|
| `BaseMonster` | 적 컴포넌트 조립, 데이터 주입, 피격·사망·도착 처리 | 구현, 성 도착 처리 미연결 |
| `MonsterData` | 체력·속도·이동 방식·방어막·공격·이동 중 대상 범주를 보관하는 SO | 구현 |
| `MonsterMovement` | 이동 시작·정지·도착 이벤트의 공통 기반 | 구현 |
| `GroundSplineMovement` | 스플라인 경로를 따라 이동 | 구현 |
| `AirDirectMovement` | 메인 성을 향해 직선 이동 | 구현 |
| `MonsterAttack` | 이동 중 대상 탐색, 이동 정지·재개, 쿨다운, 효과 실행 | 구현 |
| `MonsterTargetType` | 이동 중 공격할 수 있는 대상 범주 | 구현 (`None`, `Tower`) |
| `IMonsterTarget` | 몬스터가 이동 중 탐색할 수 있는 대상 계약 | 구현 |
| `Tower` | `IMonsterTarget` 구현, 피해 수신, 비활성화·재활성화 | 구현 |
| `AttackSO` | 공격 사거리·간격·효과 목록을 보관하는 공용 SO | 구현 |
| `AttackEffectSO` | 공격에 조합할 개별 효과의 추상 기반 | 구현 |
| `DamageEffectSO` | `IDamageable` 대상에게 즉발 피해 적용 | 구현 |
| `Health` | 현재·최대 체력, 피해, 사망 이벤트, 완전 회복 | 구현 |

## 3. 데이터 구조

### MonsterData

`MonsterData`는 적 종류별 고정 데이터를 보관합니다.

- `NameLocKey`: 몬스터 이름 스트링테이블 key
- `MaxHealth`: 최대 체력
- `MoveSpeed`: 이동 속도
- `MovementType`: 지상 또는 공중 이동 방식
- `HasShield`, `ShieldAmount`: 선택적 방어막 설정
- `Attack`: 사용할 `AttackSO`
- `EnRouteTargetTypes`: 이동 중 공격할 대상 범주

모든 적이 메인 성을 공격해야 하므로 최종적으로 모든 적 데이터에 유효한 `AttackSO`가 필요합니다. 현재 코드는 `AttackSO`가 비어 있으면 `MonsterAttack` 초기화를 건너뛰는 방어 조건을 유지하고 있습니다.

### MonsterTargetType

`MonsterTargetType`은 최종 목적지가 아니라 **이동 중 공격할 대상**만 나타냅니다.

| 값 | 의미 |
|---|---|
| `None` | 이동 중 별도 대상을 공격하지 않고 메인 성까지 진격 |
| `Tower` | 이동 중 공격 사거리 안의 타워를 공격 |

메인 성은 모든 적의 공통 최종 목표이므로 이 값으로 선택하지 않습니다.

## 4. 초기화 흐름

스포너가 `BaseMonster.Setup(data, path, mainCastle)`을 호출하면 다음 순서로 초기화합니다.

1. `MonsterData`를 저장합니다.
2. `Health`를 최대 체력으로 초기화하고 사망 이벤트를 구독합니다.
3. 방어막 설정이 있으면 `MonsterShield`를 초기화합니다.
4. `MonsterAttack`과 `AttackSO`가 있으면 다음 정보를 공격 컴포넌트에 전달합니다.
   - `AttackSO`
   - `MonsterData.EnRouteTargetTypes`
   - 현재 `MonsterMovement`
5. 이동 방식에 따라 스플라인 경로 또는 메인 성 위치를 전달합니다.
6. 이동 도착 이벤트를 구독하고 이동을 시작합니다.

`MonsterAttack`은 초기화 시 현재 대상을 비우고 다음 공격 가능 시각을 현재 시각으로 설정합니다. 따라서 첫 대상을 발견하면 즉시 공격할 수 있습니다.

## 5. 이동 중 공격 흐름

`MonsterAttack.Update`는 다음 흐름으로 동작합니다.

```text
초기화 및 이동 상태 확인
  → 이동 중 공격 대상이 None이면 탐색하지 않음
  → 현재 대상이 유효한지 검사
  → 유효하지 않으면 대상 해제 후 이동 재개
  → 대상이 없으면 사거리 안에서 가장 가까운 허용 대상 탐색
  → 대상 발견 시 이동 정지
  → 공격 간격이 지나면 AttackSO.Execute
  → 대상이 비활성화되거나 사거리 밖이면 이동 재개
```

대상 탐색은 `Physics2D.OverlapCircleAll`을 사용합니다.

1. 몬스터 위치를 중심으로 `AttackSO.Range` 범위의 Collider를 찾습니다.
2. `MonsterAttack.TargetLayers`에 포함된 Collider만 검색합니다.
3. Collider의 부모에서 `IMonsterTarget`을 찾습니다.
4. 죽지 않았고 `EnRouteTargetTypes`에 포함된 대상만 남깁니다.
5. 조건을 만족하는 대상 중 가장 가까운 대상을 선택합니다.

타워를 선택하면 `MonsterMovement.Stop()`을 호출합니다. 타워가 비활성화되거나, 파괴되거나, 사거리를 벗어나면 현재 대상을 비우고 `MonsterMovement.Begin()`을 호출해 기존 경로 이동을 재개합니다.

현재 대상 우선순위는 **사거리 안의 가장 가까운 허용 대상**입니다. 별도의 타워 우선순위 정책은 구현하지 않았습니다.

## 6. 공격 효과 적용

몬스터와 타워는 같은 공격 파이프라인을 사용합니다.

```text
MonsterAttack 또는 TowerAttack
  → AttackSO.Execute(target, context)
    → AttackEffectSO.Apply(target, context)
      → DamageEffectSO
        → IDamageable.TakeDamage(DamageInfo)
```

`AttackSO`는 사거리, 공격 간격, 효과 목록만 보관합니다. 현재 대상과 다음 공격 시각 같은 런타임 상태는 공유 SO에 저장하지 않고 각 공격 컴포넌트가 보관합니다.

현재 즉발 피해는 `DamageEffectSO`가 적용합니다. 공격 이펙트, 투사체, 화상·둔화 같은 지속 효과는 아직 연결하지 않았습니다.

## 7. 피격과 사망

### 몬스터

`BaseMonster.TakeDamage`는 다음 순서로 처리합니다.

1. 이미 죽은 몬스터면 무시합니다.
2. 피격 디버그 로그를 출력합니다.
3. 방어막이 있으면 방어막이 먼저 피해를 흡수합니다.
4. 남은 피해가 있으면 `Health`에 적용합니다.
5. 체력이 0이 되면 `Health.Died` 이벤트를 통해 몬스터 GameObject를 삭제합니다.

현재 피격 로그 예시:

```text
[BaseMonster] MonsterName이 공격받았습니다. 피해량: 10. 체력 : 40
```

로그의 체력은 피해를 적용하기 전 값입니다.

### 타워

`Tower.TakeDamage`는 이미 비활성화된 타워의 피해를 무시하고, 살아 있는 타워에 피해를 적용합니다.

현재 피격 로그 예시:

```text
[Tower] TowerName이 공격받았습니다. 피해량: 10. 체력 100
```

로그의 체력은 피해를 적용하기 전 값입니다.

## 8. 타워 비활성화와 재활성화

타워는 체력이 0이 되어도 `Destroy`되지 않습니다.

```text
체력 0
  → Health.Died
  → TowerAttack 비활성화
  → 타워를 몬스터의 유효 대상에서 제외
  → TowerData.ReviveDelay만큼 대기
  → 체력 완전 회복
  → 공격 기능 재활성화
```

타워 비활성화 시 설정된 대기시간을 출력합니다.

```text
[Tower] TowerName이 비활성화되었습니다. 재활성화 대기시간: 5초
```

재활성화 시 실제 비활성화 경과시간을 출력합니다.

```text
[Tower] TowerName이 재활성화되었습니다. 실제 비활성화 시간: 5.02초
```

`RestoreAtMorning`이 먼저 호출되면 진행 중인 지연 복구를 취소하고 즉시 회복합니다. 이 경우에도 실제 비활성화 경과시간을 출력합니다. 비활성화되지 않은 정상 타워에 `RestoreAtMorning`이 호출되면 재활성화 로그를 출력하지 않습니다.

## 9. Unity 테스트 준비

이동 중 타워 공격을 테스트하려면 다음 설정이 필요합니다.

1. 몬스터 프리팹에 `BaseMonster`, `Health`, 이동 컴포넌트, `MonsterAttack`, `Collider2D`가 있어야 합니다.
2. 몬스터에 연결되는 `MonsterData.Attack`에 유효한 `AttackSO`가 있어야 합니다.
3. 타워 공격형 데이터의 `EnRouteTargetTypes`를 `Tower`로 설정합니다.
4. 메인 성 직행형 데이터의 `EnRouteTargetTypes`를 `None`으로 설정합니다.
5. 타워에 `Tower`, `Health`, `TowerAttack`, `Collider2D`가 있어야 합니다.
6. `MonsterAttack.TargetLayers`가 타워가 속한 레이어를 포함해야 합니다.
7. `AttackSO`에 사거리, 공격 간격, `DamageEffectSO`가 연결되어야 합니다.
8. 테스트 씬의 스포너가 몬스터에 `MonsterData`, 경로, 메인 성 위치를 전달해야 합니다.

현재 Unity 컴파일 오류는 0개로 확인했습니다. 실제 플레이 모드의 전체 공격 흐름은 테스트 씬 설정을 기준으로 추가 검증이 필요합니다.

## 10. 현재 미구현 및 주의사항

### 메인 성 공격

`BaseMonster.HandleArrivedAtCastle`은 아직 비어 있습니다. 현재 모든 적은 메인 성까지 이동하고 도착 시 멈추지만, 성이 파괴될 때까지 공격하는 최종 공격 상태는 구현되지 않았습니다.

다음 구현에서는 메인 성의 `IDamageable` 참조를 `MonsterAttack`에 전달하고, 도착 이벤트에서 이동 중 타깃 탐색을 종료한 뒤 성을 강제 최종 대상으로 설정해야 합니다.

### 탐색 성능

현재 `Physics2D.OverlapCircleAll`을 매 프레임 호출하므로 탐색할 때 배열이 할당됩니다. 프로토타입 기능 검증 후 몬스터 수가 많아지면 다음 방식을 검토해야 합니다.

- 탐색 주기 적용
- `OverlapCircleNonAlloc` 사용
- 트리거 기반 후보 목록 관리

### 타워 복구 정책

현재 타워는 `ReviveDelay` 후 자동 재활성화됩니다. 최종 기획이 밤 동안 비활성화 후 아침 복구만 허용하는 방식이라면 낮·밤 시스템과 연결할 때 정책을 다시 확인해야 합니다.

### 공격 표현

현재 몬스터 공격은 `AttackSO` 효과를 즉시 적용합니다. 작은 공격 이펙트, 애니메이션, 투사체 표현은 아직 없습니다. 필요한 에셋은 임의 생성하지 않고 팀 제공 리소스를 연결해야 합니다.

## 11. 다음 작업 순서

1. 메인 성을 모든 적의 최종 공격 대상으로 전달합니다.
2. `HandleArrivedAtCastle`에서 성 공격 상태를 시작합니다.
3. 성이 파괴될 때까지 공격 간격에 맞춰 효과를 적용합니다.
4. 테스트 씬에서 `None` 적과 `Tower` 적의 이동 차이를 검증합니다.
5. 타워 비활성화 후 몬스터가 이동을 재개하는지 검증합니다.
6. 메인 성 체력이 0이 될 때까지 모든 적이 최종 공격을 유지하는지 검증합니다.
7. 검증 후 탐색 비용과 공격 표현을 보완합니다.
