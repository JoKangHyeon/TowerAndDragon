# 구현 현황 — Tower and Dragons

> **이 문서가 현재 상태의 단일 진입점입니다.** 시스템이 지금 어떻게 동작하는지 알고 싶으면 여기부터 보세요.
> 기획(무엇을 만들 것인가)은 `기획종합_v2.md`, 그 시점의 작업 기록은 이슈별 문서를 봅니다(§8 문서 지도).
>
> 최종 갱신: 2026-08-16 · 기준: `master` (`bbdf7bdf`)

**범위 한정**: §1~§5는 **코드 기준**입니다. 씬 배선은 §7에 적은 것만 확인했습니다.
이 프로젝트는 미배선 참조가 조용히 fail-open/fail-closed로 퇴화하도록 **의도적으로** 설계돼 있어서,
"코드가 있다"가 "플레이 씬에서 동작한다"를 뜻하지 않습니다.

씬: 본게임 `SampleScene` · 튜토리얼 `Tutorial` · 진입 `StartScene` (나머지 6개는 개인 테스트 씬)

## 2. 게임 루프

```
낮 시작 ─ StartDay()
  ① OnDayStart        생산 정산    Factory 생산, 알 성장, 스킬 리셋, 성 회복, 이동권 리셋
  ② OnDayStartUpkeep  소비 정산    인구 식량 → 지역 자재 → 새끼용 슬라임
  ③ OnDayReady        파생·연출    웨이브 스냅샷 확정, 포탈 개방, 조명
  ④ OnDaySettled      관측 전용    자동저장
     ↓ (플레이어가 "밤으로" 버튼 · IDayEndBlockQuery가 막지 않으면)
밤 ─ 포탈에서 웨이브 스폰 → 전멸 시 OnNightEnd
  원정 하루 진행 · RP 지급 · 새끼용 버프 재계산 · 보스 주기 완료 판정
     ↓
다시 StartDay()
```

**①②는 실행할 때마다 자원이 변하고, ③④는 몇 번 실행해도 같습니다.** 이 경계가 세이브 계약입니다 —
이어하기는 `SeedRestoredDay()` + `ResumeDay()`로 **③④만 재생**해서, 낮에 저장→로드를 반복해도
생산분이 증식하지 않습니다.

**승리 2경로 · 패배 1경로**
- 승리 ① 4주기(28일) 보스 격파 → `WaveCycleProgression.AllCyclesCompleted`
- 승리 ② 포탈 4곳에 봉인석 전부 건설 → 그 순간 4포탈 동시 봉인 (개별 봉인석은 봉인하지 않음)
- 패배 메인 성 체력 0

## 3. 시스템별 현재 구현

### 그리드 (`Scripts/Grid/`)
- 청크는 **임의 모양 셀 집합**입니다(정사각형 격자를 버림). `ChunkLayoutTable`을 에디터 윈도우로 저작하고,
  지정 누락 셀은 근접 청크에 흡수합니다.
- 청크 인접은 좌표 산술이 아니라 **셀 접촉**에서 파생 — `bordering`(변 공유, 점령 출격 판정)과
  `surrounding`(변+꼭짓점, 시야)을 구분합니다.
- 아이소메트릭 고저차 대응: 마우스 → 셀 역변환이 후보마다 "그 높이만큼 내려서 되짚으면 자기 자신인가"를
  검사합니다. 전투 판정도 원이 아니라 **타원**입니다.
- 안개는 별도 오버레이가 아니라 **지형 타일 자체를 틴트**합니다(고저차 경계 이음매 문제를 구조적으로 제거).
- 셀 생산력 = `5 + round(대각선정도 × 성으로부터 거리 × 0.4)` → 청크 자원별 배율 → 셀 오버라이드 순.

### 자원·생산 (`Scripts/Managers/ResourceManager.cs`, `Buildings/Factory.cs`)
- 자원 12종: 기본 3(식량·나무·돌) + 특화 4 + 슬라임 5(지형별).
- `Factory`는 서브클래스 없이 `ResourceProductionData`만 교체합니다. 생산 공식 한 곳:
  `footprint 생산력 × 충원율 × 새끼용 버프 × 지형 페널티`.
- `ResourceForecast`가 **실제 정산과 같은 규칙 클래스**로 다음날 증감을 계산하고 출처별 내역을 툴팁에 냅니다.

### 인구 (`Scripts/Population/`)
- 배치 분류 6종: 타워 / 생산 / 점령 / 연구 / **랜드마크** / None.
- 정원은 캐시하지 않고 조회마다 연구 배율을 거칩니다.
- 식량 유지비 1명당 1/일. 부족분만큼 기아로 사망하며, **가용 → 타워 → 연구 → 랜드마크 → 생산 → 점령** 순서로 뺍니다
  (생산을 먼저 빼면 다음날 기아가 커지는 악순환이라).
- 배치 UX는 창이 아니라 `WorkerModeController`(V) — 건물 직접 클릭, 좌 +1 / 우 −1 / Shift 최대 / Ctrl 5.

### 전투 (`Scripts/Combat/`, `Buildings/Tower/`, `Monster/`)
- 데이터 조립: `TowerData·MonsterData → AttackSO → AttackEffectSO[] → StatusEffectSO`.
  코드 수정 없이 에셋만으로 "화염 화살(피해+화상)" 같은 조합을 만듭니다.
- **타워는 파괴되지 않고 비활성화**됩니다. 부활 게이지가 충원율에 비례해 차오르고, 아침엔 즉시 복구됩니다.
- 공속 = `기본간격 / 충원율 / (연구·용 × 오라 × 지형)`. 인구 0이면 침묵.
- 몬스터는 상속이 아니라 컴포넌트 조립(체력/방어막/이동/공격/상태/특수행동).
- 상태이상 중첩: 이동속도는 **가장 강한 것 하나만**(곱하면 0에 수렴), 지속피해는 ID별 병렬,
  스택형은 임계치 도달 즉시 발동.
- 속성 상성은 **이진 판정**입니다 — 면역형(그 속성만 차단) / 전용형(그 속성만 통함). 유불리 배율은 없습니다.

### 점령 (`Scripts/Conquest/`, `Managers/ConquestManager.cs`)
- 조건: 대상이 시야 안 + 변을 공유하는 점령지 인접 + 진행 중 원정 없음.
- 비용·소요일 모두 연구/용 효과로 줄어듭니다. 밤이 끝날 때마다 하루씩 진행됩니다.
- 완료 시: 점령 → 주변 시야 확장 → **자투리 청크 편입** → **적 강화 프로필 누적** → 보상.
- 자투리 편입은 육지 접촉 셀 2개 이상 + "그 청크가 가장 많이 맞닿은 이웃"일 때만 흡수하고,
  미리보기와 실제 편입이 같은 판정을 씁니다.

### 연구 (`Scripts/Research/`) — **3갈래**
- 갈래: 타워 / 생산시설 / 편의. 티어 T1~T5가 주기에 연동됩니다(T1 시작, T2 1주기, T3 2주기, T4·T5 3주기 종료).
- RP는 **활성 연구소 1채**의 배치 인구에 비례해 밤 종료 시 지급. 연구는 대기 없이 즉시 완료.
- 효과 12종이 pull 방식으로 집계됩니다(완료 노드 → 효과 → 합산). 그래서 세이브는 노드 집합만 복원하면 됩니다.

### 용 (`Scripts/Dragon/`, `Progression/`)
- 연구와 **완전히 별개 시스템**이며, 공통 골격(선행+게이트+코스트)만 `ProgressionManagerBase`로 공유합니다.
- 어미용 5속성(얼음·불·시간·암석·생명) 중 하나가 활성. 해금은 영구지만 **효과는 활성 속성일 때만** 살아납니다.
- 트리 = 속성 × 8슬롯(액티브 해금 / 액티브 강화2 / 패시브 강화2 / 궁극 / 새끼용 타워형 / 새끼용 지역형).
- 저장소에서 데이터가 가장 많은 시스템입니다(SO 217개, 에디터 생성기가 생성).

### 새끼용 (`Scripts/Buildings/BabyDragon/`)
- 알 획득(시작 지급 / 주기 보스 보상 / 랜드마크 / 디버그) → 매일 성장 → 부화 → 배치 → 모드 선택 → 매일 슬라임.
- **인구 대신 슬라임 먹이로 가동**합니다. 먹이는 전부-또는-전무 — 전액을 못 내면 그날 정지합니다.
- 버프형 효과 3종: 주변 생산 배율 / **건설 제한 해제**(얼음이 화산 지대를 열어줌) / **지형 페널티 무효화**.
  범위를 벗어난 건물은 자동으로 정지하고 인구가 회수됩니다.
- 공격형은 일반 타워와 같은 공격 파이프라인을 씁니다.

### 랜드마크 (`Scripts/Landmark/`) — 08-12 추가
- 청크 테이블로 배치. **점령 완료 이벤트가 아니라 청크 상태 변화**를 감지합니다
  (자투리 편입으로 들어온 랜드마크도 보상을 받게 하려고).
- 보상: 새끼용 알 / 자원 / 연구 해금. 지급이 전부 성공한 뒤에만 수령으로 기록합니다.
- 가동형 랜드마크는 인구를 받습니다.

### 세이브/로드 (`Scripts/Save/`)
- 자동저장은 낮 정산이 끝난 경계(`OnDaySettled`), 수동 저장은 낮 아무 때나.
- 로드는 **항상 씬 재로드**를 거칩니다(살아 있는 몬스터·투사체를 정리할 방법이 없어서).
- 복원 순서에 의존성이 있습니다 — 특히 랜드마크 수령 이력이 영토 복원보다 **먼저**여야 하고
  (아니면 보상 재지급), 총인구가 원정 인구 배치보다 먼저여야 합니다.
- **건물 배치는 저장되지 않습니다** (§6).

### UI·편의
- 진입은 `UI_TitleWindow` 하나. 새 게임과 이어하기의 차이는 `SaveLoadRequest`(static) 뿐입니다.
- 배타 모드(건설 B / 인구 V / 점령 C / 새끼용 Tab)는 `UIManager`가 조정하고, 한 번에 하나만 열립니다.
- 건물은 롱프레스로 이동 모드 진입, R로 회전, 우클릭 취소. 이동은 연구 기반 **일일 이동 예산**을 씁니다.
- 건물 위 효과 배지는 프리팹을 건드리지 않고 런타임에 붙습니다.
- 게임 속도는 플레이어 일시정지와 창 일시정지를 분리해 관리합니다(창은 겹칠 수 있어 카운트).

## 6. 알려진 공백

우선순위 순입니다.

1. **건물 배치가 세이브에 저장되지 않습니다.** 이어하기하면 지어 둔 타워·생산시설이 사라집니다.
   `SaveDtos.MapStateDto.Buildings`에 TODO가 있고, 그 여파로 새끼용의 `IsInTower`를 복원 시 강제로 `false`로 만듭니다.
   착수하려면 `Building`에 안정적인 PrefabId + `BuildingCatalog`에 id→프리팹 조회가 필요합니다.
2. **`Building.IsOpen`(건물 해금)이 죽은 코드입니다.** 어디서도 읽지 않습니다.
   기획의 "외곽 기초자원 채집 해금", "속성 타워 해금" 노드가 이걸 기다리고 있습니다.
3. **`GridMap.ResearchUnlockQuery`(청크 단위 자원 해금)도 죽은 코드입니다.** 소비 지점만 있고 대입이 없습니다.
   쓰려면 생산량 폴백이 필수입니다 — 셀에 자원노드가 없으면 생산량이 0이라 "연구했는데 0"이 됩니다.
4. **`ISealStoneUnlockQuery`도 구현체가 없습니다.** null이면 해금으로 접히므로(fail-open) 봉인석은 연구 없이 항상 해금 상태입니다.
5. 연구 노드 10개가 효과 없이 이름만 있습니다. 타워 갈래 **T5가 완전히 비어** 있습니다(밸런싱으로 노드 3개 제거 후 `tower_reverse_engineering`이 추가된 상태).
   → `연구효과_미구현_보고서.md`
6. 몬스터 사망 시 자원 드랍이 TODO로 남아 있습니다. 슬라임은 현재 슬라임 농장 생산으로만 얻습니다.
7. 오브젝트 풀링 보류 — 몬스터는 사망 시 `Destroy`.

## 9. 이 문서를 갱신할 때

무엇을 어떻게 확인했는지 남겨 둡니다. 다음 사람이 처음부터 다시 파지 않아도 되도록.

- **§1~§6(코드 사실)**: 해당 스크립트를 직접 읽어서 확인했습니다. 숫자·상수는 코드에서 그대로 가져왔습니다
  (예: 주기 7일 = `WaveCycleRules.WAVES_PER_CYCLE`).
- **§7(씬 배선)**: 스크립트의 `.cs.meta`에서 guid를 얻고, 그 guid를 `Scenes/*.unity`에서 검색했습니다.
  존재만으로는 부족해서 `DailySettlementManager` 블록은 직렬화된 참조 필드까지 확인했습니다.
  프리팹 배선은 프리팹 `.meta`의 guid를 씬에서 검색합니다.
- **죽은 코드 판정**: 인터페이스 이름으로 전체 검색해 **대입하는 곳이 있는지**를 봤습니다.
  소비 지점만 있고 대입이 없으면 죽은 코드입니다.
- **§4(변화 과정)**: `git log --merges` 의 PR 병합 목록에서 뽑았습니다. 일반 커밋 로그는 리베이스로
  중복이 많아 쓰기 어렵습니다.

갱신 시 **§1 표와 §6 공백 목록을 먼저** 맞추세요. 나머지는 바뀔 일이 적습니다.
