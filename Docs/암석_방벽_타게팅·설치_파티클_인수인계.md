# 암석 방벽 타게팅·설치 파티클 인수인계

작성일: 2026-09-02

## 목적

암석 어미용 액티브 `METEOR_BARRICADE`에 다음 두 연출을 추가한다.

1. **타게팅 이동 펄스**: 방벽 프리뷰가 새로운 설치 가능 타일로 이동할 때 그 타일을 짧게 비춘다.
2. **실제 설치 충격**: 방벽 설치 성공 순간 메테오 낙하 잔광과 암석 파편·먼지 충격을 한 번 재생한다.

화면 전체 암석 오버레이 `FX_DragonSkillCastOverlay_Stone` 및 피격 몬스터별
`Impact_BD_Stone`과는 별개의 역할이다. 기존 두 연출은 변경하지 않는다.

## 생성 자산

| 용도 | 프리팹 | 재생 계약 |
|---|---|---|
| 타게팅 이동 | `Assets/Prefabs/VFX/Dragon/Stone/FX_StoneBarricade_TargetTilePulse.prefab` | 스냅된 설치 가능 `anchor`가 달라질 때만 1회 재생 |
| 실제 설치 | `Assets/Prefabs/VFX/Dragon/Stone/FX_StoneBarricade_PlacementImpact.prefab` | `RegisterFootprint` 성공 후 설치 지점에서 1회 재생 |

두 프리팹은 `Assets/Editor/BuildStoneBarricadeSkillVfx.cs`가 만든다. 외부 번들 원본을 직접
수정하지 않는다.

## 후보 비교와 선택 근거

### 타게팅 이동

- **선택**: `Assets/Imported/Prefabs/BabyDragonEffect/Range/FX_BD_BuffRange_Stone.prefab`
- 보라색 원형 마커·글로우가 이미 암석 속성과 맞고, `Scale` 자식이 아이소메트릭 바닥 타원 비율을
  가지고 있다.
- 원본은 계속 켜 두는 범위 표시라 루프하지만, 파생본은 각 시스템을 짧은 버스트 1회로 바꿨다.
- `Simulation Space = World`라 다음 타일로 프리뷰가 움직여도 직전 타일의 잔광이 수명 동안 남는다.

`FX_BD_AttackRange_Stone`은 표시 요소가 더 많아 기존 `RangeIndicator`와 정보가 겹치므로 제외했다.

### 실제 설치

- **충격 선택**: `Assets/Imported/Prefabs/Projectile/Tower/Impact_Tower_Stone.prefab`
- 암석 파편, 먼지, 지면 글로우가 이미 프로젝트의 암석 타워 언어와 일치한다.
- **낙하 잔광 선택**:
  `Assets/Imported/Vefects/Anime VFX URP/Shared/Materials/M_VFX_Trail_03.mat`
- 별도 텍스처를 생성하지 않고 기존 URP 트레일 재질로 `MeteorStreak`을 조합했다. 중앙 섬광은
  트레일 재질을 한 장 더 쓰면 네모난 빌보드로 읽혀, 원본 임팩트의 `glow_Center`만 사용한다.
- 원본 임팩트에 있던 루프 시스템은 파생본에서 모두 1회 재생으로 바꿨다.

`FX_Crack_RockAOE`는 범위가 넓고 바닥 데칼 비중이 커서 반경 1.5의 피해 범위 및 기존
`RangeIndicator`와 시각적으로 충돌하므로 제외했다.

## 코드 배선 계획

이 문서는 배선 계획만 남긴다. 현재 작업의 산출물은 두 파티클 프리팹이며 런타임 코드는 별도 작업이다.

### 1. 데이터 필드

`Assets/Scripts/UI/Skill/SkillSO.cs`의 방벽 설치 전용 구역에 선택 참조를 추가한다.

```csharp
[Header("방벽 연출")]
[WiringOptional]
public GameObject BarricadePreviewMoveVfxPrefab;

[WiringOptional]
public GameObject BarricadePlacementVfxPrefab;

[Min(0f)]
public float BarricadePlacementVfxLifetimeSeconds = 1.2f;
```

`SK_Dragon_Meteor.asset`에 위 두 프리팹을 배선한다. `.asset` 텍스트를 직접 편집하지 않고 Coplay MCP로
배선한다.

### 2. 타게팅 이동 펄스

`MeteorBarricadeSkill`에 마지막 유효 앵커를 저장한다.

```csharp
private Vector3Int? _lastPreviewVfxAnchor;
```

`UpdatePreview`에서 설치 가능한 `anchor`와 `worldPos`를 구한 뒤 다음 조건을 모두 만족할 때만
타게팅 프리팹을 1회 재생한다.

- 이번 `anchor`가 직전 앵커와 다름
- `TryResolveTemporaryObstacleAnchor`가 성공함
- 프리팹 참조가 채워져 있음

매 프레임 재생하면 같은 타일에 파티클이 수십 겹 쌓이므로 **월드 좌표 비교가 아니라 `anchor` 변화로
게이트**한다. 재생은 `ProjectilePool.PlayForSeconds`를 사용한다. 타게팅 프리팹은 최대 약 0.42초만
남으므로 0.6초 반납이면 충분하다.

설치 불가능한 곳으로 이동하면 `_lastPreviewVfxAnchor = null`, `ClearPreview`에서도 동일하게 초기화한다.
같은 타일을 떠났다가 다시 들어왔을 때는 다시 펄스가 나와야 한다.

### 3. 실제 설치 충격

`MeteorBarricadeSkill.ApplyEffect`에서 다음 순서를 유지한다.

1. 설치 가능 여부 검증
2. 피해와 피격 몬스터별 `Impact_BD_Stone`
3. 방벽 인스턴스 생성
4. `RegisterFootprint` 성공
5. `StoneBarricade.Initialize`
6. `FX_StoneBarricade_PlacementImpact`를 `worldPos`에 1회 재생
7. `true` 반환 후 `SkillTargetingController`가 화면 암석 오버레이 재생

반드시 `RegisterFootprint` 성공 분기 안에서 재생한다. 실패한 설치에 메테오가 떨어지면 플레이어에게
스킬이 소비됐다는 잘못된 신호가 된다.

설치 VFX는 방벽 한 개에 한 번만 나와야 하므로 기존 `SkillSO.TargetVfxPrefab`을 재사용하지 않는다.
그 필드는 범위 안에서 피해를 입은 **몬스터마다** `Impact_BD_Stone`을 띄우는 용도다.

## 확인 항목

- 마우스가 같은 타일 안에서 움직일 때 펄스가 반복되지 않는다.
- 새 설치 가능 타일로 넘어갈 때 펄스가 한 번 나온다.
- 설치 불가능한 위치에서는 펄스가 나오지 않는다.
- 취소 후 다시 타게팅하면 첫 유효 타일에서 펄스가 나온다.
- 실제 설치 성공 시에만 낙하 잔광과 암석 충격이 한 번 나온다.
- 설치 VFX가 방벽 중심에서 벗어나지 않는다.
- 기존 화면 오버레이와 몬스터별 임팩트가 그대로 유지된다.
- 타게팅 중 빠르게 움직여도 파티클 수가 계속 증가하지 않고 수명 후 풀로 돌아간다.
- 컴파일 에러 0, 플레이 모드 진입 가능.

## 조정 포인트

- 타게팅 펄스가 너무 크면 생성기의 `PREVIEW_SCALE`만 조정한다.
- 타게팅 잔상이 너무 길면 `PREVIEW_LIFETIME_SECONDS`를 줄인다.
- 낙하선이 화면에서 기울어 보이면 `STREAK_ANGLE_DEGREES`를 조정한다.
- 낙하선 끝이 방벽 중심과 안 맞으면 `STREAK_X`, `STREAK_Y`를 조정한다.
- 설치 충격이 방벽보다 크면 `IMPACT_SCALE_MULTIPLIER`를 조정한다.

프리팹 YAML을 직접 수정하지 말고 생성기 상수를 바꾼 뒤 Coplay MCP로 `Execute`를 다시 호출한다.
수동 실행이 필요한 경우 Unity 메뉴 `Tools > Tower and Dragons > Build Stone Barricade VFX`도 같은
메서드를 호출한다.

- 두 프리팹 생성 완료.

  중앙 섬광을 담당한다.
