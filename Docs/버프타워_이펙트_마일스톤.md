# 버프 타워 이펙트 마일스톤 (2026-08-25 ~)

> 설계 근거: [버프타워 이펙트 설계](./버프타워_이펙트_설계.md) — 왜 이렇게 하는지는 그쪽을 본다.
> 이 문서는 **구현 진행표**다. 설계가 바뀌면 설계 문서를 먼저 고치고 여기에 반영한다.
>
> 이 문서는 [타워 투사체 연출 마일스톤](./타워_투사체_연출_마일스톤.md)의 **M7(TimeTower 마법진)을 대체한다.**
>
> **⚠️ 2026-08-25 3차 전환**: 상시 표시 방식(M3~M5)을 **폐기**하고
> **클릭한 타워의 범위 + 수혜자 표시**로 바꿨다. 현행 작업은 **N0부터**다.
> M0~M8은 이력으로 남긴다 — 거기서 얻은 측정·교훈이 N에서도 그대로 쓰인다.
>
> **⚠️ 2026-08-25 3차-b 정정 (중요)**: 수혜자 표시를 **2차에서 만든 구체 `FX_BuffOrb_*` 4색**으로
> 확정했다. 방향(선택 기반)은 3차 그대로다. **폐기된 것은 "상시 표시"였고 "구체"가 아니었다.**
> → `FX_BuffOrb_*` · `M_BuffOrb.mat`을 **지우지 않는다.** 감싸기 파티클 작업(N1·N2)은 **폐기.**
> 필드 개명(`_recipientHighlightPrefab`)도 **취소**다. 설계 §0·§5·§10을 먼저 읽을 것.
>
> **별도 세션에서 새끼용 범위 인디케이터를 같은 기법으로 만들고 있다.** 설계 §7을 먼저 읽을 것.

## 이 문서를 처음 여는 에이전트에게

1. **[현행 진행 현황](#현행-진행-현황-3차)의 `⬜ 대기`인 첫 마일스톤**을 찾는다 (N 번호)
2. 선행 조건을 [확인 명령](#확인-명령)으로 직접 검증한다 — 표가 아니라 명령 결과를 믿는다
3. **완료 판정**을 전부 만족시키고 표와 작업 로그를 갱신한다

**N 번호가 현행이고 M 번호는 이력이다.** 거기서 작업을 시작하지 말 것.
다만 **M3 산출물(`FX_BuffOrb_*` 4색)은 현행 자산이다** — 이력표를 "전부 끝난 것"으로 읽고
지우지 않도록 주의한다 (N0의 ⛔ 목록).

## 작업 원칙

- **커밋은 하지 않는다.** 변경분을 정리해 보고하고 커밋은 담당자가 직접 한다
- `Assets/Imported` 아래 임포트 원본은 수정하지 않는다. 가공본은 복제해서 따로 만든다
  (`Assets/Imported`는 팀 공유 별도 저장소다 — 작업노트 §0)
- 씬·프리팹은 Coplay MCP로 다루고, 플레이 모드가 켜진 상태에서 코드를 고치지 않는다
- 리터럴 상수 금지 · 지연은 `UniTask` (CLAUDE.md)
- Coplay의 생성형 기능(3D·텍스처·이미지·음악·SFX 생성)은 사용 금지
- 마일스톤 하나 = **컴파일 에러 0 + 플레이 모드 진입 가능 + 밤 전투 정상**
- **새끼용 세션과 기법이 갈라지지 않게 한다** (설계 §7-1 표가 기준)

## 가공본 위치

- 생명 타워 투사체: `Assets/Imported/Prefabs/Projectile/Tower/`
- (새끼용 세션은 `Assets/Imported/Prefabs/BabyDragon/Range/` — 건드리지 않는다)

## N0 — 상시 표시 걷기 (프리팹은 남긴다) ★

**목표**: 늘 떠 있던 구체를 걷어낸다. **이 단계가 끝나면 선택과 무관하게 뜨는 구체가 사라진다.**
**프리팹·머티리얼은 지우지 않는다** — N5가 같은 것을 쓴다.

### 지울 것 (코드만)

| 대상 | 경로 | 이유 |
|---|---|---|
| `TowerAuraOrbStrength` 파일 + `TowerBuffOrbDisplay.Layout`의 세기 계산 호출 | `Assets/Scripts/Buildings/ElementalTower/` | 세기 연동 폐기. 크기는 `BASE_DIAMETER` 고정 (설계 §10) |
| `TowerBuffOrbCoordinator`의 `GridMap` 전수 등록 · `LateUpdate` 순회 | 같은 폴더 | **상시 표시가 여기서 나온다.** 걷으면 화면이 조용해진다 |

### ⚠️ `TowerBuffOrbDisplay`의 딕셔너리·호선 배치는 N0에서 건드리지 않는다 ★

오라별 딕셔너리(`_activeByAura`)와 호선 배치를 N0에서 먼저 걷으면
`Tick`·`Reconcile`이 없어진 필드를 참조한 채로 남아 **컴파일이 깨진다** —
"마일스톤 하나 = 컴파일 에러 0" 규칙을 스스로 어기게 된다.

- N0에서는 **호출자만 없앤다.** 클래스는 그대로 남지만 아무도 부르지 않아 화면에 안 뜬다
- **N5가 이 파일을 수혜자 타워별로 통째로 고쳐 쓴다** — 그때 딕셔너리 키와 배치가 함께 바뀐다
- 세기 계산만 N0에서 떼는 것은 안전하다 (`TowerAuraOrbStrength` 호출 한 줄 → 고정 크기)

**클래스 두 개(`TowerBuffOrbDisplay`·`TowerBuffOrbCoordinator`)는 파일을 지우지 않는다.**
이름을 유지하는 이유는 씬에 붙은 컴포넌트와 연결된 참조를 살리기 위해서다 (설계 §8-2).

**N5로 넘길 조각**: `ResolveAnchor`(발밑 앵커) · `ApplySortingOrder`(Building 레이어 +
`DepthSortOrder + 1`) · `Orb` 렌더러 캐시 · 풀 대여/반납 · 상수 `BASE_HEIGHT 1.4` ·
`BASE_DIAMETER 0.31` · `SORTING_ORDER_OFFSET 1`.

### ⛔ 지우면 안 되는 것 (3차 문서가 삭제 대상으로 적었던 것들) ★★

| 대상 | 경로 |
|---|---|
| `FX_BuffOrb_*` 4종 · `M_BuffOrb.mat` | `Assets/Imported/Prefabs/Aura/` |
| `CoplayScripts/BuildBuffOrbs.cs` (색 재생성 생성기) · `VerifyBuffOrbs.cs` (검증) | |
| `TowerAuraDataSO._recipientOrbPrefab`과 오라 에셋 4장의 배선 | |
| `FX_Aura_*` 4종 (범위 마커) | `Assets/Imported/Prefabs/Aura/` |
| `TowerAuraSystem.CollectRecipientAuras` · `IsEffectiveOn` · 재진입 가드 | |
| `output/vfx_check/*` 측정 기록 · `SurveyBuffOrbCandidates.cs` (조사 이력) | |

**3차 문서는 이 목록의 앞 두 줄을 "삭제"로 적어 뒀다. 그 판정이 취소됐다.**

### 씬

`Haneul_TowerEffectScene`의 `Systems/Composites`에 붙은 `TowerBuffOrbCoordinator`는
**떼지 않는다.** N4에서 내용이 바뀌지만 `_towerAuraSystem` 배선은 그대로 쓴다(설계 §8-2).
나머지 5개 씬에는 아직 붙이지 않았다 — N8에서 한다.

### 완료 판정

- 컴파일 에러 0, 플레이 모드 진입 가능
- **선택하지 않은 상태에서는 구체가 뜨지 않는다** (프리팹은 프로젝트에 그대로 있다)
- `ls Assets/Imported/Prefabs/Aura/ | grep -i bufforb` → **4종이 그대로 보인다**
- **오라 수치·동작은 그대로다** (연출만 걷었으므로 버프는 계속 걸려야 한다)
- 풀에 반납 안 된 인스턴스가 남지 않는다

## N1 · N2 — ❌ 폐기 (감싸기 파티클 선정·제작)

3차는 타워를 **감싸는** 파티클을 새로 고르고 4색으로 굽기로 했다. **하지 않는다.**

- 전제가 "구체는 폐기됐다"였는데 그 판정이 취소됐다 (설계 §0)
- `FX_BuffOrb_*` 4색은 M3에서 이미 제작·측정을 마쳤다
- 감싸기는 범위 마커(바닥 타원)와 형태가 겹쳐 오히려 읽기 어렵다 (설계 §5-2)

**감싸기 후보 측정치는 설계 §5-3에 이력으로 남겨 뒀다.** 나중에 감싸기가 다시 필요해지면
거기서 시작한다 — **지금은 열린 작업이 아니다.**

`Glow 02`를 "너무 작다"고 뺀 3차의 서술은 **감싸기 기준의 판정**이었다.
머리 위 구체로는 이 크기가 정답이고 `FX_BuffOrb_*`가 그 자식으로 만들어져 있다 (설계 §5-4).

| `_rangeMarkerPrefab` | **신설** — 범위 마커(`FX_Aura_*`)를 꽂을 자리 |

- 개명하지 않는 이유: 개명의 근거가 "새 감싸기 프리팹을 꽂는다"였고 그 전제가 사라졌다.
  이름만 바꾸면 **오라 에셋 4장의 배선을 다시 확인해야 하는 위험만 남는다**
- `[WiringOptional]` + `OnValidate` 파티클 검사는 그대로 둔다 (새 필드에도 같은 검사를 붙인다)
- 오라 4장에 `_rangeMarkerPrefab` 배선 (`TAD_TimeTowerAura` · `TAD_StealthTowerAura` ·
  `TAD_SoulTowerAura` · `TAD_EnhancementAura`)

### 완료 판정

- 컴파일 에러 0 (**`Assembly-CSharp.dll` 타임스탬프로 확인** — Coplay 응답은 캐시일 수 있다)
- **에셋 diff가 순수 추가·삭제뿐** — 기존 수치와 `_recipientOrbPrefab` 배선이 하나도 안 바뀐다
- 새 필드를 읽는 런타임이 아직 없다 (그래서 화면 변화 0이 보장된다)

## N4 — 런타임: 범위 마커

**목표**: 오라 타워를 클릭하면 발밑에 `FX_Aura_*`가 유효 반경으로 뜬다.

### 구현된 모습 (as-built)

```csharp
// TowerBuffOrbCoordinator.LateUpdate (요약)
if (!TryResolveRangeMarker(out Tower source, out GameObject prefab, out float radius))
{ ReleaseRangeMarker(); return; }
_rangeMarker ??= ProjectilePool.AcquirePersistent(prefab);   // 프리팹이 바뀌면 반납 후 재대여
_rangeMarker.position   = source.transform.position;
_rangeMarker.rotation   = Quaternion.identity;
_rangeMarker.localScale = Vector3.one * radius;              // 루트 스케일 1 = 반경 1
```

`TryResolveRangeMarker`가 거르는 것: 선택이 `Tower`가 아님 · **`BabyDragonTower`** ·
`TryGetActiveAura` 실패(감전·비활성·인구 0) · `RangeMarkerPrefab` 미배선 · 반경 0.

### 지킨 것 ★

- **`TryGetActiveAura`의 유효 반경**을 쓴다. `TryGetPreviewRadius`(항상 2)를 쓰면
  인구 절반인 타워에서 "원 안인데 구체가 안 뜨는 타워"가 생긴다 (설계 §4-2)
- 마커 프리팹은 `_rangeMarkerPrefab`에서 읽는다 — 경로를 코드에 박지 않는다
- 선형 인디케이터는 `ShowBuffRangeIndicatorFor`에서 **`aura.HasRangeMarker`일 때만** 숨긴다.
  마커를 안 꽂은 오라는 기존 선을 그대로 쓴다
- **새끼용 제외** — `BabyDragonTower`도 `Tower`를 물려받고 버프 모드에서 `TryGetActiveAura`가
  통과한다. 그쪽 범위는 `BabyDragonRangeVfxDisplay`가 그리므로 겹쳐 그리지 않는다

### 씬 재배선이 없다 ★

`BuildingPlacementController`는 `BuildingPlacementManager` 프리팹 안에 있어 씬마다 프리팹
인스턴스 내부를 배선해야 한다. `BabyDragonRangeVfxDisplay`와 같이 `FindFirstObjectByType`로
런타임에 한 번 찾는다. `_towerAuraSystem`은 이미 배선돼 있으므로 손댈 것이 없다.

### 자산 재생성이 함께 들어갔다 (계획 밖) ★

M2 마커가 실제 씬에서 너무 흐려 **새끼용 버프 범위와 같은 소스·처리로 다시 구웠다**
(`CoplayScripts/RebuildAuraMarkers.cs`, 설계 §4-0). 다시 손댈 때 지켜야 하는 것:

- **같은 경로에 저장한다** — GUID·루트 fileID가 유지돼 오라 4장 배선이 살아 있다(실측 확인)
- **맥동 주기를 박지 않는다** — `FX_BD_BuffRange_<속성>`의 `Circle`에서 읽는다
  (시간·은신·강화 0.8초 / 영혼 1.0초. 새끼용 쪽이 바뀌면 스크립트를 다시 돌린다)
- 색은 `DragonAttributePalette` — 시간=Time · 은신=Stone · 영혼=Ice · 강화=Fire

### 완료 판정

- 오라 타워를 클릭하면 마커가 뜨고, 선택을 풀면 사라진다 ✅
- **인구를 옮기면 원이 그 자리에서 커지고 작아진다** ✅
- 감전·비활성·인구 0이면 사라진다 ✅ (**인구 0에서 안 뜨는 것은 기존 선형 인디케이터와 같은 동작**)
- 선형 인디케이터와 겹쳐 보이지 않는다 ✅
- 마커 선명도가 새끼용 범위 표시와 같다 ✅
- **맥동 속도가 새끼용과 같다 — 미확인 (남은 1건)**
- 일반 공격 타워의 사거리 표시는 그대로다 / 철거·씬 이동 시 반납된다 — 미확인

## N5 — 런타임: 수혜자 구체 ★ 이 작업의 본체

**목표**: 클릭한 오라 타워의 범위 안 수혜 타워 **머리 위에 구체 하나씩** 띄운다.

### 쓰는 자산 — 새로 만들지 않는다

`FX_BuffOrb_Time` · `FX_BuffOrb_Stealth` · `FX_BuffOrb_Soul` · `FX_BuffOrb_Enhancement` (M3).
오라 데이터의 `_recipientOrbPrefab`에서 읽으므로 **소스가 정해지면 색이 따라온다** —
색을 고르는 코드가 따로 없다.

### 새로 필요한 것 — 반대 방향 수집

`CollectRecipientAuras`는 "이 타워가 **받는** 오라"를 모은다.
여기서는 "이 오라가 **주는** 타워들"이 필요하다 — 소스 기준 수집을 새로 넣는다.

- `TowerAuraSystem`의 재진입 가드를 그대로 쓴다 (영혼 오라가 되짚어 올 수 있다)
- **`IsEffectiveOn`으로 거른다** — 효과 없는 타워에 구체를 띄우면 거짓 신호다 (설계 §2-4)
- 최대 6개 (반경 2 안의 칸 수)

### 2차 코드에서 바뀌는 것 (설계 §8-2)

| 항목 | 2차 (상시) | N5 (선택 기반) |
|---|---|---|
| 표시기 키 | 오라별 — 한 타워에 구체 여럿 | **수혜자 타워별 — 구체 하나** |
| 배치 | 호선 (`SPACING_RATIO` · `CURVATURE`) | **중심축 위 한 점** (발밑 기준 높이 `BASE_HEIGHT 1.4`) |
| 크기 | 세기비 연동 (`TowerAuraOrbStrength`) | **고정** (`BASE_DIAMETER 0.31`) |
| 갱신 대상 | 씬의 모든 타워 | **선택된 오라 하나** |
| 직렬화 필드 | `_gridMap` · `_towerAuraSystem` | `_towerAuraSystem`만 (선택 판정은 Find) |

**그대로 쓰는 조각**: `ResolveAnchor` · `ApplySortingOrder` · `Orb` 렌더러 캐시 · 풀 대여/반납.

### 클릭한 타워 자신에게는 구체를 띄우지 않는다 ★ (설계 §3-5)

**오라 4종 모두 소스 제외로 통일한다.** 예외 없음.

- 소스는 발밑 범위 마커로 이미 식별된다 — 구체를 얹어도 새로 알려주는 것이 없다
- 구체의 뜻이 "이 타워는 받는 쪽"으로 하나로 고정된다
- `TowerAuraSystem`의 수집 루프가 이미 `source == target`을 건너뛴다 —
  **따로 코드를 넣지 않아도 이 규칙이 지켜진다.** 반대로 소스를 넣으려면 예외를 새로 써야 했다

은신은 근거상 자기에게도 듣지만(`Tower.cs`의 `TryGetActiveAura(this)`),
**그 상태는 상시 반투명(N6)이 알린다** — 구체로 중복해 말하지 않는다.

### 정렬

`Building` 레이어, `order = tower.DepthSortOrder + 1`.
**Overlay로 올리면 안 된다** — 뎁스 정렬을 잃어 뒤쪽 구체가 앞쪽 타워를 덮는다 (설계 §6).

### 성능

- 선택된 타워 하나에 대해서만 돈다 — 2차처럼 모든 타워가 그리드를 훑지 않는다
- 렌더러는 **대여 시점에 한 번만** 찾는다 (매 프레임 `GetComponentsInChildren`는 할당이 생긴다)

### 완료 판정

- 시간 타워를 클릭하면 **범위 안 공격 타워들 머리 위에 노란 구체가 뜬다**
- 구체 색이 클릭한 타워의 색을 따른다 (4종 각각 확인)
- **한 타워에 구체가 하나만 뜬다** (호선이 남아 있지 않다)
- 버프 타워끼리는 구체가 안 뜬다 (시간·강화 기준)
- **영혼 타워를 클릭하면 인구가 부족한 타워에 뜬다** (정원 찬 타워는 안 뜸)
- **은신 타워를 클릭하면 범위 안 버프 타워에도 뜬다** (은신은 모두에게 듣는다)
- **클릭한 타워 자신의 머리 위에는 뜨지 않는다** (4종 모두 — 설계 §3-5)
- 인구를 옮기면 구체 목록이 그 자리에서 바뀐다
- **앞쪽 타워의 구체가 뒤쪽보다 위에 그려진다**
- 6개가 동시에 떠도 어지럽지 않다
- 선택을 풀면 전부 반납된다 (풀에 빌려준 채 남지 않는다)

### ⚠️ 영혼 타워 2개를 서로의 반경 안에 놓고 깜빡임을 확인한다

`TowerAuraSystem`의 재진입 가드 주석이 경고하는 상황이다 — 진짜 순환이 생기고
그리드 순회 순서에 따라 결과가 갈릴 여지가 있다.

**3차는 2차보다 위험이 낮다** — 선택된 타워 하나만 도므로 깜빡임이 생겨도 한 곳이다.
그래도 확인은 한다. 깜빡이면 히스테리시스, 그래도 안 되면 고정점 반복(별건).

## N6 — 은신 반투명

**목표**: 은신 오라 안의 타워를 반투명하게 만든다. 선택과 무관한 **상시** 표시다.

- `SpriteRenderer.color`의 알파 조절 — VFX 프리팹으로는 안 된다
- 조건은 `Tower.TargetType == MonsterTargetType.None`
- **은신 타워 자신도 은신 대상이다**
- 알파 값은 실제로 놓고 정한다

**3차에서 값이 올라간 항목이다** — 선택 표시는 클릭해야 보이지만 반투명은 상시라
"이 타워는 지금 숨어 있다"를 평소에도 알린다.

### 완료 판정

- 은신 오라 안의 타워가 반투명해지고, 오라가 꺼지면 돌아온다
- **반투명 상태에서도 클릭해 인구를 배치할 수 있다**
- 몬스터가 은신 타워를 지나쳐 간다 (기존 동작 회귀 없음)
- 은신 타워를 클릭했을 때 범위 마커·수혜자 구체는 선명하다

## 이력 상세 — 1차·2차에서 얻은 것

**3차에서도 유효한 측정·교훈이다. 다시 겪지 말 것.**

### 회전 보정 — `startRotationX = 0` (M0)

Hovl 마커는 자식 대부분이 Mesh 렌더 + `startRotationX: 90°`라
회전 0·정사영 카메라에서 **한 픽셀도 안 그려진다**(링 자식 전부 0픽셀).

| 보정 | 링 | 화살표·꼬리 |
|---|---|---|
| (a) `startRotationX=0` | 살아남 | **살아남** ← 채택 |
| (b) 루트 X −90 | 살아남 | **죽음** |

**전체 픽셀 수는 5,333 대 5,221로 비슷해 보였다.** 자식 단위로 재야 (b)가 화살표를
죽이는 것이 보인다 — 합만 보면 못 잡는다.

**새끼용 세션도 독립적으로 같은 결론에 도달했다**(`BuildBabyDragonRangeVfx` 227행).

### 맥동 평탄화 — 진폭과 빈도는 다른 축 (M2)

원인은 "주기 1초에 버스트 1회"라 입자가 같은 위상으로 태어나 같이 죽는 것이었다.

| 후보 | 변동폭 | 봉우리/초 |
|---|---|---|
| 원본 | 48% | 1.00 |
| 버스트 4등분 | 5% | **2.67** ← 진폭은 잡혔지만 더 어지러움 |
| **주기 ×3, 수명 ×12** | **7%** | **0.67** ← 채택 |

**변동폭만 재고 빈도를 안 재서 첫 시도가 "숫자상 성공"으로 보였다.**
지표를 하나만 잡으면 그 지표만 좋아진 답으로 수렴한다.

### ⚠️ 그 맥동 평탄화는 나중에 폐기됐다 (N4에서) ★

**위 표의 채택안(주기 ×3, 수명 ×12)이 실제 씬에서 너무 흐렸다.** 입자를 넓게 퍼뜨리면
변동폭은 잡히지만 순간 밝기가 그만큼 묽어진다. 마커는 새끼용과 같은 처리(원본 맥동 유지)로
다시 구웠다 — 설계 §4-0.

**교훈이 하나 더 붙는다: 굽는 판에서 잰 지표(변동폭·빈도)가 다 통과해도 "화면에서 밝은가"는
따로 봐야 한다.** M2는 그것을 안 봤다.

### 움직이는 자식에 수명을 곱하지 말 것 (M2)

수명 ×12를 걸면 움직이는 입자는 12배 멀리 간다. **출처가 `startSpeed` 하나가 아니다** —
fantasy 마커는 속도 0인데 `velocityOverLifetime` + `forceOverLifetime y=-2`로 움직여
**한없이 땅으로 꺼졌다**(낙하는 수명의 제곱에 비례).

`IsMoving`은 네 가지를 다 본다: `startSpeed` · `gravityModifier` ·
`velocityOverLifetime.enabled` · `forceOverLifetime.enabled`.

### 밝기·크기 지표는 위치 버그를 못 잡는다 (M2)

마커가 꺼지는 동안에도 변동폭·링 지름은 **전부 정상**이었다.
"얼마나 밝은가"와 "얼마나 넓은가"만 재고 **"어디에 있는가"를 아무도 안 봤다.**
→ 드리프트 검사(여러 시점의 세로 위치)를 넣었다.

### 가산 블렌드는 알파로 재면 안 된다 (M3)

셰이더가 `_Src=1 _Dst=1` 순수 가산이라 투명 배경에 구우면 알파가 0.03으로 읽힌다.
**세 번 연달아 틀렸다**: 임계 0.08 → "안 그려짐" / 임계 0.015 → 지름 0.4(실제 0.91) /
최대 알파 0.03 → "거의 투명".

**불투명 검정 배경 + 밝기(RGB 최대) 판정**으로 바꾸자 전부 제 값이 나왔다.

밝기를 올리는 손잡이도 색·알파가 아니라 **머티리얼 `_EmissionIntensity`**다.

### 시간 변화를 잴 때는 시드를 고정한다 (M2)

`useAutoRandomSeed = false` + 고정 시드. 안 그러면 인스턴스마다 위상이 달라
**시드 잡음을 시간 변동으로 오독한다**(링 지름이 4.03↔4.48로 흔들려 보였다).

### Building 레이어에는 뎁스 정렬이 있다 (M5)

작업노트 §4의 "정렬 레이어 안에 뎁스 정렬이 없다"는 **타워에는 해당하지 않는다.**
`Building.SetDepthSortOrder`가 `-(x+y)`를 넣고 `GridMap`이 세 경로에서 부른다.
→ 연출은 `tower.DepthSortOrder`를 따라가야 한다. **Overlay로 올리면 오히려 정렬을 잃는다.**

### Coplay `save_scene`이 씬을 복사한다 (M5)

씬 **이름**을 넘기면 원래 경로가 아니라 `Assets/` 루트에 **새 GUID로 사본**을 만든다.
원본은 변경 없이 남아 **"배선했는데 안 뜬다"**가 된다.

호출 후 `ls Assets/*.unity`로 확인할 것. 정리: 사본 내용을 원본 경로에 덮어쓰고 →
사본과 `.meta`를 지우고 → `open_scene`으로 원본을 다시 연다(원본 `.meta`를 건드리지 않아야 GUID가 산다).

### 컴파일 확인은 DLL 타임스탬프로 (M4·M5)

Coplay `check_compile_errors`는 캐시를 돌려줄 수 있다.
`Library/ScriptAssemblies/Assembly-CSharp.dll`이 **소스 수정 이후에** 재생성됐는지 본다.
