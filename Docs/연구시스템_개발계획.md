## 0. 요약 (TL;DR)

- **연구는 `ResearchManager`(신규, 독립 매니저)가 전담.** RP(연구 포인트)는 자원이 아니므로 `ResourceManager`에 넣지 않고 `ResearchManager`가 자체 카운터로 관리한다.
- **연구 3갈래(타워/생산/편의).** 용 스킬트리는 별도 시스템 — 이 계획서 범위 밖(`용_스킬트리_로드맵.md`).
- **RP 획득**: 밤 종료(정산) 시 연구소 배치 인구에 비례해 지급. **RP 누적·이월**(상한 없음, 밸런싱).
- **연구 실행**: RP + 자원 코스트 **즉시 소모 → 즉시 효과 적용**. 대기 일수·타이머 없음 → UniTask 대기 로직 불필요.
- **이번 마일스톤 세이브/로드 없음.** 노드 안정 ID는 두되 직렬화는 구현하지 않는다.
- **효과는 pull(조회) 방식.** 시스템이 필요 시 `ResearchManager`에서 값을 조회. 완료 노드 집합에서 매번 재계산(중복·순서 버그 차단).

## 1. 범위 (Scope) — 매우 중요

"시스템이 이미 잡혀 있는 요소만 먼저 구현" 원칙에 따라 3단계로 분류한다.

### 1-A. 이번 마일스톤 구현 (MVP) — 기존 소비처가 이미 존재

| 기능 | 연동 지점(기존 코드) | 상태 |
|---|---|---|
| RP 시스템(획득·누적·소모) | `CycleManager.OnNightEnd` 구독 | 훅 준비됨 |
| 연구소 건물 + 인구 배치 | `PopulationManager.TryCreateAllocation(Research, …)` | 패턴 존재(`FactoryPopulation`) |
| 연구소 증축 → 최대 인구 증가 | `PopulationManager.TryIncreaseMaxPopulation(int)` | **API 준비됨** |
| 생산량 보너스 | `GridMap.YieldBonusQuery` (라인 604~607에서 소비) | **소비처 준비됨** |
| 외곽 기초자원 채집 해금 | `GridMap.ResearchUnlockQuery` (라인 552에서 소비) | **소비처 준비됨** |
| 티어-주기 게이팅 | `CycleManager.CurrentCycleNumber`(=일차) → 주기 파생 | §6 참조 |
| 노드 해금/코스트 소모/즉시 효과 | 신규 `ResearchManager` | 신규 |
| 최소 UI(3탭·RP표시·해금버튼) | 신규 | 신규 |

### 1-B. 여력 시 2차 — 기존 시스템에 pull-훅 "추가"가 필요

| 기능 | 필요한 작업 | 비고 |
|---|---|---|
| 타워 스탯 강화(공격력·사거리·공속) | `TowerAttack`이 `Attack.Range`/`Attack.Interval`을 직접 사용 → `ResearchManager`의 배수를 곱하도록 조회 훅 추가 | 전투 코드 수정 |
| 타워 필요 인구 감소 | `TowerPopulation.Initialize`의 `_tower.Data.PopulationCapacity`를 연구 보정값으로 조정 | 인구 코드 수정 |

### 1-C. 보류 (노드는 두되 효과는 stub) — 대상 시스템 부재/미확정

| 기능 | 보류 사유 |
|---|---|
| 타워 이동 해금 | 타워 이동 시스템 미존재(코드 검색 결과 없음) |
| 시야 반경 확장 | `FogOfWarRenderer`는 청크 상태 기반이며 "반경 확장" API 없음 |
| 성 자동 회복/긴급 수리 | `Castle`에 Heal/Repair API 없음(`Health.Initialize`만 존재) |
| 속성 타워/관통·스플래시 | 속성 타워 건설 시스템 미확정 |
| 대각선 지대 개발·슬라임 양식·자동 생산/정산 | 기획 `[미정]` 또는 대상 시설 미정 |
| 세이브/로드 | 이번 마일스톤 제외(확정) |

> **stub 규칙**: 보류 효과의 노드는 SO로 만들되 `IResearchEffect` 구현체를 비워 두거나(no-op) `[미정]` 표시. UI에는 "준비 중"으로 노출하거나 숨긴다. 데이터 스키마는 지금 확정해 두어 후속 연결 시 재작업이 없게 한다.

## 2. 아키텍처 개요

```
GameManager (기존)
 ├─ Construct 주입 (기존 패턴: ResourceManager/SkillManager와 동일)
 └─ ResearchManager (신규)
      ├─ RP 풀(int) 자체 관리                     ← ResourceManager와 무관
      ├─ 완료 노드 HashSet<ResearchNodeData>
      ├─ implements IChunkYieldBonusQuery          → GridMap.YieldBonusQuery 에 주입
      ├─ implements IChunkResearchUnlockQuery      → GridMap.ResearchUnlockQuery 에 주입
      ├─ 구독: CycleManager.OnNightEnd             → RP 지급(연구소 배치 인구 비례)
      └─ 참조: PopulationManager                   → 증축(TryIncreaseMaxPopulation)

ResearchLab (신규 건물, MonoBehaviour)
 └─ ResearchLabPopulation (신규, FactoryPopulation 복제)
      └─ PopulationManager.TryCreateAllocation(PopulationAssignmentType.Research, capacity)
```

원칙: `ResearchManager`는 **싱글톤 아님.** `GameManager`가 `[SerializeField]`로 보유하고 적절한 시점에 `Construct(...)`로 의존성을 주입한다(`ResourceManager.Construct`, `SkillManager.Construct` 패턴과 동일).

## 3. 기존 코드 연동 지점 (실측)

아래는 조사로 확인된 **실제 시그니처**다. 그대로 사용/참조한다.

### 3-1. 하루 사이클 — `Managers/CycleManager.cs`
```csharp
public UnityEvent<int> OnDayStart;   // 인자 = CurrentRun.CurrentCycle (일차, StartDay마다 +1)
public UnityEvent<int> OnDayEnd;
public UnityEvent<int> OnNightStart;
public UnityEvent<int> OnNightEnd;   // ★ RP 지급을 여기 구독 (밤 종료 정산)
public UnityEvent<CycleManager.CycleState> OnCycleChanged;
public CycleState CurrentCycle { get; }            // Day / Night
public int CurrentCycleNumber { get; }             // = RunData.CurrentCycle (사실상 '일차')
public void Construct(GameManager gameManager);
```
- 순서: `EndNight()` → `OnNightEnd(day)` → `StartDay()`(day+1, `OnDayStart`).
- **주의**: `CurrentCycle`/`CurrentCycleNumber`는 이름과 달리 **일차 카운터**다. "4주기" 개념은 별도 시스템이 아직 없으므로 §6에서 일차→주기 파생 규칙을 정의한다.

### 3-2. 정산 — `Managers/DailySettlementManager.cs`
```csharp
public UnityEvent<int, PopulationUpkeepResult> SettlementCompleted; // OnDayStart에 반응해 발화
```
- RP 지급은 이 이벤트가 아니라 **`CycleManager.OnNightEnd`에 직접 구독**한다. (SettlementCompleted는 인구 유지비 정산 성공 시에만 발화 → RP를 그 성공 여부에 결합시키지 않기 위함.)

### 3-3. 인구 — `Population/PopulationManager.cs`, `Population/PopulationAssignmentType.cs`
```csharp
public enum PopulationAssignmentType { None, Tower, Production, Conquest } // ★ Research 추가 필요
public int MaxPopulation { get; }
public int AvailablePopulation { get; }
public UnityEvent<PopulationState> PopulationChanged;
public bool TryCreateAllocation(PopulationAssignmentType type, int capacity, out PopulationAllocation allocation);
public bool TryAssign(PopulationAllocation allocation, int amount);
public bool TryUnassign(PopulationAllocation allocation, int amount);
public bool TryIncreaseMaxPopulation(int amount);   // ★ 연구소 증축에 사용
public bool TryRemoveAllocation(PopulationAllocation allocation);
```
- **할당 패턴 레퍼런스**: `Buildings/FactoryPopulation.cs`(생산), `Buildings/Tower/TowerPopulation.cs`(타워). `ResearchLabPopulation`은 이를 복제하고 `PopulationAssignmentType.Research`로 생성한다.
- **기아(Starvation) 주의**: `TryApplyStarvation`은 Tower→Production→Conquest 순으로만 감소시킨다. Research 인구를 기아 대상에 포함할지 결정 필요(§9 결정항목). 기본안: **이번 마일스톤은 미포함(연구 인구는 굶어죽지 않음)**, 알파에서 정책 재검토.

### 3-4. 맵/생산·해금 조회 — `Grid/GridMap.cs`
```csharp
public IChunkResearchUnlockQuery ResearchUnlockQuery { get; set; } // 라인 27, 552에서 소비
public IChunkYieldBonusQuery   YieldBonusQuery      { get; set; } // 라인 30, 604~607에서 소비
```
- 인터페이스(이미 존재): `Research/IChunkResearchUnlockQuery.cs`, `Research/IChunkYieldBonusQuery.cs`
```csharp
public interface IChunkResearchUnlockQuery { bool IsUnlocked(Vector2Int chunkCoord, ResourceType resourceType); }
public interface IChunkYieldBonusQuery     { int  GetYieldBonus(Vector2Int chunkCoord, ResourceType resourceType); }
```
- `ResearchManager`가 두 인터페이스를 **구현**하고, 초기화 시 `gridMap.ResearchUnlockQuery = this; gridMap.YieldBonusQuery = this;`로 주입한다.
- `ResourceType`(`GameResources/ResourceType.cs`)는 `[Flags]` enum: Food/Wood/Stone + 특화 4종(FlameHeart/SnowCrystal/TimeSand/PhilosopherStone).

### 3-5. 자원 매니저 패턴 — `Managers/ResourceManager.cs`
- 코스트의 자원 부분 차감/조회는 `ResourceManager` API 사용(단일 출처). RP는 여기 넣지 않는다.
- `ResearchManager`는 자원 코스트 지불 시 `ResourceManager`를 참조해 차감한다(주입).

## 5. 데이터 구조 (스켈레톤)

> 실제 필드는 구현 시 확정. CLAUDE.md 규칙 준수: 인스펙터 노출은 `[SerializeField] private`, public은 프로퍼티, 문자열은 스트링테이블 key(`_LOC_KEY`), 리터럴 상수 금지.

```csharp
// ResearchBranch.cs
public enum ResearchBranch { Tower, Production, Convenience }

// ResearchNodeData.cs
[CreateAssetMenu(menuName = "TowerAndDragon/Research/Node", fileName = "ResearchNode")]
public class ResearchNodeData : ScriptableObject
{
    [SerializeField] private string _nodeId;          // 안정적 고유 ID(세이브 대비, 이번엔 참조/비교용)

    [SerializeField] private int _researchPointCost;
    [SerializeField] private List<ResourceAmount> _resourceCost; // 기존 Resource/ResourceAmount 재사용
    [SerializeField] private ResearchEffectSO[] _effects;

    public string NodeId => _nodeId;
    public string NameLocKey => _nameLocKey;
    public ResearchBranch Branch => _branch;
    public int Tier => _tier;
    public IReadOnlyList<ResearchNodeData> Prerequisites => _prerequisites;
    public int ResearchPointCost => _researchPointCost;
    public IReadOnlyList<ResourceAmount> ResourceCost => _resourceCost;

```

```csharp
// ResearchManager.cs (핵심 계약만)
public class ResearchManager : MonoBehaviour, IChunkYieldBonusQuery, IChunkResearchUnlockQuery
{
    [SerializeField] private ResearchTreeData _tree;
    [SerializeField] private ResearchTierConfig _tierConfig;

    private readonly HashSet<ResearchNodeData> _completed = new();
    private int _researchPoints;

    public int ResearchPoints => _researchPoints;
    public UnityEvent<int> ResearchPointsChanged;          // UI 구독
    public UnityEvent<ResearchNodeData> NodeCompleted;     // UI 구독

    public void Construct(GameManager gm, CycleManager cycle,
                          PopulationManager pop, ResourceManager res,
                          GridMap map, ResearchLab lab) { /* 주입 + 쿼리 등록 + OnNightEnd 구독 */ }

    public bool IsCompleted(ResearchNodeData node);
    public bool IsTierUnlocked(int tier);                  // §6
    public bool CanResearch(ResearchNodeData node);        // 선행완료 && 티어해금 && 코스트충족
    public bool TryResearch(ResearchNodeData node);        // 즉시 소모→_completed.Add→효과 적용→이벤트

    // IChunkYieldBonusQuery / IChunkResearchUnlockQuery: 완료 노드의 효과를 종합해 응답(pull)
    public int  GetYieldBonus(Vector2Int chunk, ResourceType type);
    public bool IsUnlocked(Vector2Int chunk, ResourceType type);
}
```

- **효과 적용 방식**: `TryResearch` 성공 시 `_completed`에 추가만 하고, 실제 수치는 **조회 시 `_completed`를 순회해 종합**한다(pull). 예: `GetYieldBonus`는 완료된 `YieldBonusEffectSO`들의 합을 반환. 이렇게 하면 세이브/로드나 리스펙 시 재적용 중복이 원천 차단된다.
- **연구소 증축(LabCapacityEffectSO)** 은 예외적으로 완료 즉시 `PopulationManager.TryIncreaseMaxPopulation(N)`을 1회 호출한다(누적 상태 변경형). 세이브/로드가 없는 이번 마일스톤에서는 안전. (세이브 도입 시엔 "완료 노드로부터 목표 Max 재계산" 방식으로 전환 — §9 메모.)

## 6. 티어-주기 매핑 (확정 규칙)

"4주기" 진행을 추적하는 별도 시스템이 아직 없고, `CycleManager`는 **일차**만 센다. 따라서 일차→주기를 **데이터로 파생**한다.

### 규칙
```
현재주기 = min(MAX_CYCLE, ((현재일차 - 1) / 주기당일수) + 1)
티어 해금 = (현재주기 >= 티어별_요구주기)
```
- `MAX_CYCLE = 4` (기획 §6).
- `주기당일수` = `ResearchTierConfig`의 `[SerializeField] private int _daysPerCycle` — **placeholder(예: 3)**, 밸런싱/기획 확정(`[미정]`) 시 인스펙터에서만 수정.

### 티어별 요구 주기 (기본안)

| 티어 | 요구 주기 | 해금 시점(의미) |
|---|---|---|
| T1 | 1 | 게임 시작 |
| T2 | 2 | 1주기 종료(포탈 2) |
| T3 | 3 | 2주기 종료(포탈 3) |
| T4 | 4 | 3주기 종료(포탈 4) |
| T5 | 4 | 4주기 진입(최종) |

### 검산 (주기당일수=3 예시)
- 1일차 → 주기1 → T1 해금.
- 4일차 → ((4-1)/3)+1 = 2 → 주기2 → T2 해금.
- 7일차 → ((7-1)/3)+1 = 3 → 주기3 → T3.
- 10일차 → ((10-1)/3)+1 = 4 → 주기4 → T4/T5.

> **교체 지점**: 추후 진짜 "주기/포탈 개방" 시스템(예: `CycleManager`에 주기 카운터 추가, 또는 포탈 매니저)이 생기면, `ResearchManager.IsTierUnlocked`가 그 값을 소스로 쓰도록 한 곳만 바꾼다. 파생 공식은 임시 브리지다.

## 7. RP 획득·소비 흐름

### 획득 (밤 종료 정산)
1. `ResearchManager`가 `Construct`에서 `cycle.OnNightEnd.AddListener(GrantResearchPoints)` (구독은 Awake/OnEnable 성격 시점, CLAUDE.md 이벤트 순서 규칙 준수).
2. `GrantResearchPoints(int day)`:
   - `int assigned = _lab != null ? _lab.AssignedPopulation : 0;`
   - `int gained = assigned * RATE_PER_POP;`  (`RATE_PER_POP`은 `ResearchTierConfig` 등 SO 필드, 리터럴 금지)
   - `_researchPoints += gained; ResearchPointsChanged?.Invoke(_researchPoints);`

### 소비 (연구 실행, 즉시)
1. `CanResearch(node)` = `!IsCompleted && 선행 모두 완료 && IsTierUnlocked(node.Tier) && _researchPoints >= node.Cost && ResourceManager로 자원 충족`.
2. `TryResearch(node)`:
   - 코스트 검증 실패 시 false.
   - `_researchPoints -= node.ResearchPointCost;` + `ResourceManager`에서 자원 차감.
   - `_completed.Add(node);`
   - 각 `effect`에 대해: 조회형은 등록만(자동), 상태변경형(LabCapacity)은 즉시 적용.
   - `NodeCompleted?.Invoke(node); ResearchPointsChanged?.Invoke(_researchPoints);`

## 8. 작업 순서 (Phase) — 의존성·완료 기준(DoD)

각 Phase는 **컴파일 에러 0 + 플레이 진입 가능**을 공통 DoD로 한다(CLAUDE.md 커밋 규칙).

### Phase 1 — 데이터 스켈레톤 (선행: 없음)
- `ResearchBranch`, `ResearchNodeData`, `ResearchTreeData`, `ResearchTierConfig`, `IResearchEffect`, `ResearchEffectSO` 생성.
- `PopulationAssignmentType`에 `Research` 추가.
- **DoD**: SO 에셋을 Data 폴더에 1개 이상 만들 수 있고, 인스펙터에서 선행/코스트/티어 편집 가능.

### Phase 2 — ResearchManager 코어 (선행: P1)
- RP 풀, `_completed`, `IsCompleted/IsTierUnlocked/CanResearch/TryResearch`, 이벤트, `Construct`.
- `GameManager`에 `ResearchManager` 보유·`Construct` 호출 배선.
- 티어-주기 파생(§6) 구현 + 단위 테스트(순수 함수).
- **DoD**: 디버그 버튼으로 RP 수동 지급 후 노드 해금 시 `_completed`에 반영, 이벤트 발화 확인.

### Phase 3 — 연구소 건물 + 인구 + RP 획득 (선행: P2)
- `ResearchLab`, `ResearchLabPopulation`(`FactoryPopulation` 복제, `Research`로 생성).
- `ResearchManager`가 `OnNightEnd`에서 배치 인구 비례 RP 지급.
- 연구소 증축 효과(`LabCapacityEffectSO`) → `TryIncreaseMaxPopulation`.
- **DoD**: 연구소에 인구 배치 → 밤 넘기면 RP 증가, 증축 연구 시 Max 인구 증가.

### Phase 4 — 생산/해금 효과 연결 (선행: P2)
- `YieldBonusEffectSO`, `ChunkUnlockEffectSO` 구현.
- `ResearchManager`가 `IChunkYieldBonusQuery`/`IChunkResearchUnlockQuery` 구현, `GridMap`에 주입.
- **DoD**: 생산량 보너스 연구 시 해당 청크 생산량 증가, 외곽 채집 해금 연구 시 채집 가능(GridMap 라인 552/607 경로로 확인).

### Phase 5 — 최소 UI (선행: P2~P4)
- `UI_ResearchWindow`: 3탭, RP 표시, 노드 카드(잠김/가능/완료 상태), 해금 버튼.
- 입력은 **InputSystem(신형)** 사용(프로젝트 규칙).
- 구독 후 현재값 1회 수동 반영(CLAUDE.md 초기 발화 누락 방지).
- **DoD**: 창에서 노드 클릭으로 실제 해금·RP 차감·효과 반영이 눈으로 확인됨. (프로토타입 시각화 `연구트리_시각화.html` 레이아웃 참조)

### Phase 6 (여력 시, 2차) — 타워 효과 (선행: P2)
- `TowerStatEffectSO` + `TowerAttack`/`TowerPopulation`에 pull-훅 추가.
- **DoD**: 타워 강화 연구 시 공격력/사거리/공속 또는 필요 인구가 실제로 변함.

## 9. 결정 필요/메모 (착수 전 또는 진행 중 확정)

- **기아 대상에 Research 인구 포함 여부** — 기본안: 이번 마일스톤 미포함. `TryApplyStarvation`의 감소 순서에 넣을지 결정.
- **연구소 증축의 세이브 대비** — 지금은 즉시 `TryIncreaseMaxPopulation`. 세이브 도입 시 "완료 노드에서 목표 Max 재계산"으로 전환(재적용 중복 방지).
- **주기당 일수 placeholder 값** — `[미정]`. 동작엔 값만 있으면 되므로 임시값으로 진행.
- **RATE_PER_POP, 노드 코스트, 게이트/티어 요구주기** — 전부 SO 노출, 밸런싱.
