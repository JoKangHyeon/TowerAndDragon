# 연구 시스템 개발 계획

> 이 문서는 이슈 #86에서 구현한 연구 시스템 코어 수직절편의 실제 계약을 정리한다.
> 연구 콘텐츠의 기준은 `기획종합_v2.md`와 `연구트리_로드맵.md`이며, `[미정]` 항목은 임의로 확정하지 않는다.

## 1. 확정 흐름

1. 플레이어가 연구소를 건설한다. 연구소는 동시에 1채만 존재할 수 있다.
2. 낮에 연구소 정원 안에서 인구를 배치하거나 회수한다.
3. 밤 종료 시 `배치 인구 × ResearchBalanceData.ResearchPointsPerPopulation`만큼 전역 RP를 얻는다.
4. 낮에 노드가 요구하는 RP와 자원을 한 번에 지불한다.
5. 연구는 대기 없이 즉시 완료되며, 완료 효과는 조회 시점부터 적용된다.

진행 중 연구, 타이머, 대기 일수는 만들지 않는다. RP는 `ResearchManager`가 관리하며 상한 없이 누적된다.

## 2. 현재 구현 범위

- 연구 데이터: `ResearchBranch`, `ResearchNodeData`, `ResearchTreeData`, `ResearchBalanceData`, `ResearchEffectSO`
- 연구 상태: 안정적인 `NodeId`와 `HashSet<string>` 기반 완료 집합
- 연구소: 건설·단일 건물 제한·철거·재건설·인구 배치
- RP: `CycleManager.OnNightEnd` 구독을 통한 정산당 1회 지급
- 연구 실행: 선행 노드·티어·단계·RP·자원 검증과 원자적 비용 차감
- 대표 효과: 초원 식량·목재·석재 생산량 +10%
- 임시 IMGUI: RP, 연구 인구/정원, 증감 버튼, 3갈래 탭, 노드 상태·비용·연구 버튼
- 씬 데이터: `Sangwook_Boss_And_Wave_And_Research`, 건설 카탈로그, 연구소 프리팹, 연구 SO 연결

현재 데이터에는 생산 갈래 T1인 `[TBD] Grassland Cultivation`만 포함한다. 타워·편의 갈래는 `[TBD] Coming Soon`으로 표시한다.

## 3. 연구 데이터 계약

### `ResearchNodeData`

- `NodeId`: 저장 데이터와 코드가 참조하는 안정 ID
- `NameLocKey`, `DescriptionLocKey`: 스트링테이블 키
- `Branch`: 타워, 생산, 편의
- `Tier`: 연구 티어
- `Prerequisites`: 다중 선행 노드
- `ResearchPointCost`: RP 비용
- `ResourceCost`: 자원 비용
- `Effects`: 완료 후 조회에 기여하는 효과 목록

`ResearchTreeData`에 등록되지 않았거나 ID가 중복된 노드는 유효한 연구 대상으로 취급하지 않는다.

## 4. `ResearchManager` 계약

### 공개 상태와 이벤트

```csharp
public int ResearchPoints { get; }
public ResearchLab ActiveLab { get; }
public ResearchNodeState GetNodeState(ResearchNodeData node);
public bool TryResearch(ResearchNodeData node, out ResearchFailureReason reason);
public bool IsCompleted(string nodeId);
public bool RegisterLab(ResearchLab lab);
public bool UnregisterLab(ResearchLab lab);

public UnityEvent<int> ResearchPointsChanged { get; }
public UnityEvent<ResearchNodeData> NodeCompleted { get; }
public UnityEvent<ResearchLab> ActiveLabChanged { get; }
```

### 연구 실행 순서

1. 트리에 등록된 노드인지 확인한다.
2. 이미 완료했는지 확인한다.
3. 현재 단계가 낮인지 확인한다.
4. T1인지, 선행 노드가 완료됐는지 확인한다.
5. RP와 자원이 충분한지 확인한다.
6. 자원과 RP를 차감한다.
7. 완료 ID를 등록한다.
8. RP 변경과 완료 이벤트를 발행한다.

검증 실패 시 RP, 자원, 완료 상태를 변경하지 않는다. 완료한 노드는 다시 실행할 수 없다.

## 5. 티어와 진행 시스템

현재 `CycleManager.CurrentCycleNumber`는 실제 연구 주기가 아니라 일차다. 일차를 임의의 4주기로 환산하지 않는다.

- T1: 현재 수직절편에서 사용 가능
- T2 이상: 실제 주기 또는 포탈 진행 소스가 구현될 때까지 `TierLocked`

후속 구현에서는 실제 진행 시스템을 `ResearchManager`에 주입해 티어 잠금만 교체한다. 임시 `daysPerCycle`, `ResearchTierConfig`, 일차→주기 환산 공식은 사용하지 않는다.

## 6. 연구소와 인구

`ResearchLabCoordinator`가 `GridMap.OnBuildingAdded`와 `GridMap.OnBuildingRemoving`을 구독한다.

- 추가: `PopulationAssignmentType.Research` 할당 생성 후 `ResearchManager.RegisterLab`
- 제거: 할당을 제거해 배치 인구를 반환한 후 `ResearchManager.UnregisterLab`
- 배치 변경: 낮에만 `ResearchLabPopulation.TryAssign/TryUnassign` 허용
- 철거: 누적 RP와 완료 노드는 `ResearchManager`에 남으므로 유지
- 재건설: 활성 연구소가 없어진 뒤 다시 건설 가능

연구소 증축은 현재 범위 밖이다. 후속 증축 효과는 전역 `PopulationManager.TryIncreaseMaxPopulation`을 호출하지 않고, 해당 연구소의 `PopulationAllocation` 정원을 늘리는 전용 API를 사용해야 한다.

기아 감소 순서에는 현재 연구 인구를 추가하지 않는다.

## 7. 생산 배율 계약

기존 정수 가산형 생산 훅 대신 다음 배율 조회 계약을 사용한다.

```csharp
public interface IChunkYieldMultiplierQuery
{
    float GetYieldMultiplier(Vector2Int chunkCoord, ResourceType resourceType);
}
```

`ResearchManager`가 이 계약을 구현하고 `GridMap.YieldMultiplierQuery`에 등록된다.

생산 정산 순서:

1. 건물 풋프린트가 포함된 청크별로 기본 생산 소계를 구한다.
2. 청크 지형과 자원 종류에 맞는 완료 연구의 증가율을 합산한다.
3. `1.0 + 증가율 합계`를 청크 소계에 곱한다.
4. 청크별 결과를 반올림한다.
5. 반올림된 청크 결과를 모두 합산한다.

완료 연구가 없으면 배율은 항상 `1.0`이므로 기존 생산량은 바뀌지 않는다. `YieldMultiplierEffectSO`는 대상 지형, 자원 플래그, 증가율을 데이터로 보유한다.

## 8. UI와 단계 제한

- 연구 UI는 `UI_Canvas`나 `UIManager`에 연결하지 않고 씬 루트의 `ResearchLabDebugGUI.OnGUI`로 그린다.
- 기존 타워 인구 배치 디버그 GUI처럼 마지막으로 선택한 `ResearchLab`을 추적해 화면 오른쪽에 표시한다.
- 표시 내용은 RP, 전체·배치·가용 인구, 연구소 배치 인구/정원, 3갈래 선택, 노드 설명·비용·상태·연구 버튼이다.
- 낮에는 인구 증감과 연구를 실행할 수 있다. 밤에도 창은 보이지만 변경 버튼은 잠기며 연구 상태는 낮 전용으로 표시된다.
- IMGUI 기본 `GUI.skin`을 사용하고 표시 문자열은 영어로 통일한다. 별도 TMP 폰트나 신규 아트는 사용하지 않는다.

## 10. 후속 범위

- T2~T5와 실제 주기/포탈 진행 연결
- 타워·편의 연구 효과
- 연구소 증축 전용 정원 API
- 외곽 4자원 해금과 광물 자원 추가
- 용 스킬트리
- 세이브/로드와 완료 `NodeId` 직렬화
- 기아 시 연구 인구 감소 정책

## 11. 검증 기준

- 두 번째 연구소는 비용 차감 없이 거부된다.
- 철거 시 연구 인구가 반환되고, RP와 완료 상태는 유지되며 재건설할 수 있다.
- 밤에는 연구 인구 변경과 연구 실행이 불가능하다.
- 2명 배치 후 밤 종료 시 RP가 정확히 10 증가한다.
- 비용 부족 또는 중복 연구 실패 시 상태와 보유량이 변하지 않는다.
- 초원 경작은 RP 10과 식량 10을 한 번만 차감하고 즉시 완료된다.
- 생산 배율은 청크별 반올림 후 합산되며, 대표 검증에서는 식량 생산량이 45에서 50으로 증가한다.
- 연구소 선택 후 임시 IMGUI가 표시되고, 현재 RP·인구·연구 상태를 매 프레임 반영한다.
- Unity 컴파일 오류가 없고 `Sangwook_Boss_And_Wave_And_Research` 플레이 모드에 진입할 수 있다.
