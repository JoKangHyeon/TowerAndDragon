02

게임이 실제로 도는 방식

하루는 4단계로 순환합니다. CycleManager가 Day/Night 두 상태와 5개 이벤트 (OnDayStart · OnDayEnd · OnNightStart · OnNightEnd · OnCycleChanged)만 발행하고, 각 시스템이 필요한 이벤트를 스스로 구독하는 중앙 상태머신 없는 이벤트 구독형 구조입니다.

PHASE 1 · 시간 무제한

낮 — 운영

  • 격자에 타워·생산시설 건설 (고스트 미리보기·회전·철거 환불)
  • 인구를 생산/방어/점령/연구 4갈래에 배분
  • 점령 원정 출격 · 연구 실행 · 용 속성 변경
  • 플레이어가 “밤으로” 버튼을 눌러야 진행
PHASE 2 · 전멸까지

밤 — 방어

  • 개방된 포탈에서 스플라인 경로로 적 진격
  • 타워 자동 전투 (인구 배치율 = 공격속도)
  • 어미용 액티브 스킬로 개입
  • 적 전멸 시 자동으로 밤 종료
PHASE 3 · 자동

정산 — 결과

  • 생산시설 산출 → 자원 획득
  • 연구소 배치 인구 × 5 = 연구포인트(RP)
  • 점령 원정 일수 진행 / 완료 시 영토·인구 획득
  • 인구 유지비(식량) 소모, 부족 시 기아
PHASE 4 · 진행

다음 날 — 확장

  • 7일차마다 보스 웨이브
  • 주기 종료 시 새 포탈 개방 (北→南→東→西)
  • 점령한 땅의 가치만큼 적 강화 누적
  • 28일차 최종 보스 격파 = 승리
실제 세팅된 진행 규칙 — WaveCycleRules에 상수로 고정: 주기당 7일 · 총 4주기 = 28일 · 포탈 개방 순서 North → South → East → West. 28일 전체 웨이브 데이터가 제작되어 있으며, 7·14·21·28일차가 보스 웨이브입니다. 포탈은 누적 개방되어 4주기에는 4방향에서 동시에 진격합니다.

어떻게 구현되어 있는가 — 아키텍처

미션 필수 요건인 데이터 기반 설계를 축으로, 5개 계층이 이벤트로만 연결됩니다. “로직은 코드, 수치는 에셋”을 일관되게 지켰고 그 결과 기획 수치 변경이 코드 수정 없이 가능합니다.

① 데이터 계층 — ScriptableObject 187개 웨이브 스케줄·몬스터·타워·공격·효과·연구노드·용스킬노드·자원·생산시설·점령 비용/기간 테이블·산출량 테이블이 전부 에셋. 연구 27노드와 용 30노드는 에디터 생성기 스크립트가 GUID를 유지하며 멱등 생성하고, 로컬라이즈 CSV 행까지 자동으로 추가합니다.
② 사이클 계층 — 이벤트 허브 CycleManager가 낮/밤 2상태와 5개 UnityEvent만 발행. 각 시스템이 필요한 이벤트를 스스로 구독하므로 시스템 간 직접 참조가 거의 없습니다. 이벤트 발행은 try/catch로 격리해 한 구독자의 예외가 루프를 멈추지 않습니다.
③ 도메인 계층 — 조립형 컴포넌트 몬스터는 상속이 아니라 체력 + 공격 + 이동 + 특수행동 컴포넌트 조립. 타워/새끼용은 ITowerStaffing, 인구 UI는 IPopulationAllocationTarget, 창 배타는 IExclusiveMode, 연구·용 공용 판정은 ProgressionRules — 인터페이스로 변형을 흡수합니다.
④ 중재 계층 — Coordinator 패턴 인구 4갈래·자원·연구소·새끼용 배치는 각각 전용 Coordinator가 GridMap.OnBuildingAdded/Removing을 구독해 자동 연결·해제. 건물 프리팹은 매니저 참조를 들고 있지 않아도(null) 씬에 놓이면 코디네이터가 주입합니다.
⑤ 비동기 — UniTask 전면 적용 웨이브 스폰·타워 부활·조명 전환·초기화 순서 보정 전부 UniTask. 코루틴 사용 0건, async void 금지, 파괴 시 자동 취소 토큰 사용 — 팀 규칙(CLAUDE.md)이 실제 코드에 지켜지고 있습니다.

07

리스크와 즉시 조치 항목

중요한 특징이 있습니다 — 남은 문제 대부분이 “못 만든 것”이 아니라 “만들었는데 연결이 안 된 것”입니다. 즉 해결 비용이 상대적으로 낮습니다.

P1
일일 정산 매니저가 메인 씬에 배치되지 않음

식량 유지비 소모와 기아 처리를 담당하는 DailySettlementManager가 어떤 실사용 씬에도 없습니다. 로직 자체는 완성되어 있고 테스터로는 동작이 확인됩니다. 현재 플레이하면 인구가 식량을 먹지 않아 경제 압박이라는 핵심 재미 요소가 작동하지 않습니다.

→ 조치: 메인 씬에 정산 매니저 + 인구 유지비 시스템 배치 및 참조 연결 (수십 분 규모)
P1
특화자원 생산시설 4종이 메인 씬 건설 목록에 미등록

SO·프리팹·스프라이트가 모두 완성됐고 이하늘 작업 씬에서는 확인되지만, 메인 씬이 쓰는 건설 창에는 기본 3종 + 슬라임 농장 4개만 등록되어 있어 특화자원 4종을 게임 내에서 얻을 수 없습니다. 여기에 슬라임 산출 배율 데이터가 0건이라 슬라임도 기본값만 나옵니다. 결과적으로 용 성장 · 새끼용 급여 · 연구 상위 노드 · 봉인석까지 연쇄적으로 막힙니다.

→ 조치: 건설 창 Factory 탭에 특화 4종 등록 + 청크/셀 산출 테이블에 슬라임 5종 배율 입력
P1
성장 시스템의 효과 계층이 비어 있음

연구 27노드 중 실효 노드 2개, 용 스킬 30노드는 전부 stub입니다. 트리를 클릭해 해금하는 경험은 완성됐지만 해금해도 게임이 변하지 않아 성장 재미가 검증되지 않은 상태입니다.

→ 조치: 우선 체감 큰 6~8개 노드(타워 사거리·공격속도·필요인구 감소, 외곽 기초자원 채집, 시야 확장, 성 회복)에 효과 SO 우선 구현
P2
플레이어 공격 수단(어미용 스킬)에 접근할 수 없음

스킬 HUD 바인더가 메인 씬에 없어 스킬 발동을 시작하는 코드 경로가 런타임에 존재하지 않습니다. 미션 필수 요건 중 하나이므로 프로토타입 시연 전 반드시 연결이 필요합니다.

→ 조치: HUD에 스킬 슬롯 배치 + 속성별 스킬 에셋 최소 2종 제작(빙결, 메테오)
P2
점령 페널티(적 난이도 상승)가 실효 없음

강화 프로필이 2개뿐이고 61청크 중 4개만 연결, 포탈의 지형 타입도 미설정이라 대부분 적용되지 않습니다. “확장할수록 위험해진다”는 핵심 긴장 구조가 현재 체감되지 않습니다.

→ 조치: 포탈 지형 타입 설정 + 지형별 강화 프로필 5종 작성 후 청크 일괄 연결
P2
3·4주기 웨이브가 복제 데이터

15~20일차 6개가 서로 동일, 22~27일차 6개도 동일합니다. 후반 난이도 곡선이 사실상 평평해 28일 완주 플레이의 체험 검증이 불완전합니다.

→ 조치: 특수형 몬스터(자폭·감전) 편성을 포함한 후반 웨이브 재설계
P3
제출 전 정리 항목

메인 씬에 디버그 컴포넌트 4종(웨이브 스킵 F키, 인구 테스터, 연구소 GUI 등)이 활성 상태이고, Debug.Log가 상시 출력되는 지점이 여러 곳 있습니다. 번역은 [미정] 비율이 약 75%이고 한국어 CSV를 로드하는 코드가 아직 없어 실행 시 영문 테이블만 사용됩니다.

→ 조치: 베타 단계에 디버그 UI 비노출 · 로그 정리 · 언어 로드 호출 추가를 일괄 처리
P3
자동 테스트·CI 부재

EditMode 테스트 2개(웨이브 주기 규칙, 포탈 개방)만 존재하고 GitHub Actions 등 CI 파이프라인이 없습니다. 4명이 씬·프리팹을 동시 수정하는 구조에서 배선 누락형 회귀를 잡아낼 안전망이 없습니다. 실제로 위 P1 항목들이 이 유형입니다.

→ 조치: 씬 필수 컴포넌트 존재 여부를 검사하는 PlayMode 스모크 테스트 1개 추가만으로도 큰 효과
08

마일스톤과 다음 단계

프로토타입 마감(7/31)까지 2일. 기능 제작은 계획을 상회했고, 남은 시간은 연결과 검증에 쓰는 것이 합리적입니다.
