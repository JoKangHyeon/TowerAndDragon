## 3. 발견된 문제

1. **[버그] 대공 타워의 PrefabId가 `TP_Musket`으로 잘못 설정됨.** `TP_Anti_Air.prefab`을 확인해 보니 `_prefabId` 필드가 `TP_Musket`(총탑과 동일 값)으로 남아 있다 — 총탑을 복제해 만든 뒤 값을 바꾸지 않은 것으로 보인다. 건설 패널에는 정상 노출되지만, **건물 세이브·로드가 이번에 구현되면서 PrefabId 문자열로 `BuildingCatalog`를 조회해 복원**하므로, 대공 타워를 지은 뒤 저장→불러오기를 하면 **총탑(Musket)으로 바뀌어 복원된다.** `BuildingCatalog.asset` 자체에도 대공 타워 항목이 아예 없어 `Tools/Building Catalog/검증` 메뉴로 잡히는 사안이다. PrefabId를 `TP_Anti_Air` 등 고유값으로 바꾸고 카탈로그를 재구성해야 한다.
2. 위 사례처럼, 새 건물을 추가할 때 `Tools/Building Catalog/검증`을 돌리지 않으면 "지을 수는 있는데 불러오면 사라지거나 다른 건물로 바뀌는" 문제가 조용히 생길 수 있다. 건물 추가 체크리스트에 이 검증 단계를 넣는 것을 권장.
3. 기존에 알려져 있던 공백 중 이번 확인에서도 그대로였던 것 — `Building.IsOpen`(건물 해금) 죽은 코드, `GridMap.ResearchUnlockQuery`·`ISealStoneUnlockQuery` 구현체 없음(fail-open), 몬스터 사망 시 자원 드랍 TODO, 몬스터(적) 오브젝트 풀링 미적용(이번에 풀링된 것은 주민 캐릭터뿐, 몬스터는 여전히 사망 시 `Destroy`).
4. `Docs/구현현황.md`가 08-16 스냅샷에 멈춰 있어 위 1번 항목·건물 세이브 구현·봉인석 배선 등이 반영돼 있지 않다. 다음 갱신 시 §1 표와 §6 공백 목록을 이번 확인 내용으로 맞출 것.
