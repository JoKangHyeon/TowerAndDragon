# 타워 시스템 현황

작성일: 2026-07-10 · 대상: GitHub 이슈 #6 `[Feature] 타워 시스템`

상세 게임 기획은 `Docs/기획종합_v2.md`를 우선합니다. 이 문서는 기획 내용을 복제하지 않고, 현재 타워 시스템의 코드 구조와 구현·검증 현황을 정리합니다.

> 타워 인구 할당, 충원율 기반 공격 속도와 인구 유지비 연결의 최신 설계는
> [인구·자원·점령·웨이브 통합 설계 및 작업계획](./인구_자원_점령_웨이브_통합_설계.md)을 우선합니다.

## 1. 현재 목표

이슈 #6의 기본 목표는 타워 설치, 자동 타깃 선정과 공격, 공격 효과 적용, 체력 관리, 체력 소진 시 일시 비활성화, 지연 부활, 아침 최대 체력 회복입니다.

현재 코드는 타워의 데이터·전투·체력 생명주기를 구현한 상태입니다. 실제 건설 UI 및 그리드 배치 연결과 플레이 모드 검증은 아직 완료되지 않았습니다.

## 2. 구성 요소

| 구성 요소 | 역할 | 현재 상태 |
|---|---|---|
| `Building` | 건물 공통 기반. 스프라이트와 점유 형태 보관 | 골격 구현 |
| `FootprintShape` | 건물이 차지하는 셀의 너비·높이·점유 오프셋 제공 | 구현, 검증 보완 필요 |
| `TowerData` | 타워 이름 key, 최대 체력, 부활 지연시간, 공격 데이터 보관 | 구현 |
| `Tower` | 타워 조립, 피해 수신, 비활성화·부활·아침 회복 관리 | 구현 |
| `TowerAttack` | 적 탐색, 타깃 유지, 공격 간격 관리, 공격 실행 | 기본 구현 |
| `Health` | 현재/최대 체력, 피해, 사망 이벤트, 완전 회복 | 타워 지원 확장 완료 |
| `AttackSO` | 사거리·공격 간격·공격 효과 목록을 담는 공용 데이터 | 기존 구현 재사용 |
| `AttackContext` | 한 번의 공격을 실행한 주체 등 상황 정보 전달 | 기존 구현 재사용 |
| `DamageEffectSO` | `IDamageable` 대상에게 즉발 피해 적용 | 기존 구현 재사용 |

## 3. 데이터 구조

`TowerData`는 타워 종류별 고정 데이터를 담는 ScriptableObject입니다.

- `NameLocKey`: 스트링테이블에서 타워 이름을 찾기 위한 key
- `MaxHealth`: 최대 체력
- `ReviveDelay`: 체력이 0이 된 뒤 다시 활성화되기까지의 시간
- `Attack`: 타워가 사용할 `AttackSO`
- `CanAttack`: `AttackSO`가 연결되어 있는지 나타내는 파생 프로퍼티

공격력·사거리·공격 간격은 `TowerData`에 중복 저장하지 않습니다. `AttackSO`가 사거리와 간격을 보관하고, 연결된 `AttackEffectSO`들이 피해 및 후속 효과를 정의합니다. `AttackSO`는 여러 공격자가 공유하는 정적 데이터이므로 현재 타깃과 쿨다운 같은 런타임 상태를 저장하지 않습니다.

현재 샘플 구성은 다음과 같습니다.

- `TowerData_Sample`: 최대 체력 100, 부활 지연시간 10초, `Attack1` 참조
- `Attack1`: 사거리 2, 공격 간격 1초, 피해 효과 1개 참조

위 수치는 테스트용 데이터이며 확정 기획 수치로 간주하지 않습니다.

## 4. 타워 생명주기

`Tower`는 `Building`을 상속하고 `IDamageable`을 구현합니다. `Health`와 `TowerAttack`은 `[RequireComponent]`로 요구합니다.

1. `Awake`에서 `Health`와 `TowerAttack`을 캐싱합니다.
2. 인스펙터에 `TowerData`가 있으면 `Start`에서 `Setup`을 호출합니다. 건설 시스템이 생성 후 데이터를 주입하는 경우에도 공개 `Setup(TowerData)`을 사용할 수 있습니다.
3. `Setup`에서 체력을 초기화하고 `Health.Died`를 구독한 뒤 공격 데이터를 `TowerAttack`에 전달합니다.
4. `TakeDamage`는 이미 비활성 상태인지 검사한 후 피해량을 `Health`에 전달합니다.
5. 체력이 0이 되면 공격을 중지하고 `ReviveDelay`만큼 기다립니다.
6. 지연시간이 끝나면 체력을 최대치로 회복하고 공격 가능한 타워를 다시 활성화합니다.
7. `RestoreAtMorning`이 호출되면 진행 중인 부활 대기를 취소하고 즉시 최대 체력 회복 및 재활성화를 수행합니다.
8. 오브젝트가 파괴될 때 `Died` 이벤트 구독을 해제합니다.

타워 GameObject 자체는 체력이 0이 되어도 비활성화하지 않습니다. GameObject를 끄면 자체 코루틴도 정지해 자동 부활할 수 없기 때문입니다. 현재는 공격 기능만 중지하고 타워의 생명주기 컴포넌트는 계속 실행합니다.

## 5. 자동 공격 흐름

`TowerAttack`은 `AttackSO`를 받아 다음 런타임 상태를 별도로 관리합니다.

- 현재 타깃
- 다음 공격 가능 시각
- 현재 공격 활성화 여부
- 탐색 대상 `LayerMask`

매 프레임의 처리 흐름은 다음과 같습니다.

1. 공격이 비활성 상태이면 종료합니다.
2. 현재 타깃이 없거나, 사망했거나, 사거리를 벗어났으면 새 타깃을 찾습니다.
3. `Physics2D.OverlapCircleAll`로 사거리 안의 Collider를 검색합니다.
4. 검색 결과에서 살아 있는 `BaseMonster`만 남기고 가장 가까운 적을 선택합니다.
5. 공격 간격이 지났으면 `AttackContext`에 타워 GameObject를 공격 주체로 담습니다.
6. `AttackSO.Execute`를 호출해 연결된 공격 효과들을 대상에게 순서대로 적용합니다.

현재 우선순위는 **사거리 내 가장 가까운 적**입니다. 지상/공중 우선, 성에 가까운 적 우선 등 별도 정책은 확정되지 않았으므로 구현하지 않았습니다.

## 6. 공용 전투 파이프라인

타워는 몬스터 시스템과 같은 전투 계약을 사용합니다.

```text
TowerAttack
  → AttackSO.Execute(target, context)
    → AttackEffectSO.Apply(target, context)
      → IDamageable.TakeDamage(DamageInfo)
        → BaseMonster
          → Health
```

`AttackContext`는 공격 정의가 아니라 **이번 공격의 상황 정보**입니다. 현재는 공격 주체 `Source`만 보관하며, 이후 공격자 위치, 강화 수치, 속성 등 효과 실행에 필요한 정보가 확정되면 확장할 수 있습니다.

## 7. 디버깅 및 테스트 설정

`TowerAttack`의 `Show Debug Logs`를 켜면 다음 시점에 로그를 출력합니다.

- 새 타깃 선정
- 실제 공격 실행

에디터에서 타워를 선택하면 초기화 이후 공격 사거리를 붉은 원형 Gizmo로 표시합니다.

자동 공격이 작동하려면 다음 설정이 모두 필요합니다.

1. 타워에 `Tower`, `Health`, `TowerAttack` 컴포넌트가 있어야 합니다.
2. 타워에 유효한 `TowerData`가 연결되어야 합니다.
3. `TowerData`에 유효한 `AttackSO`가 연결되어야 합니다.
4. `TowerAttack.Target Layers`에 `Enemy` 레이어가 포함되어야 합니다.
5. 적 GameObject가 `Enemy` 레이어여야 합니다.
6. 적 프리팹에 `Collider2D`가 있어야 `Physics2D.OverlapCircleAll` 검색에 포함됩니다.
7. 적이 `AttackSO.Range` 안에 들어와야 합니다.

현재 확인된 설정은 `Enemy` 레이어 등록, 몬스터 프리팹의 Enemy 레이어 지정, 테스트 씬 타워의 Target Layers 지정, `TowerData_Sample`과 `Attack1` 연결입니다.

현재 `Monster_Ground_Basic` 프리팹에는 `Collider2D`가 없어 타워의 물리 탐색 결과에 포함되지 않습니다. 테스트 전에 `CircleCollider2D` 또는 `BoxCollider2D`를 추가해야 합니다. 또한 `Show Debug Logs`는 기본적으로 꺼져 있으므로 인스펙터에서 켜야 로그를 확인할 수 있습니다.

## 9. 남은 작업

우선순위가 높은 후속 작업은 다음과 같습니다.

1. 몬스터 프리팹에 `Collider2D`를 구성하고 테스트 씬에서 자동 공격을 검증합니다.
2. 타워 프리팹에 필요한 컴포넌트와 레이어·데이터 연결을 확정합니다.
3. 체력 0 상태를 표현할 비주얼 또는 애니메이션을 연결합니다. 에셋은 임의 생성하지 않고 팀 제공 리소스를 사용합니다.
4. 실제 낮 전환 시스템에서 모든 타워의 `RestoreAtMorning`을 호출하도록 연결합니다.
5. `GridMap`의 실제 건물 생성 및 `GridCell.PlaceBuilding` 호출과 타워 프리팹을 연결합니다.
6. 건설 비용, 인구 On/Off, 철거·환급, 강화는 관련 기획과 시스템이 확정된 뒤 별도 범위로 구현합니다.

## 10. 알려진 개선 사항

- `Physics2D.OverlapCircleAll`은 탐색할 때마다 배열을 할당합니다. 프로토타입 검증 후 타워와 적 수가 늘어나면 비할당 검색 또는 트리거 기반 후보 관리로 교체를 검토합니다.
- `TowerAttack`이 현재 `BaseMonster`에 직접 의존합니다. 공격 가능한 진영이나 대상 종류가 늘어나면 위치와 진영 정보를 제공하는 공용 타깃 계약 도입을 검토합니다.
- `FootprintShape.IsOccupied`는 좌표 범위와 `_cells` 배열 길이를 검증하지 않습니다. 인스펙터에서 크기와 배열이 어긋나지 않도록 `OnValidate` 또는 전용 편집기 보완이 필요합니다.
- `Health.TakeDamage`의 임시 로그 접두사가 `[BaseMonster]`이지만 `Health`는 타워도 공용으로 사용합니다. 공용 명칭으로 수정하거나 호출 주체별 디버그 로그로 분리해야 합니다.
- 공격 이펙트와 투사체 표현은 아직 연결하지 않았습니다. 현재 공격 효과는 즉시 적용됩니다.
