# 타워 시스템 — 초기 설계 기록

> **2026-07-18 스냅샷입니다. 현재 상태는 `Docs/구현현황.md`를 보세요.**
> 이 문서에는 그때 내린 설계 결정과 그 이유만 남겼습니다. 당시의 "남은 작업 / 검증 현황"은
> 대부분 해소되어 삭제했습니다(충원율 연동, 아침 회복 연결, 콜라이더 구성 등).
> 대상 이슈: GitHub #6 `[Feature] 타워 시스템`

## 지금도 유효한 설계 결정

### 공격력·사거리·간격을 `TowerData`에 두지 않는다
`AttackSO`가 사거리와 간격을 갖고, 연결된 `AttackEffectSO`들이 피해와 후속 효과를 정의합니다.
`TowerData`에는 이름 key·정원·최대체력·부활 지연만 둡니다.
`AttackSO`는 여러 공격자가 **공유하는 정적 데이터**이므로 현재 타깃·쿨다운 같은 런타임 상태를
저장하지 않습니다. 그 상태는 실행 컴포넌트(`TowerAttack`/`MonsterAttack`)가 보관합니다.

→ 이 덕분에 타워와 몬스터가 같은 전투 파이프라인을 씁니다:
`AttackSO.Execute → AttackEffectSO.Apply → IDamageable.TakeDamage → Health`

### 체력이 0이어도 GameObject를 끄지 않는다
GameObject를 끄면 그 위에서 도는 부활 대기도 함께 멈춰 스스로 되살아날 수 없습니다.
그래서 **공격 기능만 중지**하고 생명주기 컴포넌트는 계속 돌립니다.
"타워는 파괴되지 않고 비활성화된다"는 기획이 이 형태로 구현돼 있습니다.

### `AttackContext`는 공격 정의가 아니라 이번 공격의 상황 정보다
당시엔 공격 주체(`Source`)만 담았고, 이후 필요한 정보가 확정될 때마다 확장하도록 열어 뒀습니다.
(현재는 공격력 보정·부가 상태이상·레이어마스크·공격 속성·대공/대지 필터까지 실려 있습니다.)

### 타깃 우선순위는 "사거리 내 가장 가까운 적"
지상/공중 우선, 성에 가까운 적 우선 같은 정책은 기획이 확정되지 않아 구현하지 않았습니다.
(현재도 이 정책이 유지되고 있으며, 여기에 대공/대지 필터만 추가됐습니다.)

## 당시 남겨 둔 개선 사항 (일부는 여전히 유효)

- `Physics2D.OverlapCircleAll`은 탐색할 때마다 배열을 할당합니다. 타워·적 수가 늘면
  비할당 검색이나 트리거 기반 후보 관리로 교체를 검토합니다. — **여전히 유효**
- `FootprintShape.IsOccupied`가 좌표 범위와 배열 길이를 검증하지 않습니다.
- `Health.TakeDamage`의 로그 접두사가 `[BaseMonster]`인데 `Health`는 타워도 공용으로 씁니다.
