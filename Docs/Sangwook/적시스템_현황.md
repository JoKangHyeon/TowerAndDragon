## 지금도 유효한 설계 결정

### 적 종류를 상속이 아니라 컴포넌트 조립으로 표현한다
`BaseMonster`는 "모든 것을 가진 부모 클래스"가 아니라 **오케스트레이터**입니다.
프리팹에 붙은 컴포넌트(`Health` / `MonsterShield` / `MonsterMovement` / `MonsterAttack`)를 조립하고
생명주기(주입 → 이동 → 피해 라우팅 → 사망)만 관리합니다.

지상/공중 × 공격 유무 × 방어막 유무의 조합은 **어떤 컴포넌트를 붙이고 어떤 `MonsterData`를
주입하느냐**로 표현합니다. 이 방침 덕분에 이후 탱커·용사냥꾼·보호형·마비형·자폭형·속성 면역형이
전부 상속 없이 데이터와 `SpecialBehaviorSO` 추가만으로 들어왔습니다.

### `MonsterTargetType`은 최종 목적지가 아니라 "이동 중 공격할 대상"이다
메인 성은 모든 적의 공통 최종 목표이므로 이 enum으로 선택하지 않습니다.
`None`이면 성까지 그냥 진격하고, `Tower`면 이동 중 사거리 안의 타워를 칩니다.
(이후 `Dragon`이 추가되어 새끼용도 이동 중 대상이 됐습니다.)

### 적과 타워가 같은 전투 파이프라인을 쓴다
```text
MonsterAttack 또는 TowerAttack
  → AttackSO.Execute(target, context)
    → AttackEffectSO.Apply(target, context)
      → IDamageable.TakeDamage(DamageInfo)
```
`AttackSO`는 사거리·간격·효과 목록만 갖는 **공유 정적 데이터**입니다. 현재 타깃과 다음 공격 시각
같은 런타임 상태는 공유 SO에 저장하지 않고 각 실행 컴포넌트가 보관합니다.

### 피해 흡수 순서: 방어막 → 체력
`BaseMonster.TakeDamage`는 방어막이 있으면 먼저 흡수시키고 남은 피해만 `Health`에 넘깁니다.
(이후 여기에 속성 면역 판정이 맨 앞에 추가됐습니다.)

### 타워는 `Destroy`되지 않는다
체력 0 → 공격만 비활성화 → 몬스터의 유효 대상에서 제외 → 대기 후 회복.
GameObject를 끄면 부활 대기까지 멈추기 때문입니다.

## 당시 남겨 둔 것 중 아직 유효한 것

- `Physics2D.OverlapCircleAll`을 매 프레임 호출해 탐색마다 배열이 할당됩니다.
  몬스터 수가 늘면 탐색 주기 적용 / `NonAlloc` / 트리거 기반 후보 관리를 검토합니다.
- 타워 복구 정책: 당시엔 `ReviveDelay` 자동 재활성화만 있었습니다.
  현재는 **충원율에 비례해 게이지가 차오르고, 아침엔 즉시 복구**되는 형태로 확장됐습니다
  (인구가 0인 타워는 부활하지 않습니다).
