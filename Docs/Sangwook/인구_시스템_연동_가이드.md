# 인구 시스템 연동 가이드

작성일: 2026-07-18

대상: UI·타워·생산·점령·자원·정산 시스템 작업자

기준 브랜치: `feature/16-poulation-system`

이 문서는 다른 시스템에서 현재 인구 코어를 안전하게 사용하는 방법을
정리한다. 구현 현황은
[인구 시스템 코어 진행상황](./인구_시스템_코어_진행상황.md)을, 확정 규칙과
장기 구조는
[인구·자원·점령·웨이브 통합 설계](./인구_자원_점령_웨이브_통합_설계.md)를
함께 확인한다.

상세 게임 기획은 `Docs/기획종합_v2.md`가 우선한다. 아래 예제의 생산·점령
클래스 이름은 연결 형태를 설명하기 위한 예시이며, 존재하지 않는 타입을
그대로 추가하라는 의미가 아니다.

---

## 1. 핵심 규칙

### 인구는 소비 자원이 아니다

식량·목재처럼 지불 후 사라지는 값이 아니라 사용처에 배치했다가 다시
회수하는 공용 인력이다.

```text
MaxPopulation = AssignedPopulation + AvailablePopulation
```

- `MaxPopulation`: 살아 있는 전체 인구
- `AssignedPopulation`: 모든 사용처에 배치된 인구 합
- `AvailablePopulation`: 새로 배치할 수 있는 인구

인구를 `ResourceCost.Subtract`로 차감하거나 각 건물에서 별도 전역 인구
값을 만들면 안 된다.

### 각 사용처는 자기 할당 하나를 가진다

```text
PopulationManager
  ├─ Tower A의 PopulationAllocation
  ├─ Tower B의 PopulationAllocation
  ├─ Farm A의 PopulationAllocation
  ├─ Mine A의 PopulationAllocation
  └─ Conquest Expedition A의 PopulationAllocation
```

농장·벌목장·광산은 모두 `Production` 분류지만 서로 다른 할당 객체를
사용한다. 점령 원정도 원정마다 별도 `Conquest` 할당을 가진다.

### 외부에서는 숫자를 직접 변경하지 않는다

- `PopulationAllocation`을 `new`로 직접 만들지 않는다.
- `AssignedPopulation`을 직접 대입하지 않는다.
- `MaxPopulation`을 다른 시스템에서 별도 보관하지 않는다.
- 모든 변경은 `PopulationManager`의 공개 `Try` API를 사용한다.

## 2. 타입별 역할

| 타입 | 용도 | 외부 시스템의 사용 방식 |
|---|---|---|
| `PopulationManager` | 전체 인구와 모든 할당의 원본 | 조회, 할당 생성, 배치·회수 요청, 이벤트 구독 |
| `PopulationAllocation` | 사용처 한 곳의 배치 상태 | 읽기만 수행하고 생명주기 동안 참조 보관 |
| `PopulationState` | 전체 인구 상태 스냅숏 | UI와 이벤트 수신자가 값 표시 |
| `PopulationAssignmentType` | 타워·생산·점령 정책 분류 | 할당 생성 시 올바른 분류 지정 |
| `TowerPopulation` | 타워와 할당 사이의 현재 어댑터 | 타워 UI·전투 계층에서 조회 및 요청 |
| `TowerPopulationCoordinator` | 건설·철거 시 타워 할당 연결 | 씬에서 GridMap과 Manager 참조 설정 |

## 3. 읽기 API

### 전체 인구 조회

```csharp
int maxPopulation = populationManager.MaxPopulation;
int assignedPopulation = populationManager.AssignedPopulation;
int availablePopulation = populationManager.AvailablePopulation;
PopulationState state = populationManager.CurrentState;
```

UI처럼 세 값을 함께 사용한다면 `CurrentState`를 한 번 받아 사용하는 편이
명확하다.

### 개별 할당 조회

```csharp
int capacity = allocation.Capacity;
int assigned = allocation.AssignedPopulation;
int availableCapacity = allocation.AvailableCapacity;
float staffingRatio = allocation.StaffingRatio;
PopulationAssignmentType type = allocation.AssignmentType;
```

`StaffingRatio`는 0부터 1 사이의 충원 비율이다. 생산량과 공격 간격 계산은
이 값을 읽되 할당 값을 직접 수정하지 않는다.

타워에서는 할당을 외부에 공개하지 않고 다음 어댑터 프로퍼티를 사용한다.

```csharp
towerPopulation.AssignedPopulation
towerPopulation.Capacity
towerPopulation.AvailableCapacity
towerPopulation.StaffingRatio
towerPopulation.IsInitialized
```

## 4. 변경 API와 반환 의미

### 할당 생성

```csharp
bool created = populationManager.TryCreateAllocation(
    PopulationAssignmentType.Production,
    capacity,
    out PopulationAllocation allocation);
```

타입이 `None`이거나 수용량이 0 이하면 실패한다. 할당 생성만으로 전역
인구 값은 달라지지 않으므로 `PopulationChanged`는 발생하지 않는다.

### 인구 배치

```csharp
bool assigned = populationManager.TryAssign(allocation, amount);
```

다음 경우 실패한다.

- 이 Manager에 등록되지 않은 할당
- 요청량이 0 이하
- 개별 수용량 초과
- 전체 가용 인구 초과

성공한 경우에만 값이 바뀌고 이벤트가 한 번 발생한다.

### 인구 회수

```csharp
bool unassigned = populationManager.TryUnassign(allocation, amount);
```

요청량이 0 이하이거나 현재 배치량보다 많으면 실패한다.

### 전체 회수와 할당 제거

```csharp
populationManager.TryReleaseAll(allocation);
populationManager.TryRemoveAllocation(allocation);
```

`TryReleaseAll`은 할당을 계속 사용할 때 인구만 전부 가용 상태로 돌린다.
이미 0명이면 성공하지만 이벤트는 발생하지 않는다.

`TryRemoveAllocation`은 사용처의 생명주기가 끝날 때 사용한다. 배치 인구가
있으면 먼저 반환하고 할당 등록을 제거한다. 제거된 할당은 재사용할 수 없다.

### 최대 인구 증가

```csharp
populationManager.TryIncreaseMaxPopulation(rewardPopulation);
```

현재는 양수 증가만 지원한다. 점령 완료 보상을 유지비 계산 전에 적용할 때
사용한다. 기아에 의한 감소 API는 아직 없다.

## 5. 공통 생명주기 패턴

```text
사용처 생성
→ PopulationManager 참조 확보
→ AssignmentType과 Capacity로 할당 생성
→ 할당 참조 보관
→ TryAssign / TryUnassign
→ 계산 계층은 StaffingRatio 읽기
→ 사용처 종료 시 TryRemoveAllocation
→ 로컬 할당 참조 비우기
```

권장 어댑터의 책임은 다음과 같다.

- 중복 초기화 방지
- 자신의 할당 참조 보관
- Manager `Try` API 전달
- UI와 계산 계층에 읽기 전용 상태 제공
- 종료 시 할당을 한 번만 제거

`PopulationManager`에 농장·타워·점령의 구체적인 동작을 넣지 않는다.

## 6. 생산 시설 연결

농장·벌목장·광산은 각자 별도 할당을 만들고 타입은 모두 `Production`으로
지정한다.

### 필요한 데이터

생산 시설의 데이터 에셋에는 최소한 다음 값이 필요하다.

- `PopulationCapacity`
- `BaseProductionAmount`
- 생산 자원 종류

현재 배치 인구는 런타임 값이므로 ScriptableObject에 저장하지 않는다.

### 할당 생성

```csharp
bool created = populationManager.TryCreateAllocation(
    PopulationAssignmentType.Production,
    populationCapacity,
    out _populationAllocation);
```

생산 시설이 `GridMap`을 통해 건설·철거된다면
`OnBuildingAdded`와 `OnBuildingRemoving`을 구독하는 생산 전용
Coordinator를 둔다. 생산 처리 코드를 `GridMap` 안에 넣지 않는다.

### 생산량 계산

```csharp
float rawProduction =
    baseProductionAmount * allocation.StaffingRatio;
int productionAmount = Mathf.FloorToInt(rawProduction);
```

확정 규칙은 소수점 버림이다.

| 충원 상태 | 결과 |
|---|---|
| 0% | 생산량 0 |
| 50% | 기본 생산량의 절반 후 버림 |
| 100% | 기본 생산량 전체 |

생산 시설은 계산한 생산량을 정식 자원 관리자에게 지급 요청할 뿐 자원
보유량 자체를 소유하지 않는다.

### 철거

```csharp
populationManager.TryRemoveAllocation(_populationAllocation);
_populationAllocation = null;
```

사용처가 사라질 때 `TryReleaseAll`만 호출하면 빈 할당이 Manager에 남는다.
철거에서는 `TryRemoveAllocation`을 사용한다.

## 7. 점령 시스템 연결

점령 인구는 소비하지 않고 원정 기간 동안 예약한다.

### 원정 시작 전 검증

- 점령 가능한 청크인가
- 동일 대상에 진행 중인 원정이 없는가
- `AvailablePopulation >= RequiredPopulation`인가
- 필요한 식량·목재·석재·광물을 보유했는가

### 원정 시작

```text
모든 조건 사전 검증
→ Conquest 할당 생성
→ 필요 인구 전원 배치
→ 자원 소비
→ 원정 객체에 allocation 참조 저장
```

```csharp
bool created = populationManager.TryCreateAllocation(
    PopulationAssignmentType.Conquest,
    requiredPopulation,
    out PopulationAllocation allocation);

if (!created)
{
    return false;
}

if (!populationManager.TryAssign(allocation, requiredPopulation))
{
    populationManager.TryRemoveAllocation(allocation);
    return false;
}
```

자원 소비나 원정 생성이 이후에 실패하면
`TryRemoveAllocation(allocation)`으로 인구를 되돌린다. 장기적으로는 자원
소비와 인구 예약을 하나의 조정 계층에서 원자적으로 확정하는 것이 안전하다.

### 원정 진행

- 원정 객체가 자기 할당 참조를 유지한다.
- 해당 인구는 가용 인구에서 제외된다.
- 기아 시스템은 `Conquest` 분류의 할당 인구를 감소시키면 안 된다.

### 원정 완료

```text
원정 인구 반환 및 할당 제거
→ 청크 점령 상태 적용
→ 점령 인구 보상 증가
→ TerrainType별 적 강화 영구 누적
→ 그날 유지비 계산
```

```csharp
populationManager.TryRemoveAllocation(
    expedition.PopulationAllocation);
populationManager.TryIncreaseMaxPopulation(populationReward);
```

점령 보상은 완료된 날부터 유지비 대상이므로 유지비 계산보다 먼저 적용한다.

원정 취소와 자원 환급 규칙은 아직 미정이다. 취소·실패·런 종료의 모든
경로에서 할당이 한 번만 정리되도록 공통 종료 함수를 둔다.

## 8. 타워 연결

현재 타워 할당의 생성·제거는 이미 다음 흐름으로 연결되어 있다.

```text
GridMap.OnBuildingAdded
→ TowerPopulationCoordinator
→ TowerPopulation.Initialize

GridMap.OnBuildingRemoving
→ TowerPopulationCoordinator
→ TowerPopulation.Release
```

타워 UI 또는 전투 코드는 `TowerPopulation`을 가져와 읽는다.

```csharp
TowerPopulation towerPopulation =
    tower.GetComponent<TowerPopulation>();
float staffingRatio = towerPopulation.StaffingRatio;
```

전투 연결 규칙:

```text
StaffingRatio == 0
→ 공격 중지

StaffingRatio > 0
→ EffectiveAttackInterval =
   BaseAttackInterval / StaffingRatio
```

타워의 체력 비활성 상태와 인구 부족 상태를 하나의 bool로 덮어쓰지 않는다.
최종 공격 가능 여부는 물리 상태, 충원율, 공격 데이터 유효성을 조합한다.

타워가 체력 0으로 비활성화되어도 인구는 유지한다. 플레이어가 직접
회수하거나 철거할 때만 반환한다.

## 9. UI 연결

### 전체 인구 UI

전역 UI는 `PopulationChanged`를 구독하고 받은 `PopulationState`로
표시한다.

```csharp
private void OnEnable()
{
    _populationManager.PopulationChanged += RefreshPopulation;
    RefreshPopulation(_populationManager.CurrentState);
}

private void OnDisable()
{
    if (_populationManager != null)
    {
        _populationManager.PopulationChanged -= RefreshPopulation;
    }
}

private void RefreshPopulation(PopulationState state)
{
    // MaxPopulation, AssignedPopulation,
    // AvailablePopulation 표시
}
```

초기 화면은 이벤트 전에 보여야 하므로 구독 직후 `CurrentState`로 한 번
갱신한다.

### 개별 사용처 UI

- 타워: `TowerPopulation`의 읽기 프로퍼티
- 생산 시설: 생산용 어댑터의 읽기 프로퍼티
- 점령: 원정이 보관한 `PopulationAllocation`의 읽기 프로퍼티

현재 이벤트에는 어떤 할당이 변했는지 포함되지 않는다. 개별 UI는 이벤트가
오면 현재 선택 대상의 값을 다시 읽는 방식으로 시작한다. 목록 규모나 변경
원인 표시가 필요하면 이벤트 데이터 확장을 별도 이슈로 진행한다.

### 정식 UI 주의사항

`TowerPopulationDebugGUI`는 Canvas 없이 검증하기 위한 테스트 도구다.
정식 UI에서는 다음을 지킨다.

- 기존 Canvas와 UI 구조 사용
- 사용자 표시 문자열은 스트링테이블 key 사용
- 버튼 활성 조건과 실제 `Try` 결과를 모두 처리
- 실패할 수 있는 호출 전에 화면 값을 임의 변경하지 않음
- 비활성화 또는 파괴 시 이벤트 구독 해제

## 10. 자원·유지비·기아 연결

### 자원

- 인구를 `ResourceCost`의 일반 소비 항목으로 처리하지 않는다.
- 자원 관리자는 식량·목재·석재·광물의 획득과 소비를 담당한다.
- 인구 Manager는 전체 인구와 배치 상태만 담당한다.
- 두 시스템을 함께 바꾸는 기능은 조정자가 사전 검증과 실패 복구를 담당한다.

### 유지비

식량 유지비는 배치 여부와 무관하게 `MaxPopulation` 전체를 기준으로 한다.

```text
DailyFoodUpkeep = MaxPopulation
```

### 기아

현재 Manager에는 최대 인구 감소 API가 없으므로 다른 코드에서
`_maxPopulation`을 직접 수정하면 안 된다. 먼저 불변식을 지키는 감소 정책
API를 Manager 내부에 추가해야 한다.

확정된 감소 우선순위:

```text
가용 인구
→ 타워 배치 인구
→ 생산 배치 인구
→ 중단
```

`Conquest` 할당 인구는 보호한다. 감소 후에도
`AssignedPopulation <= MaxPopulation`을 유지해야 한다.

## 11. 건물 생명주기 이벤트

`GridMap`은 범용 시점만 제공한다.

```csharp
_gridMap.OnBuildingAdded += HandleBuildingAdded;
_gridMap.OnBuildingRemoving += HandleBuildingRemoving;
```

구독과 해제는 대칭으로 작성한다.

```csharp
private void OnEnable()
{
    _gridMap.OnBuildingAdded += HandleBuildingAdded;
    _gridMap.OnBuildingRemoving += HandleBuildingRemoving;
}

private void OnDisable()
{
    if (_gridMap == null)
    {
        return;
    }

    _gridMap.OnBuildingAdded -= HandleBuildingAdded;
    _gridMap.OnBuildingRemoving -= HandleBuildingRemoving;
}
```

주의사항:

- `OnBuildingAdded`는 정상 등록 후 발생한다.
- `OnBuildingRemoving`은 실제 제거와 `Destroy` 전에 발생한다.
- 건물 이동은 같은 인스턴스를 유지하므로 두 이벤트가 발생하지 않는다.
- `GridMap.RemoveBuilding`을 우회한 직접 `Destroy`는 현재 잡히지 않는다.
- Coordinator 구독 전에 이미 등록된 건물은 별도 초기화가 필요할 수 있다.

## 12. 자주 발생하는 실수

### 같은 사용처에서 할당을 여러 번 생성

초기화 플래그 또는 할당 null 검사를 둔다. 현재 `TowerPopulation`은
`IsInitialized`로 중복 생성을 막는다.

### 철거 시 전체 회수만 호출

인구는 돌아오지만 빈 할당이 남는다. 사용처가 사라지면
`TryRemoveAllocation`을 사용한다.

### `TryAssign` 결과를 확인하지 않음

수용량 또는 가용 인구 부족으로 실패할 수 있다. 성공했다고 가정하고 UI나
효과를 먼저 변경하지 않는다.

### 건물 종류마다 enum 추가

농장·벌목장·광산은 정책상 모두 `Production`이다. 구체적 종류는 건물
데이터가 담당한다.

### ScriptableObject에 현재 배치량 저장

SO는 여러 인스턴스가 공유한다. SO에는 수용량 같은 정적 데이터만 두고
현재 배치량은 런타임 어댑터와 할당에 둔다.

### 이벤트 구독 해제를 누락

씬 전환이나 재활성화 뒤 중복 호출될 수 있다. 구독과 해제는 항상 대칭으로
둔다.

### Manager 밖에서 인구 감소

전체 합과 할당 수치가 어긋난다. 기아 API 추가 전에는 직접 처리하지 않는다.
