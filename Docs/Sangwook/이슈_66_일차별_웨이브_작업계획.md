## 1. 이슈 요구사항

이슈 #66의 요구사항은 다음과 같다.

- 각 일차별 웨이브 정보를 ScriptableObject로 저장한다.
- 현재 일차에 지정된 웨이브 정보대로 적을 생성한다.
- SO의 기본 수량 외에 점령 등의 외부 요인으로 스폰 수량을 조절할 수 있어야 한다.

완료 기준:

- 각 일차별로 지정된 수의 적이 생성된다.
- 외부 요인을 적용하면 실제 생성 수가 달라진다.

## 2. 현재 구현 기준선

이미 구현된 부분:

- `WaveDefinitionSO`: 한 번의 밤에 실행할 포탈별 편성을 저장한다.
- `PortalWaveData`: 포탈 방향, 시작 지연과 생성 그룹 목록을 저장한다.
- `SpawnGroupData`: 적 프리팹, 적 데이터, 기본 생성 수, 간격과 지연을 저장한다.
- `WaveManager`: 전달받은 웨이브 SO에 따라 활성 포탈에서 적을 생성하고 전멸을 감시한다.
- `CycleManager.OnNightStart`: 현재 일차를 `int` 인자로 전달한다.
- `ConquestManager.AccumulatedEnemyScaling`: 누적된 점령 적 강화 값을 제공한다.
- `EnemyScalingModifier.SpawnCountBonus`: 외부 스폰 수 가산값을 표현한다.

현재 부족한 부분:

- `WaveTestStarter`가 매일 같은 `WaveDefinitionSO` 하나만 실행한다.
- 현재 일차에 맞는 웨이브 SO를 선택하는 일정 데이터와 해석 계층이 없다.
- `SpawnCountBonus`가 실제 웨이브 생성 수 계산에 연결되지 않았다.
- 점령 보너스를 어느 포탈과 생성 그룹에 배분할지 실행 정책이 없다.
- 일차 선택 및 외부 보정에 대한 자동 테스트가 없다.

현재 테스트 데이터는 `Assets/Data/WaveData/WaveDefinition_Test.asset` 하나다.

## 3. 작업 목표와 범위

### 이번 이슈에 포함

1. 일차별 웨이브 일정 데이터 추가
2. 밤 시작 시 현재 일차의 `WaveDefinitionSO` 선택
3. 외부 스폰 수 보정값을 런타임 웨이브 계산에 적용
4. 기본 SO를 변경하지 않는 실행 구조
5. 데이터 검증, 자동 테스트와 수동 플레이 검증
6. 최소 2일차 이상의 테스트용 웨이브 데이터 및 씬 참조 연결

### 이번 이슈에서 제외

- 공격력, 체력, 이동 속도와 방어막 보정
- 보스 종류와 주기별 보스 일정 확정
- 실제 밸런스 수치 확정
- 저장 및 불러오기
- 오브젝트 풀링 전환
- 점령/웨이브 공식의 기획 확정

`EnemyScalingModifier.AttackPowerBonus`는 이미 존재하지만 이슈 #66의 완료
기준에는 없으므로 별도 후속 작업으로 둔다.

## 4. 권장 구조

```text
CycleManager.OnNightStart(currentDay)
  -> DailyWaveController
       -> WaveScheduleSO에서 현재 일차의 WaveDefinitionSO 조회
       -> 외부 스폰 보정값 스냅숏 조회
       -> WaveResolver가 런타임 실행 계획 계산
       -> WaveManager가 실행 계획대로 생성
```

책임 분리:

| 구성 요소 | 책임 |
|---|---|
| `WaveScheduleSO` | 일차와 `WaveDefinitionSO`의 명시적 연결 및 데이터 검증 |
| `DailyWaveController` | 밤 시작 이벤트 구독, 현재 일차 조회, 실행 요청 조율 |
| `WaveResolver` | 기본 생성 수와 외부 보정값을 결합하여 런타임 수량 계산 |
| `WaveManager` | 계산된 계획에 따른 생성, 생존 적 추적과 전멸 판정 |
| `ConquestManager` | 점령 강화 상태의 원본 제공; 웨이브 실행 책임 없음 |

`WaveManager`가 일차 선택이나 점령 상태 누적을 직접 담당하지 않게 한다.
기본 SO를 런타임에 수정하지 말고, 해석 결과를 별도 값 또는 런타임 계획으로
전달해야 다음 날 데이터가 오염되지 않는다.

## 5. 데이터 설계

### 5.1 일차별 일정

배열 인덱스를 곧바로 일차로 해석하기보다 명시적인 엔트리를 권장한다.

```text
WaveScheduleSO
  Entries
    - Day: 1
      WaveDefinition: Day01
    - Day: 2
      WaveDefinition: Day02
```

필수 검증:

- 일차는 1 이상이어야 한다.
- 같은 일차가 중복되면 안 된다.
- `WaveDefinitionSO` 참조가 비어 있으면 안 된다.
- 요청한 일차가 없으면 오류를 기록하고 웨이브를 시작하지 않는다.

주기당 일수와 보스 일정은 `[미정]`이므로 코드 공식으로 만들지 않고 데이터로
교체할 수 있어야 한다.

### 5.2 외부 보정

밤이 시작될 때 보정값을 한 번 스냅숏으로 가져온다. 웨이브 실행 중 외부
상태가 변해도 이미 시작한 밤의 생성 수는 바뀌지 않게 한다.

최종 생성 수는 0 미만이 될 수 없으며, 계산 중 SO의 `SpawnCount`를 직접
변경하지 않는다.

## 6. 스폰 보너스 정책

`SpawnCountBonus +N`을 모든 활성 포탈의 모든 생성 그룹에 각각 더하면
포탈 수와 그룹 수만큼 증가량이 증폭된다. 따라서 `+N`을 웨이브 전체의 총
추가 생성 수로 취급하는 것을 기본 권장안으로 둔다.

```text
FinalWaveTotal = BaseWaveTotal + TotalSpawnCountBonus
```

하지만 다음 세부 배분 정책은 기획서의 웨이브 공식과 함께 아직 `[미정]`이다.

- 어느 활성 포탈에 추가 수량을 배분하는가
- 여러 생성 그룹 중 어느 적 종류에 배분하는가
- 바이옴별 보너스를 같은 `TerrainType`의 포탈에만 적용하는가
- 나머지가 생길 때의 분배 순서와 우선순위

구현 시 권장 대응:

- 배분 정책을 `WaveResolver` 내부의 독립된 결정 로직으로 격리한다.
- 결과가 항상 재현 가능하도록 포탈/그룹 순서를 명시적으로 사용한다.
- 정책 확정 전에는 테스트용 단순 분배임을 표시하고 확정 밸런스로 간주하지 않는다.
- `Docs/Sangwook/인구_자원_점령_웨이브_통합_설계.md`의 바이옴별 영구 강화
  설계와 충돌하지 않도록 확장 가능한 입력 형태를 유지한다.

## 7. 구현 순서

### 1단계 — 일정 데이터

- `WaveScheduleSO`와 일차별 엔트리 타입 추가
- 현재 일차 조회 API 추가
- 중복, 누락과 잘못된 일차 검증 추가

### 2단계 — 밤 시작 연결

- `WaveTestStarter`를 테스트 전용으로 유지하거나 `DailyWaveController`로 교체
- `OnNightStart(int currentDay)`의 인자를 실제로 사용
- 해당 일차 데이터가 없을 때 안전하게 중단

### 3단계 — 런타임 해석

- 기본 웨이브와 외부 보정값을 결합하는 `WaveResolver` 추가
- SO를 복제·수정하지 않는 런타임 실행 데이터 정의
- 최종 생성 수 경계 검증

### 4단계 — 점령 연결

- 밤 시작 시 `ConquestManager`의 누적 스폰 보정값을 스냅숏으로 전달
- 외부 요인이 없으면 기본 SO 수량과 완전히 동일하게 실행
- 외부 요인이 있으면 합의된 총량만큼 실제 생성 수가 변경되는지 검증

### 5단계 — 데이터와 씬

- 최소 1일차와 2일차용 서로 다른 테스트 SO 생성
- 일정 SO에 일차별 참조 등록
- 테스트 씬의 `CycleManager`, 컨트롤러, `WaveManager`, `ConquestManager` 참조 연결
- 기존 `WaveManager.AllMonstersDefeated -> CycleManager.EndNight()` 연결 유지 확인

### 6단계 — 검증

- 자동 테스트 실행
- Unity 컴파일 오류 0 확인
- 플레이 모드에서 2일 이상의 낮/밤 전환 확인
- 프리팹과 씬의 누락 참조 확인
- `git diff --check` 확인

## 8. 테스트 체크리스트

### 일정 선택

- 1일차에는 1일차 SO가 선택된다.
- 2일차에는 2일차 SO가 선택된다.
- 두 일차의 편성과 기본 생성 수가 실제 결과에 반영된다.
- 중복 일차와 빈 SO 참조가 검증에서 발견된다.
- 등록되지 않은 일차에는 웨이브가 시작되지 않는다.

### 외부 보정

- 보너스가 0이면 기본 SO의 총 생성 수와 같다.
- 보너스가 양수이면 약속한 총량만큼 증가한다.
- 최종 생성 수는 음수가 되지 않는다.
- 같은 보정값과 데이터로 항상 같은 분배 결과가 나온다.
- 웨이브 도중 점령 값이 변해도 진행 중인 웨이브 수량은 변하지 않는다.
- 실행 후 `WaveDefinitionSO`와 `SpawnGroupData`의 직렬화 값이 바뀌지 않는다.

### 기존 기능 회귀

- 비활성 포탈에서는 적이 생성되지 않는다.
- 여러 활성 포탈의 생성이 정상 실행된다.
- 중복 웨이브 시작이 차단된다.
- 모든 적 전멸 전에는 밤이 끝나지 않는다.
- 마지막 적 전멸 후 다음 낮으로 전환된다.
- 플레이 모드 종료 또는 취소 시 예외가 발생하지 않는다.

## 10. 완료 정의

다음 조건을 모두 만족하면 이슈 #66 구현 완료로 판단한다.

- 현재 일차에 등록된 `WaveDefinitionSO`가 자동 선택된다.
- SO에 지정한 기본 수량의 적이 정확히 생성된다.
- 점령 등 외부 스폰 보정값이 실제 생성 수에 반영된다.
- 기본 SO 데이터가 런타임에 변경되지 않는다.
- 잘못된 일정 데이터와 누락된 일차를 안전하게 처리한다.
- 관련 자동 테스트와 플레이 모드 검증을 통과한다.
- Unity 컴파일 오류가 0이다.
- 씬과 프리팹에 누락된 필수 참조가 없다.
