- 작성일: 2026-08-03
- 대상 이슈: [GitHub #135 - 속성형 타워 추가](https://github.com/JoKangHyeon/TowerAndDragon/issues/135)
- 작업 브랜치: `feature/135-elemental-towers`
- 기준 커밋: `6eb4c2a` (`시간 타워 오라 (버프) 적용 및 테스트 완료`)
- 검증 씬: `Assets/Scenes/Sangwook_TowersAndEnemies.unity`
- 현재 상태: **얼음·화염·암석·시간 타워의 핵심 런타임 동작과 테스트 씬 건설 연결을 완료했다. 시간 타워의 건설 미리보기 및 설치 후 버프 범위 표시는 아직 구현되지 않았다.**

상세 게임 기획은 `Docs/기획종합_v2.md`를 우선한다. 이 문서는 이슈 #135에서 실제로 구현된 코드·데이터·씬 연결과 검증 결과를 기록하며, `[미정]`인 건설 비용과 최종 밸런스를 확정하지 않는다.

## 1. 결론 요약

현재 속성 타워는 기존 타워 전투 파이프라인을 재사용하고, 속성별 차이는 ScriptableObject 조합으로 구성한다.

- 얼음 타워: 투사체 명중 피해와 이동속도 감소
- 화염 타워: 투사체 명중 피해와 지속 화상 피해
- 암석 타워: 느린 공격 속도의 높은 광역 피해
- 시간 타워: 직접 공격하지 않고 주변 타워의 공격 속도와 재활성화 속도를 증가
- 생명 타워: 아직 구현하지 않음

시간 타워를 위해 공용 `TowerAuraDataSO`와 `TowerAuraSystem`을 추가했다. 같은 계약을 `BabyDragonData`에도 선택적으로 연결할 수 있도록 기반을 마련했지만, 현재 새끼용 데이터 에셋에는 신규 `TowerAuraDataSO`가 연결되어 있지 않다.

## 3. 데이터 기반 구성

### 3.1 공통 데이터 타입

`ElementalTowerData`는 기존 `TowerData`를 상속하며 다음 속성 정보를 추가한다.

- `DragonType`: Ice, Fire, Time, Stone, Life 구분
- `TowerAura`: 선택적 `TowerAuraDataSO` 참조
- `HasTowerAura`: 유효한 반경을 가진 오라가 연결됐는지 확인

공격형 속성 타워는 기존 공격 조합을 그대로 사용한다.

```text
ElementalTowerData
  → AttackSO
    → DamageEffectSO
    → StatusAttackEffectSO
      → StatusEffectSO
  → Projectile
    → 명중 시 AttackSO.Execute
```

시간 타워는 `AttackSO`와 투사체를 연결하지 않고 오라 데이터만 사용한다.

```text
ElementalTowerData 또는 BabyDragonData
  → TowerAuraDataSO
    → TowerAuraSystem
      → 범위 내 타워의 TowerAttack
      → 범위 내 타워의 재활성화 진행도
```

### 3.2 얼음 타워

| 에셋 | 역할 | 현재 값 |
| --- | --- | --- |
| `TD_IceTower` | 타워 본체 데이터 | Ice, 사거리 공격 및 얼음 투사체 연결 |
| `TA_IceTower` | 공격 정의 | 사거리 4, 간격 1초 |
| `TAE_IceDamage` | 즉발 피해 | 피해 10 |
| `TAE_IceSlow` | 상태 부여 | `TS_IceSlow` 연결 |
| `TS_IceSlow` | 이동속도 상태 | `tower_ice_slow`, 2초, 속도 0.8배 |
| `Projectile_Ice` | 공격 투사체 | 속도 10으로 발사 |
| `TP_IceTower` | 건설 프리팹 | `TD_IceTower`, `TowerPopulation` 연결 |

같은 `StatusId`의 둔화가 다시 적용되면 지속시간이 갱신된다. 서로 다른 이동속도 상태가 겹치면 `MonsterStatusReceiver`가 가장 강한 둔화 하나를 선택하므로 곱연산으로 과도하게 느려지지 않는다.

### 3.3 화염 타워

| 에셋 | 역할 | 현재 값 |
| --- | --- | --- |
| `TD_FireTower` | 타워 본체 데이터 | Fire, 화염 공격 및 투사체 연결 |
| `TA_FireTower` | 공격 정의 | 사거리 4, 간격 1초 |
| `TAE_FireDamage` | 즉발 피해 | 피해 10 |
| `TAE_FireBurn` | 상태 부여 | `TS_FireBurn` 연결 |
| `TS_FireBurn` | 지속 피해 상태 | `tower_fire_burn`, 3초, 1초마다 피해 1 |
| `Projectile_Fire` | 공격 투사체 | 속도 10으로 발사 |
| `TP_FireTower` | 건설 프리팹 | `TD_FireTower`, `TowerPopulation` 연결 |

화상 상태에서 다시 공격받아도 즉발 피해는 매번 들어간다. 같은 `StatusId`의 화상은 별도 스택으로 늘어나지 않고 남은 지속시간만 갱신하며, 진행 중인 틱 타이머는 유지한다. 다른 `StatusId`의 지속 피해는 병렬로 적용할 수 있다.

### 3.4 암석 타워

| 에셋 | 역할 | 현재 값 |
| --- | --- | --- |
| `TD_StoneTower` | 타워 본체 데이터 | Stone, 암석 공격 및 투사체 연결 |
| `TA_StoneTower` | 공격 정의 | 사거리 6, 간격 2.5초, 광역 반경 2 |
| `TAE_StoneDamage` | 광역 피해 | 피해 24 |
| `Projectile_Stone` | 공격 투사체 | 속도 5로 발사 |
| `TP_StoneTower` | 건설 프리팹 | `TD_StoneTower`, `TowerPopulation` 연결 |

`AttackSO`에 선택적 `AreaRadius`를 추가해 광역 공격을 공용화했다. 광역 공격은 최초 명중 대상을 중심으로 후보를 수집한 뒤 아이소메트릭 비율을 반영한 타원 판정으로 실제 대상을 선별한다. `AttackContext.TargetLayers`를 사용하므로 공격자의 대상 레이어 범위를 벗어난 오브젝트에는 적용하지 않는다.

현재 암석 속성 타워에는 순간 경직을 넣지 않았다. 이슈에서 정한 속성 타워 역할인 높은 광역 피해와 느린 공격 속도만 구현했다.

### 3.5 시간 타워

| 에셋 | 역할 | 현재 값 |
| --- | --- | --- |
| `TD_TimeTower` | 타워 본체 데이터 | Time, 공격·투사체 없음, 오라 연결 |
| `TAD_TimeTowerAura` | 오라 정의 | 기본 반경 2, 공격 속도 2배, 재활성화 속도 2배 |
| `TP_TimeTower` | 건설 프리팹 | `TD_TimeTower`, `TowerPopulation` 연결 |

시간 타워는 순수 버프형이므로 `AttackSO`, 투사체와 투사체 속도를 비워 두었다. `Tower`의 필수 구성 때문에 프리팹에는 `TowerAttack` 컴포넌트가 남아 있지만, `TowerData.CanAttack`이 false이므로 타깃 탐색과 공격을 실행하지 않는다.

#### 충원율 기반 범위

시간 타워는 버프 배율을 낮추지 않고 유효 범위만 충원율에 따라 조정한다.

```text
실제 오라 반경 = TowerAuraDataSO.Radius × StaffingRatio
```

정원 7명, 기본 반경 2 기준 예시는 다음과 같다.

| 배치 인구 | 충원율 | 실제 반경 | 버프 강도 |
| ---: | ---: | ---: | --- |
| 0 | 0% | 오라 비활성 | 없음 |
| 1 | 약 14.3% | 약 0.29 | 범위 안에서는 2배 |
| 4 | 약 57.1% | 약 1.14 | 범위 안에서는 2배 |
| 7 | 100% | 2 | 범위 안에서는 2배 |

`TowerAuraDataSO.ScaleRadiusWithStaffing` 옵션이 켜진 오라에만 이 규칙을 적용한다. 현재 `TAD_TimeTowerAura`만 옵션이 켜져 있어 새끼용과 향후 다른 오라의 범위에는 자동으로 영향을 주지 않는다.

#### 가동 및 비활성화 규칙

시간 타워의 오라는 다음 조건을 모두 만족할 때만 활성화된다.

- 타워가 재활성화 대기 상태가 아님
- 마비 상태가 아님
- `TowerAuraDataSO`가 연결되어 있고 기본 반경이 0보다 큼
- `ITowerStaffing`이 존재하고 최소 1명 이상 배치되어 `CanOperate`가 true

시간 타워가 체력 0으로 비활성화되면 오라는 즉시 조회 대상에서 제외된다. 재활성화되고 인구가 남아 있으면 별도의 재등록 없이 다시 버프를 제공한다. 오라 제공자는 자신에게 버프를 주지 않지만, 다른 시간 타워의 오라는 받을 수 있다.

#### 공격 속도 버프

범위 안 공격 타워의 실제 공격 간격은 기존 충원율과 연구·용 배율에 오라 배율을 추가해 계산한다.

```text
실제 공격 간격
= AttackSO.Interval
  ÷ 대상 타워 StaffingRatio
  ÷ 연구·용 공격속도 배율
  ÷ 오라 공격속도 배율
```

공격 간격은 공격 직후 다음 공격 시각을 예약하는 구조다. 시간 타워가 비활성화되더라도 이미 계산된 현재 쿨다운 한 번은 짧아진 상태로 남을 수 있으며, 다음 공격부터 기본 속도로 돌아간다.

#### 재활성화 속도 버프

기존의 단일 `UniTask.Delay` 대기 대신 재활성화 진행도를 매 프레임 누적하도록 변경했다.

```text
프레임 진행량
= Time.deltaTime
   × 현재 오라 ReviveSpeedMultiplier
   ÷ 기본 ReviveDelay
```

시간 타워가 가동되는 동안에는 게이지가 빠르게 진행되고, 시간 타워가 비활성화되면 기존 진행도는 유지한 채 기본 속도로 전환한다. 시간 타워가 다시 가동되면 남은 구간부터 다시 가속한다. `IReviveProgress`가 같은 누적 진행도를 사용하므로 체력바의 재활성화 게이지와 실제 완료 시점이 일치한다.

## 4. 공용 오라 시스템

### 4.1 구성 요소

| 구성 요소 | 역할 | 상태 |
| --- | --- | --- |
| `ITowerAuraDataProvider` | 타워 데이터가 선택적으로 오라를 제공하는 공통 계약 | 구현 |
| `TowerAuraDataSO` | 반경과 공격·회복·방어 배율 데이터 | 구현 |
| `TowerAuraModifiers` | 여러 오라 중 속성별 가장 강한 값을 조합 | 구현 |
| `TowerAuraSystem` | `GridMap.Buildings`를 순회해 활성 오라와 타원 범위 판정 | 구현 |
| `TowerStatMultiplierCoordinator` | 신규·선배치 타워에 오라 시스템을 주입하고 제거 시 해제 | 구현 |

여러 오라가 겹치면 배율을 곱하거나 더하지 않고 각 항목의 가장 강한 값만 선택한다. 시간 타워 2개가 겹쳐도 공격 속도 4배가 되지 않고 2배를 유지한다.

`TowerAuraDataSO`에는 다음 값이 있다.

- `Radius`
- `ScaleRadiusWithStaffing`
- `DamageMultiplier`
- `AttackSpeedMultiplier`
- `ReviveSpeedMultiplier`
- `MaxHealthMultiplier`
- `ShieldAmount`

현재 런타임에 실제 연결된 값은 피해 배율, 공격 속도 배율, 재활성화 속도 배율이다. 최대 체력 배율과 보호막은 데이터 및 조합 구조만 있고 `Tower`와 `Health`에 적용하는 런타임 소비자가 아직 없다.

### 4.2 새끼용 공유 기반

`BabyDragonData`도 `ITowerAuraDataProvider`를 구현한다. `BabyDragonTower`는 기존 `BuffRadius`가 있거나 신규 `TowerAuraDataSO`가 있으면 버프 모드를 사용할 수 있다.

신규 오라가 실제로 적용되려면 다음 조건을 만족해야 한다.

- 새끼용이 먹이를 먹어 `CanOperate` 상태임
- 현재 모드가 `BabyDragonMode.Buff`임
- `BabyDragonData.TowerAura`에 유효한 에셋이 연결됨

현재 `BD_Ice`, `BD_Fire`, `BD_Time`, `BD_Stone`, `BD_Life` 에셋에는 신규 `TowerAura` 참조가 연결되어 있지 않다. 따라서 공통화 코드 기반만 준비된 상태이며, 기존 `Area Buff`의 생산량 버프 시스템은 별도 경로로 유지된다.

## 5. 씬과 BuildMode UI 연결

### 5.1 테스트 씬

`Assets/Scenes/Sangwook_TowersAndEnemies.unity`에 다음을 연결했다.

- `Systems/Composites`에 `TowerAuraSystem` 추가
- `TowerAuraSystem.GridMap` → 씬의 `GridMap`
- `TowerStatMultiplierCoordinator.TowerAuraSystem` → 같은 오브젝트의 `TowerAuraSystem`
- BuildMode 첫 번째 타워 탭의 배열 크기 7
- 배열 3~6번에 `TP_IceTower`, `TP_FireTower`, `TP_StoneTower`, `TP_TimeTower` 연결

`TowerAuraSystem`은 씬에 하나만 존재하며 개별 타워 프리팹에 추가하지 않는다. 현재 오라 시스템과 네 속성 타워 BuildMode 등록은 `Sangwook_TowersAndEnemies` 씬에만 존재한다.

### 5.2 프리팹 공통 구성

네 속성 타워 프리팹은 기존 타워 구조를 사용한다.

- `Tower`
- `Health`
- `TowerAttack`
- `TowerPopulation`
- 속성별 `ElementalTowerData`
- 공격형 타워의 경우 속성별 투사체와 `AttackSO`

시간 타워도 `Tower`의 `[RequireComponent(typeof(TowerAttack))]` 계약 때문에 `TowerAttack`을 보유하지만 공격 데이터가 없어 실제 공격은 비활성화된다.

## 7. 알려진 문제와 남은 작업

### 7.1 시간 타워 버프 범위 표시

현재 시간 타워는 실제 버프 범위를 정상적으로 판정하지만 UI에 원이 나타나지 않는다.

원인은 두 표시 경로가 시간 타워의 공용 오라 데이터를 처리하지 않기 때문이다.

- `MouseSelectController.DrawAttackRangeIndicator`: `TowerData.CanAttack`이 false이면 숨김
- `MouseSelectController.DrawBuffRangeIndicator`: `BabyDragonTower.BuffRadius`만 처리
- `BuildingPlacementController.ShowAttackRangeIndicatorFor`: `TowerData.CanAttack`이 false이면 숨김
- `BuildingPlacementController.ShowBuffRangeIndicatorFor`: `BabyDragonTower.BuffRadius`만 처리

빈 `AttackSO`를 연결해 공격 사거리로 위장하지 않는다. 후속 수정에서는 `ITowerAuraDataProvider`를 처리하도록 버프 범위 표시를 확장한다.

권장 표시 규칙은 다음과 같다.

- 신규 건설 미리보기: 100% 충원 기준 최대 오라 반경
- 설치 후 선택: 현재 `StaffingRatio`가 적용된 실제 반경
- 설치된 시간 타워 이동 미리보기: 현재 충원율 기준 실제 반경
- 실제 판정과 UI가 별도 공식을 갖지 않도록 공용 유효 반경 계산 함수 사용

### 7.2 씬 확장

현재 테스트 씬 한 곳만 연결되어 있다. 실제 게임 씬에 적용할 때는 다음 두 항목을 함께 반영해야 한다.

1. `Systems/Composites`의 `TowerAuraSystem` 및 코디네이터 참조
2. 해당 씬 BuildMode UI의 타워 탭에 네 속성 타워 프리팹 등록

공용 `BuildMode_window.prefab` 자체에는 속성 타워가 등록되어 있지 않고 테스트 씬의 프리팹 오버라이드로만 추가되어 있다. 실제 적용 범위를 팀에서 확정한 뒤 프리팹 또는 대상 씬에 반영한다.

### 7.3 기능 후속 범위

- 생명 속성 타워 구현
- 새끼용 속성별 `TowerAuraDataSO` 생성 및 데이터 연결
- 오라의 최대 체력 배율과 보호막 런타임 적용
- 시간 타워 공격 쿨다운 도중 오라가 사라질 때 남은 쿨다운을 즉시 재계산할지 결정
- 속성 타워 전용 자동화 테스트 추가
- 최종 건설 비용과 속성별 특화 자원 확정
- 스트링테이블 이름 key 및 최종 UI 문구 정리
- 실제 게임 씬과 공용 BuildMode 프리팹 반영 범위 확정
