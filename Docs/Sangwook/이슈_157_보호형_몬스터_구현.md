# 이슈 #157 — 보호형 몬스터 구현

작성일: 2026-08-04
대상: 이슈 #157(보호형 몬스터 추가 부분)
상태: 코드 구현 완료(컴파일 에러 0) — 후속 검토 필요 항목 있음(6절 참고)

## 1. 요구사항

- 회복형 힐러 몬스터처럼 자신의 범위 내 몬스터들에게 보호막을 부여
- 보호형의 범위 내에 들어온 몬스터는 보호막을 가짐. 범위 밖으로 벗어나면 보호막이 사라짐
- 한 번 보호막이 붙었던 몬스터는 다시 보호막이 생기지 않음

`특수형몬스터_계획.md`에서 뼈대(`ISpecialBehavior`/`SpecialBehaviorSO`/`SpecialBehaviorRunner`)와 치유형(`HealAuraBehaviorSO`), 자폭형(`SelfDestructBehaviorSO`)까지는 이미 구현돼 있었고, 이번 작업은 그 진행 순서의 4번째 항목(보호형)에 해당합니다.

## 2. 설계 방향

치유형과 같은 "오라(지속)" 버킷으로 분류하고(계획 문서 5절), 상속이 아닌 조합 원칙을 그대로 따라 `MonsterData.SpecialBehaviors` 슬롯에 새 SO만 추가하는 방식으로 구현했습니다. 프리팹 구조 변경은 없었습니다 — 기존 몬스터 프리팹(`MP_Ground_Basic` 등)에 이미 `MonsterShield` 컴포넌트가 비활성 상태(`_maxShield = 0`)로 붙어 있어서, 계획 문서 9절의 "미정" 항목("방어막 없는 대상에게 어떻게 부여할지")이 실제로는 이미 해결돼 있었습니다.

### 2.1 `MonsterShield.Clear()` 추가

기존 `MonsterShield`는 `Initialize`(부여)와 `Absorb`(피해 흡수)만 있고, 부여받은 방어막을 되돌리는 기능이 없었습니다. 범위 이탈 시 회수를 위해 추가했습니다.

```csharp
public void Clear()
{
    _maxShield = 0f;
    _currentShield = 0f;
    ShieldChanged?.Invoke(_currentShield, _maxShield);
}
```

`ShieldBroken`은 발화하지 않습니다 — 피해로 깨진 게 아니라 회수된 것이기 때문입니다. 체력바(`UI_WorldHealthBar`)는 `IShieldInfo`를 매 프레임 폴링하므로 별도 이벤트 배선 없이 즉시 반영됩니다.

### 2.2 `BaseMonster`에 부여/회수 캡슐화 메서드 추가

특수 행동이 `_shield` 필드에 직접 접근하지 않도록, 기존 `Heal(float)`과 같은 패턴으로 추가했습니다.

```csharp
public bool GrantShield(float amount)
{
    if (IsDead || _shield == null || _shield.HasShield)
    {
        return false;
    }

    _shield.Initialize(amount);
    return true;
}

public void RevokeGrantedShield()
{
    _shield?.Clear();
}
```

`GrantShield`가 `bool`을 반환하는 이유: 이미 자체 방어막을 가진 몬스터(`MP_Ground_Tank` 등)에게는 덮어쓰지 않고 스킵하는데, 호출부(보호형 오라)가 "이번에 내가 실제로 부여했는지"를 알아야 이후 회수 대상 추적(`_currentlyProtected`)이 꼬이지 않습니다.

### 2.3 `AuraTargetScanner` 공용 유틸 도입

치유형과 보호형 모두 "주기적으로 범위 내 아군 몬스터 탐색"이라는 동일한 메커니즘을 쓰고 있어(계획 문서 5절에서도 같은 버킷으로 분류), `OverlapCircleAll` + 후보 필터링(자기 자신/사망 제외) 부분만 정적 유틸로 분리했습니다. 타이머·효과 로직까지 상속 계층으로 묶지는 않았습니다 — 현재 오라형 인스턴스가 2개뿐이라 과설계를 피하고, 이미 배포된 `HealAuraBehavior.asset`의 직렬화 값이 깨질 위험도 줄이기 위함입니다.

```csharp
public static class AuraTargetScanner
{
    public static void FindNearbyMonsters(
        BaseMonster owner, float radius, LayerMask targetLayers, HashSet<BaseMonster> results)
    { ... }
}
```

`HealAuraBehaviorSO.HealNearbyMonsters`도 이 유틸을 쓰도록 리팩터링했습니다(필드 이름/구조는 변경 없어 기존 애셋 값에 영향 없음).

### 2.4 `ProtectionAuraBehaviorSO`

`Assets/Scripts/Combat/Effects/ProtectionAuraBehaviorSO.cs` — Heal Aura와 같은 위치 컨벤션(SO는 설정, private 중첩 클래스가 `ISpecialBehavior` 구현).

런타임 상태는 두 집합으로 분리해 추적합니다.

- `_grantedOnce`: 한 번이라도 부여를 "시도"한 대상. 인스턴스 생존 동안 평생 유지 → 재부여 금지의 핵심.
- `_currentlyProtected`: 지금 이 오라가 실제로 방어막을 걸어준 대상만. 범위 이탈 감지 및 회수 대상 판정용.

매 스캔(`_scanInterval`초 간격) 흐름:

1. `AuraTargetScanner`로 범위 내 대상 스캔 → `_scanBuffer`
2. `_scanBuffer` 중 `_grantedOnce`에 없는 대상만 `GrantShield` 시도 → 성공 시에만 `_currentlyProtected`에 추가(자체 방어막 보유자는 스킵, 단 `_grantedOnce`에는 추가해 재검사하지 않음)
3. `_currentlyProtected` 중 이번 `_scanBuffer`에 없거나 사망한 대상 → `RevokeGrantedShield` 호출 후 `_currentlyProtected`에서만 제거(`_grantedOnce`는 유지)

보호형 자신이 죽는 경우 `Dispose()`에서 이미 부여한 방어막을 회수하지 않고 그대로 둡니다(의도적 선택 — 회수까지 하려면 `Dispose`에서 `_currentlyProtected`를 순회하며 `RevokeGrantedShield`를 호출하면 됨).

`_scanInterval`은 몇 초마다 스캔(부여/회수 갱신)을 수행할지를 정하는 타이머입니다. `0`으로 두면 매 프레임 스캔되어 범위 진입/이탈이 즉시 반영되고, 값을 키우면 스캔 비용은 줄지만 그만큼 부여·회수 반응이 늦어집니다. `Initialize`에서 `_remainingTime = 0f`로 시작해 스폰 직후 첫 스캔이 지연 없이 실행됩니다(Heal Aura는 `_remainingTime = _interval`로 시작해 첫 치유가 한 박자 늦게 나감 — 보호막은 스폰 직후 바로 걸리는 게 자연스러워 다르게 설정).

## 6. 후속 검토 필요 항목

### 6.1 보호형 몬스터가 2마리 이상 겹칠 때 방어막이 영구적으로 사라지는 문제

`_grantedOnce`/`_currentlyProtected`가 오라 인스턴스(보호형 몬스터 한 마리)별로 분리돼 있어서, 두 보호형의 범위가 겹치는 지점에 있는 몬스터는 다음 순서로 문제가 생길 수 있습니다.

1. 몬스터 M이 보호형 A, B의 범위에 동시에 진입
2. A가 먼저 스캔해 M에게 방어막 부여(`A._currentlyProtected`에 추가)
3. B도 스캔하지만 M은 이미 `HasShield == true`라 `GrantShield`가 `false` 반환 → B는 `_grantedOnce`에만 M을 추가(`_currentlyProtected`엔 미추가)
4. M이 A의 범위에서만 벗어나면 A가 회수 → 방어막 소멸
5. M은 이미 B의 `_grantedOnce`에 있으므로, B의 범위 안에 계속 있어도 다시는 방어막을 못 받음

현재 이슈 범위(보호형 1개 기준 동작)에서는 문제없이 통과하지만, 보호형이 여러 마리 겹쳐 등장하는 웨이브를 만들 경우 재현됩니다. 고치려면 "이미 부여받음" 판정을 오라 인스턴스가 아니라 대상 몬스터 쪽(`BaseMonster` 또는 `MonsterShield`에 플래그)으로 옮겨야 해서 구조 변경이 필요합니다. **의사결정 보류 중.**

### 6.2 코드 정리

- `BaseMonster.cs` 상단에 안 쓰는 `using Cysharp.Threading.Tasks.Triggers;`가 섞여 들어감 — 제거 필요

### 6.3 `_scanInterval` 튜닝

현재 `0`(매 프레임 스캔)으로 설정돼 있어 범위 이탈 시 방어막이 즉시 사라지지만, 몬스터 수가 많아지면 `적시스템_현황.md`에 이미 언급된 `OverlapCircleAll` 매 프레임 호출 비용 문제와 동일한 부담이 있습니다. 프로토타입 검증 후 몬스터 수 증가 시 함께 검토 필요.
