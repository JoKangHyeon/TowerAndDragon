> **2026-07-21 스냅샷입니다. 현재 상태는 `Docs/구현현황.md`를 보세요.**

> 전부 완료되어 삭제했습니다. **여기 남은 것은 그때 확정해서 지금도 코드가 지키는 규칙**과,

## 1. 확정 규칙 (지금도 그대로)

**인구**
- 인구는 지불하면 사라지는 자원이 아니라 배치했다 회수하는 **공용 인력 풀**이다.
- `MaxPopulation = AssignedPopulation + AvailablePopulation`. 별도의 `CurrentPopulation`은 만들지 않는다.
- 배치해도 소모되지 않고 "사용할 수 없는 상태"가 될 뿐이다. 해제하면 가용으로 돌아온다.
- 점령 완료 보상으로 `MaxPopulation`이 증가하고, **완료된 날부터 유지비를 낸다.**
- 식량 부족으로 사망하면 `MaxPopulation` 자체가 감소한다.
- 원정에 배치된 인구도 기아 대상이며, **가장 마지막에** 줄어든다.
- 생산량의 소수점은 버림 처리한다.

**타워**
- 체력 0으로 비활성화된 타워의 인구는 **반환하지 않는다.** 그 인구는 타워를 수리하는 인력으로 해석한다.
  플레이어가 직접 빼거나 철거할 때만 반환된다.
- 타워의 공격 가능 여부는 단일 플래그로 표현할 수 없다. 최소 세 가지를 분리해서 조합해야 한다:
  ① 전투 가능한 물리 상태 ② 현재 충원율 ③ 유효한 공격 데이터 존재 여부.
  이렇게 해야 **인구 0인 타워가 복구 코드 때문에 다시 공격하는 문제**를 막는다.

**적 강화(점령 페널티)**
- 점령한 청크의 `DominantTerrain`이 강화 대상 바이옴을 결정하고, **같은 지형의 포탈에서 나오는 적만**
  강화된다.
- 강화는 그날만이 아니라 **플레이 전체에 영구 누적**된다.
- 일차별 기본 웨이브와 점령 영구 강화는 **별도 데이터로 유지**한다.
- `PortalDirection`과 `TerrainType`의 대응을 코드 `switch`로 하드코딩하지 않는다 —
  맵 구성이 바뀌어도 씬 데이터만 고칠 수 있어야 한다.
- **공유 SO를 런타임에 직접 수정하지 않는다.**
  `기본 웨이브 + 포탈 지형 + 그 바이옴의 누적 강화 = 런타임 웨이브 계획`을 따로 만들고,
  스폰 수 보정은 계획에만, 체력·공격력·속도·방어막 보정은 적 인스턴스 생성 시 주입한다.

**정산**
- 아침 정산은 **이벤트 구독 순서에 맡기지 않고 하나의 조정자가 명시적으로 실행**한다.
  (구독 순서는 씬 오브젝트 순서에 좌우돼 조용히 결과가 달라진다.)

## 2. 책임 경계 (지금도 그대로)

| 시스템 | 책임 | 책임 밖 |
|---|---|---|
| `PopulationManager` | 전체 인구, 할당·회수, 불변식 | 생산량, 타워 공격, 원정 진행 |
| `ResourceManager` | 자원 보유량, 획득·소비, 변경 이벤트 | 인구, 생산 시점 결정 |
| `DailySettlementManager` | 정산 **순서** 조율 | 각 시스템의 세부 계산 |
| `ConquestManager` | 원정 시작·진행·완료, 보상과 페널티 등록 | 인구 원본, 자원 원본 |
| `WaveManager` | 해석된 웨이브 실행, 적 생성·추적 | 페널티 누적, 날짜 선택 |
| `Portal` | 방향·지형·경로·스폰 위치·활성 상태 | 웨이브 선택, 강화 계산 |

## 3. 이후 실제로 달라진 것

**① 정산이 8단계 목록 → 4단계 이벤트 구조가 됐습니다.**
당시 설계는 아침에 8단계를 한 줄로 실행하는 것이었지만, 지금은 `CycleManager`가 단계를
**이벤트로 쪼개고** 점령은 아예 밤으로 옮겼습니다.

| 당시 설계 | 현재 |
|---|---|
| 1~2. 생산 계산·지급 | `OnDayStart` |
| 3~4. 원정 진행·인구 보상 | **`OnNightEnd`** (밤을 넘겨야 하루가 지난 것이므로) |
| 5~7. 유지비·식량 차감·기아 | `OnDayStartUpkeep` (생산 다음 — 당일 생산분을 쓸 수 있어야 하므로) |
| 8. 완료 알림 | `OnDayReady` / `OnDaySettled` |

**② 기아 순서에 두 분류가 끼었습니다.**
`가용 → 타워 → 생산 → 점령` → **`가용 → 타워 → 연구 → 랜드마크 → 생산 → 점령`**.
랜드마크가 생산보다 앞인 이유는 랜드마크 가동은 끊겨도 회복되지만 생산 인구를 먼저 빼면
다음날 기아가 커지기 때문입니다.

**③ 타워 공격 속도 공식이 확장됐습니다.**
`기본간격 / 충원율` → `기본간격 / 충원율 / (연구·용 배율 × 오라 × 지형 페널티)`.
충원율에는 `Clamp01`이 걸려 있습니다(정원이 줄어 배치>정원이면 1을 넘겨 비정상 가속).

**④ 강화 배율 합산 방식이 확정됐습니다.**
당시 `[미정]`이던 항목입니다. 현재는 `EnemyStatModifier`가 가산·배율을 함께 갖고,
같은 지형에 프로필이 누적됩니다.

**⑤ 자투리 청크 편입이 추가됐습니다.**
당시엔 없던 규칙으로, 독자 점령이 불가능한 모서리 청크를 인접 점령 시 흡수합니다.
