## 1. 확정 결정 (이번 세밀화)

1. **재화 = 슬라임 + 특화 자원, `ResourceManager`로 통합 관리.** 별도 통화(RP 같은) 없음. `ResourceType`에 슬라임이 이미 바이옴별 5종으로 존재(`GrassSlime`/`RockSlime`/`VolcanoSlime`/`DesertSlime`/`SnowSlime`)하므로 그대로 소비한다.
2. **새끼용 노드 = 속성별 고정 슬롯**(속성당 2개). 단, **해당 속성 새끼용을 보유해야 활성화**된다(`RunData.BabyDragons`에 그 속성이 있을 때).
3. **해금은 영구 유지, 효과는 활성 속성만 발동.** 여러 속성을 병행 육성할 수 있고, 어미용 속성 변경(낮 1회, `Dragon.TryChangeType`)은 해금 상태에 영향을 주지 않는다.

## 2. 연구 시스템과의 분리 원칙


| 구분    | 연구 (구현됨, #86)                  | 용 스킬트리 (본 문서)                             |
| ----- | ------------------------------ | ----------------------------------------- |
| UI    | 연구소 건물 클릭 → 연구 창(3탭)           | **별도 창** (어미용/HUD 진입, `[UI 진입점 미정]`)      |
| 통화    | 전역 RP(ResearchManager 자체 카운터)  | **없음.** 슬라임+특화를 `ResourceManager`에서 직접 소모 |
| 획득 절차 | 밤 종료 시 배치 인구 × 계수로 RP 지급       | 별도 획득 단계 없음(자원 생산으로 확보)                   |
| 게이팅   | 선행 + 티어(주기 소스 대기 시 TierLocked) | **선행 + 새끼용 N개 + 보유** (주기/티어 없음)           |
| 진행    | 코스트 즉시 소모 → 즉시 적용              | 동일 (즉시 소모/즉시 적용, 대기 없음)                   |
| 완료 상태 | `HashSet<string>` (NodeId)     | 동일 패턴                                     |


두 시스템은 매니저·데이터·UI가 독립이며 서로의 진행도를 공유하지 않는다.

## 3. 창 구성 — 오각형 방사형 (확정 레이아웃)

중앙에 **어미용 오각형(5속성)**, 각 꼭짓점에서 속성 가지가 바깥으로 방사.

- **중앙 오각형** — 어미용 5속성. 현재 활성 속성 표시(= `RunData.Dragon.CurrentType`), 낮 1회 변경.
- **어미용 가지(방사)** — 속성별 4단: 각성(루트) → 액티브 I → 강화 → 궁극.
- **새끼용 슬롯** — 각 속성 각성 노드에서 좌우 2개(보유 시 활성).

동작·게이팅 시연은 `용_스킬트리_프로토타입.html` 참조.

## 4. 속성 ↔ 바이옴 ↔ 재화 매핑 (확정)

기획 "생명=초원, 나머지 4속성=외곽 4바이옴"에 맞춰 노드 코스트 재화를 매핑한다.


| 속성        | 바이옴 | 슬라임(ResourceType) | 특화 자원(ResourceType) |
| --------- | --- | ----------------- | ------------------- |
| 생명(Life)  | 초원  | `GrassSlime`      | (없음 — 기초 자원 보조)     |
| 얼음(Ice)   | 설원  | `SnowSlime`       | `SnowCrystal`       |
| 불(Fire)   | 용암  | `VolcanoSlime`    | `FlameHeart`        |
| 시간(Time)  | 사막  | `DesertSlime`     | `TimeSand`          |
| 암석(Stone) | 암석  | `RockSlime`       | `PhilosopherStone`  |


즉 각 속성 가지는 **자기 바이옴의 슬라임(+특화)**을 소비한다. 확장(점령)으로 그 바이옴을 확보해야 해당 속성을 키울 수 있어, "확장 → 용 성장" 순환이 자연스럽게 걸린다.

## 5. 게이팅 규칙 (확정)

노드 해금 조건:

- **어미용 각성(L1)**: 조건 없음(루트). (단 활성/비활성과 무관하게 해금 가능)
- **어미용 액티브 I(L2)**: 각성 완료.
- **어미용 강화(L3)**: 액티브 I 완료 **+ 새끼용 노드 2개 해금**(전역 합산).
- **어미용 궁극(L4)**: 강화 완료 **+ 새끼용 노드 4개 해금**(전역 합산).
- **새끼용 슬롯(A/B)**: 같은 속성 각성 완료 **+ 해당 속성 새끼용 보유**(`RunData.BabyDragons`).

> 새끼용은 주기당 1마리(최대 4)라, "궁극(새끼용 4개)"은 자연히 후반에 열린다 — 별도 주기 티어 없이도 게임 진행에 맞춰 페이싱된다.
> 새끼용 카운트 기준(전역 vs 속성별)·게이트 임계값(2/4)은 밸런싱 `[미정]`. 현재는 프로토타입과 동일하게 **전역 합산**.

## 6. 노드 상세

### 6-1. 어미용 (속성별 4단, 효과는 기획 §10)

패시브/액티브 텍스트는 §10 표 그대로. 코스트는 §4 매핑(예시 수치는 밸런싱).


| 단계  | 노드        | 선행            | 효과                            | 예시 코스트    |
| --- | --------- | ------------- | ----------------------------- | --------- |
| L1  | 각성 *(루트)* | —             | 활성 시 패시브 맵 효과 발동              | 슬라임 소량    |
| L2  | 액티브 I     | 각성            | 속성 액티브 스킬 해금(SkillManager 등록) | 슬라임 + 특화  |
| L3  | 강화        | 액티브 I + 새끼용 2 | 패시브·액티브 수치 강화                 | 슬라임·특화 다량 |
| L4  | 궁극        | 강화 + 새끼용 4    | 속성 최종 강화                      | 슬라임·특화 대량 |


속성별 패시브 / 액티브 (§10):


| 속성  | 패시브(활성 시)                             | 액티브                                                |
| --- | ------------------------------------- | -------------------------------------------------- |
| 얼음  | 모든 기본 타워 공격에 둔화 부여                    | 모든 적을 5초 동안 빙결                                     |
| 불   | 모든 타워 공격에 화상 부여 또는 대미지 증가 `[선택 미정]`   | 모든 적 이동 경로를 따라 강한 화염 피해 부여                         |
| 시간  | 모든 타워 공격 속도 증가 및 타워 재활성화 시간 감소        | 모든 타워 즉시 재활성화                                      |
| 암석  | 석재·특화 자원·연구 포인트 생산량 증가 및 메인 성에 보호막 부여 | 당일 밤 동안 메인 성 주위에 적의 공격을 대신 받는 벽 생성 및 모든 타워에 보호막 부여 |
| 생명  | 당일 식량·목재·슬라임 생산량 증가 및 타워 최대 체력 증가     | 메인 성 체력 (20정도 예상) 회복                               |


> 암석 액티브의 벽은 해당 밤에만 유지되며, 활성 중 적은 메인 성 대신 벽을 공격한다.

### 6-2. 새끼용 슬롯 (속성별 2개, 보유 시 활성)


| 슬롯          | 선행                | 효과(타워/지역, §10)                                       |
| ----------- | ----------------- | ---------------------------------------------------- |
| 새끼용 A (타워형) | 각성 + 해당 속성 새끼용 보유 | 얼음=슬로우 타워 / 불=화상 타워 / 시간·암석·생명=`[미정]`                |
| 새끼용 B (지역형) | 각성 + 해당 속성 새끼용 보유 | 얼음=강 결빙 건물배치 / 불=시야 증가 / 시간=점령대 포함 / 암석=광산↑ / 생명=농장↑ |


- 새끼용 전투형/버프형 선택 상세는 기획 `[미정]` → 슬롯 세부 규칙 보류.

## 7. 아키텍처 계약 (구현 연구 시스템 패턴에 정렬)

`ResearchManager`(#86)와 **대칭 구조**로 신규 독립 시스템을 만든다. 경로 `Assets/Scripts/Dragon/`(또는 `Research/`와 분리된 폴더).

### 신규 파일


| 파일                                     | 종류            | 책임                         |
| -------------------------------------- | ------------- | -------------------------- |
| `DragonSkillNodeData`                  | SO            | 노드 1개(불변 콘텐츠)              |
| `DragonSkillTreeData`                  | SO            | 전체 노드 묶음                   |
| `DragonSkillEffectSO`                  | abstract SO   | 다형 효과 베이스                  |
| `PassiveAttributeEffectSO`             | SO            | 활성 속성 조건부 패시브              |
| `ActiveSkillUnlockEffectSO`            | SO            | 액티브 스킬 해금(SkillManager 연동) |
| `KinTowerEffectSO` / `KinAreaEffectSO` | SO            | 새끼용 효과                     |
| `DragonSkillManager`                   | MonoBehaviour | 완료 집합·해금·코스트 소모·효과 pull    |
| `UI/UI_DragonSkillWindow`              | MonoBehaviour | 오각형 방사형 창                  |


### `DragonSkillNodeData` (스켈레톤)

```csharp
public enum DragonNodeKind { MotherAwaken, MotherActive, MotherEnhance, MotherUltimate, KinTower, KinArea }

[CreateAssetMenu(menuName = "TowerAndDragon/Dragon/SkillNode")]
public class DragonSkillNodeData : ScriptableObject
{
    [SerializeField] private string _nodeId;             // 안정 ID(연구와 동일 패턴)
    [SerializeField] private string _nameLocKey;
    [SerializeField] private string _descriptionLocKey;
    [SerializeField] private DragonType _attribute;      // 기존 RunData.DragonType 재사용(Ice/Fire/Time/Stone/Life)
    [SerializeField] private DragonNodeKind _kind;
    [SerializeField] private DragonSkillNodeData[] _prerequisites;
    [SerializeField] private int _requiredKinCount;      // 어미용 게이트(강화=2, 궁극=4), 그 외 0
    [SerializeField] private List<ResourceAmount> _cost; // 슬라임+특화 (ResourceManager)
    [SerializeField] private DragonSkillEffectSO[] _effects;
    // getters …
}
```

### `DragonSkillManager` (계약)

```csharp
public class DragonSkillManager : MonoBehaviour
{
    private readonly HashSet<string> _unlocked = new();   // NodeId

    public int UnlockedKinCount { get; }                  // KinTower/KinArea 완료 수(게이트 판정)
    public DragonType ActiveAttribute { get; }            // = RunData.Dragon.CurrentType

    public DragonSkillNodeState GetNodeState(DragonSkillNodeData node);
    public bool IsUnlocked(string nodeId);
    public bool TryUnlock(DragonSkillNodeData node, out DragonSkillFailureReason reason);

    public UnityEvent<DragonSkillNodeData> NodeUnlocked;
    public UnityEvent<DragonType> ActiveAttributeChanged;

    public void Construct(GameManager gm, ResourceManager res, SkillManager skills, RunData run);
}
```

### `TryUnlock` 실행 순서 (연구 §4.2와 동일 철학)

1. 트리에 등록된 노드인지 확인.
2. 이미 해금했는지 확인.
3. 현재 단계가 **낮**인지 확인(속성 변경과 동일하게 낮 전용).
4. 선행 노드 모두 해금됐는지 확인.
5. 게이트 확인 — 새끼용 노드면 **해당 속성 새끼용 보유**, 어미용 게이트 노드면 **UnlockedKinCount ≥ requiredKinCount**.
6. 슬라임+특화 자원이 충분한지(`ResourceManager`) 확인.
7. 자원을 **원자적으로 차감**.
8. NodeId를 `_unlocked`에 등록.
9. 상태변경형 효과(있으면) 즉시 적용, `NodeUnlocked` 발행.

검증 실패 시 자원·완료 상태 불변. 완료 노드 재실행 불가. (연구와 동일)

### 기존 코드 연동 (실측)

- **속성/새끼용 상태**: `RunData.Dragon.CurrentType`, `RunData.Dragon.TryChangeType(...)`(낮 1회 이미 구현), `RunData.BabyDragons`(List<BabyDragon>, `DragonType` 보유).
- **액티브 스킬 발동**: 기존 `SkillManager`가 `SkillSO`→`Skill` 인스턴스를 틱·발동(일일 리셋). 액티브 해금 노드는 SkillManager가 **해금된 스킬만 노출/발동**하도록 연동(현재는 정적 `_skillDataList`에서 전부 빌드 → 해금 게이팅 훅 추가 필요).
- **자원**: `ResourceManager`(슬라임 5종 + 특화 4종 이미 관리).

## 8. 효과 적용 방식 &amp; 구현 범위 (정직한 스코프)

효과는 연구와 동일하게 **pull(조회)** 기여를 기본으로 한다. 활성 속성 패시브는 `ActiveAttribute == node.Attribute`일 때만 값을 반환.


| 효과                    | 적용 방식                                        | 구현 가능성(현 시점)                                       |
| --------------------- | -------------------------------------------- | -------------------------------------------------- |
| 해금/완료 상태·코스트·UI·속성 변경 | DragonSkillManager 자체                        | **바로 구현 가능**(연구 패턴 복제)                             |
| 액티브 스킬 해금             | `SkillManager`에 해금 게이팅 훅 추가                  | 시스템 존재 → 훅 추가로 가능(2차)                              |
| 생산 패시브(생명 농장↑/암석 광산↑) | `IChunkYieldMultiplierQuery` 기여를 활성 속성일 때 추가 | 연구가 이미 이 쿼리 사용 → 다중 소스 합산 설계 필요(2차)                |
| 전투 패시브(슬로우/화상/공속)     | TowerAttack/몬스터에 훅 필요                        | 훅 미존재 → **보류(stub)**                               |
| 액티브 강화·궁극 수치          | SkillSO/Skill 수치 조회 훅                        | 훅 미존재 → **보류(stub)**                               |
| 새끼용 타워/지역 효과          | 설치형·지역 시스템(강 결빙·시야 등)                        | 대부분 미존재 → **보류(stub)**, 시간·암석·생명 새끼용 타워는 기획 `[미정]` |


> stub 규칙(연구와 동일): 보류 효과의 노드는 SO로 만들되 효과 구현체는 no-op/`[TBD]` 표시. 데이터 스키마는 지금 확정해 후속 연결 시 재작업 없게 한다. **수직절편의 확실한 산출물은 "트리 데이터 + DragonSkillManager + 창 UI + 속성 변경 + 코스트 소모"** 이며, 실제 게임플레이 효과 대부분은 대상 시스템이 붙을 때 연결한다.

# §12. v2 세분화 설계 (초안 · 프로토타입 테스트 중)

> 목표: v1의 "속성당 일직선 4칸(각성→액티브I→강화→궁극)"은 순서대로 다 찍는 구조라 **선택이 없다**.
> 용이 게임의 핵심인 만큼, **랜덤으로 나오는 새끼용에 맞춰 집중/보완하는 전략적 분화**가 촘촘하게 나오도록 트리를 세분화한다.
> 테스트 도구: `용_스킬트리_프로토타입_v2.html` (분기+랭크 · 자원 희소성 · 랜덤 새끼용 획득 시뮬).

## 12-1. 확정한 두 가지 설계 축

1. **세분화 = 하이브리드(분기 + 랭크).** 각성 후 **2갈래로 분기**(상호 배타 아님, 자원으로만 제한)하고, 각 노드를 **여러 랭크로 점진 강화**한다.
2. **전략 유도 = 공용 자원 희소성.** 시너지/교차 노드나 게이트 확장은 쓰지 않는다. **속성별 슬라임+특화가 부족해 다 못 찍는다** → "한 속성 깊게 vs 여러 속성 얕게"가 강제된다.
   - 근거: 각 속성 가지는 §4 매핑대로 **자기 바이옴의 슬라임+특화**만 소비한다. 어떤 바이옴을 점령·유지했느냐가 곧 그 속성의 예산이다.

## 12-2. 구조 — 속성당 노드 (v1 20+10 → v2 40 노드, 각 노드 랭크제)

각성을 루트로, 두 갈래가 방사한다. (레이아웃: 오각형 중심 → 각성 → 갈래 분기)

```
                    [궁극]  (선행: 심화 중 1 + 새끼용 4)
                   /      \
        [공격 심화]        [운영 심화]   (선행: + 새끼용 2)
             |                  |
        [공격 갈래]        [운영 갈래]
                   \      /
                   [각성]  (루트, 활성 시 패시브)
                   /      \
        [새끼용 A]        [새끼용 B]   (해당 속성 보유 시)
```

| 노드 | 종류 | 최대 랭크 | 선행 | 게이트 |
| --- | --- | :---: | --- | --- |
| 각성 | 루트 | 1 | — | — |
| 공격 갈래 (b1n1) | 갈래 | 3 | 각성 | — |
| 공격 심화 (b1n2) | 갈래 | 3 | 공격 갈래 | 새끼용 노드 2 |
| 운영 갈래 (b2n1) | 갈래 | 3 | 각성 | — |
| 운영 심화 (b2n2) | 갈래 | 3 | 운영 갈래 | 새끼용 노드 2 |
| 궁극 | 궁극 | 2 | 공격 심화 **또는** 운영 심화 | 새끼용 노드 4 |
| 새끼용 A (타워형) | 새끼용 | 3 | 각성 | 해당 속성 새끼용 보유 |
| 새끼용 B (지역형) | 새끼용 | 3 | 각성 | 해당 속성 새끼용 보유 |

- **게이트는 v1 그대로 계승**: 심화=새끼용 노드 2개, 궁극=4개(전역 합산). 새끼용은 주기당 1(최대 4)이라 자연 페이싱.
- **궁극은 두 갈래 중 하나만 심화해도 열린다** → 한 갈래를 깊게 판 스페셜리스트도 궁극에 도달 가능(전문화 보상).
- **해금 영구·활성 속성만 효과 발동** 원칙은 v1과 동일.

## 12-3. 속성별 두 갈래 (효과는 §10 확정본 기반)

각 속성을 **공격(액티브·전투) 갈래**와 **운영(생산·방어) 갈래**로 쪼갠다. 속성 정체성에 맞춰 비대칭적으로 배분.

| 속성 | 각성(패시브) | 공격 갈래 → 심화 | 운영 갈래 → 심화 | 궁극 |
| --- | --- | --- | --- | --- |
| 생명 | 식량·목재·슬라임↑·타워HP↑ | 성 회복(액티브) → 생명의 숨결(밤 지속회복) | 풍요 강화(생산↑) → 번식(슬라임 추가·먹이↓) | 만개 |
| 얼음 | 기본타워 둔화 부여 | 빙결(액티브) → 한파(둔화 잔류·추가피해) | 서리 강화(둔화↑) → 빙판지대(광역 둔화장판) | 동결 지배 |
| 불 | 타워 화상 부여 | 화염(액티브) → 대화재(장판·범위↑) | 연소 강화(화상 틱↑) → 과열(받는 피해↑) | 지옥불 |
| 시간 | 공속↑·재활성화↓ | 즉시 재활성화(액티브) → 시간 역행(공속 폭증) | 가속 강화(공속↑) → 연쇄 가속(처치 시 버프) | 시간 지배 |
| 암석 | 석재·특화·RP↑·성 보호막 | 성벽(액티브) → 요새(벽HP↑·반사) | 채굴 강화(생산↑) → 정제(특화 추가·유지비↓) | 불괴 |

새끼용 슬롯(속성별 A 타워형 / B 지역형)은 v1 정의를 계승하되 **랭크제로 점진 강화**한다.
(예: 슬로우 타워 Lv1 둔화 20% → Lv3 50%+빙결확률). 시간·암석·생명 새끼용 A 타워는 이미 공격 데이터가 구현되어 있으므로 `[미정]`이 아니라 **랭크별 수치만 밸런싱 대상**이다.

## 12-4. 자원 희소성 모델 (예시 코스트 · 밸런싱 대상)

노드 종류별 랭크당 코스트. 프로토타입 상단 `COST` 상수에서 바로 실험 가능.

| 종류 | Lv1 | Lv2 | Lv3 |
| --- | --- | --- | --- |
| 각성 | 슬라임 5 | — | — |
| 갈래 노드 | 슬라임 6 · 특화 2 | 슬라임 8 · 특화 3 | 슬라임 10 · 특화 4 |
| 궁극 | 슬라임 15 · 특화 6 | 슬라임 20 · 특화 8 | — |
| 새끼용 | 슬라임 5 · 특화 2 | 슬라임 7 · 특화 2 | 슬라임 9 · 특화 3 |

- **생명은 특화가 없다**(초원=기초자원) → 특화 코스트를 슬라임으로 접어 계산.
- **한 속성 풀트리 ≈ 슬라임 178 + 특화 66**. 중반 한 바이옴 산출로는 도저히 다 못 채운다 → **선택과 집중 강제**.
- 프로토타입 예산 프리셋으로 시나리오 비교:
  - **설원 집중**: 얼음 풀트리는 가능하나 나머지는 각성만.
  - **고루 분산**: 5속성 각성 + 한 갈래 Lv1씩 — 얕고 넓게.
  - **풍족**: 밸런스 상한 참고용.

## 12-5. 랜덤 새끼용 ↔ 전략 분화 (핵심 루프)

1. 주기 보스 처치 → **랜덤 속성 새끼용 1마리**(최대 4).
2. 그 속성의 **새끼용 슬롯이 열리고**(강력한 랭크제 효과) + **어미용 심화/궁극 게이트(새끼용 2/4)에 기여**.
3. 자원은 유한 → 플레이어는 **뽑힌 속성으로 집중**(그 바이옴 점령·풀트리)하거나, **다른 갈래로 보완**(부족한 전투/운영 축)할지 선택.
4. 어미용 활성 속성은 낮 1회 변경 → 보유 조합에 맞춰 그날의 주력 패시브를 스위칭.

→ "어떤 새끼용이 나왔나 × 어떤 바이옴을 쥐었나 × 공격/운영 중 무엇이 부족한가"의 곱으로 매 판 다른 빌드가 나온다.

## 12-6. v1 → v2 구현 델타 (후속, 이번은 설계·프로토타입만)

- 데이터: `DragonSkillNodeData`에 **랭크(레벨)·랭크별 코스트·랭크별 효과 스케일** 필드 추가. 노드 수 20→40.
- 매니저: 완료 `HashSet<string>` → **`Dictionary<string,int>`(NodeId→랭크)**. `TryUnlock` → `TryRankUp`. 게이트/선행/자원 검증 로직은 v1 재사용.

## 12-7. v2 검증 기준 (프로토타입)

- 각성 없이 갈래/새끼용 클릭 → 선행 미충족 거부.
- 새끼용 2개 미만 → 심화 랭크업 거부 / 4개 미만 → 궁극 거부.
- 새끼용 노드를 내려 게이트가 깨지면 상위 노드 랭크가 **자동 클램프**.
- 자원 예산 초과 시 경고 표기(어떤 속성 풀이 부족한지) → 완성 불가한 빌드가 드러남.
- 랜덤 새끼용 획득이 "집중할 속성"을 만들고, 자원 프리셋에 따라 같은 빌드의 완성 가능 여부가 달라짐.
- (위 6개는 `용_스킬트리_프로토타입_v2.html`에서 로직 자동 검증 통과.)
