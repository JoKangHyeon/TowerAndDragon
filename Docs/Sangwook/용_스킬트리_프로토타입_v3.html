용 스킬트리 v3 — 구현 범위 재설계

구조는 v2(루트 → 2갈래 분기 + 노드별 랭크)를 유지하되, 루트가 "각성(패시브 해금)"에서 "액티브 스킬 해금"으로 바뀜 — 기본 패시브는 노드 자체가 아예 없어지고 5속성 모두 처음부터 무료·자동으로 켜져 있습니다.
노드 효과는 전부 이미 구현된 DragonSkillEffectSO 클래스·기존 액티브 스킬 애셋을 재사용합니다 — 전역 빙결·전역 화염 피해·메테오+방벽 3종 액티브는 전부 구현 완료 상태였습니다(코드 재확인 완료). "타워 최대체력 증가"만 🔧 소규모 신규 확장이 필요합니다. 새 새끼용 행동은 여전히 없음 — "빌드가 심화될수록 기존 수치의 %가 오른다"가 원칙입니다.
노드 클릭 = 1랭크 강화(자원 소모) · Shift+클릭 또는 우클릭 = 1랭크 취소(환급). 기본 패시브는 노드가 아니라 5속성 모두 처음부터 자동 적용(해금·자원 소모 불필요, 우측 "활성 속성" 카드에 표시). 트리에서 실제로 자원을 써서 여는 첫 단계는 루트(액티브 스킬 해금)이고, 그 다음 액티브 갈래(같은 스킬 업그레이드)와 패시브 갈래(생산량·기본 타워 스탯 강화)로 갈라집니다.
루트(액티브 스킬 해금) 액티브 갈래(업그레이드) 패시브 갈래 궁극 새끼용 잠김 · 🔒 선행/보유 미충족 또는 해당 속성 새끼용(A+B) 랭크 합 부족 · 해금은 영구, 효과는 활성 속성만 발동(새끼용 노드 제외)
이전 라운드까지 반영된 것(요약): 루트 = 액티브 스킬 해금(유료), 기본 패시브는 노드 없이 5속성 모두 무료·자동. 암석 액티브는 이미 구현된 METEOR_BARRICADE/MeteorBarricadeSkill/ StoneBarricade로 교체(자산 재배정만 필요, 신규 코드 없음). 심화·궁극 게이트는 "그 속성 자신의" 새끼용 A+B 랭크 합 기준(알 1마리로 자력 충족 가능).
이번 라운드: 각 속성별 세부 밸런스·범위 조정을 반영했습니다. 대부분 기존 클래스 재사용이지만, 이번엔 진짜 신규 코드가 필요한 지점이 늘었습니다 — 아래 H1~H11을 각 노드의 impl 태그에서 참조 번호로 씁니다:
  • H1 — DragonTowerStatEffectSO가 towerData를 무시하던 걸 고쳐 IElementalAttackData.DragonType으로 필터링(전체 타워 → "그 속성 타워만"). 얼음/불/암석 "가동 강화" 3곳에 필요.
  • H2 — 신규 KinTowerStatEffectSO: KinTowerStatusEffectSO와 동일하게 "이 새끼용 자신의 타워"로 한정한 피해%/공속%/사거리% 배율. 얼음·암석 kinA "공격력 증가"에 필요.
  • H3 — DragonTreeManager.GetRangeMultiplier가 지금 중립값 고정 스텁 — Damage/AttackSpeed와 같은 방식으로 실제 집계하도록 전환. 불 kinB "사거리 증가"에 필요(H2와 함께).
  • H4 — 신규 GetKinBuffRadiusBonus(dragonType) 훅(KinAreaYieldEffectSO와 동일 패턴) + BabyDragonBuffSystem이 반경 계산 시 반영. 생명 kinA, 시간 kinB "버프모드 범위 증가"에 필요.
  • H5 — 미해결: 시간 새끼용의 "버프모드"가 현재 코드상 수치 효과가 정의돼 있지 않습니다(BabyDragonBuffSystem 주석: "얼음/불/시간은 생산량 버프가 아닌 별개 지역 효과"). 시간 kinA "버프 효율 증가"를 확정하려면 시간 버프모드가 정확히 뭘 하는지부터 기획 확정이 필요합니다 — 일단 그 효과의 배율을 올리는 자리로 잡아뒀습니다.
  • H6 — Skill.HealAmount가 지금 DamagePercent와 달리 위력 배율을 안 읽습니다 — GetSkillPowerMultiplierBonus를 반영하도록 확장. 생명 "성 회복 업그레이드 II"(회복량 증가)에 필요.
  • H7 — 신규 "상태이상 지속시간 배율" 훅 + FreezeAllSkill 적용부 반영. 얼음 "전역 빙결 업그레이드 II"(빙결 시간 증가)에 필요.
  • H8 — 신규 "상태이상 틱데미지 배율" 훅(또는 랭크별로 더 강한 DamageOverTimeStatusSO 애셋 교체 — 이 경우 GetTowerHitStatus의 "첫 매치 반환" 규칙을 "최고 랭크 우선"으로 같이 고쳐야 함). 불 kinA "화상 데미지 증가"에 필요.
  • H9 — SkillSO에 고정 데미지 필드 신설 + MeteorBarricadeSkill의 피해 계산을 "현재체력 비례 %" → "고정 수치"로 전환. 암석 메테오 전체에 영향.
  • H10 — 신규 "방벽 체력 배율" 훅 + MeteorBarricadeSkill이 StoneBarricade 스폰 직후 Health.Initialize(강화된 최대체력) 호출(현재 StoneBarricade는 프리팹 고정값만 씀). 암석 "메테오+방벽 업그레이드 II"(방벽 체력 증가)에 필요.
  • H11 — 신규 "일일 사용 횟수 보너스" 훅 + Skill.UsePerDay/Reset()이 반영. 암석 "불괴"(사용 횟수 증가)에 필요.
정리하면 이번 배치는 9개 노드가 신규 코드를 필요로 합니다(H1~H4, H6~H11 — H5는 코드 이전에 기획 확정이 먼저 필요). 개별 항목은 각각 기존 패턴을 그대로 복제하는 수준(필드 1개 + 훅 1개 + 소비 지점 1곳)이라 하나하나는 작지만, 개수 자체는 이전 라운드(H_MaxHealth 하나)보다 많이 늘었습니다 — 실제 착수 전에 팀과 우선순위를 한 번 맞추시는 걸 권합니다.
시간 b2n2(원정 보급 강화) 대체안: "제거"만 지시받고 대체 내용이 없어서, 얼음/불/암석의 "가동 강화" 노드와 통일되게 "시간 속성 타워 한정 공격속도 추가 증가"(H1)로 채워뒀습니다 — 의도와 다르면 알려주세요.
