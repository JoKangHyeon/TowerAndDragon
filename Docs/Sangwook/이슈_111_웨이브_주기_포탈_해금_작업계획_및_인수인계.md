## 1. 문서 목적

이 문서는 다른 PC나 새 작업 환경에서 이슈 #111 작업을 바로 이어갈 수 있도록 다음 내용을 한곳에 정리한 인수인계 문서입니다.

- 사용자와 합의된 현재 구현 규칙
- 이미 구현된 코드와 테스트

- 다음 작업자가 따라갈 구현 순서
- 이슈 완료 판정 기준과 검증 방법

상태 표기는 다음과 같이 사용합니다.

| 표기 | 의미 |
| --- | --- |

`기획종합_v2.md`에는 주기당 일수가 아직 `[미정]`으로 남아 있지만, 이슈 #111의 현재 구현에서는 사용자 확인에 따라 **주기당 7웨이브**를 적용합니다. 기획 원본의 문구 수정은 기획 담당자의 영역이므로 이번 작업 범위에는 포함하지 않습니다.

### 2.2 이번 작업에서 확정된 규칙

1. 전체 게임 주기는 4주기입니다.
2. 한 주기는 7개의 밤 웨이브로 구성됩니다.
3. 각 주기의 7번째 웨이브는 보스 웨이브입니다.
4. 포탈 해금 순서는 **North → South → East → West**입니다.
5. 새 주기가 시작되면 다음 포탈이 누적 활성화됩니다.
6. 현재 포탈 개방의 의미는 `Portal.IsActive`를 통한 **스폰 활성화**뿐입니다.
7. 봉인 해제 애니메이션, VFX, 연출은 후속 작업입니다.
8. 3·4주기의 실제 웨이브와 보스 데이터가 없으므로 기존 데이터를 임시 반복합니다.
9. 최종 승리 처리는 아직 구현하지 않고 이벤트만 열어 둡니다.

## 4. 현재 런타임 연결 상태

### 4.1 현재 흐름

현재 씬에는 `WaveCycleProgression`이 추가되어 있으나, 실제 야간 웨이브 시작 흐름은 아직 기존 구조입니다.

```text
CycleManager.OnNightStart(currentDay)
  → DailyWaveController
  → WaveScheduleSO.TryGetWaveDefinition(currentDay)
  → WaveManager.StartWaveAsync(waveDefinition)
  → 모든 적 격파
  → CycleManager.EndNight()
```

`WaveCycleProgression`은 `GameManager`의 `CycleManager`와 `WaveCycleSchedule_Main.asset`을 참조하도록 연결되었습니다. 그러나 `DailyWaveController`가 이 진행 스냅샷을 사용하지 않고 있으며, `PortalProgressionController`도 씬에 없으므로 위 두 흐름은 아직 하나로 합쳐지지 않았습니다.

### 4.2 목표 흐름

```text
CycleManager.OnDayStart(currentDay)
  → WaveCycleProgression
  → WaveCycleScheduleSO.TryResolve(currentDay)
  → WaveCycleSnapshot 갱신
  → 새 주기이면 PortalProgressionController.ApplyCycle(cycleNumber)
  → Portal.SetSpawnActive(...)

CycleManager.OnNightStart(currentDay)
  → DailyWaveController
  → WaveCycleProgression.TryGetCurrentWaveDefinition(...)
  → WaveManager.StartWaveAsync(waveDefinition)
  → 모든 적 격파
  → CycleManager.EndNight()
  → 보스 웨이브이면 CycleCompleted 이벤트
```

## 5. 남아 있는 데이터·씬·UI 상태

### 5.1 웨이브 데이터

- 실제 `WaveCycleScheduleSO` 에셋: **1개** (`WaveCycleSchedule_Main.asset`)
- 실제 웨이브 에셋: `wave_1`~`wave_14_Boss`, **14개**
- 1주기: `wave_1`~`wave_7_Boss`, North 해금
- 2주기: `wave_8`~`wave_14_Boss`, South 해금
- 3주기: `wave_1`~`wave_7_Boss`를 직접 재참조, East 해금
- 4주기: `wave_8`~`wave_14_Boss`를 직접 재참조, West 해금
- 각 주기에는 7개의 웨이브가 등록되어 있으며 해금 순서는 North → South → East → West와 일치

현재 일정 구성은 사용자가 정한 “3·4주기에는 기존 데이터를 임시 반복” 규칙을 충족합니다. 과거 Console에 남아 있는 “주기에는 웨이브가 7개 있어야 합니다” 오류는 에셋을 채우는 도중 발생한 기록이며, 현재 저장된 에셋에는 4주기 모두 7개씩 등록되어 있습니다.

다만 일정 재사용과 포탈별 실제 스폰은 별도입니다. `WaveManager`는 `WaveDefinitionSO.PortalWaves`에 명시된 방향만 실행하므로 현재 상태에서는 다음 문제가 남습니다.

- `wave_1`~`wave_7_Boss`에는 현재 North 편성만 있어 3주기 South/East 스폰 데이터가 없음
- `wave_8`~`wave_14_Boss`에는 현재 North/South 편성만 있어 4주기 East/West 스폰 데이터가 없음
- 현재 재참조 구조를 유지하려면 각 재사용 에셋에 필요한 방향의 `PortalWaveData`를 임시 추가해야 함
- 추가된 편성은 앞선 주기에서 해당 포탈이 비활성 상태이므로 `WaveManager`가 건너뜀
- 대안으로 3·4주기용 별도 임시 에셋을 만들 수 있지만, 현재 일정은 직접 재참조 방식을 선택한 상태

### 5.2 씬

현재 작업 씬은 `Assets/Scenes/Sangwook_SampleScene.unity`입니다.

- `WaveCycleProgression` 컴포넌트: `Waves/WaveCycleProgression`에 추가됨
- `WaveCycleProgression._cycleManager`: `GameManager`의 `CycleManager` 연결됨
- `WaveCycleProgression._schedule`: `WaveCycleSchedule_Main.asset` 연결됨
- `PortalProgressionController` 컴포넌트: 없음
- `DailyWaveController`: 기존 `WaveSchedule_Test` 사용
- North/South/East/West 포탈 `_isActive`: 모두 `true`
- 포탈 방향: North/South/East/West가 각각 올바르게 지정됨
- `WaveManager.AllMonstersDefeated → CycleManager.EndNight`: 연결되어 있음
- Build Settings 등록 씬: `Assets/Scenes/SampleScene.unity`만 등록됨

씬 작업 자체는 일정 에셋과 진행 컴포넌트의 1차 연결까지 올바르게 되어 있습니다. 다만 포탈 진행 컴포넌트와 야간 웨이브 시작 경로가 빠져 있고, 현재는 4개 포탈이 모두 활성 상태이므로 주기별 해금은 아직 동작하지 않습니다.

### 5.3 UI

`Assets/Scripts/UI/UI_IngameWindow.cs`는 현재 `WAVE_FILL_LENGTH = 6`과 `+ 1` 계산으로 7일 주기를 표현합니다. 표시 결과는 7칸 주기와 맞을 수 있지만, `WaveCycleRules.WAVES_PER_CYCLE` 또는 현재 `WaveCycleSnapshot`을 사용하지 않아 규칙이 중복되어 있습니다.

초기 연결의 필수 범위는 아니지만, 런타임 연결 후 주기 표시와 실제 진행이 어긋나지 않도록 공통 규칙을 참조하도록 정리하는 것이 안전합니다.

## 6. 빠진 것과 고장 난 것의 구분

### 6.1 현재 고장 난 것으로 확인된 항목

- 컴파일 오류는 없습니다.
- 플레이 진입 시 `GameManager.Start()` 64행에서 `NullReferenceException`이 발생합니다.
- 원인은 `GameManager._defaultLights` 목록의 두 번째 항목이 비어 있는 것입니다.
- 예외가 `CycleManager.StartDay()` 호출보다 먼저 발생하므로 1일차 시작과 `WaveCycleProgression`의 스냅샷 초기화가 실행되지 않습니다.
- 이 빈 참조는 이번 씬 변경 diff에서 새로 추가된 내용은 아니지만, 현재 주기 기능의 플레이 검증을 막는 선행 문제입니다.
- Console의 `Assets/Resources.meta`, `Assets/Material.meta` GUID Parser 경고는 별개의 기존 에셋 메타 문제입니다.

### 6.2 아직 빠진 항목

1. `GameManager._defaultLights`의 빈 참조 복구
2. `DailyWaveController`와 `WaveCycleProgression`의 연결
3. 작업 씬의 `PortalProgressionController` 추가 및 참조 연결
4. 게임 시작 시 1주기 상태를 적용하여 North만 활성화하는 초기화
5. 재사용 웨이브 에셋의 3·4주기용 South/East/West 임시 포탈 편성
6. 7일차 종료 후 8일차에 South가 활성화되는 플레이 모드 검증
7. 3·4주기 East/West 포탈의 실제 스폰 검증
8. UI의 주기 규칙 중복 제거 또는 일치 여부 검증
9. 28일차 이후의 종료 흐름

- 플레이 진입 후 `CycleManager.StartDay()`가 실행되는지 확인합니다.
- `WaveCycleProgression`이 1일차 스냅샷을 가지는지 확인합니다.

### 3단계 — 야간 웨이브 시작 경로 연결

`DailyWaveController`가 기존 `WaveScheduleSO`를 직접 조회하는 대신 현재 `WaveCycleProgression`의 스냅샷에서 웨이브를 가져오도록 변경합니다.

- `_waveSchedule` 참조를 신규 진행 시스템 참조로 교체합니다.
- `OnNightStart(currentDay)`의 일차와 `CurrentSnapshot.TotalDay`가 일치하는지 방어적으로 확인합니다.
- 현재 스냅샷이나 웨이브 데이터가 없으면 오류를 기록하고 웨이브를 시작하지 않습니다.
- `WaveDefinitionSO`와 `MonsterData` 원본을 런타임에서 수정하지 않습니다.

### 4단계 — 작업 씬의 포탈 진행 연결

`Assets/Scenes/Sangwook_SampleScene.unity`에서 먼저 검증합니다.

- `WaveCycleProgression`, `CycleManager`, `WaveCycleSchedule_Main` 연결은 완료된 상태를 유지합니다.
- `PortalProgressionController`를 추가하고 진행 컴포넌트와 4개 포탈을 연결합니다.
- 각 포탈의 `PortalDirectionId`가 North/South/East/West로 중복 없이 지정되었는지 확인합니다.
- 시작 직후 1주기 규칙이 적용되어 North만 활성화되는지 확인합니다.
- 기존 `WaveManager.AllMonstersDefeated → CycleManager.EndNight` 연결은 유지합니다.

### 5단계 — 임시 포탈별 편성 보완

현재 일정 에셋의 직접 재참조 구조를 유지하면서 다음 편성을 보완합니다.

- 3주기에 재사용되는 1~7번 웨이브에 South와 East 임시 편성 추가
- 4주기에 재사용되는 8~14번 웨이브에 East와 West 임시 편성 추가
- 기존 편성 값을 복제하되 실제 기획 데이터로 오해하지 않도록 임시 편성임을 기록
- 1·2주기에서는 아직 열리지 않은 방향이 `Portal.IsActive == false`로 건너뛰어지는지 확인

### 6단계 — 자동 테스트 및 플레이 모드 검증

다음 순서로 검증합니다.

1. Unity 컴파일 오류 0개 확인
2. 기존 EditMode 테스트 20개 전체 재실행
3. 신규 일정 데이터 해석 테스트 추가 또는 보강
4. 1일차 시작 시 North만 활성화되는지 확인
5. 7번째 웨이브 격파 → 밤 종료 → 8일차 시작 시 South 활성화 확인
6. 14일차 종료 후 East, 21일차 종료 후 West 활성화 확인
7. 비활성 포탈에서는 스폰되지 않고 활성 포탈에서는 데이터에 따라 스폰되는지 확인
8. 7·14·21·28번째 웨이브가 보스로 해석되는지 확인

테스트를 빨리 진행하려면 디버그용 일차 이동을 사용할 수 있지만, 최종 확인에서는 실제 `OnNightStart → WaveManager → AllMonstersDefeated → EndNight → OnDayStart` 흐름을 최소 한 번 통과해야 합니다.

### 7단계 — 실제 사용 씬 반영 판단

`Sangwook_SampleScene`에서 검증이 끝난 뒤 팀과 실제 사용 씬을 확인합니다.

## 9. 의도적으로 남겨 둔 후속 범위

### 9.1 최종 승리 처리

`WaveCycleProgression.AllCyclesCompleted` 이벤트는 존재하지만 소비자가 없습니다. 또한 현재 `CycleManager.EndNight()`는 밤 종료 후 다음 낮을 시작하므로, 28일차 종료 후 그대로 진행하면 29일차가 되고 `WaveCycleRules`가 데이터를 찾지 못합니다.

이번 이슈에서는 승리 처리를 비워 두기로 했으므로 이벤트에 임시 승리 로직을 연결하지 않습니다. 다만 28일차 이후 진행 차단·결과 화면·세이브 처리는 별도 후속 이슈가 필요합니다.

### 9.2 포탈 연출

- 봉인 해제 애니메이션
- 포탈 VFX와 사운드
- 새 포탈 개방 안내 UI

현재는 모두 제외하며, `SetSpawnActive`의 상태 변화 지점을 후속 연출의 연결점으로 사용합니다.

### 9.3 실제 3·4주기 밸런스 데이터

현재는 3주기에 1주기 웨이브를, 4주기에 2주기 웨이브를 직접 재참조합니다. 이 구성과 추가할 임시 포탈 편성은 기능 검증용입니다. 실제 몬스터 구성·수량·간격·보스 프리팹이 확정되면 일정의 참조와 편성 데이터만 교체하고 주기 진행 코드는 유지하는 방향으로 작업합니다.

### 9.4 저장·불러오기 및 씬 재진입

`PortalProgressionController.ApplyCycle()`은 누적 상태를 다시 계산하므로 재적용 자체는 안전하도록 작성되어 있습니다. 그러나 저장된 일차를 불러오거나 씬에 재진입했을 때 올바른 포탈 상태가 복구되는지는 아직 플레이 모드로 검증하지 않았습니다.
