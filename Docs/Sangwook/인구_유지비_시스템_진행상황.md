# 인구 유지비 시스템 구현 및 테스트 현황

작성일: 2026-07-20

대상 이슈: GitHub #64 `[Feature] 인구 유지비`

기준 브랜치: `feature/64-population-maintenance`

이 문서는 인구 유지비, 식량 부족, 기아 감소 시스템의 실제 구현·씬 연결·
검증 상태를 기록한다. 전체 시스템 경계와 장기 정산 순서는
[인구·자원·점령·웨이브 통합 설계](./인구_자원_점령_웨이브_통합_설계.md)를,
인구 API 사용법은 [인구 시스템 연동 가이드](./인구_시스템_연동_가이드.md)를
함께 확인한다.

---

## 1. 이슈 규칙

- 인구 한 명은 아침마다 식량 1을 소비한다.
- 유지비는 배치 여부와 무관하게 `MaxPopulation` 전체를 기준으로 한다.
- 보유 식량은 음수가 되지 않으며, 부족하면 남은 식량까지만 소비한다.
- 식량 부족량만큼 인구가 감소한다.
- 기아 감소 순서는 가용 → 타워 → 생산 → 점령이다.
- 같은 분류 안에서는 등록된 할당 순서대로 한 명씩 순환 감소한다.

```text
RequiredFood = MaxPopulation
ConsumedFood = min(CurrentFood, RequiredFood)
FoodShortage = RequiredFood - ConsumedFood
PopulationLoss = min(FoodShortage, MaxPopulation)
```

## 2. 현재 구조

```text
CycleManager.OnDayStart
  └─ DailySettlementManager
       └─ PopulationUpkeepSystem.TrySettle
            ├─ PopulationManager.MaxPopulation 조회
            ├─ ResourceManager.ConsumeUpTo(Food)
            └─ PopulationManager.TryApplyStarvation(부족량)
```

### 책임

| 시스템 | 책임 |
|---|---|
| `DailySettlementManager` | 아침 정산 시점과 단계 호출 순서, 정산 완료 이벤트 |
| `PopulationUpkeepSystem` | 필요 식량, 실제 소비량, 부족량 계산과 기아 요청 |
| `ResourceManager` | 카탈로그 기반 자원 보유량, 부분 소비, 자원 변경 이벤트 |
| `PopulationManager` | 전체·할당 인구 원본, 우선순위에 따른 기아 감소와 불변식 |

`DailySettlementManager`는 자원이나 인구 값을 직접 수정하지 않는다.

---

## 3. 구현 완료

### 자원

- `ResourceManager.ConsumeUpTo(ResourceType, requestedAmount)`
  - 보유량과 요청량 중 작은 값만 소비한다.
  - 실제 소비량을 반환한다.
  - 기존 `TrySpend`를 사용하므로 `ResourceChanged` 이벤트가 유지된다.

### 인구와 기아

- `PopulationManager.TryApplyStarvation(requestedDeaths, out result)`
- 가용 → 타워 → 생산 → 점령 순서로 감소
- 같은 분류의 여러 할당은 한 명씩 순환 감소
- 실제 감소 인원만큼 `MaxPopulation` 감소
- 처리 완료 후 `PopulationChanged` 한 번 발생
- `StarvationResult`로 분류별 감소량 전달

### 유지비

- `PopulationUpkeepSystem.TrySettle(out result)`
- `PopulationUpkeepResult`로 다음 값을 전달
  - `RequiredFood`
  - `ConsumedFood`
  - `FoodShortage`
  - `PopulationLost`
  - 상세 `StarvationResult`

### 아침 정산

- `DailySettlementManager`가 `CycleManager.OnDayStart`를 구독한다.
- 유지비 시스템 호출 성공 시 `SettlementCompleted`를 발생시킨다.
- 구독과 해제는 `OnEnable`·`OnDisable`에서 대칭으로 처리한다.

## 4. 씬 연결

대상 씬: `Assets/Scenes/Sangwook_DailyWaveScene.unity`

`GameManager` 오브젝트에 다음 컴포넌트가 함께 연결되어 있다.

```text
GameManager
├─ CycleManager
├─ ResourceManager
├─ PopulationManager
├─ PopulationUpkeepSystem
└─ DailySettlementManager
```

현재 테스트 값:

```text
MaxPopulation = 30
Initial Food = 100
```

참조 상태:

```text
GameManager.ResourceManager → 같은 오브젝트의 ResourceManager

PopulationUpkeepSystem
├─ ResourceManager → GameManager
└─ PopulationManager → GameManager

DailySettlementManager
├─ CycleManager → GameManager
└─ PopulationUpkeepSystem → GameManager
```

`PopulationUpkeepDebugTester`도 씬에 배치되어 있으며 유지비·자원·인구
참조가 연결되어 있다.

## 5. 직접 호출 테스트

Play Mode에서 `PopulationUpkeepDebugTester`의 Context Menu를 사용한다.

- `테스트/현재 상태 출력`
- `테스트/유지비 정산 실행`
- `테스트/식량 지급` — 식량 20 지급
- `테스트/식량 전부 제거`

### 식량 충분

초기 상태에서 유지비 정산을 한 번 실행한다.

```text
정산 전: 인구 30, 식량 100
정산 후: 인구 30, 식량 70

RequiredFood = 30
ConsumedFood = 30
FoodShortage = 0
PopulationLost = 0
```

### 식량 부족

식량을 전부 제거하고 식량 20을 지급한 뒤 정산한다.

```text
정산 전: 인구 30, 식량 20
정산 후: 인구 20, 식량 0

RequiredFood = 30
ConsumedFood = 20
FoodShortage = 10
PopulationLost = 10
```

### 타워 할당 우선순위

기존 `PopulationDebugTester` 또는 `TowerPopulationDebugGUI`로 타워 인구를
배치한 뒤 가용 인구보다 큰 식량 부족을 만든다.

```text
예: 전체 30, 가용 27, 타워 3, 식량 2
부족량 28
→ 가용 27 감소
→ 타워 1 감소
→ 최종 전체 2, 타워 배치 2
```

Play Mode를 종료하면 런타임 변경값은 원래 테스트 값으로 돌아간다.

## 6. 검증 상태

| 항목 | 상태 | 비고 |
|---|---|---|
| Unity C# 컴파일 | 통과 | Coplay 기준 오류 0 |
| Play Mode 진입·종료 | 통과 | 씬 실행 가능 |
| 시스템 참조 연결 | 완료 | `Sangwook_DailyWaveScene` |

| 식량 부족·기아 시나리오 | 수동 검증 필요 | 식량 0과 인구 감소 확인 |
| 타워 할당 우선순위 | 수동 검증 필요 | 가용 인구 소진 뒤 타워 감소 확인 |

| EditMode·PlayMode 자동 테스트 | 미착수 | 테스트 어셈블리 필요 |

## 7. 남은 작업

1. 직접 호출로 식량 충분·부족·전멸 시나리오를 검증한다.
2. 타워 인구 배치 후 기아 우선순위를 검증한다.
3. 밤 종료 → 다음 낮 시작에서 유지비가 정확히 한 번 실행되는지 검증한다.
4. 오브젝트 비활성화·재활성화 후 이벤트가 중복 구독되지 않는지 확인한다.
5. 생산 정산이 추가되면 생산 지급 뒤 유지비가 실행되도록 정산 순서를 확장한다.
6. 점령 인구 감소 시 진행 중 원정의 중단·실패 정책을 연결한다.
7. EditMode·PlayMode 자동 테스트를 추가한다.

정식 유지비 결과 UI와 알림 문구는 별도 UI 작업 범위로 남긴다.
