# 인구 유지비·기아 — 설계 기록

> **2026-07-20 스냅샷입니다. 현재 상태는 `Docs/구현현황.md`를 보세요.**
> 규칙 자체는 지금도 그대로이고, 정산이 붙는 **단계와 순서만 달라졌습니다**(아래 참고).
> 대상 이슈: GitHub #64 `[Feature] 인구 유지비`

---

## 확정 규칙 (지금도 그대로)

- 인구 한 명은 아침마다 식량 1을 소비합니다.
- 유지비는 배치 여부와 무관하게 **`MaxPopulation` 전체**를 기준으로 합니다.
- 보유 식량은 음수가 되지 않으며, 부족하면 남은 식량까지만 소비합니다.
- 식량 부족량만큼 인구가 감소합니다.
- 같은 분류 안에서는 등록된 할당 순서대로 한 명씩 순환 감소합니다.

```text
RequiredFood   = MaxPopulation
ConsumedFood   = min(CurrentFood, RequiredFood)
FoodShortage   = RequiredFood - ConsumedFood
PopulationLoss = min(FoodShortage, MaxPopulation)
```

이 계산은 `PopulationUpkeepRules`(순수 static)에 있고 **UI 예측과 실제 정산이 같은 함수를 씁니다.**
표시값과 실제 차감이 어긋나지 않게 하려는 구조이며, EditMode 테스트가 붙어 있습니다.

---

## 책임 분리 (지금도 그대로)

| 시스템 | 책임 |
|---|---|
| `DailySettlementManager` | 정산 시점과 단계 호출 **순서**, 완료 이벤트 |
| `PopulationUpkeepSystem` | 필요 식량·실제 소비량·부족량 계산과 기아 요청 |
| `ResourceManager` | 자원 보유량, 부분 소비, 변경 이벤트 |
| `PopulationManager` | 인구 원본, 우선순위 기아 감소, 불변식 유지 |

`DailySettlementManager`는 자원이나 인구 값을 직접 수정하지 않습니다.

---

## 이후 달라진 것

**① 정산이 붙는 단계가 바뀌었습니다.**
당시엔 `CycleManager.OnDayStart`에 붙어 있었지만, 지금은 **`OnDayStartUpkeep`** 에 붙습니다.
`OnDayStart`(생산 정산) 다음 단계로 분리한 이유는 **그날 생산분이 반영된 재고를 기준으로 소비**해야
하기 때문입니다. 순서가 반대면 아침에 생산한 식량을 못 쓰고 굶습니다.

**② 기아 순서에 두 분류가 끼어들었습니다.**
`가용 → 타워 → 생산 → 점령` → **`가용 → 타워 → 연구 → 랜드마크 → 생산 → 점령`**.
랜드마크가 생산보다 앞인 이유: 랜드마크 가동은 보너스라 끊겨도 회복되지만,
생산 인구를 먼저 빼면 다음날 식량이 더 줄어 기아가 커지는 악순환이 됩니다.

**③ 지역 자재 유지비가 뒤에 추가됐습니다.**
설원·암석에 지은 건물은 배치 인구만큼 나무·돌을 냅니다(`TerrainUpkeepSystem`).
식량 **다음에** 정산하는데, 기아로 인구가 줄면 그만큼 자재 유지비도 줄어야 자연스럽기 때문입니다.

**④ 1일차에는 유지비를 걷지 않습니다.** 정산할 전날이 없기 때문입니다.
