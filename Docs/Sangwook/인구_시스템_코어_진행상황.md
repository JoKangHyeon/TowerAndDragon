## 2. 파일 구성

### `Assets/Scripts/Population/PopulationAssignmentType.cs`

할당 목적의 큰 분류를 정의한다.

```text
None
Tower
Production
Conquest
```

농장·벌목장·광산은 서로 다른 할당 객체를 사용하지만 모두 `Production`
분류다. 이 enum은 구체적인 건물 종류가 아니라 기아 정책과 시스템 책임을
구분하기 위한 값이다.

### `Assets/Scripts/Population/PopulationAllocation.cs`

타워나 생산 시설 한 개, 점령 원정 한 개의 인구 배치 상태를 나타낸다.

- `AssignmentType`: 타워·생산·점령 분류
- `Capacity`: 해당 사용처의 최대 배치 인구
- `AssignedPopulation`: 현재 배치 인구
- `AvailableCapacity`: 추가로 받을 수 있는 인구
- `StaffingRatio`: `AssignedPopulation / Capacity`

생성자와 `Assign`, `Unassign`은 `internal`이다. 외부 시스템은
`PopulationManager`의 공개 `Try` API를 사용한다. `AssignedPopulation`의
setter도 private이므로 외부에서 직접 대입할 수 없다.

### `Assets/Scripts/Population/PopulationState.cs`

특정 시점의 전체 인구 상태를 전달하는 읽기 전용 스냅숏이다.

- `MaxPopulation`: 플레이어가 보유한 살아 있는 전체 인구
- `AssignedPopulation`: 모든 등록 할당의 현재 배치량 합
- `AvailablePopulation`: `MaxPopulation - AssignedPopulation`

가용 인구는 생성자 인자로 따로 받지 않고 파생값으로 계산한다. 따라서
최대·할당·가용 값이 서로 어긋나는 상태를 만들지 않는다.

### `Assets/Scripts/Population/PopulationManager.cs`

전체 인구와 모든 할당을 관리하는 단일 진실 공급원이다.

- `_maxPopulation`은 씬에서 초기값을 설정한다.
- `_allocations`는 런타임에 생성된 할당 객체를 보관한다.
- `AssignedPopulation`은 등록된 할당을 순회해 계산한다.
- `AvailablePopulation`은 최대 인구에서 할당 인구를 빼서 계산한다.
- 모든 변경은 검증 성공 후 적용한다.
- 실제 상태가 바뀌면 `PopulationChanged`를 발행한다.

### `Assets/Scripts/Population/PopulationDebugTester.cs`

씬에서 인구 코어를 수동 검증하는 테스트 전용 컴포넌트다.

- 시작 시 타워 할당 한 개를 생성한다.
- `PopulationChanged`를 구독해 최대·할당·가용 인구를 로그로 출력한다.
- ContextMenu로 타워 배치, 회수와 최대 인구 증가를 실행한다.
- 파괴 시 이벤트 구독을 해제한다.

이 파일의 로그와 ContextMenu 문자열은 테스트·디버그 코드이므로 프로젝트의
코드 리터럴 규칙 예외에 해당한다.

## 3. 핵심 불변식

항상 다음 조건을 유지해야 한다.

```text
MaxPopulation >= 0
AssignedPopulation >= 0
AssignedPopulation <= MaxPopulation
AvailablePopulation = MaxPopulation - AssignedPopulation
AvailablePopulation >= 0
Allocation.AssignedPopulation >= 0
Allocation.AssignedPopulation <= Allocation.Capacity
```

`PopulationAllocation.Assign`과 `Unassign` 자체는 단순 증감만 수행한다.
범위 검증은 반드시 `PopulationManager`가 먼저 수행한다.

## 4. 공개 API와 반환 의미

### `TryCreateAllocation(type, capacity, out allocation)`

- `None` 타입이면 실패한다.
- 수용량이 0 이하면 실패한다.
- 성공 시 현재 배치량 0인 할당을 등록하고 반환한다.
- 등록만으로 전체 인구 상태는 바뀌지 않으므로 이벤트를 발생시키지 않는다.

### `TryAssign(allocation, amount)`

- 등록되지 않은 할당이면 실패한다.
- 요청량이 0 이하면 실패한다.
- 개별 할당의 남은 수용량보다 크면 실패한다.
- 전체 가용 인구보다 크면 실패한다.
- 성공 시 인구를 배치하고 이벤트를 한 번 발생시킨다.

### `TryUnassign(allocation, amount)`

- 등록되지 않은 할당이면 실패한다.
- 요청량이 0 이하이거나 현재 배치량보다 크면 실패한다.
- 성공 시 인구를 회수하고 이벤트를 한 번 발생시킨다.

### `TryIncreaseMaxPopulation(amount)`

- 증가량이 0 이하면 실패한다.
- 성공 시 최대 인구를 증가시키고 이벤트를 한 번 발생시킨다.
- 점령 완료 인구 보상 연결 시 사용할 예정이다.

### `TryReleaseAll(allocation)`

- 등록되지 않은 할당이면 실패한다.
- 이미 배치 인구가 0이면 목표가 달성된 상태이므로 성공한다.
- 배치 인구가 있으면 전부 회수하고 이벤트를 한 번 발생시킨다.
- 배치 인구가 0인 경우 상태가 바뀌지 않으므로 이벤트를 발생시키지 않는다.

### `TryRemoveAllocation(allocation)`

- 등록되지 않은 할당이면 실패한다.
- 배치 인구가 있으면 먼저 전부 반환한다.
- 할당을 관리 목록에서 제거하고 성공한다.
- 제거 후 같은 할당으로 배치·회수를 요청하면 실패한다.

## 5. 이벤트 흐름

```text
외부 시스템
→ PopulationManager의 Try API 호출
→ 등록 여부·수용량·전체 가용 인구 검증
→ PopulationAllocation 내부 값 변경
→ CurrentState 생성
→ PopulationChanged(CurrentState)
→ UI 또는 사용처가 상태 갱신
```

실패한 요청에서는 값과 이벤트가 모두 변경되지 않아야 한다.

## 6. 테스트 씬 구성

대상 씬: `Assets/Scenes/Sangwook_PopulationScene.unity`

### 씬 오브젝트

- `PopulationManager`
  - `PopulationManager` 컴포넌트 연결
  - `_maxPopulation` 테스트값 10
- `PopulationDebugTester`
  - `PopulationDebugTester` 컴포넌트 연결
  - `_populationManager`가 씬의 `PopulationManager`를 참조

### 현재 테스트 상수

```text
타워 수용량: 4
한 번의 배치량: 3
한 번의 회수량: 1
최대 인구 증가량: 5
```

한 번 3명을 배치하면 타워의 남은 수용량은 1이다. 같은 메뉴를 다시
실행하면 다시 3명을 요청하므로 용량 초과로 `false`가 반환되는 것이 정상이다.

### 확인된 기본 시나리오

```text
초기: 최대 10, 할당 0, 가용 10
타워 3명 배치: 최대 10, 할당 3, 가용 7
같은 배치 재시도: 실패, 상태 변경 없음
타워 1명 회수: 최대 10, 할당 2, 가용 8
최대 인구 5 증가: 최대 15, 할당 2, 가용 13
```

## 7. 남은 테스트 및 다음 작업

### 우선순위 1 — 테스트 컴포넌트 보완

- `TryReleaseAll` ContextMenu 추가
- `TryRemoveAllocation` ContextMenu 추가
- 제거한 할당에 다시 배치를 요청해 실패 확인
- 농장·벌목장·광산용 별도 `Production` 할당 추가
- 여러 할당이 하나의 `AvailablePopulation`을 공유하는지 확인

농장·벌목장·광산을 enum에 추가하지 않는다. 세 사용처마다 별도의
`PopulationAllocation`을 생성하고 분류만 `Production`으로 지정한다.

### 우선순위 2 — EditMode 자동 테스트

Unity Test Framework는 프로젝트에 설치되어 있다. 다음 경계 조건을 자동화한다.

- `None` 및 0 이하 수용량 생성 실패
- 정상 할당 생성
- 개별 수용량 초과 배치 실패
- 전체 가용 인구 초과 배치 실패
- 현재 배치량 초과 회수 실패
- 전체 반환 후 가용 인구 복구
- 비어 있는 할당 전체 반환 성공 및 이벤트 미발생
- 할당 제거 후 재사용 실패
- 성공한 변경에서만 이벤트 발생

### 우선순위 3 — #61 완료 및 API 공유

자동 테스트와 씬 재검증이 끝나면 #61의 완료 기준을 충족한 것으로 판단한다.
그 뒤 점령 #65, 생산 #22 담당자가 다음 계약을 사용하도록 공유한다.

- 인구는 `ResourceCost`로 소비하지 않는다.
- 점령 시작 시 `Conquest` 할당에 예약한다.
- 점령 완료 시 `TryReleaseAll` 또는 제거 경로로 반환한다.
- 점령 보상은 `TryIncreaseMaxPopulation`으로 지급한다.
- 생산 시설은 각자 `Production` 할당을 가진다.

### 우선순위 4 — #63 타워 인구 시스템

- `TowerData`에 최대 필요 인구 추가
- 타워별 `Tower` 할당 생성
- 충원율에 따른 공격 간격 적용
- 인구 0일 때 공격 중지
- 전투 비활성화 중 인구 유지
- 철거 시 할당 전체 반환 및 제거

## 9. 알려진 정리 항목

기능상 차단 문제는 아니지만 다음 작업 전에 정리하는 것을 권장한다.

- `PopulationDebugTester.AssignTowerPouplation` 오타를
  `AssignTowerPopulation`으로 수정
- `PopulationDebugTester.UnAssignTowerPopulation`을
  `UnassignTowerPopulation`으로 수정

- `PopulationDebugTester.Start`에 명시적인 `private` 접근 제한자 추가
- `PopulationAllocation.Assign (int amount)`의 메서드명 뒤 공백 제거
- 프로퍼티와 괄호 공백을 프로젝트 C# 스타일에 맞게 정리
- `TryIncreaseMaxPopulation`의 정수 오버플로 방어는 필요 시 추가
