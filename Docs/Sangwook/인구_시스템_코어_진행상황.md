## 핵심 모델 (지금도 그대로)

인구는 소비해서 사라지는 자원이 아니라, 사용처에 배치했다가 회수하는 **공용 인력 풀**입니다.

```text
MaxPopulation = AssignedPopulation + AvailablePopulation
```

- `MaxPopulation` — 살아 있는 전체 인구
- `AssignedPopulation` — 모든 등록 할당에 배치된 인구의 합
- `AvailablePopulation` — 아직 어디에도 배치되지 않은 인구

**별도의 `CurrentPopulation`을 두지 않습니다.** 기아로 죽으면 `MaxPopulation` 자체가 줄어야 하기 때문입니다.

항상 유지되는 불변식:

```text
MaxPopulation >= 0
0 <= AssignedPopulation <= MaxPopulation
AvailablePopulation = MaxPopulation - AssignedPopulation
0 <= Allocation.AssignedPopulation <= Allocation.Capacity
```

값 변경은 **반드시 `PopulationManager`를 거칩니다.** 외부에서 숫자를 직접 만지면 위 불변식이 깨집니다.

## 이후 확장된 부분 (당시엔 없던 것)

- 배치 분류가 타워/생산/점령 3종 → **6종**(+ 연구, 랜드마크, None)으로 늘었습니다.
- `Allocation.Capacity`가 고정값이 아니라 **조회할 때마다 연구 배율을 거칩니다**
  (`IPopulationCapacityModifierQuery`). 정원이 줄면 `ReconcileAssignedPopulation`으로 초과분만 회수합니다.
- `StaffingRatio`에 `Clamp01`이 걸렸습니다 — 정원이 줄어 배치>정원이 되면 타워 공속 계산에서
  1을 넘겨 비정상적으로 빨라지기 때문입니다.
- 배치·회수의 클램프 처리를 `PopulationAssignmentRules`로 뽑아 테스트를 붙였습니다.

## 아직 유효한 주의사항

- `GridMap.RemoveBuilding`을 거치지 않고 건물을 직접 `Destroy`하면 Coordinator가 제거 이벤트를
  받지 못해 할당이 남습니다. **파괴 경로를 하나로 유지해야 합니다.**
- `PopulationChanged`는 전체 상태만 전달합니다. "무엇이 왜 바뀌었는지"가 필요한 UI는
  별도 정보가 필요합니다.
- `TryIncreaseMaxPopulation`에 정수 오버플로 방어가 없습니다.
- 세이브는 `PopulationAllocation` 객체가 아니라 **사용처별 배치 수치**를 저장하고 로드 시
  재구성하는 방식이어야 합니다. — 현재 총 인구는 그렇게 복원되지만,
  **건물 배치 복원이 아직 없어 건물별 배치 인구는 복원되지 않습니다**(`Docs/구현현황.md` §6).
