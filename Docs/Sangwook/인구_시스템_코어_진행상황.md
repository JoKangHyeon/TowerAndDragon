## 2. 핵심 모델

인구는 소비해서 사라지는 자원이 아니라 사용처에 배치했다가 회수하는 공용
인력 풀이다.

```text
MaxPopulation = AssignedPopulation + AvailablePopulation
```

- `MaxPopulation`: 플레이어가 보유한 살아 있는 전체 인구
- `AssignedPopulation`: 모든 등록 할당에 배치된 인구의 합
- `AvailablePopulation`: 아직 어떤 사용처에도 배치되지 않은 인구

별도의 `CurrentPopulation`은 두지 않는다. 인구가 기아로 사망하면 향후
`MaxPopulation` 자체를 감소시켜야 한다.

항상 다음 조건을 유지해야 한다.

```text
MaxPopulation >= 0
AssignedPopulation >= 0
AssignedPopulation <= MaxPopulation
AvailablePopulation = MaxPopulation - AssignedPopulation
Allocation.AssignedPopulation >= 0
Allocation.AssignedPopulation <= Allocation.Capacity
```

## 3. 구현 파일과 역할

### 인구 코어

#### `Assets/Scripts/Population/PopulationManager.cs`

전체 인구와 등록된 모든 할당을 관리하는 단일 진실 공급원이다.

- `_maxPopulation`: 살아 있는 전체 인구
- `AssignedPopulation`: 모든 할당의 배치량 합
- `AvailablePopulation`: 최대 인구에서 할당 인구를 뺀 파생값
- `CurrentState`: UI와 이벤트 전달용 전체 상태 스냅숏
- `PopulationChanged`: 성공한 상태 변경 후 발생하는 이벤트
- 모든 변경은 공개 `Try` API를 통과한다.

#### `Assets/Scripts/Population/PopulationAllocation.cs`

타워 한 개, 생산 시설 한 개, 점령 원정 한 개와 같은 개별 사용처의 런타임
배치 상태다.

- `AssignmentType`
- `Capacity`
- `AssignedPopulation`
- `AvailableCapacity`
- `StaffingRatio`

생성자와 증감 메서드는 `internal`이다. 다른 시스템에서 직접 생성하거나
수치를 변경하지 않고 `PopulationManager`를 통해야 한다.

#### `Assets/Scripts/Population/PopulationState.cs`

특정 시점의 전체·할당·가용 인구를 전달하는 읽기 전용 스냅숏이다. UI는
가능하면 이 값을 이벤트로 받아 갱신한다.

#### `Assets/Scripts/Population/PopulationAssignmentType.cs`

인구 사용처의 상위 정책 분류다.

```text
None
Tower
Production
Conquest
```

농장·벌목장·광산을 enum에 각각 추가하지 않는다. 각 시설은 서로 다른
할당을 가지되 모두 `Production`으로 분류한다.

### 타워 연결

#### `Assets/Scripts/Buildings/Tower/TowerData.cs`

`PopulationCapacity`를 제공한다. 현재 `TD_Normal.asset`의 테스트 수용량은
2명이다. 이 값은 최대 필요 인구이며 현재 배치량은 데이터 에셋에 저장하지
않는다.

#### `Assets/Scripts/Buildings/Tower/TowerPopulation.cs`

타워 한 개와 해당 `PopulationAllocation`을 연결하는 어댑터다.

- `Initialize`: `Tower` 할당 생성
- `TryAssign`, `TryUnassign`: Manager에 배치·회수 요청
- `Release`: 전체 인구 반환 후 할당 제거
- `AssignedPopulation`, `Capacity`, `StaffingRatio`: UI와 전투 계층이 읽을 값

타워 체력이 0이 되어 비활성화되어도 `Release`를 호출하지 않는다. 타워가
수리되는 동안에도 인구가 유지되는 기획을 지키기 위해서다.

#### `Assets/Scripts/Population/TowerPopulationCoordinator.cs`

`GridMap`과 `PopulationManager`가 서로의 세부 책임을 알지 않도록 중간에서
타워 생명주기를 연결한다.

```text
건물 등록 이벤트
→ 건물이 Tower인지 확인
→ TowerPopulation.Initialize

건물 제거 직전 이벤트
→ TowerPopulation.Release
→ 인구 반환 및 할당 제거
```

#### `Assets/Scripts/Grid/GridMap.cs`

다음 범용 건물 생명주기 이벤트가 추가되었다.

- `OnBuildingAdded`: 건물이 GridMap에 정상 등록된 후 발생
- `OnBuildingRemoving`: 제거 가능한 건물을 실제 제거하기 직전에 발생

`GridMap`은 타워나 인구 처리 방법을 알지 않고 시점만 전달한다. 건물 이동은
동일 인스턴스의 생명주기가 유지되므로 이 두 이벤트를 발생시키지 않는다.

### 테스트 도구

#### `Assets/Scripts/Population/PopulationDebugTester.cs`

코어 API를 ContextMenu와 로그로 확인하는 초기 수동 테스트 도구다. 실제
타워 연동이 추가된 뒤에도 코어 단독 경계 검증용으로 남아 있다.

#### `Assets/Scripts/UI/TowerPopulationDebugGUI.cs`

정식 UI가 아닌 IMGUI 기반 테스트 도구다.

- `UI_Canvas`와 독립된 씬 루트 오브젝트에 부착
- 선택한 타워의 할당량·수용량·충원율 표시
- 전체·할당·가용 인구 표시
- 낮에만 `+1`, `-1`, `전체 회수` 가능
- 마지막으로 선택한 타워를 기억해 GUI 클릭 후에도 테스트 가능

정식 UI 구현 시 이 스크립트의 문자열이나 레이아웃을 확장하지 않고,
프로젝트 UI 구조와 스트링테이블을 사용하는 별도 UI를 만든다.

## 4. 현재 공개 API 계약

| API | 성공 조건 | 상태 변경과 이벤트 |
|---|---|---|
| `TryCreateAllocation(type, capacity, out allocation)` | `type != None`, `capacity > 0` | 할당 등록만 수행, 이벤트 없음 |
| `TryAssign(allocation, amount)` | 등록됨, 양수, 수용량·가용 인구 이내 | 배치 후 이벤트 1회 |
| `TryUnassign(allocation, amount)` | 등록됨, 양수, 현재 배치량 이내 | 회수 후 이벤트 1회 |
| `TryReleaseAll(allocation)` | 등록된 할당 | 배치량이 있으면 전부 반환하고 이벤트 1회 |
| `TryRemoveAllocation(allocation)` | 등록된 할당 | 먼저 전부 반환한 뒤 등록 제거 |
| `TryIncreaseMaxPopulation(amount)` | 양수 | 최대 인구 증가 후 이벤트 1회 |
| `TryApplyStarvation(requestedDeaths, out result)` | 양수, 현재 인구 존재 | 우선순위에 따라 감소 후 결과와 이벤트 1회 |

주의사항:

- Manager가 만들지 않은 할당이나 이미 제거한 할당은 사용할 수 없다.
- `TryReleaseAll`은 이미 0명인 경우에도 성공하지만 이벤트는 발생하지 않는다.
- `TryRemoveAllocation`은 0명인 할당 제거 자체에 대해서는 이벤트를 발생시키지
  않는다. 전역 인구 값이 바뀌지 않기 때문이다.
- 현재 이벤트에는 변경된 할당과 변경 원인이 포함되지 않고 전체 상태만
  전달된다.
- 기아 감소는 가용 → 타워 → 생산 → 점령 순서이며 같은 분류의 할당은 등록
  순서대로 한 명씩 순환 감소한다.

## 6. 확인된 테스트 흐름

```text
낮에 타워 건설
→ GridMap.OnBuildingAdded
→ TowerPopulationCoordinator
→ TowerPopulation 초기화와 수용량 2 할당 생성
→ 타워 선택
→ 우측 상단 IMGUI 표시
→ +1 배치 또는 -1/전체 회수
→ PopulationManager 상태와 타워 충원율 갱신
→ 타워 철거
→ GridMap.OnBuildingRemoving
→ 할당 인구 전체 반환 및 할당 제거
```

밤에는 타워 인구 변경 버튼이 비활성화된다. 타워가 전투 중 비활성화되어도
할당은 유지되며, 플레이어의 회수 또는 철거에서만 반환한다.

### 아직 자동으로 검증하지 않은 경계

- 같은 할당에 수용량보다 많이 배치
- 여러 타워가 하나의 가용 인구를 공유하는 경우
- 인구가 배치된 타워 철거 시 정확히 한 번만 반환되는지
- 직접 `Destroy`된 타워의 정리 경로
- 씬 시작 전에 이미 배치된 인구 사용 건물의 초기화 순서
- 낮·밤 전환 직전 GUI 입력 경계

## 7. 다음 작업 우선순위

### 우선순위 1 — 자동 테스트로 인구 코어 고정

- 생성·배치·회수·전체 반환·제거의 성공/실패 경계
- 성공한 상태 변경에서만 이벤트 발생
- 여러 할당의 전체 합과 가용 인구 불변식
- 타워 철거 시 중복 반환 방지

### 우선순위 2 — #63 타워 전투 연결 완료

- `TowerPopulation.StaffingRatio`를 공격 계산 계층에서 읽는다.
- 충원율 0이면 공격하지 않는다.
- 50% 충원 시 공격 간격 2배, 100% 충원 시 기본 간격을 적용한다.
- 체력 비활성 상태와 인구 부족 상태를 별도로 판정한다.
- 비활성 타워는 인구를 유지하고 철거 시에만 반환한다.

### 우선순위 3 — 생산 시설 연결

- 시설별 `Production` 할당을 생성한다.
- 데이터 에셋에 인구 수용량과 기본 생산량을 둔다.
- `floor(BaseProduction * StaffingRatio)`로 생산량을 계산한다.
- 건설·철거 생명주기는 타워처럼 Coordinator 계층에서 연결한다.

### 우선순위 4 — 점령 연결

- 원정별 `Conquest` 할당을 생성하고 필요 인구를 예약한다.
- 완료·취소·런 종료에서 할당을 한 번만 정리한다.
- 점령 완료 보상을 유지비 계산 전에 `TryIncreaseMaxPopulation`으로 적용한다.
- 자원 지불과 인구 예약의 중간 실패를 되돌릴 조정 계층을 둔다.

## 8. 알려진 제한과 주의사항

- `GridMap.RemoveBuilding`을 거치지 않고 타워를 직접 `Destroy`하면 현재
  Coordinator가 제거 이벤트를 받지 못한다.
- `TowerPopulation.Release`에는 `OnDestroy` 자동 정리 경로가 없다. 정식
  파괴 경로를 하나로 제한하거나 안전한 중복 방지 정리가 필요하다.
- `TowerPopulationCoordinator`가 구독하기 전에 이미 등록된 타워가 있다면
  별도 초기 스캔이 필요할 수 있다.
- 현재 `PopulationChanged`는 전체 상태만 전달하므로 복잡한 UI에는 변경
  대상과 원인 정보가 추가로 필요할 수 있다.
- `PopulationDebugTester`에는 메서드명과 공백 스타일 정리 항목이 남아 있다.
- `TryIncreaseMaxPopulation`의 정수 오버플로 방어는 아직 없다.
- 정식 저장 데이터에는 `PopulationAllocation` 객체 자체보다 사용처별 배치
  수치를 저장하고 로드 시 할당을 재구성하는 방식이 필요하다.
