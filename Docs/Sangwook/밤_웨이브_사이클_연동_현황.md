## 지금도 유효한 설계 결정

### 밤을 끝내는 것은 "전멸"이지 "스폰 완료"가 아니다

```text
낮 종료 → CycleManager.StartNight() → OnNightStart
  → 웨이브 실행 (포탈별 병렬 스폰)
  → AllSpawnsCompleted     ← 아직 밤은 안 끝난다
  → 생성된 몬스터 전멸 대기
  → AllMonstersDefeated    ← 이걸로 밤을 끝낸다
  → CycleManager.EndNight() → OnNightEnd → StartDay()
```

`AllSpawnsCompleted`와 `AllMonstersDefeated`를 **의미가 다른 두 이벤트로 분리**한 것이 핵심입니다.
적 생성이 다 끝나도 살아 있는 적이 남아 있을 수 있어서, 밤 종료 판정에는 후자만 씁니다.
이 구조는 지금도 그대로입니다.

### CycleManager는 웨이브 시스템을 직접 참조하지 않는다
UnityEvent로만 연결합니다. 덕분에 웨이브가 없는 테스트 씬에서도 낮/밤 전환이 그대로 돕니다.
(이 방침이 나중에 `IDayEndBlockQuery`·`OnDayStartUpkeep` 같은 확장 지점으로 이어졌습니다.)

### 웨이브 중복 실행 방지는 스폰이 아니라 밤 전체를 덮는다
`IsRunning`은 스폰이 끝난 뒤에도 **전멸할 때까지** 유지됩니다. 스폰 완료 시점에 풀면
같은 밤에 웨이브가 두 번 돌 수 있습니다.

### 취소는 정상 종료 흐름이다
웨이브는 `destroyCancellationToken`에 연결된 토큰으로 돌고, 취소 예외를 오류가 아니라
정상 종료로 처리합니다. 플레이 모드를 나갈 때 예외가 새지 않게 하려는 처리입니다.

## 당시 미해결로 남겨 둔 것 중 아직 유효한 것

- 몬스터 생명주기가 `Destroy` 기반입니다. **오브젝트 풀링을 넣으면** 전멸 판정을
  "목록에서 사라졌는가"가 아니라 반환 이벤트 기반으로 바꿔야 합니다.
- 게임오버가 나면 진행 중인 웨이브를 어떻게 정리할지 — 현재는 `CycleManager.EndNight`이
  `IsGameEnded`를 보고 다음 낮으로 넘어가지 않는 선까지만 처리합니다.
