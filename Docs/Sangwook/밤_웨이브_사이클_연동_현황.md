# 밤 웨이브·사이클 연동 구현 현황

작성일: 2026-07-15  
대상 이슈: GitHub #46 `[Feature] 적 스폰 기능 확장`

## 1. 작업 범위

현재 작업은 정식 일차별 웨이브 진행 시스템이 아닌 프로토타입 테스트 범위로 구현했다.

- 낮 종료 후 밤이 시작되면 지정된 `WaveDefinitionSO`의 웨이브를 자동으로 시작한다.
- 하나의 웨이브 데이터에 포함된 여러 활성 포탈에서 적을 생성한다.
- 해당 웨이브가 생성한 모든 몬스터가 죽으면 밤을 종료하고 다음 낮을 시작한다.
- 일차별 웨이브 선택, 주기, 보스 웨이브, 난이도 공식은 현재 범위에 포함하지 않는다.

## 2. 전체 동작 흐름

```text
낮 종료 입력
  → CycleManager.EndDay()
  → CycleManager.StartNight()
  → OnNightStart 이벤트
  → WaveTestStarter.StartWave(int)
  → WaveManager.StartWaveAsync(WaveDefinitionSO)
  → 활성 포탈별 스폰 작업 병렬 실행
  → 모든 스폰 완료
  → 생성된 몬스터가 모두 죽을 때까지 대기
  → AllMonstersDefeated 이벤트
  → CycleManager.EndNight()
  → OnNightEnd 이벤트
  → CycleManager.StartDay()
```

## 3. 구성 요소별 구현 내용

### CycleManager

파일: `Assets/Scripts/Managers/CycleManager.cs`

- `StartNight()`에서 현재 상태를 `Night`로 변경한 뒤 `OnNightStart`를 발생시킨다.
- `EndNight()`에서 `OnNightEnd`를 발생시킨 뒤 `StartDay()`를 호출한다.
- 웨이브 시스템을 직접 참조하지 않고 UnityEvent를 통해 연결한다.

현재 밤 종료 구현:

```csharp
public void EndNight()
{
    OnNightEnd?.Invoke(_gameManager.CurrentRun.CurrentCycle);
    StartDay();
}
```

### WaveTestStarter

파일: `Assets/Scripts/Wave_Main/WaveTestStarter.cs`

- 테스트용 웨이브 시작 연결 컴포넌트다.
- 활성화될 때 `CycleManager.OnNightStart`를 구독한다.
- 밤 시작 이벤트를 받으면 인스펙터에서 지정한 `WaveDefinitionSO`를 `WaveManager`에 전달한다.
- 비활성화될 때 이벤트 구독을 해제한다.
- 기존처럼 씬 시작 즉시 웨이브를 실행하지 않는다.

현재 연결 방식:

```csharp
private void StartWave(int _)
{
    _waveManager.StartWaveAsync(_waveDefinition).Forget();
}
```

### WaveManager

파일: `Assets/Scripts/Managers/WaveManager.cs`

#### 복수 진격로 실행

- `WaveDefinitionSO.PortalWaves`에 정의된 포탈별 데이터를 읽는다.
- 포탈 ID와 씬의 `Portal`을 연결한다.
- 비활성 포탈은 건너뛴다.
- 활성 포탈의 스폰 작업을 `UniTask.WhenAll`로 함께 실행한다.

#### 중복 실행 방지

- `IsRunning`이 `true`이면 새 웨이브 시작 요청을 거부한다.
- `IsRunning`은 스폰뿐 아니라 모든 몬스터가 죽을 때까지 유지된다.

#### 생성 몬스터 추적

- `SpawnMonster()`에서 생성한 `BaseMonster`를 `_spawnedMonsters`에 등록한다.
- 새 웨이브를 시작하기 전에 이전 추적 목록을 비운다.
- 모든 포탈의 스폰 완료 후 `AreAllMonstersDefeated()`를 매 프레임 확인한다.
- 참조가 파괴되었거나 `IsDead`인 몬스터를 목록에서 제거한다.
- 목록이 비면 `_allMonstersDefeated` 이벤트를 발생시킨다.

전멸 판정:

```csharp
private bool AreAllMonstersDefeated()
{
    _spawnedMonsters.RemoveAll(
        monster => monster == null || monster.IsDead);

    return _spawnedMonsters.Count == 0;
}
```

#### 취소 처리

- 웨이브 실행은 `destroyCancellationToken`과 연결된 토큰을 사용한다.
- `CancelWave()` 또는 `WaveManager` 파괴 시 스폰 및 전멸 대기가 취소된다.
- 취소는 정상 종료 흐름으로 처리한다.

## 4. 이벤트 의미

| 이벤트 | 발생 시점 | 현재 용도 |
|---|---|---|
| `CycleManager.OnNightStart` | 밤 상태로 전환할 때 | 테스트 웨이브 시작 |
| `WaveManager.AllSpawnsCompleted` | 모든 포탈의 몬스터 생성이 끝났을 때 | 현재 연결 없음 |
| `WaveManager.AllMonstersDefeated` | 스폰된 몬스터가 모두 죽었을 때 | `CycleManager.EndNight()` 호출 |
| `CycleManager.OnNightEnd` | 밤이 끝날 때 | 추후 정산 시스템 연결 지점 |

`AllSpawnsCompleted`와 `AllMonstersDefeated`는 의미가 다르다. 적 생성이 모두 끝나도 살아 있는 적이 남아 있을 수 있으므로 밤 종료에는 `AllMonstersDefeated`를 사용한다.

## 5. 씬 설정 현황

`Assets/Scenes/SampleScene.unity`에 다음 연결이 저장되어 있다.

- `WaveTestStarter._cycleManager` → 씬의 `CycleManager`
- `WaveTestStarter._waveManager` → 씬의 `WaveManager`
- `WaveTestStarter._waveDefinition` → 테스트용 `WaveDefinitionSO`
- `WaveManager._allMonstersDefeated` → `CycleManager.EndNight()`

웨이브 실행을 위해 `WaveManager._portals`와 각 포탈의 다음 참조도 유효해야 한다.

- 고유한 `PortalDirectionId`
- `SpawnPoint`
- `GroundPath`
- `MainCastle`
- 활성화 여부

## 7. 테스트 체크리스트

1. 플레이 모드 진입 시 낮에는 몬스터가 자동 생성되지 않는지 확인한다.
2. 낮 종료 입력 후 `CurrentCycle`이 `Night`로 바뀌는지 확인한다.
3. 지정된 테스트 웨이브가 한 번만 시작되는지 확인한다.
4. 웨이브 데이터에 지정된 여러 활성 포탈에서 적이 생성되는지 확인한다.
5. 일부 몬스터가 살아 있는 동안 밤 상태가 유지되는지 확인한다.
6. 마지막 몬스터 사망 후 `AllMonstersDefeated`가 발생하는지 확인한다.
7. 이벤트를 통해 `CycleManager.EndNight()`가 호출되는지 확인한다.
8. `OnNightEnd` 발생 후 다음 낮으로 전환되는지 확인한다.
9. 웨이브 실행 중 밤 시작을 다시 요청해도 중복 웨이브가 실행되지 않는지 확인한다.
10. 플레이 모드 종료 시 취소 관련 예외가 발생하지 않는지 확인한다.

## 8. 현재 범위의 제한 사항

- 웨이브 데이터는 `WaveTestStarter`에 지정한 하나의 `WaveDefinitionSO`를 반복 사용한다.
- 일차 및 주기에 따른 웨이브 선택은 구현하지 않았다.
- 몬스터 전멸은 `WaveManager`가 직접 생성한 몬스터 목록만 기준으로 판단한다.
- 몬스터가 성에 도달했을 때의 최종 공격 및 제거 정책은 별도 적 시스템 구현 범위다.
- 메인 성 파괴로 게임오버가 발생했을 때 진행 중인 웨이브와 사이클을 어떻게 종료할지는 아직 연결하지 않았다.
- 현재 방식은 `Destroy` 기반 몬스터 생명주기에 맞춘 테스트 구현이다. 오브젝트 풀링을 적용하면 반환 이벤트 기반 추적으로 변경해야 한다.

## 9. 후속 확장 시 고려 사항

프로토타입 검증 후에는 다음 기능을 별도 작업으로 확장한다.

- 일차별 `WaveDefinitionSO` 선택 데이터
- 주기 마지막 날 보스 웨이브 선택
- 점령지 가치에 따른 난이도 보정
- 게임오버 발생 시 웨이브 취소
- 오브젝트 풀링과 명시적인 몬스터 제거 이벤트
- 밤 종료 후 자원·연구·점령 정산 연결

위 항목은 현재 이슈 #46의 테스트 범위에서는 구현하지 않는다.
