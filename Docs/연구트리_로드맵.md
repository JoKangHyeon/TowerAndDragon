# 연구 트리 로드맵 (초안)

> 작성일: 2026-07-23 / 갱신: 2026-07-23 (① 연구소·RP·즉시 적용 모델, ② 용 분리 → 연구는 3갈래)
> 기준 문서: `기획종합_v2.md` §14(연구), §5·§8·§9·§11
> 본 문서는 **연구 시스템(3갈래)** 만 다룹니다. **용 스킬트리는 별도 문서**: `용_스킬트리_로드맵.md`.
> 구체 수치(RP·자원 코스트)는 예시이며 밸런싱 대상. 기획 `[미정]` 항목은 확정 구현하지 않습니다.

## 1. 설계 목표

- 이미지 레퍼런스(Frostpunk 기술 체계도) 느낌: **상단 탭(갈래) + 좌측 티어(단계) + 선행 노드 연결선 + 노드별 코스트**.
- 기획 컨셉 "낮의 선택이 밤의 생존을 결정한다"에 맞춰, 연구가 **낮의 자원·인구 투자처 중 하나**로 기능.
- 확장(점령) → 자원·인구 확보 → 연구 → 더 강한 방어/생산의 **순환**에 연구를 끼워 넣음.

---

## 2. 갈래(탭) 구성 — 3갈래

연구소 창은 **3개 탭**으로 구성합니다. 용 스킬트리는 이 창에 포함되지 않으며 **완전히 다른 창**입니다.

| 탭 | 성격 | 핵심 축 |
|---|---|---|
| **타워** | 방어력 강화 | 스탯 강화 / 필요 인구 감소 / 속성 타워·유틸 |
| **생산** | 생산 시설 효율 | 초원 효율 / 외곽 채집 해금 / 특화·슬라임 생산 |
| **편의** | 플레이 편의 | 시야 확장 / 타워 이동 / 성 회복·수리 / 점령 보조 / 연구소 증축 |

> 이전 초안의 "용" 갈래는 제거되어 별도 시스템(용 스킬트리)으로 이관되었습니다.

---

## 3. 티어(단계) 구성 — 주기 연동 5티어

이미지의 좌측 1~5단계를 그대로 차용하되, **게임 진행(주기)과 연동**해 잠금을 해제합니다.

| 티어 | 해금 시점(제안) | 의미 |
|---|---|---|
| T1 | 게임 시작 | 기초 강화, 진입 노드 |
| T2 | 1주기 종료(포탈 2 개방) | 초반 확장 대응 |
| T3 | 2주기 종료(포탈 3 개방) | 속성·특화 본격화 |
| T4 | 3주기 종료(포탈 4 개방) | 고급 분기 |
| T5 | 4주기 진입 | 최종 강화(엔딩 대비) |

노드 해금 조건 = **(a) 상위 티어 선행 노드 연구 완료** AND **(b) 해당 티어 도달** AND **(c) RP·자원 코스트 충족**. (이미지처럼 미충족 노드는 흐리게 표시)

> 티어–주기 매핑은 §17 미정 항목(주기당 일수)과 맞물립니다. 위 매핑은 제안값이며 팀 확정 필요.

## 4. 연구 방식 (확정)

기획 §14 확정 사항을 반영합니다.

- **연구소(1채)**에 인구(주민)를 배치 → **밤 종료 정산 시 배치 인구에 비례해 연구 포인트(RP)** 획득.
  - 자원 생산과 동일한 정산 사이클. 낮이 시간 무제한이므로, RP는 "이전 밤들에서 벌어 둔 것"을 낮에 소비하는 구조.
- **RP는 전역 풀로 누적·이월** — 자원처럼 보유하며, 모아서 비싼 연구에 사용. (저장 상한 `[미정 — 밸런싱]`)
- **연구 실행 = RP + 자원 코스트 즉시 소모 → 즉시 완료·즉시 효과 적용.** 대기 일수 없음.
- 연구소는 **1채 고정.** 초기 배치 가능 인구는 소수이며, 편의 갈래의 **"연구소 증축"** 노드로 배치 가능 최대 인구를 단계적으로 확장.
- 인구는 생산 / 방어 / 점령 / **연구** 네 갈래로 배분(§9). 연구에 인구를 몰면 RP는 빨리 벌지만 그날 방어·생산에 구멍.

### RP 생성·소비 개념 (제안)

- RP 생성량(정산 1회) = 연구소 배치 인구 × 기준 생성치 `[미정 — 밸런싱]`.
- 노드 코스트 = **RP(주 통화) + 자원(보조)**. 티어가 오를수록 RP·자원 요구가 커지고, 상위 티어는 특화 자원을 함께 요구.
- 동시 진행 개념 없음(즉시 완료). "무엇을 먼저 살지" 우선순위 선택이 핵심.

## 6. 데이터 구조 제안 (구현 관점)

ScriptableObject 기반(미션 필수 요건, CLAUDE.md)으로 다음 구조를 제안합니다. 실제 필드는 구현 시 확정.

- `ResearchNodeData` (SO): 노드 1개
  - 식별: `NameLocKey`(스트링테이블), `Branch`(enum: **Tower/Production/Convenience** — 3갈래), `Tier`(1~5), 안정적 노드 ID
  - 선행: `Prerequisites`(다른 노드 참조 리스트) — 트리가 아니라 **DAG(다중 선행 허용)**
  - 코스트: `ResearchPointCost`(int) + `ResourceCost`(기존 `GameResources`/`Resource` 재사용)
  - 효과: 별도 인터페이스(`IResearchEffect`/`ResearchEffectSO`)로 분리
- `ResearchManager` (매니저): 기존 `ResourceManager` 패턴 준수(싱글톤 아님, `GameManager`가 `Construct` 주입, `UnityEvent`로 UI 통지)
  - **RP 전역 풀** 보유, 정산 이벤트에서 연구소 배치 인구 비례로 RP 가산
  - 완료 노드는 `HashSet`으로 보관(정의 SO와 진행도 분리), 효과는 **조회(pull)** 방식으로 노출
  - 기존 `Research/IChunkResearchUnlockQuery`·`IChunkYieldBonusQuery`를 구현하는 자연스러운 위치
- **용 스킬트리는 별도 시스템**: `DragonSkillManager` 등 독립 매니저·독립 UI로 구현(연구 매니저와 분리). 상세는 `용_스킬트리_로드맵.md`.
- 리터럴·문자열 규칙(CLAUDE.md §Git 3·4) 준수: 노드 ID/이름은 상수·스트링테이블 key로 관리.
- **즉시 적용 모델**이므로 진행 타이머·UniTask 대기 로직 불필요 — 코스트 검증 후 즉시 효과 적용.
