# 새끼용 범위 표시 구현 계획

작성 2026-08-25. 관련: `Docs/버프타워_이펙트_마일스톤.md`(M0·M2 교훈), `Docs/타워이펙트_작업노트.md`

## 목표

- 새끼용 선택 시 모드에 맞는 범위를 표시한다 — **선(LineRenderer)이 경계, 파티클은 그 안쪽 장식**
- 기존 인디케이터를 없애지 않고 **살린 채로 파티클을 덧그린다**

## 확정된 설계 원칙

- 경계 판정의 단일 출처는 `RangeIndicator` — 첫 프레임부터 정확하고 맥동하지 않는다
- 파티클은 **판정선을 넘지 않는다.** 선에 딱 맞추면 선이 파티클에 묻히므로 **90~95% 지점에서 끝낸다**
- 파티클은 정규화 정확도를 책임지지 않는다 — 워밍업(`prewarm`/`Simulate`)도 불필요
- 세로 압축비는 `IsometricMath.RADIUS_Y_RATIO` 하나만 쓴다. 리터럴 금지
- **모드당 도형 2개**(선 1 + 파티클 1). 3개 이상 겹치지 않게 한다

## 이미 반영된 것 (다시 하지 말 것)

- 두 모드 모두 `Loop version/Marker circle simple <color>` 소스로 통일 — 강제 루프·주기×3·수명×12 제거
- 검 궤도 리그(`SwordRotator`/`SwordAnchor`/`SwordSize`) 제거, `BabyDragonRangeMarkerSpin.cs` 삭제
- 검을 세로 압축(`Scale`) **밖**, 루트 직속으로 이동 → 눌리지 않고 반경과 무관하게 크기 고정
- 검의 `rateOverTime`을 0으로 되돌려 원본 버스트(1초 1회) 복원
- 프리팹 구조: `루트(스케일 1)` → `Scale`(런타임 `baseScale × radius`) + `Marker`(고정)
- 정렬 링 Default/9, 검 Default/11
- 정규화 `NORMALIZED_XZ_SCALE = 0.7728` (= 기존 실측 0.84 × 0.92)

## A. 인디케이터 복원 — 모드별 하나만

이번 브랜치에서 뺀 `BabyDragonTower` 조기 return을 되돌리되, **모드에 맞는 선 하나만** 켠다.

### `BuildingPlacementController.ShowAttackRangeIndicatorFor`

- `if (building is BabyDragonTower) { Hide(); return; }` 삭제
- 새끼용은 `Mode == BabyDragonMode.Attack`일 때만 통과, 아니면 `Hide()`
- 반경은 일반 타워와 동일하게 `tower.Attack.EffectiveRange`

### `BuildingPlacementController.ShowBuffRangeIndicatorFor`

- `if (building is BabyDragonTower) { Hide(); return; }` 삭제
- 삭제된 `BabyDragonTower` 블록 복구 (`_babyDragonBuffSystem.GetEffectiveBuffRadius`, 없으면 `DragonData.BuffRadius` 폴백)
- **추가**: `Mode == BabyDragonMode.Buff` 게이트. `GetEffectiveBuffRadius`는 모드를 안 보므로 없으면 공격 모드에서도 뜬다

### `MouseSelectController.DrawAttackRangeIndicator`

- 기존 `tower is BabyDragonTower` 제외를 **모드 조건으로 교체** (이 제외는 이번 브랜치 이전부터 있던 것 — 미리보기에 공격 사거리가 아예 안 나왔다)
- 새끼용은 `Mode == Attack`일 때만 표시

### `MouseSelectController.DrawBuffRangeIndicator`

- 삭제된 `BabyDragonTower` 블록 복구 + `Mode == Buff` 게이트

### 주의

- `_babyDragonBuffSystem` 필드는 두 파일 모두 살아 있다 — 선언 추가 불필요
- **신규 배치 미리보기**는 `Record == null`이라 `Mode`가 기본값 `Attack`. `Setup()`의 `record.Mode = CanUseAttackMode ? Attack : Buff`와 일치하므로 그대로 두면 된다
- **모드 전환 반영은 자동.** `BuildingPlacementController.Update()`가 매 프레임 `RefreshSelectedRangeIndicator()`를 부른다. `ModeChanged` 구독 불필요

### 미결 — 표시 조건 불일치

- 파티클은 `!CanOperate` · `IsDead` · `IsParalyzed` · `IsReviving`에서 꺼지지만 선은 안 꺼진다
- 마비된 새끼용은 선만 뜨고 파티클이 없는 상태가 된다
- **권장: 그대로 둔다** (사거리 자체는 여전히 참). 맞추기로 하면 두 경로에 같은 조건을 넣는다

## B. 정렬

| 대상 | 정렬 | 비고 |
|---|---|---|
| `TowerRangeIndicator` (LineRenderer) | Default / **10** | 씬 값. 건드리지 않는다 |
| `BuffRangeIndicator` (LineRenderer) | Default / **10** | 씬 값. 건드리지 않는다 |
| 범위 파티클(링·Glow·Circle) | Default / **9** | 선 아래 |
| 검(`Marker`) | Default / **11** | 공중에 뜨는 게 목적이라 선 위 |

- 재배치 후에도 선이 흐리면 **Glow 머티리얼의 가산 합성**을 먼저 본다 — 아래에 그려도 겹치는 자리를 날려버린다
- 검 11이 새끼용 스프라이트(Building)보다 앞인지 확인. 묻히면 검만 더 올린다

## C. 파티클 잔여 작업

- `BuildBabyDragonRangeVfx.ISOMETRIC_Y_SCALE` 리터럴 제거 → `NORMALIZED_XZ_SCALE * IsometricMath.RADIUS_Y_RATIO`로 계산
- `NORMALIZED_XZ_SCALE = 0.7728`을 **`simple` 소스로 다시 실측해 확정.** 기존 0.84는 공격이 `swords` 소스였을 때 맞춘 값이다
  - 측정 기준은 **가장 바깥으로 보이는 요소(Glow)** — 링 가장자리로 맞추면 Glow가 선을 넘는다
  - 목표: 가시 외곽 = 판정선의 0.90~0.95
- 검 위치·크기 눈으로 확인. 현재 원본 그대로 `localPosition.y = 0.3`, 루트 스케일 1 고정
  - 새끼용 스프라이트에 묻히면 `y`만 올린다. **크기는 반경과 무관해야 한다**
- 검이 0.3초만 보여 깜빡임이 거슬리면 **수명과 속도를 같은 비율로** 조정한다 (상승 거리 = 속도 × 수명이라 형태가 유지된다)

### 손대지 말 것 (함정)

- **`main.startRotationX = 0` 유지.** M0에서 확정한 이 카메라용 보정. 루트 회전으로 대신하려 하지 말 것
- **검의 `VelocityModule`(y=20 · ClampVelocity 축당 1 · dampen 0.4)을 끄지 말 것.** `startSpeed`는 0이고 상승 연출의 출처는 이 모듈뿐이다. 껐다가 "원본처럼 안 뜬다"가 됐던 자리
- **오라용 주기×3·수명×12를 다시 가져오지 말 것.** fantasy·sci-fi 마커 기준 실측값이라 `simple`에는 성립하지 않는다
- 세로비가 2.00이 아니라 2.19로 측정되는 것은 **알파 임계값 아티팩트**(M2 기록). 도형 버그가 아니므로 쫓지 말 것
- 자식 간 `lengthInSec`이 0.99/1.00으로 어긋나면 느린 맥놀이가 생긴다 — 전부 1.0으로 맞춘다

## D. 검증 (`VerifyBabyDragonVfx`)

기존 스크립트는 `outer X/Y`를 `[MEASURE]`로만 찍고 판정에 안 써서, 검이 타원 위로 12% 튀어나간 상태(`Y=1.121`)로 "실패 0"을 통과시켰다. 합격 기준으로 승격한다.

| 항목 | 기준 |
|---|---|
| 파티클 가시 외곽 X | 판정선의 **0.90 ~ 0.95** |
| 파티클 가시 외곽 Y | 판정선의 **0.90 ~ 0.95** |
| 중심 오프셋 | 원점 기준 ±2px |
| 공격 / 버프 프리팹 간 X·Y 편차 | ±1% (같은 소스이므로 일치해야 한다) |
| 검 드리프트 | 5·15·30·45·60초 세로 위치가 원점 기준 −2 ~ +5월드 (M2 기준 유지) |

- 파티클 랜덤 시드를 고정하고, **한 주기를 훑어 가장 넓게 퍼진 한 프레임**에서 X·Y를 같이 읽는다 (다른 프레임에서 각각 최대를 잡으면 가로세로비가 왜곡된다)
- 선과 파티클을 같이 굽는 시트를 추가해 **선이 파티클 밖에 또렷하게 남는지** 눈으로 확인한다
