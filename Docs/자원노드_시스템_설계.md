# ⛏️ 자원 노드(Resource Node) 시스템

작성일: 2026-07-20 · 최종 갱신: 2026-07-21 · 브랜치: `feature/ResourceNode`

상세 게임 기획은 `Docs/기획종합_v2.md`를 우선합니다. 이 문서는 노션 "자원 노드(Resource Node) 시스템 설계" 문서(상위: TowerAndDragon — Grid & 건물 배치 시스템)를 코드베이스에 맞춰 정리한 구현 문서이며, 노션 원본 작성 이후 코드에서 먼저 확정·구현된 부분(수기 영역 Override 모드 등)을 반영했습니다.

> 🔄 **모델 개정**: 자원 노드는 별도 `ResourceNodeData`를 셀에 심는 단일 점유 모델이 아니라, **셀 하나가 여러 자원 플래그를 동시에 가질 수 있는 모델**로 설계·구현되어 있습니다.

---

## 1. 시스템 개요

### 기능 설명

- 특정 자원과 연관된 셀 영역에 자원 생산시설을 건축할 수 있다.
- 매일 밤 정산 시, 생산시설의 산출량만큼 자원이 생산된다.

### 상세 내용

- 셀은 터레인 타입에 따라 기본적으로 특정 자원 플래그(들)를 가지며, 레벨디자인상 특정 구역에는 수기로 추가 자원 플래그를 부여하거나 터레인 기본값을 완전히 덮어쓸 수 있다.
- 자원 플래그가 있는 영역에 생산시설(`Factory`)을 건설할 수 있다.
- 매일 밤 정산 시, 각 생산시설의 `YieldPerCycle`만큼 자원을 획득한다.

### 핵심 설계 원칙

> 자원 노드는 별도 GameObject가 아니라 **GridCell의 속성**으로 내재화한다.
> GridMap이 초기화될 때 터레인 타입 기반 기본값 → 수기 지정 영역 테이블을 순서대로 적용해 셀에 자원 플래그를 심는다.
> 생산시설의 풋프린트 내 **모든 셀**이 요구 자원 플래그를 가져야 건설 가능하다.

풋프린트는 "영역" 기준이며, 논·벌목장 등을 지을 수 있는 영역을 잡는 용도다. 셀 한 칸이 자원을 하나씩만 갖는 것이 아니라 여러 개를 동시에 가질 수 있으므로, 자원 노드는 "노드"가 아니라 **셀 한 칸이 가지는, 자원 생산 시설을 지을 수 있는 플래그**에 가깝다.

### 설계 선택 이유

- 자원 노드를 별도 오브젝트로 만들면 `GridCell`과 이중 관리가 발생함
- `GridCell`에 속성으로 넣으면 `CanConstruct` 선례와 일관됨
- 자원 종류는 이미 `[Flags] ResourceType`(`Conquest/ResourceType.cs`, 점령 해금 표시와 공용)이 존재하므로, 새 타입을 만들지 않고 그대로 재사용 — 복수 플래그 요구사항과 자연스럽게 맞아떨어짐
- 생산시설은 자원 종류·산출량만 다르고 동작 로직은 동일하므로, `Tower`/`TowerData` 패턴처럼 **클래스 하나(`Factory`) + 데이터 에셋(`ResourceProductionData`)**으로 통합 — 서브클래스 계층 불필요
- 풋프린트 영역 정의는 기존 건물 배치용 `FootprintShape`을 그대로 재사용

## 3. GridCell 확장 방식

```csharp
// Assets/Scripts/Grid/GridCell.cs
public ResourceType AvailableResourceNodes { get; private set; } // Flags - 셀 하나가 여러 자원을 동시에 가질 수 있음

// 그리드 생성 시점(터레인 기본값)과 수기 지정 영역(Add 모드) 적용 시점에 각각 호출되어 누적(OR)된다.
public void AddResourceNodes(ResourceType flags) => AvailableResourceNodes |= flags;

// 수기 지정 영역(Override 모드) 전용 - 터레인 기본값을 포함해 기존 값을 전부 무시하고 지정한 값으로 교체한다.
public void SetResourceNodes(ResourceType flags) => AvailableResourceNodes = flags;

public bool HasResourceNode(ResourceType flag) => (AvailableResourceNodes & flag) != 0;
```

- 셀 하나가 `Wood | Stone`처럼 동시에 여러 자원 플래그를 가질 수 있음
- `CanConstruct`(건설 가능 여부, 현재 시점 게이트)와 자원 플래그(땅의 정체성)는 **완전히 독립적인 레이어** — 지금 못 짓는 타일(예: 용암 일부)에도 자원 플래그는 미리 부여해둔다. 나중에 연구로 건설이 풀려도 자원 데이터를 소급 적용할 필요가 없기 때문.

## 4. 자원 플래그 부여 방식 — 터레인 기본값 + 수기 영역 오버레이

두 단계로 부여하며, 반드시 **① 터레인 기본값 → ② 수기 지정 영역** 순서로 적용한다.

### 4-1. 터레인 타입 기반 기본값 — `TerrainTileMap`

```csharp
// Assets/Scripts/Grid/TerrainTileMap.cs
[Serializable]
private struct Entry
{
    public TileBase Tile;
    public TerrainType TerrainType;
    public bool CanConstruct;
    public ResourceType DefaultResourceNodes; // Flags라 인스펙터에서 다중 체크 가능
}

public ResourceType ResolveDefaultResourceNodes(TileBase tile) { /* Tile 일치 엔트리의 DefaultResourceNodes 반환, 없으면 None */ }
```

데이터 저작 예시: Grass = `Food | Wood`(초원은 별도 연구 없이 기본적으로 논 해금), Rock = `Stone`, Volcano = `FlameHeart`(건설 자체는 `CanConstruct=false`인 타일이어도 자원 플래그는 부여), Desert = `TimeSand`, Snow = `SnowCrystal`.

### 4-2. 수기 지정 영역 — `ResourceNodeAreaTable` (Add / Override 모드)

터레인 기본값 위에 레벨디자인상 특정 구역만 추가로 자원을 지정하거나, 터레인 기본값을 완전히 무시하고 지정값으로 교체하고 싶을 때 사용한다. 기존 건물 풋프린트 시스템의 `FootprintShape`을 그대로 재사용해 임의 모양의 영역을 정의한다.

```csharp
// Assets/Scripts/ResourceNode/ResourceNodeAreaTable.cs
[CreateAssetMenu(menuName = "TowerAndDragon/Resource Node Area Table")]
public class ResourceNodeAreaTable : ScriptableObject
{
    // Add: 터레인 기본값 위에 추가(OR). Override: 터레인 기본값을 무시하고 지정한 값으로 완전히 교체.
    private enum ApplyMode { Add, Override }

    [Serializable]
    private struct Entry
    {
        public Vector3Int AnchorCoord;
        public FootprintShape Shape;
        public ResourceType ResourceFlags;
        public ApplyMode Mode;
    }

    [SerializeField] private Entry[] _entries;

    // GridMap이 그리드 생성(터레인 기본값 적용) 다음 단계에 호출한다.
    public void ApplyToGrid(Dictionary<Vector3Int, GridCell> cells)
    {
        foreach (Entry entry in _entries)
        {
            foreach (Vector2Int offset in entry.Shape.GetOccupiedOffsets())
            {
                Vector3Int coord = entry.AnchorCoord + new Vector3Int(offset.x, offset.y, 0);
                if (!cells.TryGetValue(coord, out GridCell cell))
                    continue;

                if (entry.Mode == ApplyMode.Override)
                    cell.SetResourceNodes(entry.ResourceFlags);
                else
                    cell.AddResourceNodes(entry.ResourceFlags);
            }
        }
    }
}
```

기획자는 앵커 좌표 + 도형 + 플래그 + 모드만 지정하면 된다(`ConquestChunkCostTable`과 동일한 "좌표별 엔트리 테이블" 패턴). 영역 적용 로직은 `ResourceNodeAreaTable` 자신이 캡슐화하고, `GridMap`은 `_cells` 딕셔너리를 넘겨 호출만 한다.

## 5. GridMap 초기화 흐름

```
GridMap.Awake()
  └→ GenerateGridFromTilemap()
        └ 셀 생성 시 TerrainTileMap.ResolveDefaultResourceNodes(tile) 호출 → 터레인 기본 자원 플래그 적용
  └→ GenerateChunks()
  └→ ApplyResourceNodeAreas() → _resourceNodeAreaTable.ApplyToGrid(_cells) 호출 (Add/Override 모드에 따라 누적 또는 교체)
```

```csharp
// Assets/Scripts/Grid/GridMap.cs
private void GenerateGridFromTilemap()
{
    foreach (var pos in _tilemap.cellBounds.allPositionsWithin)
    {
        if (!_tilemap.HasTile(pos)) continue;

        TileBase tile = _tilemap.GetTile(pos);
        GridCell cell = new GridCell(pos, _terrainTileMap.Resolve(tile), _terrainTileMap.ResolveCanConstruct(tile));
        cell.AddResourceNodes(_terrainTileMap.ResolveDefaultResourceNodes(tile));
        _cells[pos] = cell;
    }
}

private void ApplyResourceNodeAreas()
{
    if (_resourceNodeAreaTable != null)
        _resourceNodeAreaTable.ApplyToGrid(_cells);
}
```

## 6. 건설 가능 여부 판정 — 풋프린트 전체 일치 + 터레인 플래그/연구 해금 하이브리드

풋프린트 내 **모든** 셀이 요구 자원 플래그를 가져야 건설 가능하다(부분 만족 불허). 대부분의 자원(Wood/Stone/FlameHeart 등)은 섹션 4의 정적 플래그만으로 판정하면 되지만, **Food(논)는 예외**다.

### 6-1. Food/논 특수 케이스 — 아직 미연동

- 초원(Grass)은 정적 플래그로 기본 해금(연구 불필요, 섹션 4-1)
- 그 외 터레인은 터레인 무관하게 연구로 해금 가능하지만, **청크 단위로 개별 해금**되어야 한다는 것이 기획 의도다(연구 시스템 본체는 추후 별도 설계, 섹션 8)
- 현재 코드의 `FarmField`(`Buildings/FarmField.cs`)는 `_currentCap`/`_maxCap`만 가진 별개 클래스로, `Factory`처럼 `ResourceType`이나 `CanConstructResourceFootprint` 판정에 아직 연결되어 있지 않다. 논을 이 시스템에 편입할지, `Factory` + `ResourceProductionData`로 흡수할지는 미결(섹션 13)

### 6-2. 통합 판정 함수 — `GridMap.CanConstructResourceFootprint`

```csharp
// Assets/Scripts/Grid/GridMap.cs
public bool CanConstructResourceFootprint(Vector3Int anchor, FootprintShape shape, ResourceType requiredResourceNode)
{
    if (!CanConstructFootPrint(anchor, shape)) // 기존 게이트(CanConstruct, 점령 여부 등) 그대로
        return false;

    foreach (Vector3Int coord in GetFootprintCoords(anchor, shape))
    {
        if (!_cells.TryGetValue(coord, out GridCell cell))
            return false;

        bool hasTerrainNode = cell.HasResourceNode(requiredResourceNode);
        bool hasChunkUnlock = ResearchUnlockQuery != null &&
            ResearchUnlockQuery.IsUnlocked(ToChunkCoord(coord), requiredResourceNode);

        if (!hasTerrainNode && !hasChunkUnlock)
            return false; // 풋프린트 전체 셀이 만족해야 함
    }

    return true;
}
```

`BuildingPlacementController.TryConstructAt`에서 선택된 건물이 `Factory`면 `factory.RequiredResourceNode`를 꺼내 이 판정을 타고, 그 외 건물은 기존 `CanConstructFootPrint`만 탄다.

```csharp
// Assets/Scripts/Grid/BuildingPlacementController.cs:291
bool canConstruct = _selectedBuilding is Factory factory
    ? _gridMap.CanConstructResourceFootprint(anchor, _selectedBuilding.FootprintShape, factory.RequiredResourceNode)
    : _gridMap.CanConstructFootPrint(anchor, _selectedBuilding.FootprintShape);
```

## 7. 생산시설 구조 — 서브클래스 없이 데이터로 분기

`Tower`/`TowerData`와 동일하게 **클래스 하나 + 데이터 에셋**으로 벌목장/채석장/광산 등을 전부 커버한다.

```csharp
// Assets/Scripts/ResourceNode/ResourceProductionData.cs
[CreateAssetMenu(menuName = "TowerAndDragon/Resource Production Data")]
public class ResourceProductionData : ScriptableObject
{
    [SerializeField] private ResourceType _requiredResourceNode; // 건설에 필요한 자원 플래그
    [SerializeField] private ResourceType _producedResourceType; // 정산 시 실제로 생산되는 자원
    [SerializeField] private int _yieldPerCycle;

    public ResourceType RequiredResourceNode => _requiredResourceNode;
    public ResourceType ProducedResourceType => _producedResourceType;
    public int YieldPerCycle => _yieldPerCycle;
}
```

```csharp
// Assets/Scripts/Buildings/Factory.cs
public class Factory : Building
{
    [SerializeField] private ResourceProductionData _data;
    [SerializeField] private ResourceManager _resourceManager;
    [SerializeField] private CycleManager _cycleManager;

    public ResourceType RequiredResourceNode => _data != null ? _data.RequiredResourceNode : ResourceType.None;

    private void OnEnable() => _cycleManager?.OnNightEnd.AddListener(OnSettlement);
    private void OnDisable() => _cycleManager?.OnNightEnd.RemoveListener(OnSettlement);

    private void OnSettlement(int currentCycle)
    {
        if (_data == null || _resourceManager == null) return;
        _resourceManager.Add(_data.ProducedResourceType, _data.YieldPerCycle);
    }
}
```

- 서브클래스 계층도, 별도 `ProductionManager`(레지스트리 매니저)도 없음 — `ConquestManager`가 스스로 `CycleManager.OnNightEnd`를 구독하듯, `Factory`도 각 인스턴스가 스스로 구독한다.
- 인구 배치 연동(생산량에 인구 충원율을 반영할지 등)은 아직 다루지 않았다 — 섹션 13 참고.

```csharp
// Assets/Scripts/Research/IChunkResearchUnlockQuery.cs
public interface IChunkResearchUnlockQuery
```

`GridMap.ResearchUnlockQuery`는 `{ get; set; }` 프로퍼티로 열려 있어, 연구 시스템이 아직 없는 씬에서는 `null`로 두면 `hasChunkUnlock`이 항상 `false`로 빠지며 안전하게 동작한다.

## 9. 디버깅 — `ResourceNodeDebugger`

`Grid/ResourceNodeDebugger.cs`(`#if UNITY_EDITOR`, 빌드 미포함). `GridMap`과 같은 오브젝트에 붙이면 Play 모드 진입 즉시 각 셀의 `AvailableResourceNodes`를 색상 오버레이로 게임 뷰에 표시한다(`ChunkDebugger`와 동일한 스프라이트 풀링 패턴).

- 셀이 자원을 여러 개 동시에 가질 수 있어서, 가진 자원들의 고정 색을 평균 블렌드해 조합마다 구분한다.
- 초원 기본 조합(`Food | Wood | Stone`)은 가장 흔한 조합이라 검정으로 고정 표시한다.
- 나머지는 자원별 고정 원색(Food=빨강, Wood=주황, Stone=노랑, FlameHeart=시안, SnowCrystal=파랑, TimeSand=보라, PhilosopherStone=마젠타)을 평균 블렌드한다.
- Play 모드에서 셀을 좌클릭하면 콘솔에 정확한 플래그 값이 로그로 남고, 인스펙터의 디버그 필드(`_debugSelectedCellCoord`, `_debugSelectedResourceNodes`)에도 표시된다.

## 10. 전체 데이터 흐름

```
[초기화] GridMap.Awake
  └→ GenerateGridFromTilemap() → 셀 생성 + 터레인 기본 자원 플래그 적용
  └→ GenerateChunks()
  └→ ApplyResourceNodeAreas() → ResourceNodeAreaTable.ApplyToGrid() (Add/Override)

[생산시설 건설] BuildingPlacementController.TryConstructAt
  └→ 선택 건물이 Factory면 GridMap.CanConstructResourceFootprint(anchor, shape, factory.RequiredResourceNode)
         ← CanConstructFootPrint() && 풋프린트 전체 셀이 (터레인 플래그 || 청크 연구 해금) 만족
  └→ GridMap.ConstructBuilding()

[밤 정산] CycleManager.OnNightEnd
  └→ 각 Factory.OnSettlement (스스로 구독, 중앙 매니저 없음)
         └→ ResourceManager.Add(producedType, yieldPerCycle)
```

## 11. 구현 및 검증 현황

### 구현 완료

- `GridCell.AvailableResourceNodes` / `AddResourceNodes` / `SetResourceNodes` / `HasResourceNode`
- `TerrainTileMap.DefaultResourceNodes` 필드 + `ResolveDefaultResourceNodes()`
- `ResourceNodeAreaTable` — Add/Override 두 모드로 수기 영역 적용
- `GridMap.ApplyResourceNodeAreas()` / `CanConstructResourceFootprint()`
- `ResourceProductionData`, `Factory`(밤 정산 시 자원 생산)
- `BuildingPlacementController`의 `Factory` 분기 배치 판정 연동
- `IChunkResearchUnlockQuery` 인터페이스 및 `GridMap.ResearchUnlockQuery` nullable 배선
- `ResourceNodeDebugger`(에디터 전용 시각화 + 좌클릭 로그)
- `Data_ResourceNodeAreaTable.asset` 자원 노드 데이터 에셋 저작 시작

### 아직 검증하지 못한 부분

- 실제 씬에서 Grass 위 논 즉시 건설 / Rock 위 논 거부 시나리오 플레이 테스트
- 밤 정산 2회 이상 반복 시 `ResourceManager` 수치 누적 확인
- 풋프린트 일부만 자원 플래그를 가진 영역에 배치 시도 시 거부(빨간 미리보기) 확인
- `Data_ResourceNodeAreaTable.asset`의 실제 좌표/도형이 맵 확정본과 일치하는지

## 12. 주의사항 & 미결 사항

### 주의사항

- 자원 플래그와 `CanConstruct`는 독립 레이어 — 지금 못 짓는 타일에도 자원 플래그는 미리 부여해둘 것(연구 해금 시 소급 작업 불필요하게)
- `Factory._data`가 null인 채 `OnSettlement()` 호출 시 이미 방어 처리되어 있음(널이면 조용히 스킵)

### 기획/설계 미정 — 확정 후 반영 예정

| 항목 | 비고 |
| --- | --- |
| `FarmField`을 `Factory` + `ResourceProductionData` 체계로 흡수할지, 별도 클래스로 유지하며 판정만 연동할지 | 현재 `FarmField`는 `ResourceType` 판정에 연결되지 않은 상태 |
| 연구 시스템 본체(비용/기간/UI, `IChunkResearchUnlockQuery` 실제 구현체) | 청크 단위 해금 방식만 확정, 나머지는 추후 설계 |
| `CanConstruct` 자체도 연구로 해금되는 케이스가 생기는지 | 생기면 `GridCell.CanConstruct`를 고정 bool → 가변 체크로 리팩터링 필요 |
| 생산량에 인구 배치(충원율)를 반영할지, 배치 여부만으로 On/Off할지 | `Tower`의 `TowerPopulation`/충원율 패턴 재사용 여부 검토 필요([[타워시스템_현황]] 참고) |
| 각 자원 구역의 정확한 좌표/도형 | 맵 확정 후 `ResourceNodeAreaTable` asset에 계속 입력 |
| `YieldPerCycle` 수치 | 밸런스 확정 후 `ResourceProductionData` asset에 입력 |
