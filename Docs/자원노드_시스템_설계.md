# ⛏️ 자원 노드 & 생산시설 시스템

작성일: 2026-07-20 · 최종 갱신: 2026-07-21 · 브랜치: `feature/ResourceNode`

상세 게임 기획은 `Docs/기획종합_v2.md`를 우선합니다. 이 문서는 자원 노드(땅의 자원 플래그) → 생산시설 건설 → 인구 배치 → 자원 정산, 그리고 점령(원정)과의 인구 연동까지 **현재 코드베이스에 실제로 구현된 상태**를 팀원이 바로 써먹을 수 있게 정리한 문서입니다. 기획 내용을 복제하지 않고 구현 현황 위주로 씁니다.

---

## 1. 한눈에 보는 전체 그림

```
[땅] 셀마다 자원 플래그(Food/Wood/Stone/...)를 가짐 (터레인 기본값 + 수기 영역)
   │
   ▼
[건설] 자원 플래그가 있는 땅에만 생산시설(Factory: 논/벌목장/채석장 등) 건설 가능
   │
   ▼
[인구 배치] 건설된 생산시설에 인구를 배치 (최소 인구 미달 시 생산량 0, 초과 배치 시 산출량 증가)
   │
   ▼
[정산] 매일 아침 시작 시(OnDayStart) 생산시설의 산출량만큼 ResourceManager에 자원 추가
```

점령(원정)도 같은 인구 풀을 공유합니다 — 원정을 보내면 비용만큼 인구가 잠깐 "출격"으로 빠지고, 점령이 완료되면 그 인구가 돌아오면서 보상 인구가 추가로 늘어납니다.

## 2. 빠른 시작 — 지금 씬에서 바로 테스트하는 법

1. **Play 모드 진입** → BuildMode 버튼 클릭 → `FactoryButton` 탭 선택 (논/벌목장/채석장 슬롯이 뜸)
2. 슬롯 클릭 → 자원 플래그가 있는 땅(예: 초원 Food\|Wood\|Stone) 위로 마우스를 가져가 **초록색 미리보기** 확인 → 좌클릭으로 건설
   - 자원 플래그가 없는 땅에서는 미리보기가 **빨간색**이고 클릭해도 건설되지 않음
3. 건설한 생산시설을 **클릭해서 선택**(빌드모드가 아니어도 기존 건물 선택 흐름 그대로 재사용됨)
4. **`1`번 키**를 눌러 인구를 1명씩 배치 (낮에만 가능, `FactoryPopulationDebugGUI` 창이 우측 상단에 뜸)
   - 최소 필요 인구에 도달하면 화면에 `Production Ready` 표시
   - 정원(Capacity)에 도달하면 더 눌러도 배치가 안 됨(정상 동작)
   - `2`번 키로 1명씩 회수
5. 다음날 아침이 되면(`CycleManager.OnDayStart`) 자동으로 `ResourceManager`에 자원이 추가됨
6. 좌측 상단 `PopulationDebugPanel`에서 인구/Food/Wood/Stone 수치가 실시간으로 바뀌는지 확인

점령 인구 연동을 테스트하려면: 점령 모드 진입 → 청크 선택 → 원정 보내기(인구 비용이 있는 청크면 즉시 인구가 배치됨) → `ConquestManager.DebugForceCompleteAllExpeditions()`(컨텍스트 메뉴/디버그 전용)로 즉시 완료 → 인구가 반환되고 보상만큼 최대 인구가 늘어나는지 `PopulationDebugPanel`에서 확인.

## 4. 자원 플래그 — 땅의 정체성

셀은 별도 오브젝트가 아니라 `GridCell.AvailableResourceNodes`(`[Flags] ResourceType`) 하나로 자원을 표현합니다. 두 단계로 부여되며, 반드시 **① 터레인 기본값 → ② 수기 지정 영역** 순서로 적용됩니다.

| 단계 | 파일 | 방식 |
|---|---|---|
| ① 터레인 기본값 | `Grid/TerrainTileMap.cs` (`Entry.DefaultResourceNodes`) | 타일 종류별 고정값. Grass=`Food\|Wood\|Stone` 등 |
| ② 수기 영역 | `ResourceNode/ResourceNodeAreaTable.cs` | 앵커+`FootprintShape`+플래그+**Add/Override 모드** 엔트리. Add는 누적(OR), Override는 터레인 기본값을 무시하고 완전 교체 |

`GridCell.AddResourceNodes()`(누적)와 `SetResourceNodes()`(교체)가 각 모드에 대응합니다. `CanConstruct`(건설 가능 여부)와 자원 플래그는 완전히 독립된 레이어라, 지금 못 짓는 타일(용암 등)에도 자원 플래그는 미리 부여해둡니다.

```
GridMap.Awake()
  └→ GenerateGridFromTilemap() → 셀 생성 + 터레인 기본 자원 플래그
  └→ GenerateChunks()
  └→ ApplyResourceNodeAreas() → ResourceNodeAreaTable.ApplyToGrid() (Add/Override)
```

**디버깅**: `Grid/ResourceNodeDebugger.cs`(에디터 전용)를 `GridMap`과 같은 오브젝트에 붙이면 Play 모드에서 셀별 자원 플래그를 색상 오버레이로 보여주고, 좌클릭 시 콘솔에 정확한 값을 로그로 남깁니다.

## 5. 생산시설 건설 판정 — `GridMap.CanConstructBuildingFootprint`

풋프린트 내 **모든 셀**이 요구 자원 플래그를 가져야 건설 가능합니다(부분 만족 불허). 신규 배치, 마우스 미리보기, 재배치(이동) **세 곳 모두 하나의 진입점**을 거치도록 통합되어 있습니다.

```csharp
// Assets/Scripts/Grid/GridMap.cs
// 건물 타입에 따라 판정을 분기 - Factory(생산시설)는 자원 플래그 판정, 그 외는 기존 풋프린트 판정.
public bool CanConstructBuildingFootprint(List<Vector3Int> footprint, Building building, Building ignoreBuilding) =>
    building is Factory factory
        ? CanConstructResourceFootprint(footprint, factory.RequiredResourceNode, ignoreBuilding)
        : CanConstructFootPrint(footprint, ignoreBuilding);
```

호출 지점 3곳:

| 호출 위치 | 용도 |
|---|---|
| `BuildingPlacementController.TryConstructAt` | 실제 배치 확정 |
| `MouseSelectController.Update()` | 마우스 드래그 중 미리보기(초록/빨강) |
| `GridMap.MoveBuilding` | 재배치(이동) 확정 |

세 곳이 각자 다른 기준으로 판정하면 "미리보기는 초록인데 클릭하면 실패" 같은 버그가 생기므로, 반드시 이 하나의 메서드를 통해서만 판정합니다. `anchor+shape`를 받는 오버로드와 `List<Vector3Int>`(이미 계산된 좌표)를 받는 오버로드가 둘 다 있으니, 호출 위치에서 이미 footprint 좌표를 갖고 있다면 재계산하지 말고 리스트를 그대로 넘기세요(`CanConstructFootPrint`가 이미 쓰던 것과 같은 패턴).

자원 판정 자체(`CanConstructResourceFootprint`)는 청크 단위 연구 해금(`GridMap.ResearchUnlockQuery`, 아직 본체 없음)과 OR 조건입니다.

## 6. 생산시설 구조 — `Factory` + `ResourceProductionData`

`Tower`/`TowerData`와 동일한 패턴으로 **클래스 하나 + 데이터 에셋**만으로 논/벌목장/채석장을 전부 표현합니다(서브클래스 없음). 논(FarmField)도 예외가 아니라 그냥 `Factory` 데이터 하나입니다 — 초원 외 지형에서 연구로 해금되는 예외 동작은 클래스가 아니라 섹션 5의 `CanConstructResourceFootprint`(청크 연구 해금 OR 조건)에서 데이터 레벨로 처리되도록 설계되어 있어서, 논만의 별도 서브클래스가 필요 없습니다.

### 6-1. 데이터 — `ResourceProductionData`

| 필드 | 의미 |
|---|---|
| `RequiredResourceNode` | 건설에 필요한 자원 플래그 |
| `ProducedResourceType` | 정산 시 생산되는 자원 |
| `PopulationCapacity` | 배치 가능한 최대 인구 |
| `MinimumRequiredPopulation` | 기본 생산량을 내기 위한 최소 인구 (미달 시 생산량 0) |
| `YieldPerCycle` | 최소 인구 충족 시 기본 생산량 |
| `YieldPerExtraPopulation` | 최소 인구 초과 배치 1명당 추가 생산량 |

```csharp
// 최소 인구 미달 시 0, 충족 시 기본 생산량 + (초과 인원 수 * 초과 인원당 생산량)
public int CalculateYield(int assignedPopulation)
{
    if (assignedPopulation < _minimumRequiredPopulation)
        return 0;

    int extraPopulation = assignedPopulation - _minimumRequiredPopulation;
    return _yieldPerCycle + extraPopulation * _yieldPerExtraPopulation;
}
```

현재 `RPD_FarmField`/`RPD_LoggingCamp`/`RPD_Quarry` 3개 에셋 모두 `PopulationCapacity=4`, `MinimumRequiredPopulation=2`, `YieldPerCycle=5`, `YieldPerExtraPopulation=2`로 **가배치**되어 있습니다(밸런스 미확정 스텁).

### 6-2. 인구 배치 — `FactoryPopulation`

`TowerPopulation`과 완전히 동일한 패턴. `PopulationAssignmentType.Production`으로 `PopulationManager`에 배정을 만들고 `TryAssign`/`TryUnassign`으로 증감합니다.

### 6-3. 정산 — `Factory`

```csharp
// Assets/Scripts/Buildings/Factory.cs
public bool Initialize(ResourceManager resourceManager, CycleManager cycleManager)
{
    if (_isInitialized || resourceManager == null || cycleManager == null)
        return false;

    _resourceManager = resourceManager;
    _cycleManager = cycleManager;
    _population = GetComponent<FactoryPopulation>();
    _cycleManager.OnDayStart.AddListener(OnSettlement); // 밤 정산(OnNightEnd)이 아니라 아침 시작 시점
    _isInitialized = true;
    return true;
}

private void OnSettlement(int currentCycle)
{
    if (_data == null || _resourceManager == null) return;

    int assignedPopulation = _population != null ? _population.AssignedPopulation : 0;
    _resourceManager.Add(_data.ProducedResourceType, _data.CalculateYield(assignedPopulation));
}
```

`_resourceManager`/`_cycleManager`는 프리팹에 직접 넣을 수 없으므로(씬 오브젝트라서), `FactoryResourceCoordinator`가 건설 직후 `GridMap.OnBuildingAdded`를 구독해 주입합니다. 인구 배정도 동일한 이유로 `FactoryPopulationCoordinator`가 별도로 주입합니다(관심사 분리 — 자원 연결과 인구 연결을 각자 다른 코디네이터가 담당).

## 7. 점령(원정) ↔ 인구 연동 — `ConquestPopulationCoordinator`

`ConquestManager`는 의도적으로 `ResourceManager`/`PopulationManager`를 직접 모릅니다(순수 로직만 담당, 테스트하기 쉽게). 그래서 점령과 인구를 잇는 역할도 `TowerPopulationCoordinator`와 같은 패턴의 별도 코디네이터가 맡습니다.

```
[원정 발송] ConquestUIExample.OnConquerButtonClicked
  └→ ConquestManager.SendExpedition() 성공
        └→ OnExpeditionSent(chunkCoord, cost) 발행
              └→ ConquestPopulationCoordinator: cost.Population만큼 PopulationAssignmentType.Conquest로 배정·즉시 배치("출격")

[원정 완료] ConquestManager.OnSettlement(며칠 뒤 밤 정산) → CompleteConquest()
  └→ OnConquestCompleted(chunkCoord) 발행
        └→ ConquestPopulationCoordinator:
              ① 위에서 만든 Conquest 배정을 반환(인구 복귀)
              ② GetPopulationReward(chunkCoord)만큼 TryIncreaseMaxPopulation (보상 지급)
```

- 원정 인구 비용/보상은 `ConquestChunkCostTable.Entry`에 청크별로 이미 저작되어 있는 값을 그대로 씁니다(`Cost.Population`, `PopulationReward`) — 별도 테이블 불필요.
- `ConquestUIExample`은 더 이상 `held.Population = cost.Population`으로 항상 충족 처리하지 않고, `PopulationManager.AvailablePopulation`으로 실제 가용 인구를 확인합니다 — 인구가 부족하면 원정 버튼이 실제로 비활성화됩니다.
- 이벤트(`OnExpeditionSent`)는 `ConquestManager`가 이미 조회해둔 `ResourceCost`를 그대로 실어보내므로, 구독자가 테이블을 다시 조회하지 않습니다.

## 9. 구현 현황

### 구현 완료

- 자원 플래그 부여(터레인 기본값 + 수기 영역 Add/Override) 및 시각화
- 생산시설 건설 판정 통합(`CanConstructBuildingFootprint` — 신규 배치/미리보기/재배치 3곳 동일 기준, 중복 계산 없이 footprint 리스트 재사용)
- `Factory` 생산시설(논/벌목장/채석장) 건설 → 인구 배치 → `OnDayStart` 정산까지 전체 파이프라인
- 인구 배치 시 최소/초과 인원에 따른 생산량 증감(`ResourceProductionData.CalculateYield`)
- 점령 원정 인구 비용(출격) / 반환 / 보상 지급(`ConquestPopulationCoordinator`)
- `ConquestUIExample`의 인구 비용 실제 검증(더 이상 항상-충족 우회 아님)
- 위 코디네이터 3종 전부 씬 배선 완료, 디버그 도구 3종 정상 동작
- 사용하지 않던 `FarmField.cs`(구 인구 필드 `_currentCap`/`_maxCap`만 가진 별도 클래스) 및 `ExistTypeOnCell.FarmField` 삭제 — 논 프리팹은 이미 `Factory`로 동작 중이라 실제로는 죽은 코드였음(어떤 프리팹도 이 스크립트를 참조하지 않음을 GUID로 확인 후 삭제)

### 아직 안 된 것 / 미검증

- 실 플레이로 논/벌목장/채석장 3종 모두 건설 → 인구 배치 → 아침 정산 → 원정 완료 → 보상까지 이어지는 풀 시나리오 수동 검증
- 연구 시스템 본체(청크 단위 Food 해금)는 인터페이스(`IChunkResearchUnlockQuery`)만 있고 구현체 없음
- 밸런스 수치(`YieldPerCycle`, `PopulationCapacity`, `MinimumRequiredPopulation`, `YieldPerExtraPopulation`, 각 청크의 인구 비용/보상) 전부 가배치 상태

## 10. 미결 사항

| 항목 | 비고 |
| --- | --- |
| 연구 시스템 본체 | 청크 단위 Food 해금 방식만 확정, 구현체는 추후 |

| 생산/인구/점령 관련 수치 밸런스 | 전부 가배치, 확정 수치로 교체 필요 |
