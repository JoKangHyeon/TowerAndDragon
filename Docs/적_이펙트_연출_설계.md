# 🗡 적 이펙트 연출 설계 (근거리 / 원거리 / 보스)

작성일: 2026-08-27 · 참고: [타워 투사체 연출 설계](./타워_투사체_연출_설계.md) · [타워 이펙트 작업 노트](./타워이펙트_작업노트.md)

타워 투사체 연출과 같은 구조로 적 공격에 연출을 붙인다. **연출은 3종만 만든다** — 근거리 / 원거리 / 보스.

---

## 1. 한눈에 보는 전체 그림

```
[MonsterAttack.Fire]
   │
   ├─ HasProjectile == true  ──▶ [ProjectilePool.Spawn] ← MonsterData._projectilePrefab
   │                              [Projectile.Launch] ─▶ ProjectileVisual.OnLaunched  (머즐+궤적)
   │                                    │ MoveTowards
   │                              [명중] ─▶ AttackSO.Execute (피해)
   │                                    └─▶ ProjectileVisual.OnHit  (원거리 명중 이펙트)
   │
   └─ HasProjectile == false ──▶ AttackSO.Execute (피해)
                                  └─▶ ★신규 훅: AttackSO._hitVfx  (근거리 / 보스 이펙트)

[SelfDestructBehavior.Detonate] ──▶ MonsterAttack.ExecuteBlast
                                     └─▶ ★신규 훅: 같은 필드, 시전자 발밑 1회
```

- 원거리는 **코드 변경 0**이다 — 이미 있는 `Projectile` / `ProjectileVisual` 경로에 프리팹만 꽂는다.
- 근거리·보스는 투사체가 없어 훅이 없다. 그래서 신규 코드는 **이 한 곳뿐**이다.

## 2. 현재 데이터 (에셋 실측)

`MonsterData` 34종 / 몬스터 프리팹 33종 / `AttackSO`(MA_*) 13종.

### 2-1. 3분류가 데이터에 이미 있다

| 분류 | 판정 근거 | 종수 | 쓰는 AttackSO |
|---|---|---:|---|
| **원거리** | `MonsterData.HasProjectile == true` | 6 | `MA_Ranged_Air` · `MA_Ranged_DragonHunter` · `MA_Ranged_Elite_DragonHunter` · `MA_Ranged_Sniper` |
| **보스** | `MA_Boss_*`를 쓰는 것 | 7 | `MA_Boss_1`(간격 1.5) · `MA_Boss_4`(간격 2.5) |
| **근거리** | 나머지 | 21 | `MA_CloseRange`(16종) · `MA_CloseRange_Elite`(2) · `MA_CloseRange_Destroyer`(1, 광역 1.5) · `MA_SelfDestruct`(1) · `MA_Paralyze`(1) |

**새 enum·새 플래그가 필요 없다.** 분류를 코드로 판정하지 않고, 그 분류에 해당하는 에셋이 자기 연출을 든다.

### 2-2. 분류에 쓰면 안 되는 필드

| 필드 | 쓰면 안 되는 이유 |
|---|---|
| `MonsterDisplayCategory` | UI 표시 전용. 주석이 전투 판정에 쓰지 말라고 명시. 보스 7종이 전부 `Field(0)`이다 |
| `MonsterType`(Normal/Special) | 보스 7종 전부 `Normal`. 특수행동 보유 여부에 가깝다 |
| `_isCrowdControlImmune` | 보스 7 + **엘리트 3**(`Ground_Elite`·`Elite_DragonHunter`·`Elite_VoidShell`)이 켜져 있다. 엘리트가 보스 연출을 받는다 |
| `MonsterCodexCategory.Boss` | 도감 카탈로그의 `_bossPrefabs` 목록에만 있고 직렬화되지 않는다. UI 전용 |

### 2-3. 원거리 6종은 프리팹 하나를 공유한다

`Assets/Prefabs/MonsterProjectileView.prefab` — `SpriteRenderer`(주황 틴트) + `Projectile`뿐,
**`ProjectileVisual`이 없다.** 궤적·머즐·명중 이펙트가 붙을 자리가 아예 비어 있다.

| MonsterData | 사거리 | 간격 | 투사체 속도 |
|---|---:|---:|---:|
| `MD_Air_Ranged` | 2 | 1.0 | 10 |
| `MD_Ground_Ranged` | 2 | 2.5 | 10 |
| `MD_Ground_DragonHunter` | 2 | 2.5 | 10 |
| `MD_Ground_Elite_DragonHunter` | 2 | 2.5 | 10 |
| `MD_Air_Sniper` | 5.5 | 6.0 | 10 |
| `MD_Ground_Sniper` | 5.5 | 6.0 | 10 |

## 3. 설계 결정

### 3-1. 연출 참조는 `AttackSO`가 든다 (근거리·보스)

```csharp
[Header("Hit VFX (근접 공격용 - 투사체가 있으면 ProjectileVisual이 대신 그린다)")]
[WiringOptional]
[SerializeField] private GameObject _hitVfxPrefab;
[Min(0f)] [SerializeField] private float _hitVfxLifetimeSeconds;
[SerializeField] private AttackVfxAnchor _hitVfxAnchor;   // TargetBody | CasterGround
```

| 후보 | 채워야 할 에셋 | 얻는 것 |
|---|---:|---|
| **`AttackSO` (채택)** | **7** | 3분류가 그대로 나온다. 판정 코드 0 |
| `MonsterData` | 34 | 몬스터별 자유. 지금 요구가 3종이라 낭비 |
| 몬스터 프리팹 컴포넌트 | 33 | 위와 같은 비용 + `[RequireComponent]`가 기존 프리팹에 소급되지 않음 |

`StatusEffectSO._activeVfxPrefab`이 같은 이유로 상태 쪽에 붙어 있다 —
"몬스터가 아니라 **행위**가 자기 연출을 갖는다".

**대가**: 보스 연출이 **최대 2종**으로 묶인다(`MA_Boss_1` = 보스1·2·3, `MA_Boss_4` = 보스4·최종 3종).
지금 요구가 "보스 1종"이므로 문제가 없고, 보스별로 갈라야 하면 4-1의 [팀 확인] 항목을 본다.

**타워 AttackSO(TA_*)는 이 필드를 비워 둔다.** 발화 지점이 `MonsterAttack`이라 타워는 읽지 않는다.
`AttackSO.Execute` 안에서 띄우지 않는 이유: 광역 공격은 `Execute`가 대상 수만큼 도는 경로
(`MonsterAttack.ExecuteBlast`)가 있어 **한 번의 공격에 N개가 터진다.**
"공격 1회"를 아는 것은 `MonsterAttack`이다.

### 3-2. 원거리는 `MonsterData._projectilePrefab` 그대로

이미 있는 필드다. **참조 위치가 둘로 갈리는 것(원거리 = MonsterData, 근거리·보스 = AttackSO)은 의도한 것이다** —
원거리는 연출 시점이 명중이라 투사체가 들고 있어야 하고, 그 배선이 이미 존재한다.
읽는 사람이 걸려 넘어지지 않도록 코드 주석에 이 문장을 남긴다.

### 3-3. 발사 원점 — `_firePoint`가 26개 프리팹 전부 비어 있다

`MonsterAttack._firePoint`가 전부 `{fileID: 0}`이라 투사체가 `transform.position`에서 나온다.
PixelWorld 시트의 피벗은 **발밑**이라 머즐 섬광이 발에서 터진다.

| 안 | 비용 | 판단 |
|---|---|---|
| 프리팹마다 FirePoint 자식 배선 | 손배선 26회 | 루트 스케일이 0.1~2.0으로 20배 갈려 있어 값도 제각각 |
| **`SpriteRenderer.bounds.center`로 유도 (채택)** | `MonsterAttack` 한 곳 수정 | 스케일 편차를 자동 흡수. `MonsterStatusVfx`가 이미 같은 방식 |

`_firePoint`가 배선돼 있으면 그것을 우선한다 — 기존 동작을 바꾸지 않는다.

## 4. 3종 연출안

색은 **타워와 겹치지 않게** 잡는다. 현재 타워: 파랑 210(Arrow) · 오렌지(Musket) · 보라 280(StoneMeteor) ·
화염/얼음/번개 원본색. **붉은색(0도) 대역이 비어 있어 적 전용으로 쓴다.**

| | 원거리 | 근거리 | 보스 |
|---|---|---|---|
| 위치 | 명중 지점(대상 몸통) | 대상 몸통 중앙 | **시전자 발밑** |
| 앵커 | `ProjectileImpactPlacement.Body` | `TargetBody` | `CasterGround` |
| 회전 | 진행 방향 | 시전자→대상 방향 | 없음(사방 확산) |
| 수명 | 0.4~0.6초 | 0.3초 | 0.8~1.0초 |
| 후보 원본 | `Projectile_V1_05_red` + `Impact_V1_05_red` + `Muzzle_V1_05_red` | `Impact_V2_12_cuts`(베기) | `Impact_V1_19_circle_bomb` 또는 `FX_Impact_StoneCrack` 계열 |
| 읽혀야 할 것 | "날아온다" | "맞았다" | "무겁다" |

- **보스는 발밑 충격파**로 무게를 준다. 근거리와 같은 타격 연출을 크게만 키우면 구분이 안 된다.
- **자폭(`MA_SelfDestruct`)·마비(`MA_Paralyze`)는 보스 프리팹을 재사용**한다 — 발밑 광역이라 성질이 같다.
  프리팹은 3개 그대로다.
- 크기는 프리팹 루트 스케일로 잡는다. 몬스터의 자식으로 붙이지 않으므로 몬스터 스케일(0.1~2.0)에 영향받지 않는다.

### 4-1. 배선표

새 프리팹은 `Assets/Imported/Prefabs/Projectile/Enemy/`에 만든다(타워의 `.../Tower/`와 같은 자리).

| 에셋 | 넣을 것 | 앵커 | 수명 |
|---|---|---|---:|
| `MonsterProjectileView.prefab` | `ProjectileVisual` 컴포넌트 + 궤적 / `Muzzle_Enemy_Ranged` / `Impact_Enemy_Ranged` | Body | 0.5 |
| `MA_CloseRange` | `Impact_Enemy_Melee` | TargetBody | 0.3 |
| `MA_CloseRange_Elite` | `Impact_Enemy_Melee` | TargetBody | 0.3 |
| `MA_CloseRange_Destroyer` | `Impact_Enemy_Melee` | TargetBody | 0.3 |
| `MA_Boss_1` | `Impact_Enemy_Boss` | CasterGround | 0.9 |
| `MA_Boss_4` | `Impact_Enemy_Boss` | CasterGround | 0.9 |
| `MA_SelfDestruct` | `Impact_Enemy_Boss` | CasterGround | 0.9 |
| `MA_Paralyze` | `Impact_Enemy_Boss` | CasterGround | 0.9 |
| `MA_Ranged_*` 4종 | (비움 — 투사체가 그린다) | — | — |

**[팀 확인]** `MA_Boss_2`(간격 2.0) · `MA_Boss_3`(간격 2.0)는 **어느 MonsterData도 참조하지 않는 고아 에셋**이다.
보스별로 연출을 가르려면 이것을 `MD_Boss_2`·`MD_Boss_3`에 물리면 되지만,
**공격 간격이 1.5 → 2.0으로 바뀌는 밸런스 변경**이라 임의로 하지 않는다.

**참고** `MD_Ground_Immune_Life`는 참조하는 프리팹이 없어 실제로 스폰되지 않는다. 배선 대상 밖.

## 5. 필요한 코드 변경 (최소)

| 파일 | 변경 |
|---|---|
| `Combat/AttackSO.cs` | `_hitVfxPrefab` · `_hitVfxLifetimeSeconds` · `_hitVfxAnchor` 필드 + 읽기 프로퍼티. **`Execute`는 손대지 않는다** |
| `Combat/AttackVfxAnchor.cs` (신규) | `TargetBody` / `CasterGround` |
| `Combat/AttackVfxPlacement.cs` (신규) | `ProjectileVisual.ResolveVisualImpactPosition` · `ResolveGroundY`를 static 헬퍼로 추출. `ProjectileVisual`도 이것을 쓰도록 교체 |
| `Monster/MonsterAttack.cs` | ① `Fire`의 비투사체 분기에서 1회 스폰 ② `ExecuteBlast` 진입부에서 1회 스폰 ③ `_firePoint`가 널이면 `SpriteRenderer.bounds.center`를 발사 원점으로 |

- 스폰은 전부 `ProjectilePool.PlayForSeconds` — **월드 좌표에 부모 없이 뜬다.**
  몬스터의 자식으로 붙이지 말 것(루트 스케일 0.1~2.0 편차, 사망이 `Destroy`라 연출이 함께 파괴돼 풀 장부에서 샌다).
- 새 `[SerializeField]`에는 전부 `[WiringOptional]`을 단다 — 없으면 와이어링 검사기가 전 에셋에서 미연결로 잡는다.
- `AttackVfxPlacement` 추출은 **필수**다. `ProjectileVisual`은 `sealed` + `[RequireComponent(typeof(Projectile))]`이라
  근거리 경로에서 재사용할 수 없고, 복사하면 [타워 이펙트 노트 §7](./타워이펙트_작업노트.md)의
  피벗 함정을 두 번째 구현에서 다시 밟는다.

## 6. 미리 확인해 둔 함정

| # | 내용 |
|---|---|
| 1 | **간격 0 공격이 둘 있다** — `MA_SelfDestruct`·`MA_Paralyze`. `UpdateEnRouteAttack`이 `_nextAttackTime = Time.time + 0`이라 사거리 안이면 매 프레임 `Fire`가 돈다. **지금은 안전하다** — 두 몬스터(Bomber·Paralyzer)가 `SelfDestructBehavior`를 달고 있고 그것이 `DisableAutoAttack()`을 부른다. **그래서 이 둘의 연출 훅은 `Fire`가 아니라 `ExecuteBlast`에 걸어야 한다.** 간격 0 공격을 자폭 행동 없이 배선하면 그 순간 풀이 프레임마다 새 인스턴스를 뱉는다 |
| 2 | **발밑은 스프라이트 경계로 잡지 않는다.** `bounds.min.y`는 사각형 밑변이고 PixelWorld는 발 위치에 커스텀 피벗을 둔다(보스1 오차 −0.818). `MonsterMovement.GroundPlanePosition`을 쓴다 — 지형 고저차 보정까지 들어 있다 ([노트 §7](./타워이펙트_작업노트.md)) |
| 3 | **`HorizontalBillboard`는 이 카메라에서 한 픽셀도 안 그린다.** 바닥 데칼 원본을 그대로 쓰면 보스 충격파가 통째로 사라진다. `Billboard` + `alignment = View`로 바꾸고 세로를 절반으로 눌러 2:1 타원으로 만든다 ([노트 §2-1](./타워이펙트_작업노트.md)) |
| 4 | **명중 이펙트는 버스트 방출이어야 한다.** 연속 방출(rateOverTime)은 입자가 쌓이는 데 시간이 걸려 명중 순간이 빈다 ([노트 §3-5](./타워이펙트_작업노트.md)) |
| 5 | **자식 이름으로 후보를 거르지 말 것.** 이 팩들은 이름과 실제 그림이 자주 어긋난다. 반드시 렌더해 픽셀로 확인한다 ([노트 §3-1](./타워이펙트_작업노트.md)) |
| 6 | **원본 기울기는 눕히지 않는다.** 57도쯤 뒤로 누운 메시가 화면에서 눌려 보이는 것이 곧 "셀 바닥에 놓인" 그림이다 ([노트 §2-2](./타워이펙트_작업노트.md)) |
| 7 | **`MinMaxCurve.constant`는 `constantMax`의 별칭이다.** 배수를 세 줄로 걸면 제곱으로 걸린다 ([노트 §3-10](./타워이펙트_작업노트.md)) |
| 8 | **근거리 트레이서는 만들었다가 제거된 전례가 있다**([노트 §5](./타워이펙트_작업노트.md)). 교훈은 "적용 범위를 재고 넓혀라" — 이번에도 **근거리 21종에 한 번에 붙이기 전에 대표 1종으로 플레이에서 읽히는지 먼저 본다** |
| 9 | 새 프리팹은 `Assets/Imported`에 들어간다. **별도 git 저장소다** — `git -C Assets/Imported`로 따로 커밋해야 팀에 공유된다 |

## 7. 범위 밖

- 적 사망·피격 연출(맞는 쪽), 스폰·포탈 연출
- 특수행동 자체의 연출(회복 오라·보호막 오라·재생 방어막) — `SpecialBehaviorSO`가 들 문제다
- 상태이상 지속 연출 — `StatusEffectSO._activeVfxPrefab`이 이미 담당한다
- 발사·명중 섬광 라이트(`VfxFlashLight`) — 3종이 확정된 뒤 타워와 같은 방식으로 붙인다
- 새끼용(`BD_*`)·타워 연출 변경

## 8. 진행 순서 제안

1. `AttackVfxPlacement` 추출 + `ProjectileVisual` 교체 (동작 변화 0, 회귀 확인용)
2. 원거리 — `MonsterProjectileView`에 `ProjectileVisual` + 프리팹 3종(궤적·머즐·명중). **코드 없이 여기까지 확인**
3. `AttackSO` 필드 + `MonsterAttack` 훅 2곳
4. 근거리 — 대표 1종(`MA_CloseRange`)만 배선해 플레이 확인 → 나머지 2종 확산
5. 보스 — `MA_Boss_1`·`MA_Boss_4` 배선 → 자폭·마비 재사용
6. `_firePoint` 널 시 몸통 중앙 유도
7. `Assets/Imported` 커밋 + 메인 저장소 커밋
